# 00 契约 —— 这趟 run 的需求基线

> run id：<run_id>
> 冻结时间：<ISO 时间>
> **这份文件唯一的写者是用户，经 PM 转写。任何 subagent 不得改它（H4 会拒）。**

## 1. 用户原话

<把用户在 /at 后面写的那段话逐字放在这里。不要改写、不要「顺一顺」、不要补全。
后面每一个角色的产出都要对着这段话验收；一旦转写时被润色过，那次验收就失去了基准。>

## 2. PM 的理解（可改）

<PM 对原话的结构化理解：要解决什么问题、给谁用、什么算做完。这一节可以改，
第 1 节不可以。>

## 3. 明确不做的事

<原话里没有要求、但容易被顺手做掉的事，列在这里，省得后面角色自作主张。
「不写自动化测试」不写在这里：要不要测试由用户定（第 1 节原话或第 4 节修订记录），写在这里也不算数。>

## 4. 修订记录

<用户的每一次改动都作为一个带日期的修订块追加在这里——升级问题的答复，或者用户在对话里主动提出的（标「用户主动提出」）。
每追加一块，契约的 sha256 就变了——把写契约那一次回传（【契约】）给的新哈希写进 state.json 的
contract_sha；升级问题那一种，escalations[] 里问之前记的那一条把 answer 补上，用户主动提出的不记 escalation。contract_sha 没跟上的，之后每一次派发返回、
每一次写 state.json 都会报【契约】；escalations 那一条门禁不核，靠 PM 做全。>
