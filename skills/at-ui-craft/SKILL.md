# 界面设计的做法

**这个 skill 防的是两种失效**：一是规格只画了「一切正常」那一屏，加载、空、出错、边界值留给实现者现编；
二是视觉落进了谁都会做出来的默认套路，跟这个产品、这群用户没有关系。

下面是做法的主干。细则按需 `Read`，不用一次读完：

| 什么时候读 | 文件 |
|---|---|
| 写动效表之前 | `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/motion.md` |
| 定颜色、写表单与可访问性条目之前 | `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/a11y-quality.md` |
| 目标平台有 iOS | `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/platform-ios.md` |
| 目标平台有 Android | `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/platform-android.md` |
| 交线框之前、`S5` 交实现记录之前 | `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/self-check.md` |

## 1. 先读项目已有的设计来源

动笔之前在项目里找：主题文件、设计 token（CSS 变量、`tokens.json`、Tailwind 配置、`Theme`/`Color` 资源）、
组件库、已有页面的截图或样式。找到了就**沿用**：同一个按钮不要出第二种样子，同一种灰不要再调一个近似值。
要偏离的，在规格里逐条列「偏离了什么、为什么」，没有理由的偏离一律收回。

项目里一份都没有，才从零定方向——那时第 2、3 节是你的主活。新建的 token 写成一份实现者能直接搬的清单，
不要只出效果描述。

## 2. 视觉方向：两遍

**第一遍**，出一份紧凑方案：

- 这是什么产品、给谁用、这一屏的主要任务是什么（派发单与产品定义里没写的，写成你的假设）；
- 颜色：4–6 个带名字的色值（底色、正文、次要文字、强调色、危险色……），说清各自的用途；
- 字体：用哪一两款、各担什么角色，一套字号阶梯；
- 布局：一句话说清版式，配一张 ASCII 线框；对齐方式定下来；
- 一两条只属于这个产品的原则——用户记住它靠什么。

**第二遍**，拿方案对着题复核：换一个同类产品来做，会不会得到差不多的东西？会的那一部分就是默认套路，
改掉，并写一句改了什么、为什么。常见的默认套路：

- 每一节都切成同样大小的圆角卡片，同一个阴影、同一个圆角，层级靠不出来；
- 「大数字 + 小标签 + 一排统计 + 渐变点缀」当首屏；
- 标题上面一行全大写的小眉标，标题里单挑一个词换颜色或斜体；
- 内容根本不是先后顺序，却编上 01 / 02 / 03；
- 米色底配衬线标题配陶土色强调，或者近黑底配一个荧光强调色，不管题目是什么都这样配；
- 用等宽字体装「技术感」，用表情或 Unicode 符号代替图标；
- 每一节进场都淡入上移，每张卡片都有悬停动画。

题目自己点名要的样子照做——用户的话永远优先；题目没管的那一项，别把自由花在默认套路上。
**大胆只花在一处**：让一个元素成为记得住的那一个，周围保持安静。

## 3. token 与层级

- token 分两层：原始值（色板、字号阶梯、间距阶梯、圆角、阴影、时长、缓动）与语义名（`surface`、`text-muted`、
  `danger`、`focus-ring`……）。组件只用语义名；换主题、加深色模式只动映射。
- 间距用一套阶梯（如 4 的倍数），组内紧、组间松，标题上方的空比下方大。
- 圆角嵌套时内层不大于外层；阴影要有偏移和柔和的模糊，零偏移的彩色光晕是装饰不是层级。
- 层级靠字号、字重、颜色深浅与留白拉开，不靠给每块都加边框。
- 有深色模式就成对给值，深色不是把浅色取反：底色用有色调的深灰，饱和度降一档。
- 数字要对齐比较的地方（表格、金额、计时）用等宽数字。

## 4. 状态与交互

**每块会取数据或会变化的区域，都要写出它的每一种状态**。至少：

| 状态 | 要写清的 |
|---|---|
| 首次加载 | 骨架与最终布局同构、位置相同，数据到了不跳动；不用整屏转圈 |
| 刷新中 | 保留旧内容，在触发它的控件或容器上表示正在刷新 |
| 空 | 为什么空 + 一个能做的下一步；「本来就没有」与「筛选后没有」分开写 |
| 出错 | 出了什么错、怎么恢复（重试、改输入、联系谁），不道歉、不含糊 |
| 处理中 | 按钮保持原宽度与原文字、防重复提交；异步确认弹窗等结果回来再关 |
| 边界值 | 很长的文字、零条、一条、很多条、超大数字、缺字段、慢网络 |
| 权限与离线 | 没权限、未登录、离线时各长什么样（项目里有这些情形才写） |

**每个可交互的控件写五态**：默认、悬停、按下、聚焦、禁用；会进入忙碌的再加加载中，会校验的再加出错。
悬停与按下的反馈对比度要比默认高；只能悬停才看得到的信息，触屏上要有别的入口。

表单：输入不拦着打字，离开字段或提交时再校验；错误写在字段旁边，提交失败时焦点移到第一个错误；
不禁止粘贴；破坏性操作要确认或者给撤销窗口。

## 5. 动效

先问**这个动效多常出现**：一天上百次、或者由键盘快捷键触发的（命令面板开合、切换标签）不加动画；
一天几十次的（悬停、开关、展开一行）只给极短的反馈；偶尔一次的（首次进入、完成一件大事）才配得上一段编排。每个动效要说得出目的——
指明因果、维持空间关系、给出反馈或引导注意，说不出目的就删。

- 时长分档：微反馈 80–120ms，按钮与开关 120–180ms，卡片与列表项 200–300ms，面板与弹窗 250–400ms，整页转场不超过 500ms；退场比进场短。
- 缓动：进场减速（ease-out），退场加速（ease-in），屏内移动先加速后减速；空间位移不用线性。
- 只动 `transform` 与 `opacity`；不动 `width`、`height`、`top`、`left`；不写 `transition: all`。
- 动效能被打断：用户中途反向操作，从当前位置接着走，不从头播。
- **每个动效写一个 reduced-motion 减弱版**：位移、缩放、视差换成短的淡入淡出或直接切换；
  用户开了「减弱动态效果」，界面照样把状态变化交代清楚。

动效表的列与更细的档位在 `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/motion.md`。

## 6. 无障碍底线

这几条是底线，不是加分项，规格里逐条写到：

- 对比度：正文与占位文字至少 4.5:1；大号文字（约 24px，或 18.7px 加粗）、图标与控件边界、焦点指示至少 3:1。
- 焦点看得见：不去掉 outline 又不给替代；固定头部与底栏不盖住焦点；弹窗打开时焦点进去、关掉后回到原处。
- 触控目标：Web 至少 24×24px（以触屏为主的再放大），iOS 至少 44×44pt，Android 至少 48×48dp；看起来小的元素把可点区域扩出去。
- 状态不只靠颜色：出错、选中、必填同时有文字或图形。
- 每个只有图标的按钮有可读的名称；装饰性的图形对读屏隐藏；标题层级连续。
- 系统字号放大（Web 放大到 200%、iOS 动态字体、Android 字体缩放）时不截断、不重叠。

细则在 `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/a11y-quality.md`。

## 7. 响应式

至少写三档：窄屏（手机竖屏）、中屏（平板或窄窗口）、宽屏；每档写清导航放哪、栏数怎么变、什么收起。
正文行宽控制在大约 45–80 个字符；宽屏不要把内容拉满整屏。顾及安全区（刘海、圆角、底部手势条）。
长文字、长数字、长链接在窄屏上怎么断行或截断，要写出来。

## 8. 内容诚实

- 用这个产品自己的话：按钮写它会做的事（「保存修改」，不写「提交」），同一个动作从按钮到提示用同一个词。
- 线框里的示例数据要像真的：真实长度的名字、会出现的长标题、零与很大的数。
- 不编造产品没有的数据、评价、用户数、客户标志；不知道的写成待定，不填一个好看的数。
- 不确定的地方写成假设并标出来；需要拍板的，以「冒泡：」开头交给派你的角色，不自己替用户定。

## 9. `S2` 交什么

**`02-ui-spec.md`**，按这几节写：

1. 设计来源：沿用了什么、偏离了什么及理由（第 1 节）；
2. 视觉方向：第二遍复核之后的方案，复核改了什么；
3. token：原始值与语义名两张表，深色模式成对给；
4. 页面与组件：每一屏的结构、组件清单、文案；
5. 状态矩阵：区域 × 状态，一格一句，写不了的格写「不适用」和原因；
6. 交互：每个控件的五态，表单校验与错误，键盘操作；
7. 动效表：每一行写触发、属性、时长、缓动、目的、reduced-motion 减弱版；
8. 无障碍：第 6 节的底线逐条落到这个产品上；
9. 响应式：各档的布局差异；
10. 假设与待定：你替谁做了什么假设、哪些要冒泡确认；
11. 设计自检：交之前照自检清单核线框与规格的结果（第 10 节的三栏写法），写在这一份里，不写进 `05-impl/at-ui.md`——那是 `S5` 的产物。

**`02-wireframe.html`**：一份自包含的 HTML，双击就能离线打开——样式、脚本、图标都内联，不引 CDN、
不引外部字体与图片。覆盖规格里的每一种状态（可以并排排开，或用一组切换按钮），用的就是规格里的 token。
关键转场用纯 CSS 写，并包在 `@media (prefers-reduced-motion: no-preference)` 里，减弱版在外面。

## 10. `S5` 交付前自检

实现落地之后、交 `05-impl/at-ui.md` 之前，照 `${CLAUDE_PLUGIN_ROOT}/skills/at-ui-craft/references/self-check.md`
逐条核，结果写进实现记录的一节「设计自检」，分三栏：

- **看过**：真的把页面跑起来、在浏览器或模拟器里看到的；
- **从源码推断**：只读了代码、没有亲眼看的；
- **没核**：这一次核不了的，写一句为什么。

没跑起来就不会有第一栏，不要把推断写成看过。手里有看页面的浏览器工具，照那份细则的「怎么看页面」截手机宽、桌面宽、减少动态
（有深色再加深色）各一张；哪种办法都看不到，照实写「没看过效果」。
