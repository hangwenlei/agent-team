# 交付前自检

`S2` 交线框之前、`S5` 交实现记录之前，逐条过一遍。`S2` 的结果写进 `02-ui-spec.md`，`S5` 的写进自己的实现记录。
每一条落到三栏之一：

- **看过**：页面真的跑起来了，在浏览器、模拟器或真机里亲眼看到（写明在哪看的、什么尺寸）；
- **从源码推断**：只读了代码或样式表，没有亲眼看；
- **没核**：这一次核不了的，写一句为什么（没跑起来、手里没有能看页面的工具……）。

**不要把推断写成看过**；核不了的写进「没核」，不写「通过」。

标「设计专项」的几条归做设计的人；执行角色碰到这几条里的问题只记下、冒泡给派你的角色，不自己改设计。

## 一、对着规格

- [ ] 规格里的每一屏、每个组件都在，文案与规格一致。
- [ ] 用的是规格里的 token（语义名），没有新冒出来的近似色值、近似间距。
- [ ] 偏离规格的地方逐条列出并写了理由（设计专项；执行角色只列出、冒泡）。

## 二、状态

- [ ] 状态矩阵里每一格都实现了：首次加载、刷新中、空（两种）、出错、处理中、边界值。
- [ ] 骨架与最终布局同构，数据到了不跳；没有整屏转圈。
- [ ] 每个可交互控件的五态都在：默认、悬停、按下、聚焦、禁用。
- [ ] 提交中的按钮保持宽度、防重复提交；失败时错误就近显示、可以重试。
- [ ] 很长的文字、零条、很多条、缺字段时不破版。

## 三、无障碍

- [ ] 正文对比度 4.5:1，大字与图形 3:1（写出核过的几对与比值）。
- [ ] 只用键盘走一遍：每个控件到得了、焦点看得见、顺序对、弹窗能进能出。
- [ ] 触控目标达到平台下限（Web 24px、iOS 44pt、Android 48dp）。
- [ ] 只有图标的按钮有名称；状态不只靠颜色。
- [ ] 字号放大（Web 200%、iOS 最大动态字体、Android 200%）时不截断、不重叠。

## 四、动效

- [ ] 每个动效都在动效表里，时长与缓动一致。
- [ ] 只动 `transform` 与 `opacity`，没有 `transition: all`。
- [ ] 打开「减弱动态效果」之后，每个动效都换成了减弱版，状态变化照样看得出。
- [ ] 动效能被打断，连点几下不乱。

## 五、响应式

- [ ] 窄、中、宽三档各看一遍：没有横向滚动条、没有被裁掉的内容。
- [ ] 安全区处理正确（刘海、底部手势条）。
- [ ] 正文行宽没有在宽屏上被拉满。

## 六、视觉（设计专项）

- [ ] 远看（缩小或眯眼）层级清楚：主操作一眼找得到。
- [ ] 没有落进默认套路（同一个圆角卡片铺满、标题上的小眉标、无意义的编号、表情当图标）。
- [ ] 浅色、深色主题都看过（有深色模式时）。
- [ ] 去掉一件多余的装饰。

## 线框专项（`S2`）

- [ ] 双击就能离线打开，没有任何外部请求（CDN、字体、图片）。
- [ ] 每种状态都能在线框里看到。
- [ ] 关键转场是纯 CSS，完整版包在 `prefers-reduced-motion: no-preference` 里。

## 记录的写法

```markdown
## 设计自检

### 看过
- 状态：首次加载、空、出错在 Chrome 1280×800 与 390×844 下看过，骨架与内容同构。
- 键盘：Tab 走完登录表单，焦点环可见，提交失败时焦点落到第一个错误。

### 从源码推断
- 对比度：按 token 色值推算正文 7.1:1、次要文字 4.6:1，没有用工具量。
- 减弱动态效果：样式表里每个 transition 都在 no-preference 媒体查询里，没有实际切换系统设置看。

### 没核
- Android 字体放大 200%：手里没有模拟器。
```
