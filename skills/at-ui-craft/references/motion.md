# 动效细则

## 先过三道门

1. **频率**：一天出现上百次、或由键盘快捷键触发的动作（命令面板开合、切换标签、列表里的选择）不加动画；
   一天几十次的（悬停、开关、展开一行）只给极短的反馈；偶尔一次的（第一次打开、完成一笔订单）才值得编排。
2. **目的**：说得出它在交代什么——东西从哪来、到哪去（空间关系）；操作被收到了（反馈）；什么变了（状态）；
   该看哪里（引导）。只为「显得精致」的动效删掉。
3. **代价**：动效让用户多等了吗？挡住了下一次操作吗？重复看第一百次还顺眼吗？

## 时长

| 元素 | 时长 |
|---|---|
| 工具提示、微反馈 | 80–120ms |
| 按钮、开关 | 120–180ms |
| 图标切换 | 150–250ms |
| 卡片、列表项进出 | 200–300ms |
| 弹窗、抽屉、底部面板 | 250–400ms |
| 整页转场 | 300–500ms |

- 退场取进场的三分之二左右：东西离开时用户已经不看它了。
- 移动距离越远可以略长，但界面里的交互动效不超过 500ms。
- 悬停反馈 100ms 内开始，按下反馈 150ms 内开始，拖动 50ms 内跟手。
- 一组元素依次进场，每个间隔 30–60ms，整组不超过 400ms；元素多就分组，不要一个个排队。

## 缓动

| 场景 | 缓动 |
|---|---|
| 进场 | 减速：`cubic-bezier(0.2, 0, 0, 1)` 一类 |
| 退场 | 加速：`cubic-bezier(0.3, 0, 1, 1)` 一类 |
| 屏内从一处移到另一处 | 先加速后减速 |
| 旋转加载、进度条 | 线性 |
| 跟手的拖拽与松手回弹 | 弹簧（有阻尼、不来回晃） |

出错时不回弹、不弹跳；庆祝类的场景才允许明显的过冲。同一种交互在全产品里用同一条曲线、同一个时长，
写成 token（`--motion-fast`、`--ease-enter`……）。

## 写法上的规矩

- 只动 `transform` 与 `opacity`；`width`、`height`、`top`、`left`、`margin` 一动就重排，掉帧。
- 不写 `transition: all`，逐个写要过渡的属性。
- 弹出的东西从触发它的位置长出来（`transform-origin` 对准触发点），不从屏幕中央凭空冒出。
- 不从 `scale(0)` 开始：从 0.95 左右加淡入，看起来是「出现」而不是「膨胀」。
- 会被频繁打断的界面（悬停菜单、开关）用过渡而不用关键帧动画：过渡能从当前值掉头，关键帧会从头播。
- 一屏里同时在动的元素不超过三分之一；重要的状态变化不只靠透明度，再配位置、形状或文字。
- 超过 5 秒、和别的内容并排的自动播放动画，要能暂停或关掉。

## reduced-motion 减弱版

每一行动效都写一个减弱版，原则是「状态照样交代，只去掉运动」：

| 原动效 | 减弱版 |
|---|---|
| 滑入、上移进场 | 短淡入（100–150ms）或直接出现 |
| 缩放弹出 | 淡入 |
| 视差、跟随滚动 | 静止 |
| 自动轮播 | 停在第一张，给手动切换 |
| 加载旋转 | 保留（它在交代「正在进行」），或换成不旋转的进度条 |

CSS 写法：默认写减弱版，完整版包在 `@media (prefers-reduced-motion: no-preference) { … }` 里；
iOS 读「减弱动态效果」设置，Android 读「移除动画」设置，做法相同。
