# 无障碍与质量细则

## 颜色与对比

- 正文、占位文字、表单里的已填值：对背景至少 4.5:1。
- 大号文字（约 24px 常规，或约 18.7px 加粗）：至少 3:1。
- 图标、输入框边框、开关的轨道、焦点指示这类「看清才能操作」的图形：对相邻颜色至少 3:1。
- 禁用态可以低于这些值，但要让人看得出它是禁用的，而不是坏了。
- 彩色背景上的次要文字从背景的色相或前景色里调，不用中性灰（灰在彩色上发脏）。
- 图表配色要让色弱的人也分得出：再配形状、纹理或直接标注。
- 悬停、按下、聚焦时对比度只升不降。

在规格里给每一对前景 / 背景写出比值；没有工具算的，写出色值，并在自检里标「未核对比度」。

## 键盘与焦点

- 每个能点的东西用键盘也到得了、用得了，顺序跟视觉顺序一致。
- 焦点指示用 `:focus-visible`，至少 2px、与相邻颜色 3:1；不写 `outline: none` 又不给替代。
- 弹窗、抽屉打开时焦点进去并困在里面，`Esc` 关闭，关闭后焦点回到打开它的控件。
- 固定的头部与底栏不盖住获得焦点的元素（锚点与焦点留出 `scroll-margin`）。
- 拖拽、滑动、捏合都要有点按或键盘的替代做法。

## 语义与读屏

- 先用原生元素：导航用链接，动作用按钮，表格用表格；不用 `div` 加点击事件冒充。
- 只有图标的按钮写可读的名称（`aria-label` 或可访问的文字）；装饰性图形对读屏隐藏。
- 标题层级连续，一页一个主标题；有「跳到正文」的入口。
- 提示、校验结果、轻提示用礼貌的实时区域播报，不抢焦点。
- 状态不只靠颜色：出错的字段同时有图标与文字，选中的同时有勾或加粗。

## 触控与输入

- 触控目标：Web 至少 24×24px，以触屏为主的放到 44px；iOS 至少 44×44pt；Android 至少 48×48dp。
  目标之间留出间隔，看起来小的元素把可点区域扩出去，而不是把图标放大。
- 移动端输入框字号不小于 16px，避免系统自动缩放页面；不禁止用户缩放。
- 输入框带正确的类型与自动填充提示（邮箱、电话、验证码、密码），允许密码管理器与粘贴验证码。
- 复选框、单选框的文字与控件是同一个可点区域。

## 文字与内容承载

- 系统字号放大到 200%（Web）、最大动态字体（iOS）、字体缩放 200%（Android）时，不截断关键文字、不重叠。
- 容器要扛得住很短、一般、很长三种内容；弹性布局的子项允许收缩（`min-width: 0`），长词能断行。
- 日期、时间、数字、货币按用户的语言区域格式化；比较用的数字用等宽数字。
- 品牌名、代码、标识符不让自动翻译改掉。

## 常被漏掉的质量点

- 骨架与最终内容同构，图片写明尺寸，数据到了不跳。
- 浏览器自带的部分也属于设计：文字选中色、光标色、滚动条、链接下划线的位置，从 token 里取。
- 深色主题声明 `color-scheme: dark`，原生下拉框显式给背景与文字色。
- 网址反映状态：筛选、标签页、分页、展开的面板能被分享和用前进后退找回。
- 离开有未保存修改的页面前提醒。
