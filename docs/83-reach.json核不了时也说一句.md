# reach.json 核不了时也说一句

> 2026-10-11，分支 `r41-reach-unchecked`。第四十一轮（从开放边界索引挑）：`docs/42` §4「不核的几种时候一声不吭」。

## 0. 一句话结论

- 项目经理写完 `.agent-team/reach.json`，门禁按当前 `project.json` 与花名册重算核一遍，对不上就回一段【触达表】。核不了的几种时候——`project.json` 不在、
  这一刻读不出（被短暂占用，复核之后补的，§8）、有阻断、花名册读不出（插件问题）、刚写的 `reach.json` 读不出——原来一声不吭，而 `/agent-team:at-init` 说「这一次没再收到【触达表】，就是对上了」：没核被读成了对上。
  现在核不了时也回一段【触达表】：「这一次没有核刚写进 `.agent-team/reach.json` 的那一份」、为什么、怎么办，并点明没收到核对结果不等于对上了；at-init 那一句补上
  「收到的是『这一次没有核』那一段的，照它说的做，不算对上」。

## 1. 问题

- `reachNoticeFor` 在核不了时返回空，账本这一次什么都不说；没有 run 的那一条缝（`/agent-team:at-init` 写 `reach.json` 时）在 `project.json` 不在、或者这一刻读不出
  （只读一次）时也不说（读得到、却解析不出的，原来就有「它在别处被弄坏」那一段）。
- 前两种（有阻断、插件问题）之前写 `project.json` 那一次的【触达表】已经叫项目经理先别写；可它写了，门禁还是不说话，at-init 的那一句就让它当成对上了。

## 2. 修法

- `hooks/gate.mjs` 的 `reachNoticeFor` 与 `reachUnchecked`：核不了时按原因各给一段（`REACH_UNCHECKED` 打头、`REACH_NOT_MATCHED` 收尾）——`project.json` 不在（先跑
  at-init 写好它，写它那一次的【触达表】给出正确的那一份）、插件的花名册读不出（不要照着改；插件重装或更新之后新开会话再跑 at-init 落盘，刚写的这一份不当成上一份
  配置——与写 `project.json` 那一次的「这次算不出来」同一个出路）、有阻断（有阻断时门禁不核，先改到没有阻断——与「这次不发」同一个口径，不说算得不对）、刚写的读不出
  （再写一次；异常消息里的路径是项目根拼出来的，照规矩过 `quote`）。「不是对象」那一支是防御，两个调用方都只传对象或 null。写的人不是项目经理的，这几种后面都加
  「这件事归项目经理：原样冒泡，不要自己写 project.json 或 reach.json」。
- 没有 run 的那一条缝：`project.json` 不在也调它；在、这一刻却读不出时照写 `project.json` 那一条缝重读（`readProjectText`，最多三次）——读到对象照常核，一直读不到说
  「这一刻读不出来，过一会儿再写一次」，读得到却解析不出的照旧落到「它在别处被弄坏」那一条缝，那一条缝用这一次重读的结果、不再读第二轮。
- `commands/at-init.md`：那一句补上收到「这一次没有核」的不算对上。

## 3. 判据与变异

- `tests/reach-unchecked.test.mjs`：有阻断（有 run、没有 run）、花名册读不出（拷一份插件、换掉花名册；不给 JSON；出路是新开会话再跑 at-init）、刚写的读不出（建成一个目录）、
  `project.json` 不在（有 run、没有 run）四种都说「这一次没有核」与「没收到核对结果不等于对上了」；at-init 时 `project.json` 被占用（`tests/fixtures/fail-project-read.cjs`
  预加载、读它时抛 EBUSY）：失败一次重读读到了照常核，一直失败说这一刻读不出；对得上照旧不出声；不是项目经理写的叫它冒泡；正文那一句。原来钉着 at-init 那一句的判据
  （`tests/ledger-status-prose.test.mjs`）跟着改。
  > **订正（2026-10-11，`docs/84` §8）**：`tests/fixtures/fail-project-read.cjs` 已删，那一条判据改用 `tests/helpers/fail-read.mjs`（包的是已有的 `tests/helpers/project-reads.cjs`）。
- 变异（备份在仓库外，每一刀改完逐字节还原）：阻断时不说、插件问题不说、读不出不说、不在不说、没有 run 时不认不在、不分写者——每一刀都有判据红。复核之后又加了：
  不重读、重读读到了也不用、读不到也不说、插件问题照旧说法、不复用重读（坏文件停顿翻倍，原来那条「两次停顿」的判据红）、非项目经理不加后缀——每一刀都有判据红。

## 4. 仍然开着的边界

- **`project.json` 读得到、却解析不出时**（没有 run 的那一条缝）：照旧落到「它在别处被弄坏」那一条缝，那一段说 `project.json` 的问题，不提 `reach.json` 没核。
  > **收口（2026-10-11，`docs/87`，v6.4.0）**：写 `reach.json` 那一条缝自己接住这一种——同一段回传里先说【触达表】这一次没有核，再接【project.json】那一段；
  > 有 run 的时候同样。
- **run 进行中、`project.json` 这一刻读不出**：运行上下文判成读不出、走另一支（`docs/30` 那一族），这一条缝管不到。
- **只报不拦**：项目经理照旧可以在核不了的时候写 `reach.json`；at-status 照它报。

## 5. 没量到的

- 真实会话里 at-init 在阻断处写了 `reach.json`、收到「这一次没有核」之后怎么做。

## 6. 归属

- `hooks/gate.mjs` 的 `reachNoticeFor`、`REACH_UNCHECKED`、`REACH_NOT_MATCHED` 与没有 run 的那一条缝；`commands/at-init.md`；判据在 `tests/reach-unchecked.test.mjs`。

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：at-init 的正路（首跑、重跑、只有「要改」「请确认」）与旧版一致；照新说法做（改到没有阻断、写好 `project.json`、再写一次）
都收得住；同一次回传不打架。没有高的，一个中等、几个小问题：

- **中：at-init 时 `project.json` 被短暂占用，写 `reach.json` 照旧一声不吭**——这一格正是 `docs/42` §4 原文点名的「那一刻读不出（这条缝只读一次）」，文档却写成整条
  关上了；「它在别处被弄坏」那一段只对读得到、解析不出的说话。→ 照写 `project.json` 那一条缝重读最多三次，一直读不到说这一次没有核。
- **低**：花名册读不出时说「保持原样」，可 `reach.json` 已经被覆盖了，出路也少了「新开会话再跑 at-init」（→ 与写 `project.json` 那一次看齐）；有阻断时说「照它算的触达表
  不准」违背既有的措辞裁定（→ 改成有阻断时门禁不核）；「不是对象」那一支是死代码，文档却算成新堵上的一格（→ 文档改了，代码里注明是防御）；`staleReachFor` 的注释、
  HANDOFF 说宽了（→ 改了）；「不在」的出路两处不一，非项目经理写者的后缀只禁 `reach.json`（→ 统一成跑 at-init，后缀两份都禁）；异常消息没补进 trusted-echo 的
  入口清单（→ 消息里的路径是项目根拼出来的，没有谁写得进的值，照规矩过 `quote`，§2 写明）。
