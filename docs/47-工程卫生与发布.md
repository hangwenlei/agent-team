- **第 48 条**：`.gitignore` 加了 `.playwright-mcp/` 与 `scratchpad/`；加了 `.gitattributes`（`* text=auto eol=lf`）；`hooks/`、`scripts/`、`tests/helpers/`、

- **第 45 条**：有了 `CHANGELOG.md`（一版一行、最新的在最上面），版本号往前挪时版本检查要求它最上面那一行就是这一版；推 `main`、判据与版本检查都过了

## 1. 修法

### 1.1 第 33 条：五处判据缺口

- **G10、CK4**：新判据 `tests/gate-fail-closed.test.mjs`。外部输入自然触发不到判定中途的崩溃，用 `tests/helpers/inject-throw.cjs` 预加载让它中途抛异常：H1 认目标
  角色时调 `startsWith`（`prefix:` 注入），H6 读验收结论首行时调 `normalize`（macOS 上路径归一化先调它，同样在判定中途）。核最外层 catch 对 fail closed 的
  检查项给出拒绝、理由带上异常消息；H6 那一条先核不注入时这次收口放行，再核注入之后拒。
- **WP1**：`tests/writepath.test.mjs` 追加——认领 `src/server` 的，写得了 `src/server/` 下与 `src/server` 本身，写不了 `src/server2/`、`src/serverless.ts`。
- **C9**：`tests/runctx.test.mjs` 追加——`current-run` 末尾带 LF、CRLF、空白，照样认出那一趟。
- **RW6**：`tests/rework-guard.test.mjs` 追加——`rework` 缺了、写成 null、数组、字符串时当空对象：没有返工史放行（不崩、不把数组下标当段），有返工史照「不可重置」
  拒（拒的是判据本身，不是崩溃之后的兜底）。

### 1.2 第 48 条：工程卫生

- `.gitignore`：加 `.playwright-mcp/`（Playwright 的快照只能写在仓库下这个目录，测完要删，忘了也不进仓库）与 `scratchpad/`（忽略只管 git——`node --test`
  照样递归收它下面的 `*.test.mjs`，所以仓库里还是不要建它）。
- `.gitattributes`：`* text=auto eol=lf`（`docs/11` §5.28 的修法）。索引里本来就统一是 LF（加之前核过：每一个跟踪文件都是 `i/lf`），所以不需要另做一次重新
  归一化的提交；加了之后每个系统签出的工作区副本都是 LF，Windows 上装下来的插件副本也是 LF。之前签出的 CRLF 副本在 git 重新签出之前还是 CRLF，git 不把
  它们报成改动（核过）。
- 语法检查：`tests/hygiene.test.mjs` 对 `hooks/`、`scripts/`、`tests/helpers/`、`tests/fixtures/` 下的每一份 `.mjs`、`.cjs`、`.js`（判据文件除外——它们由 `node --test`
  加载，语法错了当场就红）跑一遍 `node --check`。它起的是语法检查、不执行门禁代码，登记进 `tests/gate-runner.test.mjs` 的白名单。
- 分支：本地 11 条已合进 `main` 的删掉；`m3c-missing-pointer` 没合，但它的树与已合的 `m3c-clean` 逐字相同（`e7285fc`），一并删掉。远端本来就只有 `main`。
- 不建 `package.json` 照旧（HANDOFF 的长期决策）：语法检查进了判据，CI 在三个系统上跑它。

### 1.3 第 45 条：更新记录与 tag

- `CHANGELOG.md`：开头一段说明（一版一行、最新的在最上面、版本号的挪法、每一版都有 tag），下面每一版一行「- x.y.z：这一版改了什么」。2.9.0 及更早的 48 版照它
  第一次合进 `main`（`main` 的 first-parent 历史上 `plugin.json` 第一次是那个版本的提交）的那一次提交的标题整理，去掉提交类别前缀与末尾的版本号注记。
- 版本检查（`scripts/lib/version-bump.mjs` 的 `latestChangelogVersion` 与 `judgeVersionBump` 的 `changelog`）：版本号往前挪时，事件之后那个提交的 `CHANGELOG.md`
  最上面那一行（第一个以「- 」开头的行）要是「- 这一版：…」（冒号后面有话）——没有这个文件、没写这一版、写在下面、最上面那一行写坏了，都不通过。CLI 总是
  传它；纯函数不传就不核（只测版本号那几条的判据）。
- tag：`ci.yml` 加一个 `tag` 作业——只在推 `main` 上、`test` 与 `version-bump` 都过了之后，按 `plugin.json` 的版本打 `vX.Y.Z`，远端已经有了就不动；只有这个作业有
  写权限，工作流默认只读。`ci.yml`、`min-node.yml` 的 `push` 改成只认分支（`branches: ['**']`）：不写的话推 tag 也会触发它们。
- 历史各版的 tag：合进 `main` 时照 §1.3 第一条认出的提交补打（只推 tag，不改提交）。
- README 两半：更新那一段写明每一版改了什么在 `CHANGELOG.md`、每一版都有 tag；开发者那一节的版本纪律补一句每挪一次在最上面加一行、推 `main` 之后 CI 打 tag。

## 3. 实测

- CI：功能分支与合进 `main` 之后各跑一遍（ci 三个系统、min-node）。`tag` 作业只在推 `main` 时跑，结果写在合并之后的收口里。

## 4. 不做的与仍然开着的

- **at-outsider 挪出载荷：不做。** 它是花名册不变量（「任何角色都不该能派它」）的对照物：`roster.json` 里有它的键，`hooks/lib/project.mjs`、`writepath.mjs` 按它判，
  十来份判据拿它当被拒的那一方。挪出 `agents/`，要么花名册里留一个指向不存在的角色的键，要么判据改用测试期另搭的花名册——两样都让判据测的不再是发出去的那一份。
  用户这边的代价是 agent 列表里多一个只有 `Read`、描述写着「测试替身，不是真角色」、谁都派不到的条目。**什么会让答案改变**：有用户因为它困惑；或者做「载荷挪进
  子目录」时一起挪（那时测试本来就要指向另一份花名册）。
- **载荷挪进子目录（L）**：照旧暂缓（`docs/39` §2.4）。
- **tag 作业挂了**：`main` 已经推上去、用户已经能更新，只是少了那一版的 tag——下一次推 `main` 不会补它（只打当前版本）；要人看着 CI 补打。
- **历史各版的更新记录照提交标题整理**：早期几版的标题写的是过程（「九次还是十次」这类），不是给用户看的结论；不回头改写。
- **之前签出的 CRLF 副本**：在 git 重新签出之前还是 CRLF；锚串替换照旧断言命中数、写完扫控制字节。
