# stage_roles 记成空数组时的报法

> 2026-10-11，分支 `r39-stage-roles-empty`。第三十九轮（从开放边界索引挑）：`docs/48` §4「`stage_roles` 里一段的值是 `[]`（记了账、一个都没叫）时，
> `/agent-team:at-status` 与 `/agent-team:at-resume` 怎么报那一段，正文没写」。

## 0. 一句话结论

- 产物随参与者展开的段（`S2`、`S5`）里，这一段的记录里一个产者都没有（记成 `[]`、或者只记了协调者——`S5` 里被叫去分发的 `at-architect`）时，按段展开是
  空集：`participantsOf` 给空、`isStageDone` 答「没齐」、不并派发记录（`docs/77`）。两条命令照这个口径说：
  - `/agent-team:at-resume`：空集要么是还没记账，要么是记了账、一个产者都没叫，两种都不说明没人干过活，照磁盘核；整段裁掉了又要从这一段继续派人的，派之前先把
    要派的人从 `trimmed` 里拿掉。
  - `/agent-team:at-status`：还停在这一段的照「本段未记账」那样标、那样报（包括 ✗）；已经推进出去的先看 `trimmed`，分「整段裁掉」与「记了账、一个产者都没叫」，
    这一段的产者交的、后面某一段要它当前置的那几份（`S2` 里 `at-product` 的 `01-prd.md`）照磁盘报 ✓ / ✗，其余不报 ✗。产物固定的段记成 `[]` 展开不是空集，
    照常按展开结果报。「当前阶段」那一格也认这一种。
- 推进那一侧（H6）对没有键与记成 `[]` 不同：没有键拒（「核不了」），记成 `[]` 放行、而且并上派发记录要它们交（`advance.mjs` 的 `departureNeeds`）。这一轮不动门禁。

## 1. 问题

- at-status 原来只对「有 `stage_roles` 却还没有这一段的键」说「本段未记账」；记成 `[]` 的段落进「展开不为空的照常报」那一句之外，报成什么正文没写。
- at-resume 原来把空集写成「这一段还没记账（`stage_roles` 里还没有这一段）」，与它自己叫模型去读的 `stages.produces.md`（「键在、值是 `[]`：记了账、这一段一个
  产者都没叫」）说法相反；整段裁掉了又要继续派人时，没说要先从 `trimmed` 里拿掉。「不算齐了」那一条的标题本来就覆盖了空集，照磁盘核这一点不变。

## 2. 修法

- `commands/at-resume.md`：「展开出来是空集」那一条改成「空集要么是这一段还没记账……要么是记了账、一个产者都没叫（这一段记的是 `[]`、或者只记了协调者），两种都
  不说明没人干过活」，后面加整段裁掉了又要派人时先从 `trimmed` 里拿掉。
- `commands/at-status.md`：「本段未记账」那一段后面加一段（只管产物随参与者展开的段，见 §0）；「当前阶段」那一格的「还没有这一段」后面加「或者记的是 `[]` 或者
  只记了协调者」。

## 3. 判据与变异

- `tests/stage-roles-empty-prose.test.mjs`：at-resume 那一条的整句与 `trimmed` 那一句；at-status 那一段的五个承重短语（触发条件含只记协调者、停在这一段照「本段未记账」
  包括 ✗、推进出去的按 `trimmed` 分两种标法、前置照磁盘报 ✓ / ✗ 其余不报、产物固定的段照常报），位置在「本段未记账」之后、`S5` 实现记录之前，「当前阶段」那一格。
  原来钉着旧措辞的两条（`tests/ledger-status-prose.test.mjs` 的「当前阶段」、`tests/stage-roles-prose.test.mjs` 的「空集」）跟着改。
- 变异（备份在仓库外，每一刀改完逐字节还原）：两种标法对调、`trimmed` 条件放宽成「有一个在」、前置也不报 ✗、删掉停在这一段那句、不认只记协调者、不限产物固定的段、
  at-resume 不提 `trimmed`、at-resume 不认「记了账」——每一刀都有判据红。

## 4. 仍然开着的边界

- **at-status、at-resume 是正文**：判据只核写没写，模型照不照着报没有判据去跑（`docs/42` §4 那一条）。
- **「整段裁掉」照 `trimmed` 认**：门禁的整段裁掉还要这一段一个都没叫过（派发记录里也没有，`advance.mjs` 的 `wholeStageTrimmed`）；at-status 不读派发记录，
  派过又裁掉的也会被标成「整段裁掉」。
- **推进那一侧对 `[]` 照旧放行**：`S2` 记成 `[]`、没裁、`01-prd.md` 不在时 H6 放行，到 `S3` 派人时 H2 才按前置拒（`docs/77` §4「`stage_roles` 记成 `[]`」那一条）；
  at-status 现在会对那份前置报 ✗。

## 5. 没量到的

- 真实会话里 `stage_roles` 记成 `[]`、或者只记了协调者之后跑 at-status、at-resume 的报法。

## 6. 归属

- `commands/at-status.md`、`commands/at-resume.md`；判据在 `tests/stage-roles-empty-prose.test.mjs`。

## 7. 受影响的旧说法

以本文为准，原话不改，订正与收口写在原话的标题底下：

- `docs/48` §4「`stage_roles` 里一段的值是 `[]`」：写了收口。
- `docs/00-开放边界.md`：`docs/48` §4 那一行改了，这一份的 §4、§5 登上。

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：照新正文做（停在 `S5`、先记成 `[]`、照磁盘核、推进那一次记账）没有撞上门禁的拒绝；`participantsOf` 与 `isStageDone` 的
口径与正文一致；运行时正文的规矩没破。四个中等、三个小问题：

- **中 1：没限定到产物随参与者展开的段**——第一版写「记的是 `[]` 时展开同样是空集」，对 `S3`、`S6`、`S7` 不成立（展开出固定产物），而且「不报 ✗」与「展开不为空的照常报」
  对同一格相反。→ 限定段；产物固定的段照常报。
- **中 2：只记了协调者没覆盖**——门禁把它与 `[]` 当一类，正文两段都碰不到它。→ 触发条件写成「记录里一个产者都没有」。
- **中 3：`S2` 记成 `[]`、没裁、`01-prd.md` 不在时不报 ✗**——比「叫过又裁」报得还宽，下一段被拒的原因藏起来了。→ 后面某一段要它当前置的那几份照磁盘报。
- **中 4：停在这一段时自相矛盾**——一边标「一个都没叫」，一边照「本段未记账」按分工报。→ 停在这一段的直接照「本段未记账」标、那样报，包括 ✗。
- **低**：§0 与判据头注释说门禁对 `[]` 与没有键同一个口径，H6 其实不同（→ §0 写明）；at-resume 的说法与 `stages.produces.md`、at-status 相反，整段裁掉又要派人时没说先从
  `trimmed` 拿掉（→ 改了）；换标法、放宽条件、改「不报 ✗」的口径都打不红（→ 判据钉承重短语）；§1、§4 两处说过头（→ 改了）。
