**七条验证项全部拿到真实环境证据，全部记录级；两条观察项都有答案。**

所以 Task 3 新加的那条不变量**不是机械承重的**——漏一个名字，那条边照样能走。

正文里必须有 `Agent(...)`。（裁定与落地见 §3.7 末尾：「理由换成认知上的」。）

**这一趟是这个项目第一次有真实 run 走完 S1→S8**（M1 的链到 S5，M2a 也到 S5）：

逐字相同、`never_invoked` 由 PM 自己算出且与我的独立复算一致。

整趟没有产出，而 `isStageDone` 与账本比对都因为 `roster` 里没有 `at-ui` 而看不见它们**。

验证项 1 的另一半因此要说准确：`at-ui` 写自己那两份的能力**在夹具 run 里验到了（两次）**，

### 3.1 第 1 条：`at-ui` 在 S2 真能写出自己那两份——**记录级证据**

     "spawnDepth":2,…}

两份转录里的写入（`sidechain` 一列为 `true` 表示这是子代理自己那条支线）：

    --- 子代理 agent-a336467d2829c3241  agentType=agent-team:at-product ---
    2026-09-20 10:56:12  Write   true   docs/product/01-prd.md
    2026-09-20 10:56:30  Agent   true   agent-team:at-ui
    2026-09-20 10:57:44  Write   true   runs/20260920-1100-s2-whitelist/01-prd.md

## 10. 附注

### 10.1 `claude --bg --resume <id>` 续一个**仍在运行**的后台会话，会起一个副本

本轮三次 `--resume` 全部撞到，CLI 原话（逐字）：

    note: session 0f7498bc is already running in the background, so this started a copy as f46ae3ff. `claude attach 0f7498bc` opens the original.

三次分别是 `0f7498bc → f46ae3ff`、`32fcd28c → 066a9d2b`、`fee5ea53 → aef80f84`。

**这不是错误，CLI 明说了它做了什么**，而且副本**继承了上下文**（`f46ae3ff` 直接接着
`at-init` 的结果往下跑 `/agent-team:at`），也**继承了 `--plugin-dir`**（副本会话里
hook 的 `【产物】`/`【阶段】`/`【触达表】`回传一共触发了十几次）。但它有两条后果值得记下：

1. **原会话仍然活着**，于是同一个探针工程下会并存两个会话。本轮没有造成冲突（原会话
   `idle` 且不再动作），但两个会话都写同一个 `.agent-team` 是一个真实存在的竞争面。
2. **session id 变了**，`claude logs <原 id>` 看不到续跑的输出，转录 jsonl 也换了一份。
   收尾清理时要按**副本的 id**去找，按原 id 找会以为什么都没发生。

`docs/11` §5.5 记的是「`--resume` 不继承 `--plugin-dir`」（那条本轮照纪律规避，未重测）；
这一条是**另一件事**，此前没有记录。

### 10.2 角色先写进自己的 `project.paths` 地盘、再被 H5b 顶回去补 run 目录

对照组与实验组的 `at-product`、两组的 `at-ui`，**四次全部**先把产物写进
`project.paths` 里划给自己的目录（`docs/product/`、`docs/ui/`），被 H5b
