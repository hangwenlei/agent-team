# 推进出第一段时记上契约的账

> 2026-10-11，分支 `r21-s1-exit-contract-sha`。第二十一轮（从开放边界索引挑）：`docs/37` §5「PENDING 而契约不在，一律当还没写——过了第一段契约
> 丢了、`contract_sha` 还是 PENDING，派发返回与写 `state.json` 时都不报」（`docs/60` §4 也登着它）。

## 0. 一句话结论

- 推进出第一段的那一次写入，`contract_sha` 要与磁盘上的契约对得上，H6 才放行；对不上（还是 PENDING、记的是别的值、不是合法的 sha）就拒，出路照用【契约】
  那一句。之后「PENDING 而契约不在」那一格就走不到了——除非用 Bash 改 `state.json`，或者是这一版之前就推进出第一段的旧 run。

## 1. 问题

- `compareContractSha` 把「PENDING、契约不在」当成「还没写」（ok）：第一段里这是对的——契约还没写出来。过了第一段，契约丢了、`contract_sha` 又一直没记
  （项目经理在第一段里没照回传记），派发返回、写 `state.json`、派验证段时都不说话。
- `docs/37` 那一轮试过按阶段分（过了第一段算 `missing`），一批停在后段、PENDING 又不写契约的夹具跟着变红，退回了。
- 第一段的产物就是契约：推进出第一段时契约一定在（H6 的推进判据要它交齐），那一刻正好能要求把账记上。

## 2. 修法

- `hooks/gate.mjs` 的 H6（`rework`）：推进出第一段的那一次（写入前停在第一段、写入后到了后面的段），排在第 1 节对原话之后，拿这次写入的 `contract_sha` 对
  磁盘上的契约（`compareContractSha`）：不过就拒，`agent-team H6 返工预算：推进出 <第一段> 之前，这次写入的 contract_sha 要与磁盘上的契约对得上。` +
  【契约】那一句（`contractCheckNotice`：PENDING 的叫它记写契约那一次回传给的值、手上没有就原样重写一次契约拿回传；漂了的列几种可能、不报磁盘上算出来的值；
  不合法的叫它写成 PENDING 再重写契约）。契约在、这一次读不出（被占着）不拦，留一行痕。
- 第一段里别的写入（原地重写、记 PENDING）不核——写契约之前、记账之前照常写 `state.json`。
- 正文：`commands/at.md` 第 1 节那一句「之后每一次派发返回、每一次写 state.json，门禁都拿它对一遍」补上「推进出 S1 那一次」。
- `tests/gate-user-words.test.mjs` 的 `advance` 推进出第一段时原来带着 PENDING：改成照项目经理的做法记上门禁按契约算的值（真实的推进那一刻早该记上了）。

## 3. 判据与变异

- `tests/gate-s1-exit-contract.test.mjs`：记的就是磁盘上的——放行；还是 PENDING——拒，理由带【契约】那一句；记的是别的合法值、不是合法的 sha——拒，各给那一支的
  出路，漂了的不报磁盘上算出来的值；第一段里原地重写、记 PENDING——不核；契约在却读不出（只在 POSIX 上用权限造）——不拦、留痕；正文那一句在。
- 变异（备份在仓库外，每一刀改完逐字节还原）：推进出 S1 不核契约的账、核写入前的值、理由不带【契约】那一句、只在绑着原话时核——每一刀都有判据红。「读不出
  也拒」那一刀只有 POSIX 那一格打得红，Windows 上那一格跳过、它存活；在本机用 PowerShell 以 `FileShare.None` 独占打开契约、同时跑一次推进出 S1，手工核过：
  原代码不按这一条拦、stderr 留痕，变异体拒。
- 没起真实会话：H6 的判定在子进程里全走到了。

## 4. 仍然开着的边界

- **这一版之前就推进出第一段的旧 run**：PENDING 而契约不在的那一格照旧不说。
- **Bash 改 `state.json`**（`docs/00-开放边界.md` §2 那一族）：推进之后再把 `contract_sha` 改回 PENDING、删掉契约，照旧不说。

## 5. 没量到的
