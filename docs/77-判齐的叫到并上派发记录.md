# 判齐的叫到并上派发记录

> 2026-10-11，分支 `r35-stage-done-dispatched`。第三十五轮（从开放边界索引挑）：`docs/76` §4 的三条——「改动前就有的几格对不上」里派发记录里有、
> `stage_roles` 没记的那一格，「协调者进度不认 `trimmed`」，「非项目经理的写者收到的那句『这一段的产物都在磁盘上了』」。

## 0. 一句话结论

- `isStageDone` 多收一个 `dispatched`（门禁派发记录按段拆开）：参与者（`stage_roles` 那一段，没有 `stage_roles` 的旧 run 是整趟 `roster`）里已经有这一段的
  产者时，并上派发记录里在这一段派出去过的人——推进判据的「叫到」（`advance.mjs` 的 `calledIn`）就是这样并的。派发记录里有、`stage_roles` 没记的人没交时，
  【阶段】不再说「齐了」（照着推进 H6 会拒）。参与者里一个产者都没有的不并（还没记账、记成 `[]` 或只有协调者、旧 run 的 `roster` 里还没有这一段的人）：
  并了会把空名单变成非空，协调者只派出一部分人时提前判齐；有产者时并上只会多要，不会比改动前更早判齐（两轮复核之后，§8）。`hooks/gate.mjs` 里三处调用都传。
- 协调者返回时报的进度认 `trimmed`：叫到之后又裁掉、已经停下的人，没交的那几份里 `mayWaive` 许的写成「没交，`trimmed` 里记着它在这一段裁掉了，
  这一份免了」，不再算成「停下了却没交齐」；还是上一轮的、还在跑的、不随参与者变的固定产物不免（与 `isStageDone`、推进同一个口径）。「还在跑」按这个角色
  在这一段最近的一次派发认，那一行自己那一次派发也要见过它停下、不是被拦（复核之后，§8）。
- 执行段里给非项目经理写者的那一句改成「这一段要交的产物都在磁盘上了」。

## 1. 问题

- S5 里架构师派了 `at-backend` 与 `at-frontend`，项目经理只把 `at-backend` 记进 `stage_roles`。`at-backend` 交了、`at-frontend` 没交：
  项目经理写 `state.json` 时【阶段】说「S5 的产物已经齐了」，照着推进，H6 按「叫到 = `stage_roles` 并上派发记录」拒（`05-impl/at-frontend.md` 不在）。
  交付物核验判「停在旧阶段」、协调者返回时判齐也是同一个函数，同样只看 `stage_roles`。
- 协调者返回时的进度逐个列它派出去的人：已经写进 `trimmed` 的那个人，那一行仍是「还没有——它停下时冒泡了」，收尾仍说「停下了却没交齐的……或者推进
  那一次照出路写 `trimmed`」——它已经写了。

## 2. 修法

- `hooks/lib/state.mjs` 的 `isStageDone({ …, dispatched })`：`state` 给了、传进来的 `roster`（调用方给的是 `participantsOf`）是数组、里面有这一段的产者时，
  参与者 = `roster` 并上 `dispatchedIn(stage, dispatched)`（`advance.mjs` 导出的同一份），再与这一段的产者求交；别的照旧。
- `hooks/gate.mjs`：新函数 `dispatchedByStageOf(ctx)`（读派发记录、按段拆开，读不出给 `null`）；三处 `isStageDone` 调用都传 `dispatched: dispatchedByStageOf(ctx)`。
- `hooks/gate.mjs` 的 `progressOf`：叫到之后又裁掉（`trimmedAt`）、不在 `runningRolesIn` 里的人，那几份里不在磁盘上或是空文件、不是固定产物、不是上一轮的、
  `mayWaive` 许的，而且那一行自己那一次派发最后一回停下不是空、不是「拦」，状态记成 `waived`。`runningRolesIn`（`docs/76` 加的）改成按每个角色在这一段最近的
  一次派发认。`hooks/lib/completion.mjs` 的 `coordinatorProgress`：`waived` 写成那一句、不算没交齐；一份都不在磁盘上（全免了）的那一行，它停下时冒泡了
  不再叫 PM 去读；有一份在磁盘上的照旧叫读。
- `hooks/lib/ledger.mjs`：执行段给非项目经理写者的那一句加「要交的」。

## 3. 判据与变异

- `tests/stage-done-dispatched.test.mjs`：
  - 纯函数：记了账时并上派发记录（派出去过、没记的人没交就不齐；别的段的派发不算；它交了就齐；不给 `dispatched` 的照旧）；叫到之后又裁掉、只在派发记录里有的
    免掉，还在跑的不免；没记账（没有这一段的键、值不是数组）不并（旧 run 按整趟 `roster` 认；起初一律并，第一轮复核改成一律不并，第二轮改成按有没有产者认，§8）。
  - 子进程：派发记录里有、没记的 `at-frontend` 没交——【阶段】不说齐了、往 S6 推进 H6 拒（两边同一个口径）；它交了、或者 `trimmed` 记着它、已经停下——
    【阶段】说齐了、H6 放行。
  - 调用点：`hooks/` 下每一处 `isStageDone` 调用都传 `dispatched: dispatchedByStageOf(ctx)`，调用只在 `hooks/gate.mjs`（与 `tests/stage-trim-done.test.mjs` 的调用点判据同一个扫描写法）。
  - 进度：裁掉、停下（被拦一回再冒泡）的 `at-frontend` 那一行写免了、收尾不说「停下了却没交齐」、不说「它停下时冒泡了」；它还在跑时照旧「可能还在跑」；空文件免；
    还是上一轮的不免；自造的链上后面一段要它当前置的不免（拷一份插件换掉阶段链）。
- 变异（备份在仓库外，每一刀改完逐字节还原）：不并派发记录、没记账也并、值不是数组也算记了账、`dispatchedByStageOf` 永远 `null`、进度不看还在跑、不问 `mayWaive`、
  还旧也免、空文件不免、免了的算没交齐、免了的照说冒泡、不看 `trimmed`——每一刀都有判据红。
- 复核之后（§8）补的：旧 run 与记录里没有产者的不并（纯函数两格、【阶段】一格）；派出去还在跑、没记账的人（【阶段】一格）；交付物核验（前台协调者跑完）与
  完成核验两处调用的行为各一格；进度里空文件而且还旧、固定产物、同一段里先被中断再重派各一格；重派那一格【阶段】也有一格；调用点判据要值后面直接收尾、
  键只出现一次（`tests/stage-trim-done.test.mjs` 那三个键同样收紧）。变异：记录里没有产者也并、旧 run 也并、只认停下过的派发、交付物核验与完成核验那两处
  在值后面再写一个 `dispatched: null`、还在跑按角色的全部派发认、进度不排固定产物、空文件还旧也免——每一刀都有判据红。原来那一刀「还旧也免」（把 `stale`
  状态算进可免）现在是等价变异：`!fresh.isStale` 已经把还旧的排掉了。
- 第二轮复核之后（§8）补的：旧 run 的 `roster` 里没有这一段的产者不并、有的并（含 S2 用过 `at-ui` 的那一格）；进度里这个协调者派的那一次还在跑或最后一回
  被拦、别的协调者派的同一个角色冒泡停下了，这一行不写免了；S2 里 `at-ui` 一份在磁盘上、一份免了又冒泡，照旧叫读。变异：记账不问产者、旧 run 不并、进度不看
  这一行自己的停下、这一行停在拦也免、全免了也叫读、有一份免了就不叫读——每一刀都有判据红。

## 4. 仍然开着的边界

- **参与者里没有产者时照旧不并**：这一段的 `stage_roles` 还没有键、记的人里没有这一段的产者、旧 run 的 `roster` 里还没有这一段的人，派发记录里的人不算
  参与者，【阶段】照旧不说齐了（`docs/32` §4 的时序那一条，有意）。返工轮里从上一轮带过来的这一段记录是 `[]` 或只有协调者（上一轮这一段一个产者都没叫）
  也一样：这一轮的人都交了，【阶段】照旧不说、H6 放行（与改动前一样）。
- **`stage_roles` 记成 `[]`、S6 整段裁掉**：推进放行而【阶段】不发（`docs/76` §4 那一格的另一半，没动）。
- **派发记录里的人只看「派出去过」**：派出去过又被项目经理认定不该派的（H5a 说这次派发不该发生的那种），照样算叫到，要它交或者写进 `trimmed`——与推进同一档。
- **进度里「还在跑」与「拦过」两种口径**：`runningRolesIn` 把最后一回是「拦」的算还在跑（不免），进度那一行却说「门禁最后一回拦了它，它却结束了」、收尾照旧叫
  写 `trimmed`。只在裁掉的人最后一回停下是拦时出现。
- **派了没记、已裁、被中断或最后一回是拦的人**：【阶段】不说齐了（算还在跑、不免），推进照样放行——`docs/76` §4「中断的子代理永远算还在跑」延伸到漏记的人身上；
  改动前这一格【阶段】说齐。
- **「还在跑」按每个角色最近的一次派发认（日志里的先后）**：同一段里同一个角色并行派出两个、先派的那个还在跑、后派的停下了，算它停下了；前台派发的派发行
  在它跑完之后才写（只在 `-p`、SDK 宿主下），先派的前台那一次停下了、后派的后台那一次还在跑时，日志里最近的是前台那一次，也算它停下了。
- **真实顺序里「这一份免了」少见**：项目经理多半是读了协调者的回报才决定裁掉、写 `trimmed`，进度那一条已经发过了；之后同一个协调者再返回、或者重复的通知
  才看得到它。

## 5. 没量到的

- 真实会话里项目经理漏记一个派出去的人、【阶段】不再说齐了之后照「漏记」补记；协调者返回时进度里出现「这一份免了」。

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：两个提交各导出一份，同一组输入对新旧两份门禁按真实顺序各跑一遍比较。返工轮里派发记录不分轮次（两边都不过滤，
这次改动修好了上一轮漏记的人那份还旧时【阶段】说齐、H6 拒的一格）、协调者自己不是产者被滤掉、跨 run、正路（推进那一次才记账）都核过没问题。两个中等、五个小问题：

- **中 1：旧 run 与段中途先记下的段，【阶段】提前说齐**（退步）——旧 run 的 roster 也是推进那一次才累加的，S2 里 `at-product` 先写了 `01-prd.md`、`at-ui`
  还没派，新门禁就说 S2 齐了；项目经理在段中途先记下 S5 为 `[]` 或只有协调者，架构师派出的第一个人交了就说齐了。→ 记账改成「这一段的记录里有这一段的产者」，
  旧 run 不并。
- **中 2：三刀会改变行为的变异判据全绿**——只认停下过的派发、交付物核验与完成核验那两处在值后面再写一个 `null`。调用点判据只认值的开头；那两处没有行为判据；
  子进程判据里派出去的人都停下了。→ 收紧调用点判据；两处各补行为判据；补「还在跑、没记账」一格。
- **低**：进度里空文件而且还旧的照样写免了，照着推进 H6 拒（→ 排掉还旧的）；自造的链上固定产物也写免了（→ 排掉）；同一段里先被中断、重派的那一次停下了，
  进度照旧不免、收尾照旧叫写 `trimmed`（→「还在跑」按最近的一次派发认）；派了没记、已裁、被中断或拦过就结束的人【阶段】从说齐变成不说（→ 登在 §4）；
  文档：`[]` 那一格在第一版里其实动了（→ 中 1 修过之后没动了）、更新记录说「不再叫你去写 trimmed」说过头（→ 改了）、真实顺序里「免了」少见（→ 登在 §4）。

修订推上分支之后起了第二个复核的子代理，专查两条改写（记账的认法、「还在跑」的认法）：三个提交各导出一份，`isStageDone` 对照 H6 推进判据做了差分随机比较
（几组种子、每组几万个状态）——给空的「还在跑」时两类坏格子都是改动前的子集，给随机的「还在跑」时多出来的只有 §4 登过的那一格；产物固定的段三个版本逐项相同；
进度里「免了」与 `isStageDone`、H6 在七种磁盘与 `rework_base` 组合下一致。没有高的、中等的，五个小问题：

- **低 1：进度那一行按别的派发判了可免**——两个架构师都派了 `at-frontend`，这个协调者派的那一次还在跑、另一个派的冒泡停下了（日志里最近），这一行写成免了、
  收尾说都交了。→ 那一行自己那一次派发也要见过它停下、不是被拦。
- **低 2：前台派发的派发行在跑完之后才写**，「最近的一次」可能是先派的那一次。→ 登在 §4。
- **低 3：旧 run 在 S2 用过 `at-ui`（它也是 S5 的产者），S5 段中途【阶段】说齐、H6 拒**——第一轮修订让旧 run 一律不并，这一格退回改动前；§8 中 1 那句「旧 run
  段中途照样是没记账」对它不成立。→ 记账改成「传进来的参与者里有这一段的产者」，旧 run 的整趟 `roster` 也一样认：并派发记录只往非空的名单里加人，不会提前判齐。
- **低 4：返工轮里带过来的记录没有产者（`[]`、只有协调者）、带插件前缀或不是字符串**，整轮【阶段】都不说齐、H6 放行（与改动前一样；后两种 `validateState` 报）。
  → 登在 §4。
- **低 5：一行里只要有一份免了，就不再提醒「交了却冒泡」**——S2 里 `at-ui` 只写了「卡住了」的 `02-ui-spec.md`、冒泡，`02-wireframe.html` 免了，收尾说都交了。
  → 只有一份都不在磁盘上的那一行才不叫读。
