# 判齐的叫到并上派发记录

> 2026-10-11，分支 `r35-stage-done-dispatched`。第三十五轮（从开放边界索引挑）：`docs/76` §4 的三条——「改动前就有的几格对不上」里派发记录里有、
> `stage_roles` 没记的那一格，「协调者进度不认 `trimmed`」，「非项目经理的写者收到的那句『这一段的产物都在磁盘上了』」。

## 0. 一句话结论

- `isStageDone` 多收一个 `dispatched`（门禁派发记录按段拆开）：这一段记了账（`stage_roles` 里这一段是数组，或者没有 `stage_roles` 的旧 run）时，
  并上派发记录里在这一段派出去过的人——推进判据的「叫到」（`advance.mjs` 的 `calledIn`）就是这样并的。派发记录里有、`stage_roles` 没记的人没交时，
  【阶段】不再说「齐了」（照着推进 H6 会拒）。没记账的不并：协调者只派出一部分人时会提前判齐。`hooks/gate.mjs` 里三处调用都传。
- 协调者返回时报的进度认 `trimmed`：叫到之后又裁掉、已经停下的人，没交的那几份里 `mayWaive` 许的写成「没交，`trimmed` 里记着它在这一段裁掉了，
  这一份免了」，不再算成「停下了却没交齐」、收尾不再叫项目经理去写 `trimmed`；还是上一轮的、还在跑的不免（与 `isStageDone`、推进同一个口径）。
- 执行段里给非项目经理写者的那一句改成「这一段要交的产物都在磁盘上了」。

## 1. 问题

- S5 里架构师派了 `at-backend` 与 `at-frontend`，项目经理只把 `at-backend` 记进 `stage_roles`。`at-backend` 交了、`at-frontend` 没交：
  项目经理写 `state.json` 时【阶段】说「S5 的产物已经齐了」，照着推进，H6 按「叫到 = `stage_roles` 并上派发记录」拒（`05-impl/at-frontend.md` 不在）。
  交付物核验判「停在旧阶段」、协调者返回时判齐也是同一个函数，同样只看 `stage_roles`。
- 协调者返回时的进度逐个列它派出去的人：已经写进 `trimmed` 的那个人，那一行仍是「还没有——它停下时冒泡了」，收尾仍说「停下了却没交齐的……或者推进
  那一次照出路写 `trimmed`」——它已经写了。

## 2. 修法

- `hooks/lib/state.mjs` 的 `isStageDone({ …, dispatched })`：`state` 给了、这一段记了账（没有 `stage_roles`，或者 `stage_roles[stage]` 是数组）、`roster`
  是数组时，参与者 = `roster` 并上 `dispatchedIn(stage, dispatched)`（`advance.mjs` 导出的同一份），再与这一段的产者求交；别的照旧。
- `hooks/gate.mjs`：新函数 `dispatchedByStageOf(ctx)`（读派发记录、按段拆开，读不出给 `null`）；三处 `isStageDone` 调用都传 `dispatched: dispatchedByStageOf(ctx)`。
- `hooks/gate.mjs` 的 `progressOf`：叫到之后又裁掉（`trimmedAt`）、不在 `runningRolesIn` 里的人，那几份里不在磁盘上或是空文件、`mayWaive` 许的，状态记成 `waived`。
  `hooks/lib/completion.mjs` 的 `coordinatorProgress`：`waived` 写成那一句、不算没交齐；有 `waived` 的那一行，它停下时冒泡了也不再叫 PM 去读那一份。
- `hooks/lib/ledger.mjs`：执行段给非项目经理写者的那一句加「要交的」。

## 3. 判据与变异

- `tests/stage-done-dispatched.test.mjs`：
  - 纯函数：记了账时并上派发记录（派出去过、没记的人没交就不齐；别的段的派发不算；它交了就齐；不给 `dispatched` 的照旧）；叫到之后又裁掉、只在派发记录里有的
    免掉，还在跑的不免；旧 run 整趟 `roster` 并上派发记录；没记账（没有这一段的键、值不是数组）不并。
  - 子进程：派发记录里有、没记的 `at-frontend` 没交——【阶段】不说齐了、往 S6 推进 H6 拒（两边同一个口径）；它交了、或者 `trimmed` 记着它、已经停下——
    【阶段】说齐了、H6 放行。
  - 调用点：`hooks/` 下每一处 `isStageDone` 调用都传 `dispatched: dispatchedByStageOf(ctx)`，调用只在 `hooks/gate.mjs`（与 `tests/stage-trim-done.test.mjs` 的调用点判据同一个扫描写法）。
  - 进度：裁掉、停下（被拦一回再冒泡）的 `at-frontend` 那一行写免了、收尾不说「停下了却没交齐」、不说「它停下时冒泡了」；它还在跑时照旧「可能还在跑」；空文件免；
    还是上一轮的不免；自造的链上后面一段要它当前置的不免（拷一份插件换掉阶段链）。
- 变异（备份在仓库外，每一刀改完逐字节还原）：不并派发记录、没记账也并、值不是数组也算记了账、`dispatchedByStageOf` 永远 `null`、进度不看还在跑、不问 `mayWaive`、
  还旧也免、空文件不免、免了的算没交齐、免了的照说冒泡、不看 `trimmed`——每一刀都有判据红。

## 4. 仍然开着的边界

- **没记账时照旧不并**：这一段的 `stage_roles` 还没有键时，派发记录里的人不算参与者，【阶段】照旧不说齐了（`docs/32` §4 的时序那一条，有意）。
- **`stage_roles` 记成 `[]`、S6 整段裁掉**：推进放行而【阶段】不发（`docs/76` §4 那一格的另一半，没动）。
- **派发记录里的人只看「派出去过」**：派出去过又被项目经理认定不该派的（H5a 说这次派发不该发生的那种），照样算叫到，要它交或者写进 `trimmed`——与推进同一档。
- **进度里「还在跑」与「拦过」两种口径**：`runningRolesIn` 把最后一回是「拦」的算还在跑（不免），进度那一行却说「门禁最后一回拦了它，它却结束了」、收尾照旧叫
  写 `trimmed`。只在裁掉的人最后一回停下是拦时出现。

## 5. 没量到的

- 真实会话里项目经理漏记一个派出去的人、【阶段】不再说齐了之后照「漏记」补记；协调者返回时进度里出现「这一份免了」。

## 6. 归属

  与三处调用；`hooks/lib/completion.mjs` 的 `coordinatorProgress`；`hooks/lib/ledger.mjs` 那一句；判据在 `tests/stage-done-dispatched.test.mjs`。
