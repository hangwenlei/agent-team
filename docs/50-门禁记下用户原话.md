# 门禁记下用户原话

> 2026-10-07，M4o，分支 `m4o-user-words`。第八轮，从 `docs/00-开放边界.md` §1 挑的一条：全量审查第 20 条（中）剩下的修法 A——门禁记下用户在
> `/agent-team:at` 后面写的那段话，契约第 1 节对着它核。`docs/45` 做了修法 B（推进出第一段之后锁住第 1 节），修法 A 一直卡在「先在最低支持版本上
> 核 UserPromptExpansion 这个事件」（`docs/39` §6、`docs/45` §4）。

## 0. 一句话结论

- **平台**：斜杠命令展开时平台发 UserPromptExpansion，输入里的 `command_args` 就是换进 `$ARGUMENTS` 的那一份。本机能跑的最旧版本 2.1.278 上
  事件就在，`-p` 与 `--bg` 都触发（§1）。下限 2.1.276 的二进制本机已经没有；插件 hooks.json 里不认识的事件名会被平台跳过、不连累别的门禁，
  所以那几版上要是还没有这个事件，结果只是不记、不核，退回今天的行为。
- **修法**：`/agent-team:at` 展开时，门禁把原话、会话 id、那一刻已有的 run 记进项目一级的 `.agent-team/user-words.json`。这个会话之后第一次在
  一趟新建的 run（还停在第一段）里写 `state.json` 或契约，门禁把记录绑进那一趟的 run 目录。
  - 第一段里写契约时，第 1 节对不上原话，【契约】当场说是哪一行。
  - 第一段的产物齐了，【阶段】那一句跟着补上。
  - 推进出第一段那一次，H6 拒。
  - 行尾空白不计，整段写成引用块也认。
  - 两份记录都是门禁专属文件。
- **真实会话**：项目经理建 run 时记录绑上了，第 1 节逐字照抄，推进到 S2 放行，全程没有误报（§4）。
- 实测时顺手发现：UserPromptSubmit、UserPromptExpansion 上 hook 的输出不进转录。现行参考的留痕判读表原来说那两行「一行」，订正了。

## 1. 平台实测

### 1.1 事件与字段

探针插件挂三条：UserPromptExpansion 带 matcher、不带 matcher 各一条，UserPromptSubmit 一条，把 stdin 原样记下。在 2.1.286 与 2.1.278 的二进制上各用
`-p` 跑；2.1.286 另用 `--bg` 跑。参数带多行、首尾空白、中文、引号与反引号：

- UserPromptExpansion 先于 UserPromptSubmit 触发，字段如下：
  - `expansion_type`：`slash_command`；
  - `command_name`：带插件名的全名 `probe:at`；
  - `command_source`：`plugin`；
  - `command_args`：去掉了首尾空白，中间的换行与行尾空格保留；
  - `prompt`：命令名加一个空格加 `command_args`；
  - `session_id`：与主会话之后各次工具调用的 hook 输入里那一个相同。
- 从转录核过：换进命令正文的 `$ARGUMENTS` 就是 `command_args`，一字不差。
- UserPromptSubmit 拿到的是用户敲的原样，首尾空白没去。
- 2.1.278 与 2.1.286 上，上面每一条都一样。

matcher：

- 写成锚定的 `^probe:at$` 只放 `probe:at`。
- 写成 `probe:at`（含冒号，平台按正则不锚定匹配）连 `probe:at-x` 一起放进来。
- 写成 `at`（只有字母，平台按名字整串比）连 `probe:at` 都不放。

门禁注册写 `^agent-team:at$`，门禁自己再核一遍 `command_name`。

裸名 `/at` 不会解析成插件命令：

- `-p` 下当成普通文字发给模型，不触发展开；
- `--bg` 下报「Unknown command: /at」，命令不执行。

插件命令只能用全名调用，`command_name` 就是 `agent-team:at`。

### 1.2 下限

- 2.1.276 的二进制本机已经不在（`docs/28` 当时读过它）。2.1.278 的二进制里这个事件有完整的输入定义（`expansion_type`、`command_name`、
  `command_args`、`command_source`、`prompt`），并且在能拦截的事件之列。Claude Code 的公开更新记录里一次都没提过这个事件。
- 往探针 hooks.json 里加一个不存在的事件名：2.1.278 与 2.1.286 上，其余钩子照常触发。更新记录 2.1.101 有一条：settings.json 里认不出的 hook
  事件名不再让整份文件作废。
- 推断：下限上要是还没有这个事件，那一条注册被跳过，记录器不触发，门禁不记、不核（退回修法 B），别的门禁不受影响。这是推断，没在 2.1.276 上跑过。

### 1.3 留痕不进转录

探针 hook 在 exit 0 时往 stderr 写一行留痕样式的字：

- 转录里，UserPromptExpansion 与 UserPromptSubmit 上一条 hook 记录都没有（`-p` 与 `--bg` 都是）；
- `--debug-file` 的调试日志里，两个事件各有一条 `Hook <事件> (<事件>) success:`，后面跟着那一行。

现行参考的判读表原来说 `approval-prompt`、`completion` 两行在转录里每次「一行」，查不到量过的记录。改成「转录里没有，调试日志里一行」，新的一行同样
这么写，表下补一条说明（`docs/00-现行参考.md` §1）。

### 1.4 第 1 节在真实会话里的写法

翻之前各场实测的转录：

- 大多数项目经理把原话直接写在「## 1. 用户原话」底下；
- 也有一批整段写成引用块（每行前面一个「> 」）。

门禁两种写法都认，判据之外不再收紧。

## 2. 修法

### 2.1 记录器

新检查项 `user-words`：

- 挂 UserPromptExpansion，matcher 是 `^agent-team:at$`。它是生命周期事件里唯一带 matcher 的一项，`checks.mjs` 里声明，接线判据照声明核。
- 输入是 `/agent-team:at`、参数不是空白、带会话 id 时（`hooks/lib/user-words.mjs` 的 `wordsOf`），往项目一级的 `.agent-team/user-words.json` 整份重写
  一份：原话、会话 id、那一刻 `runs/` 下已有的名字（`runs_before`）、`bound` 与 `dropped` 都是 null。最近的一次命令为准。
- `.agent-team` 不在不建它。没跑过 at-init 的项目，项目经理本来就会停下叫用户先跑 at-init，之后用户再发一次命令。
- 不拦任何东西：这个事件上 exit 2 会把用户的命令拦掉。stdout 一个字都不写，只往 stderr 留一行。
- 记录器标 `recorder: true`、`records: 'user-words'`。读不出输入、崩溃、加载失败、Node 太旧时，说的是「这次的原话没有记下」「这一趟契约第 1 节不跟它核」，
  不说「回答」「再批准一次」。

### 2.2 绑定与作废

`bindDecision` 判，`gate.mjs` 的 `userWordsFor` 读写；账本与 H6 共用：

- 只看同一个会话、还没绑也没作废的记录。
- 项目经理在一趟**新建的** run（不在 `runs_before` 里）停在第一段时写 `state.json` 或契约：绑。记录写进那一趟的 run 目录（多一个 `bound_at`），项目一级
  那份标上 `bound`。之后这一趟只认 run 目录里那一份。
- 项目经理写了一趟**命令之前就有**、没收口的 run：作废，项目一级那份标上 `dropped`。那是续跑了它（`/agent-team:at` 第 1 节「用户选续跑」那一支），这条命令的
  需求被搁下了；之后另起的一趟抄的是用户的消息，不是这条命令的参数。
- 替它收口的那一次（写完之后它已经收口）不作废：收口之后照常建新的一趟，这条命令的需求接着用。
- 已经绑过的不再绑：收口之后照第 6 节自己另起的第二趟不绑、不核。
- H6 也会绑：契约不经账本写成（例如用 Bash 写），推进出第一段那一次 H6 自己绑、照样核。

### 2.3 核

`section1Mismatch` 的认法：

- 从「## 1.」那一行往下跳过空行，逐行就是原话；之后到下一个编号节标题之间只能有空行。
- 行尾空白、BOM、CRLF 不计。
- 整段写成引用块也认：每行一个「>」或「> 」，空行写「>」或空着。
- 按原话的行数往下认：原话里自带的「## 安装」「## 2. 第二部分」不会把它切断。
- 对不上时报第几行、两边各是什么（都过 `quote`），以及原话记在哪（这一趟 run 目录的 `user-words.json`，args 那一项）。

三处说同一句（`wordsMismatchText` 与 `WORDS_FIX`）：

- **账本**：还在第一段、项目经理写契约时，【契约】当场说，末尾是「改好之前推进不出 S1」。写 `state.json` 时第一段的产物齐了，【阶段】「齐了」那一句
  补上「推进出 S1 会被拒」。
- **H6**：推进出第一段那一次拒，末尾是「再推进」。排在契约判据之后、验收判据之前。第一段推进时契约基线还没有，两样不会一起说。
- 走过第一段之后，三处都不按原话核。第 1 节之后再变，归契约基线管（`docs/45`）。

### 2.4 门禁专属文件

- `control-files.mjs` 的 `GATE_FILES` 加 `runs/*/user-words.json`。
- 新增 `PROJECT_GATE_FILES = ['user-words.json']`：项目一级那份是唯一一份不在 `runs/<id>/` 下的门禁专属文件，命令展开那一刻这一趟的 run 还没建。
- `isGateFile`、`mayBeGateFile` 两样都认。H3 对任何人的 Edit/Write 都拒。Bash 照样写得进（与别的门禁专属文件同一档）。

### 2.5 正文

- `/agent-team:at` 第 2 节加三句：门禁记下了 `$ARGUMENTS`、在哪两刻核、哪几种情形不核。
- 契约格式 skill、契约模板第 1 节的占位各加一句。
- README 两半的目录树列上两份记录。

## 4. 实测

**真实会话**（2.1.286，`--bg`，bypassPermissions，留痕开着，带调试日志）。在受信任的探针目录下建一个只有 `project.json` 的项目，
发 `/agent-team:at 做一个命令行小工具，运行后打印 hello world。写完契约、推进到 S2 就停下，不要派人。`：

- 记录器经 boot.mjs 触发，项目一级记下原话、会话 id，`runs_before` 为空。
- 项目经理建 run 时写 `state.json` 那一刻，记录绑进了新 run 目录。
- 契约第 1 节逐字照抄（直接写的那一种）；推进到 S2，H6 放行。
- 转录里没有一次「对不上原话」。调试日志里有记录器那一行和留痕行，转录里没有（§1.3）。

会话收尾 stop、rm，探针目录删掉。

**分支 CI**：结果写在合并之后的收口里。

## 5. 仍然开着的边界

- **命令没带参数**：需求在之后的对话里给出时，不记、不核。
- **收口之后照第 6 节自己另起的一趟**：抄的是用户的消息，不是这条命令的参数，不核。
- **按会话 id 绑**：换了会话才第一次在这一趟里写 `state.json` 或契约的（续会话换了 id、桌面端重开），不绑、不核。
- **续跑之后另起一趟**：用户选了续跑，项目经理却没写过那一趟就另起一趟，这条命令的原话会绑给新的一趟。新的一趟要是抄的不是它，第 1 节推进不出去。
  走得到这一步要先违背 `/agent-team:at` 第 1 节（续跑就是接着写那一趟）。
- **下限上没实测**：2.1.276、2.1.277 上有没有这个事件没跑过（§1.2）。没有就不记、不核。
- **两个会话在同一个项目里先后发命令**：项目一级那份整份重写，后发的盖掉先发的；先发的那个会话写契约时会话 id 对不上，不绑、不核。
- **原话里有门禁认得的编号节标题**（「## 2. …」）：原话核对按行数认、不受影响；契约基线的第 1 节在那一行切断，那之后的原话推进出第一段之后改了
  不拦（`docs/45` §4 的切法）。
- **写法**：
  - 引用块只认整段一致的写法；前几行带「>」、后几行不带的认不出，第 1 节推进不出去，要照着改成一致的。
  - 模型照抄不出来的字符（行中间的零宽字符、NBSP），比对照样按字面，对不上就推进不出去。没见过。
- **Bash 改两份记录**：与别的门禁专属文件同一档（「`Bash` 不经门禁」那一族）。
- **第 20 条的另一半**：`at-acceptance` 收不到契约漂移的告警（`docs/37` §5），照旧。

## 6. 没量到的

- 真实会话里项目经理把第 1 节转写偏了、门禁当场说、改回去的那一路（只有子进程判据）。
- 交互终端与桌面端（只量了 `-p` 与 `--bg`），default、auto 两种权限模式（第 44 条）。
- 续会话之后会话 id 变不变。
