# quote 把看不见的字写成码点

> 2026-10-10，M4x，分支 `m4x-quote-format-chars`。第十七轮（从开放边界索引挑）：`docs/27` §4「同形字」里零宽字符那一半、`docs/29` §5
> 「`quote` 不转义格式字符与双向控制符」。`docs/29` §7 把这一条归给「下一个动 `hooks/lib/trusted.mjs` 的人」，第十五轮（`docs/57`）动过它、没做这一条。

## 0. 一句话结论

- `quote`、`safeJson` 把看不见的字写成码点：格式字符（Unicode 的 Cf：零宽字符、双向控制符、BOM、软连字符、标签字符……）、别的默认不可见的字
  （Unicode 的 Default_Ignorable_Code_Point：变体选择符、组合字形连接符、谚文填充符……）、DEL 与 C1 控制字符；`inline` 遇到它们退到 `quote`。
  写成码点的结果仍是合法 JSON，解析回来与原值相同。
- 契约第 1 节对着用户原话核时，这些字同样不计；对不上的那一句引原话时去掉它们，不显示成转义。
- 门禁自己的文字不经过这几个函数，一个字不变。

## 1. 问题

- `JSON.stringify` 只转义 C0 控制字符、引号、反斜杠与孤立的代理项。别的看不见的字原样进回传、拒绝理由与留痕：
  - **零宽字符**夹进受信前缀中间：`quote` 按字面消前缀，消不掉；读的人和模型看着跟真的前缀一样。
  - **双向控制符**（U+202E 之类）在终端与界面上把后面的字倒过来显示，用户看到的不是写进去的。
  - **标签字符**（U+E0001、U+E0020–E007F，连同标签块里没分配的那些）整段不可见，模型却读得到——一句话藏在里面，人看不出来。
  - **变体选择符**（U+FE00–FE0F、U+E0100–E01EF、蒙古文的 U+180B–180D、U+180F）是组合记号、不在 Cf 里，同样不占位置；一串跟在一个表情后面就能编码任意字节。
    组合字形连接符（U+034F）、谚文填充符（U+3164 之类）也是默认不可见、却不在 Cf 里。
  - **C1 控制字符**（U+0080–U+009F，例如 U+009B）在一部分终端里是转义序列的开头，stderr 的留痕会进终端。
- `inline` 原来只认 C0、DEL、几种行分隔符与孤立的代理项：调用方参数里夹的格式字符原样输出。

## 2. 修法

- `hooks/lib/trusted.mjs`：
  - `HIDDEN_CLASS` = 几种行分隔符 + `\p{Cf}` + `\p{Default_Ignorable_Code_Point}` + U+007F–U+009F。`escapeHidden` 把每一个写成 `\uXXXX`（星平面的写成一对
    代理项的转义），取代原来只管行分隔符的那一步。两个属性都要：Cf 里有不算默认不可见的（阿拉伯数字符号、行间注解），默认不可见的里有不是 Cf 的（变体选择符、
    谚文填充符）。
  - `quote` 的三条路（字符串、不是字符串的值的 JSON 写法、截过的值）最后都经 `escapeHidden`；`safeJson` 也经它。`inline` 多判一条：带这些字的退到 `quote`。
  - 先截断、再转义：上限数的是原值的码点，一个转义不会被截成半截。
- `hooks/lib/user-words.mjs`：比之前剥掉的从格式字符扩到同一批默认不可见的字（表情后面的 U+FE0F 最常见，模型照抄时留不留没准）；`wordsMismatchText` 引原话
  与契约行之前去掉它们——`quote` 会把它们写成转义，照抄进第 1 节就成了几个看得见的字，反倒对不上。`WORDS_FIX` 说它们不计。
- **牵动面**（照 `docs/27` §2.1 的表逐行过）：
  - `quote`（磁盘上谁都写得进的值）：带这些字的值多出几个码点，别的不变。经 `quote` 的值多是用来点名「哪一个不对」的，多出来的码点正好说明它跟看上去的
    不一样。叫项目经理照着抄的只有契约第 1 节那一句，见上。用户的问答、冒泡理由这类整段引的文字，带表情时也会多出码点。
  - `inline`（调用方自己的参数、由项目根拼出的路径）：夹了这些字的从原样变成带引号的转义；干净的逐字不变。**项目根的目录名里有一个带变体选择符的表情或
    零宽连接符**时，由它拼出的每一条路径都退到 `quote`：加引号，Windows 上的反斜杠写成两个，按 120 个码点截成「头…尾」（文件名在尾巴里留得下）。
  - `shaOrNote`：只回显合法形状，不受影响。
  - `safeJson`（触达表）：项目经理照这份重写 `reach.json`，门禁按解析后的值核（`hooks/lib/ledger.mjs` 的 `reachCheckNotice`），写成码点的照样对得上。
  - **代价**：带零宽连接符的组合表情、带变体选择符的表情显示成表情加码点；从右往左写的文字里的方向标记（U+200E、U+200F、U+061C）也写成码点。
- 插件自己的文案（含「⚠️」，U+26A0 加 U+FE0F）不经这几个函数，不变。

## 3. 判据与变异

- `tests/trusted.test.mjs`：
  - 逐个码点（零宽字符、双向控制符、词连接符与几个不可见运算符、BOM、软连字符、阿拉伯字母标记、蒙古文元音分隔符与自由变体选择符、行间注解、DEL、C1、
    标签字符与标签块里没分配的、变体选择符、组合字形连接符、谚文填充符、高棉文的两个元音、未分配的 U+2065 与 U+FFF0–FFF8、速记与乐谱的格式控制）：
    结果里不剩原样的，写出那个码点，解析回原值。
  - 夹了零宽字符的「受信前缀」；不是字符串的值、截过的字符串、截过的不是字符串的值；组合表情、带变体选择符的表情（含「⚠️」）与一串变体选择符；
    `inline` 退到 `quote`；`safeJson`。
- `tests/trusted-echo.test.mjs`：
  - 新载荷 `fmt`：几种格式字符、变体选择符、组合字形连接符、谚文填充符、标签块里没分配的一格，不带控制字符——带了的话 `inline` 单凭控制字符就退到 `quote`，
    它对这些字的判定一次都走不到。
  - 新断言 ⑥：所有输出里没有原样的格式字符、默认不可见的字、DEL 与 C1 控制字符。插件自己的「⚠️」只在 JSON 引号串之外扣掉再查——值都在引号里，
    引号里原样的「⚠️」照样算。项目根目录名、另一趟 run 目录名那两格也造了 `fmt`。
  - 正向锚点：认得出引号里原样的（含变体选择符与组合字形连接符），放过写成码点的，放过门禁自己话里的「⚠️」、不放过引号里的。原来「行首藏在零宽字符后面」
    那条锚点改成认具体那一条违规——⑥ 也会为同一个零宽字符报一条，只数条数就被它顶替了。
- `tests/user-words.test.mjs`：原话带变体选择符、零宽连接符、组合字形连接符、谚文填充符，契约里没有它们照样认，表情本身少了照样对不上；对不上的那一句里
  没有码点转义；`WORDS_FIX` 说它们不计。
- 变异（备份在仓库外，每一刀改完逐字节还原），每一刀都有判据红：
  - 第一版：不管 Cf、不管 DEL 与 C1、不管变体选择符（两段一起、各一段）、`inline` 不看格式字符、只转义第一个码元、`safeJson` 不转义、`quote` 只在字符串
    那一支转义、`quote` 完全不转义、去掉 `u` 旗标、判据不查 ⑥。「`inline` 不看格式字符」那一刀由 trusted-echo 里调用方参数的那几个入口打红。
  - 复核修订：不管默认不可见的字、不管 Cf（只靠默认不可见）、截过的不是字符串的值不转义、值里的「⚠️」放过、原话比对不剥默认不可见的字、对不上的那一句
    照引原样、判据里「⚠️」在引号里也豁免、⑥ 的检测器不管默认不可见的字。
- 没起真实会话：这几个是纯函数，门禁各处的用法不变。

## 4. 仍然开着的边界

- **看得见、长得像的字**：全角字母、西里尔字母这类同形字与 NBSP 照样原样回显，仍待在一对引号里、不在行首（`docs/27` §4 那一条剩下的一半）。
- **显示成空白、却不在这几类里的字**：盲文空白（U+2800）之类不转义。
- **私用区与默认不可见之外的未分配码点**不转义。
- **Unicode 的版本跟着 Node**：Cf 与默认不可见的范围由运行门禁的 Node 自带的 Unicode 数据定，旧的 Node 上后来才加进去的几个字不转义（推测，没在
  `MIN_NODE` 上逐个量）。
- **原话里的 DEL 与 C1 控制字符**在对不上的那一句里显示成转义（它们不是比对时不计的那一类）；出路是照 run 目录里记录文件的 args 抄。

## 5. 没量到的

- 真实会话里模型读到写成码点的值之后怎么转述、怎么改：没起会话。
- C1 控制字符在各家终端里的实际效果：没量。

## 8. 复核与修订

第一版（只认 Cf、两段变体选择符与 C1）推上分支、CI 全绿之后，起了一个对抗复核的子代理：逐个码点枚举、在门禁子进程上实测、随机生成二十万个值做模糊
测试、对实现与判据做变异。结论是实现对、没有高严重度问题；一个中等、几个小问题，都在这一轮改了：

- **中 1：不在 Cf 里的默认不可见的字照样原样输出。** 组合字形连接符、谚文填充符、蒙古文自由变体选择符、标签块里没分配的那些——`state.stage` 写成「受信前缀」
  中间夹一个 U+034F，ledger 的回传里原样出现。「零宽字符那一半关上了」说过头了。→ `HIDDEN_CLASS` 加 `\p{Default_Ignorable_Code_Point}`（它包含两段
  变体选择符，原来单列的两段删掉）；判据的码点列表与 `fmt` 载荷补上。
- **低 2：截过的不是字符串的值那一条路没有判据钉着**——那一支不转义，两份判据全绿。→ 补一例超过上限的对象，头尾各夹一个。
- **低 3：⑥ 的锚点没钉住变体选择符，「⚠️」按整段扣**，值里原样的「⚠️」也被放过。→ 锚点加变体选择符与组合字形连接符；「⚠️」只在 JSON 引号串之外扣；
  值里的「⚠️」写成码点另配一条。
- **低 4：牵动面漏了契约第 1 节那一句。** 用户原话里带表情时，拒绝理由显示 `️`，照抄进第 1 节仍对不上；原话比对只剥 Cf、不剥变体选择符。→ 比对与显示
  都去掉默认不可见的字，`WORDS_FIX` 说它们不计（§2）。
- **低 5：项目根目录名里有带变体选择符的表情时，所有经 `inline` 的路径都变形。** 有意接受，代价写进 §2。
- **低 6：文档陈旧**——`docs/27` §2.1 那张表、`hooks/lib/project.mjs` 一处注释。→ 写了订正、改了注释。
- **低 7：Unicode 版本跟着 Node**（推测）。登进 §4。
- 复核也确认了：输出始终是合法 JSON、解析回原值、拼不出受信前缀；先截断再转义没有半截转义；`MIN_NODE` 上的 min-node 作业是绿的（`u` 旗标与 `\p{…}` 可用）；
  插件自己的文案里看不见的字只有「⚠️」；其余出口（异常消息、写路径隔离的路径与调用者、留痕）都经这几个函数或只出 ASCII。
