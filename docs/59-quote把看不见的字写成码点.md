# quote 把看不见的字写成码点

> 2026-10-10，M4x，分支 `m4x-quote-format-chars`。第十七轮（从开放边界索引挑）：`docs/27` §4「同形字」里零宽字符那一半、`docs/29` §5
> 「`quote` 不转义格式字符与双向控制符」。`docs/29` §7 把这一条归给「下一个动 `hooks/lib/trusted.mjs` 的人」，第十五轮（`docs/57`）动过它、没做这一条。

## 0. 一句话结论

- `quote`、`safeJson` 把格式字符（Unicode 的 Cf：零宽字符、双向控制符、BOM、软连字符、标签字符……）、DEL 与 C1 控制字符、变体选择符写成码点；
  `inline` 遇到它们退到 `quote`。写成码点的结果仍是合法 JSON，解析回来与原值相同。
- 门禁自己的文字不经过这几个函数，一个字不变。

## 1. 问题

- `JSON.stringify` 只转义 C0 控制字符、引号、反斜杠与孤立的代理项。别的看不见的字原样进回传、拒绝理由与留痕：
  - **零宽字符**夹进受信前缀中间：`quote` 按字面消前缀，消不掉；读的人和模型看着跟真的前缀一样。
  - **双向控制符**（U+202E 之类）在终端与界面上把后面的字倒过来显示，用户看到的不是写进去的。
  - **标签字符**（U+E0000–E007F）整段不可见，模型却读得到——一句话藏在里面，人看不出来。
  - **变体选择符**（U+FE00–FE0F、U+E0100–E01EF）是组合记号、不在 Cf 里，同样不占位置；一串跟在一个表情后面就能编码任意字节。
  - **C1 控制字符**（U+0080–U+009F，例如 U+009B）在一部分终端里是转义序列的开头，stderr 的留痕会进终端。
- `inline` 原来只认 C0、DEL、几种行分隔符与孤立的代理项：调用方参数里夹的格式字符原样输出。

## 2. 修法

- `hooks/lib/trusted.mjs`：
  - `HIDDEN_CLASS` = 几种行分隔符 + `\p{Cf}` + U+007F–U+009F + 两段变体选择符。`escapeHidden` 把每一个写成 `\uXXXX`（星平面的写成一对代理项的转义），
    取代原来只管行分隔符的那一步。
  - `quote` 的三条路（字符串、不是字符串的值的 JSON 写法、截过的值）最后都经 `escapeHidden`；`safeJson` 也经它。`inline` 多判一条：带这些字的退到 `quote`。
  - 先截断、再转义：上限数的是原值的码点，一个转义不会被截成半截。
- **牵动面**（照 `docs/27` §2.1 的表逐行过）：
  - `quote`（磁盘上谁都写得进的值）：带这些字的值多出几个码点，别的不变。经 `quote` 的值是用来点名「哪一个不对」的，多出来的码点正好说明它跟看上去的不一样。
  - `inline`（调用方自己的参数、由项目根拼出的路径）：夹了这些字的从原样变成带引号的转义；干净的逐字不变。
  - `shaOrNote`：只回显合法形状，不受影响。
  - `safeJson`（触达表）：项目经理照这份重写 `reach.json`，门禁按解析后的值核（`hooks/lib/ledger.mjs` 的 `reachCheckNotice`），写成码点的照样对得上。
  - **代价**：带零宽连接符的组合表情、带变体选择符的表情显示成表情加码点；从右往左写的文字里的方向标记（U+200E、U+200F、U+061C）也写成码点。
    门禁回显的是文件名、键名、阶段名这类值，代价落在少见的写法上。
- 插件自己的文案（含「⚠️」，U+26A0 加 U+FE0F）不经这几个函数，不变。

## 3. 判据与变异

- `tests/trusted.test.mjs`：
  - 逐个码点（零宽字符、双向控制符、词连接符与几个不可见运算符、BOM、软连字符、阿拉伯字母标记、蒙古文元音分隔符、行间注解、DEL、C1、标签字符、
    变体选择符）：结果里不剩原样的，写出那个码点，解析回原值。
  - 夹了零宽字符的「受信前缀」；不是字符串的值与截过的值；组合表情、带变体选择符的表情与一串变体选择符；`inline` 退到 `quote`；`safeJson`。
- `tests/trusted-echo.test.mjs`：
  - 新载荷 `fmt`：几种格式字符加变体选择符，不带控制字符——带了的话 `inline` 单凭控制字符就退到 `quote`，它对格式字符的判定一次都走不到。
  - 新断言 ⑥：所有输出里没有原样的格式字符、DEL 与 C1 控制字符、变体选择符（插件自己的「⚠️」扣掉再查）。项目根目录名、另一趟 run 目录名那两格也造了它。
  - 正向锚点：认得出引号里原样的，放过写成码点的。原来「行首藏在零宽字符后面」那条锚点改成认具体那一条违规——⑥ 也会为同一个零宽字符报一条，
    只数条数就被它顶替了。
- 变异（备份在仓库外，每一刀改完逐字节还原）：不管 Cf、不管 DEL 与 C1、不管变体选择符（两段一起、各一段）、`inline` 不看格式字符、只转义第一个码元、
  `safeJson` 不转义、`quote` 只在字符串那一支转义、`quote` 完全不转义、去掉 `u` 旗标、判据不查 ⑥——每一刀都有判据红。「`inline` 不看格式字符」那一刀
  由 trusted-echo 里调用方参数的那几个入口打红。
- 没起真实会话：这几个是纯函数，门禁各处的用法不变。

## 4. 仍然开着的边界

- **看得见、长得像的字**：全角字母、西里尔字母这类同形字与 NBSP 照样原样回显，仍待在一对引号里、不在行首（`docs/27` §4 那一条剩下的一半）。
- **显示成空白、却不在这几类里的字**：谚文填充符（U+3164 之类）、盲文空白（U+2800）不转义。
- **私用区与未分配的码点**不转义。

## 5. 没量到的

- 真实会话里模型读到写成码点的值之后怎么转述、怎么改：没起会话。
- C1 控制字符在各家终端里的实际效果：没量。

## 6. 归属

- `hooks/lib/trusted.mjs` 的 `HIDDEN_CLASS`、`escapeHidden`、`inline`；判据在 `tests/trusted.test.mjs`、`tests/trusted-echo.test.mjs`。
