# 106 并行微调的开销

**日期**：2026-11-06　**版本**：8.1.0　**起因**：`docs/105` §9 终审留着的「开销」那一条

---

## 0. 一句话结论

门禁一个进程里 `runs/` 只扫一遍、派发记录按需读，先看原话记录再读 `state.json`，没有链接时不逐个 `realpath`。200 趟收口的完整 run 加 1 趟时，一次子代理写入的
writepath 从 169ms 回到 116ms（基线约 100ms）；200 趟收口的微调加 1 趟开着时，从 223ms 到 158ms。

## 1. 起因

终审实测：每个 hook 进程把 `runs/` 扫两到四遍（`tweaksAt` 在挑这一趟、认不出的团队角色、认领、互斥、【微调】各调一次），每一趟都读 `state.json`、对每个目录做一次
`realpath`（只为去重链接的别名）；按 agent_id 认时还把每一趟收口了的微调的派发记录都读一遍。`runs/` 只增不减，正常的完整一趟也付这笔钱，碰到设计的反目标「主流程变慢」。

## 2. 做法

- **进程内只扫一遍**：`tweaksAt` 与 `agentIdsAt` 的结果记在进程里（`TWEAKS_MEMO`、`AGENT_IDS_MEMO`）。门禁自己写了归属（建 run、接手）、run 目录里的原话记录、派发记录
  之后 `forgetRuns` 清掉，之后再问照新的读。
- **先看原话记录**：run 目录的 `user-words.json` 不是 at-tweak 的不读 `state.json`（完整的 run 都在这一步就跳过）；归属只给没收尾的微调读。
- **没有链接不逐个 `realpath`**：同一个目录的别名只有链接造得出来；`runs/` 下有链接时才逐个规范化去重。
- **派发记录按需读**（`runpick.mjs` 的 `pickRun` 收 getter）：依次问开着的微调 → `current-run` 那一趟 → 收口了的微调 → 按会话认之前别的 run；前面认到了，后面的不读。
  按会话认的退路只在这个会话名下恰好一趟没收尾的微调时才去问别的 run。结果与改动之前相同（agent_id 只会在一趟的派发记录里）。

## 3. 判据

- `tests/runpick.test.mjs`「pickRun 按需读」：用 getter 数读了哪几趟——开着的那一趟认到了不读收口了的；在 `current-run` 那一趟就不读收口了的微调；会话名下没有微调时
  不问别的 run。三刀变异（不先问 `current-run` 那一趟、先问别的 run 再看会话、开着的与收口的混着找）都红。
- 原有判据（挑这一趟、认领、互斥、放弃、整趟并行、第二步的整趟微调）照绿：全量 3088 过、0 失败。
- 进程内的记忆与清理只靠结果不变核（门禁自己写了之后同一个进程里再问的情形，正路上走不到：接手与「可以了，收尾」不会在同一次回答里——批准记录器要求单独一道题）。

## 4. 量数

`node <基准脚本>`：仓库外造项目，`tests/helpers/gate-runner.mjs` 起门禁子进程，每项 15 次取中位数（毫秒，含起 node 进程；Windows 11，同一台机器）。

| 项目里的 run | writepath（子代理写项目文件）改动前 → 改动后 | readiness（项目经理派人）改动前 → 改动后 |
|---|---|---|
| 微调：0 趟收口 + 1 趟开着 | 104 → 99 | 101 → 97 |
| 微调：200 趟收口 + 1 趟开着 | 223 → 158 | 202 → 159 |
| 完整 run：0 趟收口 + 1 趟开着 | 101 → 100 | 104 → 104 |
| 完整 run：200 趟收口 + 1 趟开着 | 169 → 116 | 154 → 113 |

## 5. 仍然开着的边界

- 收口了的微调攒到几百趟：每一趟还要读原话记录与 `state.json` 才知道它收没收口，200 趟时一次检查仍多约 60ms。再要省得给门禁加一份索引（又一份门禁专属文件，跨会话同写要锁）。
- `current-run` 不在、只有微调的项目里，`readRunContext` 判 no-run 之前要把每个目录认一遍（`runctx.mjs` 的 `isTweakRunDir`，不经进程内的记忆）。

## 6. 没量到的

- macOS、Linux 上的量数（这一次只在 Windows 上量）；交互会话里一次子代理写入经过的四道门禁加起来的时间。

## 7. 版本

8.1.0：门禁是插件会加载的，挪中间一位。
