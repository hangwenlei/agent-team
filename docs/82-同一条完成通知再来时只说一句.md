# 同一条完成通知再来时只说一句

> 2026-10-11，分支 `r40-completion-repeat`。第四十轮（从开放边界索引挑）：`docs/38` §5「重复通知会重复回传」，也是 `docs/80` §4「同一个通知到了不止一次时
> 进度整段重报」。

## 0. 一句话结论

- 平台对同一个 task-id 会送不止一条完成通知（`docs/38` §1.3 的实测），完成核验每一条都把同一段话整段重报。现在门禁在派发记录里
  记下这一条通知上一次回传的指纹（`told` 行），同一个 `agent_id` 再来一条、结论没变时改说一句短的：「这条完成通知门禁之前已经核过一次、结论没变——照那一次的回传
  处理」，并给看不到那一次时的出路（读它的回报、照 `/agent-team:at` 第 3 节「核实」去 run 目录核实）；结论变了（停下的结果变了、交了一部分、进度里谁停下了）
  照常整段报；交齐了照旧不出声；收口之后的那一句、别的一趟的通知照旧每次说。`/agent-team:at` 第 3 节写了这种回传的意思。出路与收口那一支是复核之后改的（§8）。

## 1. 问题

- 同一条结论反复整段出现在项目经理的上下文里：缺产物那一段、协调者进度那一段，每来一条通知都再来一遍（`docs/80` 让协调者自己没交齐时也报进度之后，量翻了一倍）。
- 不能改成一声不吭：项目经理会把门禁没说话读成「核过了、没问题」——交齐了时门禁本来就不出声。

## 2. 修法

- `hooks/lib/completion.mjs`：`toldLine({ at, agentId, role, stage, sha })`（`kind: 'told'`）；`readDispatchLog` 多认一种行，回给 `told: Map(agent_id → 最后一次的指纹)`，
  指纹不是 `sha256:<64 位十六进制>` 的跳过。
- `hooks/gate.mjs` 的完成核验：每一条通知核完之后（`settle`，在下一条开始前与最后各结一次），它在回传里那一截按 `sha256OfContract` 算指纹，与 `told` 里记的比——相同
  就把那一截换成那一句短的；不同就照常留着、往派发记录追加一行 `told`。什么都没说的不记；只对这一趟派发记录里有、花名册与阶段链认得、这一趟还没收口的派发做
  （别的一趟的通知、收口之后的那一句照旧每次说，也不往已收口的 run 写）。写不进派发记录只留痕（说清是下一条会照常整段报），下一次照常整段报。
- `commands/at.md` 第 3 节：交付物核验那一段补一句——同一个子代理的通知再来、结论没变时回传只说一句，照那一次的回传办。

## 3. 判据与变异

- `tests/completion-repeat.test.mjs`：`told` 行的解析（最后一次为准、形状不对的跳过）；第二回、第三回只说一句、不整段重报；之间门禁拦过它一回（成因变了）照常整段报，
  交了就不出声；记下的是派发记录里的一行 `told`；一条消息里两个子代理的通知各按各的指纹认；短话里有 `/agent-team:at-status` 的出路。
- 变异（备份在仓库外，每一刀改完逐字节还原）：末尾不结算、不比指纹、不记指纹、解析不认 `told`、重复时不出声、循环开头不结算、不认指纹的形状——每一刀都有判据红。
- 复核之后（§8）补的：多段回传（缺产物加进度）第二回整段只说一句、它派出去的人交齐停下之后第三回整段报；交齐了的来两回都不出声、不记；收口之后的那一句照旧、
  不往已收口的 run 写；别的一趟的通知照旧每次说；指纹是字符串却不是 sha 的形状也跳过；正文那一句。变异：去重挪回收口之前、指纹只算第一段、短话只换第一段、
  空回传也去重、只认字符串不认形状——每一刀都有判据红。

## 4. 仍然开着的边界

- **指纹按整段回传算**：回传里任何一个字变了（比如进度里另一个人的状态变了）就算结论变了、整段重报；只看「这个人交没交」不看别的那种去重没做。
- **`told` 行 `Bash` 写得进**：删了它，下一次照常整段报；伪造一行同指纹的，下一次只说一句（`docs/00-开放边界.md` §2「`Bash` 不经门禁」那一族）。
- **只对这一趟派发记录里的派发**：别的一趟的通知（切走指针之前派的）照旧每次报那一段。
- **短话依赖项目经理还看得到上一次**：上下文压缩过之后看不到的，靠短话里给的出路（读回报、去 run 目录核实）；成因、谁还在跑这些只在派发记录里，at-status
  不读它，补不回来。
- **同一个角色派了两个、两条都只说一句时分不出是哪一个**：短话只带角色与段，不带 agent_id。

## 5. 没量到的

- 真实会话（交互终端、桌面端）里同一个 task-id 送了几条通知、项目经理读到短话之后怎么做。

## 6. 归属

- `hooks/lib/completion.mjs` 的 `toldLine`、`readDispatchLog`；`hooks/gate.mjs` 完成核验那一支的 `settle`；判据在 `tests/completion-repeat.test.mjs`。

## 7. 受影响的旧说法

以本文为准，原话不改，订正与收口写在原话的标题底下：

- `docs/38` §5「重复通知会重复回传」：写了收口。
- `docs/80` §4「同一个通知到了不止一次」：写了收口。
- `docs/00-开放边界.md`：`docs/38` §5、`docs/80` §4 两行改了，这一份的 §4、§5 登上。

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：一条消息里多个 task-id、当前这一趟与别的一趟混排时切片边界都对；`told` 行写进的就是 `dispatchOf` 查的那一份；新旧两版的
`readDispatchLog` 都跳过 `told` 行，别的消费方（`dispatchedByStage`、`lastStop`、`elsewhereRunOf`）不受影响；写不进时不拦。两个中等、几个小问题：

- **中 1：收口之后的那一句也被换成短话，还往已收口的 run 写了 `told` 行**——与 §2 的说法相反，H5a、H5b 对收了口的那一趟都不记。→ 去重从收口那一支之后开始。
- **中 2：多段回传、交齐了不出声、别的一趟、指纹形状都没有判据**——指纹只算第一段、短话只换第一段、空回传也去重、别的一趟也去重、只认字符串，全量都绿；
  前两刀会把 `docs/80` §4 那个情形（它派出去的人后来交齐了）报成「结论没变」。→ 各补一格。
- **低**：短话里的 `/agent-team:at-status` 补不回成因与谁还在跑（→ 出路改成读回报、去 run 目录核实，§4 登上）；写不进时留痕说「这一次少核」，其实是下一条会多报
  （→ 改了）；§0 与判据头注释的平台事实说法与 `docs/38` §1.3 不一致（→ 改成引它）；两处注释说派发记录只有两种行、只有 H5a 与 H5b 写（→ 改了）；同一个角色两个
  子代理的短话分不出（→ 登在 §4）；`/agent-team:at` 第 3 节没提这种回传（→ 补了一句）。
