# 一趟真实会话与原话记录的绑定

> 2026-10-10，M4w，分支 `m4w-bind-words-new-rundir`。第十六轮：起一趟端到端的真实会话，实地看 3.2.0 到 3.8.0 那几轮只有判据覆盖的新行为。这一趟
> 发现「契约第 1 节对着用户原话核」在真实会话里从没生效过，当轮修好、再起几趟短会话复测。

## 0. 一句话结论

- 一趟真实会话从空的 git 仓库起，`/agent-team:at-init` 之后 `/agent-team:at` 一个命令行小工具，一路走到收口，门禁除了每轮的自检没有拒过任何一次。
- 但原话记录没有绑进那一趟：建 run 的那一次（H6，PreToolUse）run 目录还不在，往里写记录抛 ENOENT、被吞掉，项目一级那份却已经标了 `bound`——
  这一趟从此不核第 1 节。子进程判据的夹具都先建了 run 目录，测不到。现在绑分两步：H6 只在项目一级那份记下打算绑到哪一趟（`binding`），同一次
  Write 落盘之后账本（PostToolUse）才标 `bound`、写 run 目录那份。复测的几趟都绑上了，写入被拒过一次的那一趟也是。

## 1. 实测 M13（S1 到 S8）

- **设置**：CLI 2.1.286，SDK 宿主（`-p` 加 stream-json），`sonnet`，门禁留痕开着；插件是 `main`（v3.8.0）用 `git archive` 导出的副本，经 `--plugin-dir`
  加载。项目是只有一份 `README.md`、一次初始提交的空 git 仓库。驱动对 `AskUserQuestion` 选第一项、问题与答案落盘，按名字一把杀进程的命令拒掉
  （这一趟一条都没拒）。
- **两条消息**：`/agent-team:at-init`；`/agent-team:at 做一个命令行小工具 wordcount：……Node.js，不用 TypeScript，零依赖。要有自动化测试，npm test 能跑。
  在 src/ 下放一份 CLAUDE.md，写清这个目录的代码约定。一路走到收口，中间要我定的事照常问我。`
- **走法**：at-init 问要不要把 `.agent-team/` 加进 `.gitignore`（选了加）。S1 契约第 1 节逐字照抄。S2 只派 `at-product`（`at-ui` 照命令行工具裁掉，
  `trimmed` 与 `never_invoked` 都记了）；S3 派架构师。S4 项目经理先用不改仓库的 git 命令记了代码基线，然后主动问用户：「`CLAUDE.md` 属于敏感位置……
  门禁也不允许把它连带在 `src/` 目录前缀里放行。是否批准把单个文件 `src/CLAUDE.md` 补进 at-backend 的写入权限」（选了批准）；照这个答复改契约、
  把 `src/CLAUDE.md` 写明补进 `at-backend` 的 `paths`、重写触达表。S5 派架构师，架构师前台派 `at-backend`，`src/CLAUDE.md` 照写明的前缀写进去、没被拒；
  S6、S7 各派一次，结论都是通过；S8 写交付文档、收口。整趟七分钟左右。
- **门禁**：每轮第一次写 `.agent-team` 之前都自检（「在线」）；此外没有一次拒绝。派发记录里六次派发都有放行的停下行，所以收口之后的【派发】清单
  不出现（`docs/56`）。`state.json` 的键与模板逐项相同，没有「认不出的键」（`docs/55`）。项目经理推进之前读产物，自己跑了 `npm test`（全过）。
- **发现**：项目一级的 `.agent-team/user-words.json` 标着 `bound` 那一趟，那一趟的 run 目录里却没有 `user-words.json`。H6 在项目经理第一次 Write
  `runs/<id>/state.json` 时绑定：先把项目一级那份标上 `bound`，再往 run 目录里写——项目经理不先建目录，Write 落盘时才建，这时目录还不在，
  写入抛 ENOENT、被接住只往 stderr 留一行（PreToolUse 上的 stderr 不进转录）。这一趟的第 1 节碰巧是照抄的，没出事；转写走了样，门禁也不会说。
  第八轮（`docs/50`）的真实会话跑的是绑在写契约那一次的第一版，复核修订挪到 H6 之后，这一路只有子进程判据，夹具的 `createRun` 先建了目录。
- **别的观察**：项目经理写的时刻是编出来的。契约的「冻结时间」与 `history` 的头几条接近本地时间（UTC-7）、却带着 `Z`；后面几条与 `closed_at`
  （`13:15Z`）比本地时间走得还快——`state.json` 最后一次落盘在本地 12:53。复测那几趟写的是整点、半点（`12:00Z`、`13:30` 打头的 run id），
  真实时刻是本地 13:24 前后。门禁只核 ISO 形状。

## 2. 修法

- 绑分两步（`hooks/gate.mjs`）：
  - **H6（PreToolUse）**：`settleWords` 判出「绑」时只往项目一级那份记 `binding: <run id>`，不碰 run 目录、不标 `bound`。这一刻这次写入还可能被
    用户的权限确认拒掉，同一次写入上的几道门禁又是并行的——H6 放行不等于这次写入落盘。H6 这一步只认项目经理的写入（`isContractWriter`）：别的角色
    写 `state.json` 被 H3 拒，H6 这边不能先替它记下 `binding`。
  - **账本（PostToolUse，同一次 Write）**：`finishWordsBinding` 按路径认 `.agent-team/runs/<id>/state.json`，不经运行上下文（这一刻 `current-run` 多半
    还没写：`/agent-team:at` 第 1 节先写 `state.json`、再写指针）。项目经理写的、文件在磁盘上、项目一级那份同一个会话、`binding` 指着这一趟、还没绑
    也没作废（`hooks/lib/user-words.mjs` 的 `finishBinding`）——先标 `bound`、清掉 `binding`，再写 run 目录那份（带 `bound_at`）。
- 判据的夹具照真实会话的顺序：H6（目录还不在）→ 落盘 → 账本 → 写指针；新加的几格从 at-init 之后的形状起（`.agent-team` 下没有 `runs/`、没有
  `current-run`）。

    第 1 节对不上时【契约】照样说。

  - 第二步只认项目经理、同一个会话、`binding` 指着的那一趟、文件在磁盘上、路径是 `runs/<id>/state.json`（同一趟的契约、`.agent-team` 下别的目录里

## 4. 仍然开着的边界

- **绑做了一半**：H6 记下了 `binding`、这次 Write 也落了盘，账本那一步却没跑成（门禁子进程起不来之类）——同一个会话里项目经理之后再写那一趟的
  `state.json` 时补上；一直没再写的，这一趟不核第 1 节。
- **时间是项目经理自己写的**：「冻结时间」、`history` 的时刻与 `closed_at` 门禁只核 ISO 形状，不核是不是真时间、是不是 UTC。

## 5. 没量到的

- 这一趟没碰上、所以没量到的：S2 里 `at-ui` 被拒（`docs/54`，这一趟裁掉了 `at-ui`）、`state.json` 里拼错的键（`docs/55`）、收口时还有人在跑（`docs/56`）、
  截断（`docs/57`）、项目经理把第 1 节转写走样之后被门禁指出、改回去的那一路。
- 交互终端，default、auto 两种权限模式（第 44 条）；写入被拒那一格是驱动替用户拒的，不是真人在权限确认里拒。

## 8. 复核与修订

第一版修法（H6 先 `mkdirSync` run 目录、再写原话记录）推上分支、CI 全绿之后，起了一个对抗复核的子代理，在仓库外的临时项目里照真实顺序喂
`boot.mjs` 做实验、对第一版做变异。两个中等问题、两个小问题，都在这一轮改了：

- **中 1：写入被拒时留下空壳目录，新的一趟照样不核第 1 节。** 门禁在权限判定之前跑，H6 放行之后这次 Write 还可能被用户拒掉。第一版在 H6 里就建了
  目录、写了记录、标了 `bound`：`runs/<id>/` 里只剩一份原话记录，项目从「没有 run」翻成「指针丢了」，下一次自检会叫项目经理另起一个 run id；照做的话
  新的一趟没有原话记录（项目一级那份已经标了 `bound`、指着空壳），第 1 节静默不核。沿用同一个 id 也不对。→ 改成 §2 的两步，并且两步都只认
  项目经理的写入。
- **中 2：新判据没照真实形状造。** 第一版新加的那一格里 `runs/` 还在、`current-run` 也指着 r1，真实会话的 `runs_before` 是空的。两刀存活：非递归的
  `mkdirSync`（真实形状下照旧 ENOENT）、「开头无条件建目录」。→ 新的几格从 at-init 之后的形状起，并钉住「H6 不建目录」「没落盘就什么都不留」。
- **低 3：建目录用的路径没规范化。** 两步之后 H6 不再建目录，这一条随之消失。
- **低 4：§1 把编出来的时刻说成了时区写错。** 改了 §1 那一条，并把复测那几趟写的时刻一起记上。
- 复核也确认了：门禁专属的其余几份（`delivered.json`、`contract-base.json`、`dispatches.jsonl`、`approvals.jsonl`）第一次写入都在 run 目录已经在之后，
  没有同族问题；run 目录经 `isControlFile` 限定在 `.agent-team/runs/<一段>/` 下。
