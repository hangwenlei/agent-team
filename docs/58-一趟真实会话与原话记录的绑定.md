# 一趟真实会话与原话记录的绑定

> 2026-10-10，M4w，分支 `m4w-bind-words-new-rundir`。第十六轮：起一趟端到端的真实会话，实地看 3.2.0 到 3.8.0 那几轮只有判据覆盖的新行为。这一趟
> 发现「契约第 1 节对着用户原话核」在真实会话里从没生效过，当轮修好、再起一趟短会话复测。

## 0. 一句话结论

- 一趟真实会话从空的 git 仓库起，`/agent-team:at-init` 之后 `/agent-team:at` 一个命令行小工具，一路走到收口，门禁除了每轮的自检没有拒过任何一次。
- 但原话记录没有绑进那一趟：建 run 的那一次（H6，PreToolUse）run 目录还不在，往里写记录抛 ENOENT、被吞掉，项目一级那份却已经标了 `bound`——
  这一趟从此不核第 1 节。子进程判据的夹具都先建了 run 目录，测不到。现在先建目录再写；复测那一趟绑上了。

## 1. 实测 M13（S1 到 S8）

- **设置**：CLI 2.1.286，SDK 宿主（`-p` 加 stream-json），`sonnet`，门禁留痕开着；插件是 `main`（v3.8.0）用 `git archive` 导出的副本，经 `--plugin-dir`
  加载。项目是只有一份 `README.md`、一次初始提交的空 git 仓库。驱动对 `AskUserQuestion` 选第一项、问题与答案落盘，按名字一把杀进程的命令拒掉
  （这一趟一条都没拒）。
- **两条消息**：`/agent-team:at-init`；`/agent-team:at 做一个命令行小工具 wordcount：……Node.js，不用 TypeScript，零依赖。要有自动化测试，npm test 能跑。
  在 src/ 下放一份 CLAUDE.md，写清这个目录的代码约定。一路走到收口，中间要我定的事照常问我。`
- **走法**：at-init 问要不要把 `.agent-team/` 加进 `.gitignore`（选了加）。S1 契约第 1 节逐字照抄。S2 只派 `at-product`（`at-ui` 照命令行工具裁掉，
  `trimmed` 与 `never_invoked` 都记了）；S3 派架构师。S4 项目经理先用不改仓库的 git 命令记了代码基线，然后主动问用户：「`CLAUDE.md` 属于敏感位置……
  门禁也不允许把它连带在 `src/` 目录前缀里放行。是否批准把单个文件 `src/CLAUDE.md` 补进 at-backend 的写入权限」（选了批准）；照这个答复改契约、
  把 `src/CLAUDE.md` 写明补进 `at-backend` 的 `paths`、重写触达表。S5 派架构师，架构师前台派 `at-backend`，`src/CLAUDE.md` 照写明的前缀写进去、没被拒；
  S6、S7 各派一次，结论都是通过；S8 写交付文档、收口。整趟七分钟左右。
- **门禁**：每轮第一次写 `.agent-team` 之前都自检（「在线」）；此外没有一次拒绝。派发记录里六次派发都有放行的停下行，所以收口之后的【派发】清单
  不出现（`docs/56`）。`state.json` 的键与模板逐项相同，没有「认不出的键」（`docs/55`）。项目经理推进之前读产物，自己跑了 `npm test`（全过）。
- **发现**：项目一级的 `.agent-team/user-words.json` 标着 `bound` 那一趟，那一趟的 run 目录里却没有 `user-words.json`。H6 在项目经理第一次 Write
  `runs/<id>/state.json` 时绑定：先把项目一级那份标上 `bound`，再往 run 目录里写——项目经理不先建目录，Write 落盘时才建，这时目录还不在，
  写入抛 ENOENT、被接住只往 stderr 留一行（PreToolUse 上的 stderr 不进转录）。这一趟的第 1 节碰巧是照抄的，没出事；转写走了样，门禁也不会说。
  第八轮（`docs/50`）的真实会话跑的是绑在写契约那一次的第一版，复核修订挪到 H6 之后，这一路只有子进程判据，夹具的 `createRun` 先建了目录。
- **别的观察**：项目经理把「冻结时间」与 `closed_at` 写成本地时间、却带着 `Z`（真实的 UTC 时间晚七个小时）——门禁只核 ISO 形状。

## 2. 修法

- `hooks/gate.mjs` 的 `settleWords`：标上 `bound` 之后、写 run 目录那一份之前，先 `mkdirSync(runDir, { recursive: true })`。Write 落盘时本来就要建这个目录。

## 3. 判据、变异与复测

- `tests/gate-user-words.test.mjs`：照真实会话的顺序造一格——项目里没有 run 目录，记录器记下原话，H6 判建 run 的那一次 Write（目录还不在），然后才落盘、
  写指针；那一趟要有原话记录，第 1 节对不上时【契约】照样说。修之前这一格红。
- 变异（备份在仓库外，改完逐字节还原）：撤掉建目录那一行，这一格红。
- **复测 M13b**：插件副本换上这一处修法，另起一个空仓库，`/agent-team:at 做一个命令行小工具 greet：运行后打印 hello world。这次写完契约、推进到 S2 就
  停下，先别派人。`——那一趟的 run 目录里有了原话记录（带 `bound_at`），第 1 节照抄，推进到 S2 时 H6 放行。
- 两场会话结束之后按命令行里的探针目录名查过进程，没有残留；SDK 宿主的会话自己退出了（不是 `--bg`，不用 `stop`、`rm`）。

## 4. 仍然开着的边界

- **H6 先建了目录、这次 Write 却没落盘**（例如交互终端里用户拒了这次写入）：run 目录里只剩一份原话记录、没有 `state.json`；项目经理照常重写时照常建
  `state.json`，换了 run id 的话留下一个只有原话记录的空目录。
- **时间是项目经理自己写的**：「冻结时间」与 `closed_at` 门禁只核 ISO 形状，不核是不是真时间、是不是 UTC。

## 5. 没量到的

- 这一趟没碰上、所以没量到的：S2 里 `at-ui` 被拒（`docs/54`，这一趟裁掉了 `at-ui`）、`state.json` 里拼错的键（`docs/55`）、收口时还有人在跑（`docs/56`）、
  截断（`docs/57`）、项目经理把第 1 节转写走样之后被门禁指出、改回去的那一路。
- 交互终端，default、auto 两种权限模式（第 44 条）。

## 6. 归属
