# 拒绝路实测与已写下的时间

> 2026-10-13，分支 `r50-keep-old-times`。用户照维护者给的步骤跑了两场专门走拒绝路的真实会话（桌面端 CLI 2.1.295，Opus 5.5，思考程度 high，插件 6.8.0；
> 项目、插件安装由维护者事先备好）。照结果修一处正文的歧义，README 补一段默认权限模式。

## 0. 一句话结论

- **R1（默认权限模式，用户拒掉一次写入）**：拒掉之后这一轮停下（平台的规矩，不是门禁），说「继续」接着做；被拒的那次建 run 没落盘，项目经理换了编号重建，门禁记下的
  原话绑到了重建的那一趟（`docs/58` 那两步第一次在真人拒绝下走过）；各角色的权限请求都弹到了桌面端；收口。
- **R2（auto 模式，项目里本来就挂着一条测试）**：测试报告判不通过；门禁在测试报告写成那一刻就说推进出 S6 会被拒、给出「照现状交付」的问法；项目经理先记一条升级再问；
  用户选了它，记录器记下批准、绑在那一刻的测试报告上；答复那一块记成用掉批准的那一块、不算改需求；推进、验收、收口放行（`docs/46`、`docs/66` 那条路第一次在真实会话里走通）。
- **时间**：两场 `history` 的 at 都照门禁给的写，等过角色之后的推进项目经理都先再自检取一次时间。但两场收口那一次都把挨着的 S8 那一条已有的时间换成了收口时间、
  随后自己改回去（整份重写 `state.json` 时把手头这件事的时间带进了挨着的那一条；S1 到 S7 的推进一次都没改过旧时间）。几处说法写明只有这次新写的那个时间照最新的写，
  已经写下的原样带着。

## 1. 实测

| 场次 | 设置 | 做了什么 | 结果 |
|---|---|---|---|
| R1 | 空目录 `at-trial-r1`；默认权限模式（每次都询问） | `/agent-team:at-init`；`/agent-team:at 写一个 Node.js 脚本 hello.js，运行时输出 hello；要有自动化测试。`；用户拒掉一次请求，说「继续」；再拒掉第一次写 `state.json`，说「继续」；之后一律允许 | 收口；测试与验收都通过 |
| R2 | 维护者备好的 `at-trial-r2`（记笔记的命令行小工具，git 仓库，一次提交；`tests/format.test.js` 本来就挂着，README 写着那份文件归别人在改）；auto 模式 | `/agent-team:at-init`（问要不要把 `.agent-team/` 加进 `.gitignore`，选了加）；`/agent-team:at 给这个笔记小工具加一个 count 命令……要有自动化测试。`；测试没全过时选「照现状交付」 | 收口；测试报告「结论：不通过」（只挂那一条旧的），照现状交付放行；验收通过 |

## 2. 观察

- **默认权限模式下第一下弹的是读插件的文件**：插件装在项目文件夹之外，项目经理开工就要读插件目录里的模板与 skill，读也要确认。用户第一次拒的就是这一下，不是 `state.json`。
  拒掉任何一次，平台回「STOP what you are doing and wait for the user」，这一轮停下；说「继续」之后从门禁自检重新开始。
- **R1 拒掉 `state.json` 之后**：被拒的那次（run `20261013-1341-hello-script`）没落盘、目录也没建出来；项目经理说「继续」之后用新编号 `20261013-1342-hello-script` 重建，
  项目一级的原话记录 `bound` 是重建的那一趟、run 目录那份照样写了，契约第 1 节对上原话，契约基线是新口径（`slicing: 2`、`section1_next`）。
- **桌面端默认权限模式下各角色的请求都弹给了用户**（桌面端的派发是前台的），一路跑到收口；用户没反馈卡住。
- **R2 的照现状交付**：`approvals.jsonl` 一行（`source: ask`、`kind: deliver-as-is`、`product: 06-test.md`、`stage: S6`），门禁当场回【门禁】说批准只对那一份测试报告有效；
  契约基线的 `deliver_used` 记了那份测试报告的 sha、`deliver_blocks` 记了答复那一块，`verify_base` 空（没被当成改需求）。H6 拒推进那一刀没触发：【阶段】在 S6「齐了」时
  就预告了会拒、给了问法，项目经理照着先问了。项目经理先把升级记成 `tradeoff`，读到【阶段】里「要用户在没过的用例与契约之间取舍的是 `contract-conflict`」之后改了过来。
- **时间**：R1 的八条 `history` 与 `closed_at`、R2 的八条与 `closed_at`，都与写入之前那一次自检或【阶段】给的门禁时间逐秒相同（R1 第一条 `13:42:41` 就是那一轮自检的时间）。
  等过角色之后的推进，项目经理都先说一句「先取一次门禁时间」、再自检一次（R1 五次、R2 四次）；刚收到【阶段】的推进直接用它给的时间——正文那一句「等过就再自检
  取一次」起了作用。
- **收口改了旧时间**：R1 收口那一次把 S8 那一条从 `13:56:59` 改成 `13:57:48`（与 `closed_at` 相同），随后再写一次改回；R2 同样（`14:00:27` 改成 `14:00:53` 再改回），
  R2 还在改升级类别那一次把那条升级的 at 换成了新的时间。被换的只有这两种：收口那一次挨着的最后一条、正在改写的那一条；R2 推进到 S7 那一次，已有那条升级的 at 原样留着。
  项目经理自己说是「误把……改成了」。门禁不拦（history 的时间门禁不核），项目经理自己发现、自己改回，多写了一次。

## 3. 裁定、修法与判据

- **修正文的歧义**：「state.json 里的时间……用这次写入之前最后拿到的门禁时间」改成「这次新写的时间（history 新追加的那一条、escalations 新记的那一条的 at、closed_at）……；
  已经写下的时间原样带着，不跟着换」。同一个意思写进自检的回复、【阶段】推进那一句（「已有的 history 与 escalations 条目原样带着」）与收口那一句（「history 原样带着，
  连时间也不改」），`/agent-team:at` 第 6 节收口那一步加「已有的条目连时间也不改」，返工预算那一处重写被拒的写入时，新追加的那一条照最新的门禁时间写。真正对着病因的
  是收口那两句；照不照新说法，要下一次真实会话才看得到（§5）。
- **门禁不加「已有条目的时间不许改」**：history 的时间不进任何判据（返工计数数的是段名，契约基线用门禁自己的 `revised_at` 与派发记录），只是记录；拦下来也省不掉
  那一次重写。改 history 旧条目段名的拒绝理由原来说「at 可以订正」，与正文相抵，改成「已有的条目原样带着，段名、时间都不改，也不许删」。
- **README 补一段**（两半）：默认权限模式下会频繁弹窗——每次写文件、跑命令都要确认，插件装在项目之外，项目经理和部分角色读插件自带的说明也要确认；拒掉项目经理的
  一次请求这一轮就停下，说「继续」接着做；嫌多可以用 auto 模式。
- **判据** `tests/gate-clock.test.mjs`：几处说法整句钉；README 两半各整段钉；改旧条目段名的拒绝理由不再说订正。
- **变异**（备份在仓库外，改完逐字节还原，每刀跑全量），每一刀都红：自检不说已写下的原样带着、推进不说已有的条目原样带着、收口不说连时间也不改、正文那一句不说原样带着、
  正文收口那一步不说不改、README 中文那一段、README 英文那一句；复核之后：【阶段】不提 escalations、拒绝理由退回「at 可以订正」、正文重写被拒写入那一句去掉、
  README 两半各删半句。

## 4. 仍然开着的边界

- **门禁不拦改已有条目的时间**（有意，见 §3）：项目经理照不照新说法只靠正文与回传。
- **H6 因测试不通过拒推进**那一刀在真实会话里没触发（【阶段】提前给了问法，项目经理先问了）。
- **交互终端的默认权限模式**（第 44 条）：照旧没量。

## 5. 没量到的

- 真实会话里项目经理照新说法收口、不再改已有的时间。
- 子代理的请求被拒之后会不会同样停下（两场只拒过项目经理的请求）。

  `README.md`；判据见 §3。

## 8. 复核与修订

第一版（01d04b0）推上分支之后起了一个对抗复核的子代理。下面这些核过了：其余运行时正文与门禁回传没有诱导改旧时间或估时间的说法；本文对着转录与磁盘逐项相符（时间
逐秒相同、被拒那一趟没落盘、原话绑到重建的那一趟、批准与契约基线）；收口写在原话底下；README 两半对齐、没有版本号与 docs 编号；不加门禁的结论站得住。没有高，两个中、
几个低：

- **中 1：病因说偏了**——被换的只有收口那一次挨着的最后一条与正在改写的那一条，不是「所有时间都换成最新的」；不加门禁的理由也站偏了。→ §0、§2、§3 改写诊断，理由
  改成「history 的时间不进任何判据，只是记录」。
- **中 2：README 那一段说偏了**——默认模式下弹窗主要来自写文件、跑命令，读插件说明只是额外的一部分；「允许读取插件所在的目录」没实测、说法含糊（目录带版本号，
  顺手放开整个 `~/.claude` 会连凭据一起放开）；「拒掉任何一次」只在项目经理身上量到。→ 照实改写，删掉那条出路，收窄成拒掉项目经理的请求。
- **低**：CHANGELOG 把没量到的效果写成了既成事实（→ 只写说明改了什么）；改旧条目段名的拒绝理由还说「at 可以订正」（→ 改掉）；README 那条判据比名字弱（→ 两半整段钉）；
  「每次推进前都自检」说过头（→ 等过角色之后的推进）；`docs/00` 第 44 条与 `docs/92` 两行没跟上（→ 改了）；【阶段】那句读起来只管 history（→ 带上 escalations）；
  重写被拒的写入时那一条的时间（→ 正文补一句）。
