# 认领的目录不连带自动加载的位置

> 2026-10-10，M4r，分支 `m4r-guarded-below-claims`。第十一轮，从 `docs/00-开放边界.md` §3 挑的：`docs/41` §4「有键的角色在自己前缀下写嵌套的
> `CLAUDE.md`、`.claude/`」（`docs/39` §2.2 第 34 条那一格）。正文是复核修订之后的样子，复核与改了什么在 §8。

## 0. 一句话结论

- 原来一个角色认领了 `src/server/`，就能在它下面新建 `CLAUDE.md`、`.claude/`、`.git/hooks/…`，H3 放行：前两样 Claude Code 在那个目录下干活时会当成
  指令或配置加载，`.git` 目录里的 hook 会被 git 执行——一次被诱导的写入能留下之后每个会话都会读到的指令。现在认领一个目录不连带它下面的 `CLAUDE.md`、
  `CLAUDE.local.md`、`.claude`、`.git`、`.agent-team`：落在这些上面的写入，H3 拒；前缀本身写明了它的（S4 照 `sensitive` 问过用户补进去的）照放行，
  `.agent-team` 除外——它不划给任何角色，写明了也拒。

## 1. 修法

- `hooks/lib/writepath.mjs` 的 `guardedBelow`：目标在调用者认领的前缀之下时，看前缀之下新出现的那一截，逐段按名字查（不分大小写，哪一段都认）：
  - `CLAUDE.md`、`CLAUDE.local.md`：Claude Code 在这个目录下干活时当成指令加载；
  - `.claude`：里面的 skill、命令与设置会被加载；
  - `.git`（目录或文件）：git 把那里当成仓库，hook 会被执行；
  - `.agent-team`：门禁从 cwd 往上认最近的项目根，嵌套一个就换掉了判据。它不看前缀写没写明：相对项目根的整条路径上有一段是它，就拒——
    写明认领一个嵌套的 `.agent-team`，照样换掉门禁认的项目根；项目根下那一个里的非控制文件，写明了也拒。
- 有一条前缀之下的那一截干净（或者目标正好就是前缀写明的那个文件）就放行——宽的前缀之下带着、窄的前缀写明了的，照放行。「在前缀之下」与「前缀之下
  那一截」由同一个 `restUnder` 算（`underAny` 也用它）；一条前缀都对不上时不放行。
- 接在两处放行之前：执行角色与协调者「写在自己前缀下」那一步，与建了键的 `at-qa`、`at-acceptance` 那一格（后者照它那一格的说法拒，不说怎么开口子）。
  项目经理与主线程不受 `paths` 管，照旧。
- 拒绝理由说清落在哪一类、会怎样，出路照 S4 那条路：冒泡给上级，由项目经理先问用户、把那个文件或目录本身写进它名下。那个位置已经写明划给了别的角色
  时，说归谁、经上级协调，不给「写进你名下」。`.agent-team` 不划给任何角色（S4：落在 `.agent-team/` 下的一律不补），出路是别建它、冒泡。拼进理由的
  只有调用者名、这次给的路径（`inline`）、花名册里的角色名（`quote`）与插件自己的说法，不引 `project.json` 里的前缀。
- `project.json` 的检查（`hooks/lib/project.mjs`）对任何深度的 `.agent-team` 都报（原来只看第一段）。
- `/agent-team:at` 的 S4 补了一句：执行角色为这几处冒泡上来的，`.agent-team` 一律不补，别的照 `sensitive` 先问用户，批了就把它本身补进名下（判据钉着）。
  README 两半「这不是沙箱」那一条补了同样的结论（判据整条钉着，跟着改）。
- 为什么不与 S4 冲突（`docs/41` §4 当时不堵的理由）：S4 让用户批了之后补的是写明那个位置的前缀（`.claude/`、`src/web/CLAUDE.md`），判的是前缀之下
  新出现的那一截，写明了的不在那一截里。

## 2. 判据与变异

- `tests/writepath-autoloaded.test.mjs`：
  - 每一类各拒、各说各的后果、不分大小写；
  - 名字只差一点的（`.gitignore`、`.github`、`.claudeignore`、`CLAUDE.md.bak`、`my.git`、`claude.mdx`，以及段名是 `constructor`、`__proto__` 的）照常放行；
  - 前缀写明的（单个文件、目录、`tools/.git/`）放行，写明的那一截之下再出现的照拒，宽窄两条前缀都盖得住时有一条干净就放行；前缀带 `..` 照解析后的位置判；
  - `.agent-team` 写明了也拒（嵌套的、项目根下的），`project.json` 的检查对嵌套的也报；
  - 已经写明划给别人的，说归谁、不给「写进你名下」；
  - 协调者同样拒，项目经理、主线程放行；建了键的 `at-qa` 照它那一格的说法拒；S4 那一句；子进程经门禁走一遍。
- `tests/readme-sync.test.mjs` 的「这不是沙箱」整条比对跟着改。

变异（备份在仓库外，改完逐字节还原）各红：一律不拦；前缀正好写明那个文件也拦；有一条前缀之下带着就拦；`.agent-team` 也给「写进你名下」；建了键的
`at-qa` 不判；拒绝理由不带出路；漏了 `.git`、`CLAUDE.local.md`、`.agent-team`、`.claude` 各一刀；执行角色那一步不判；查表用普通对象；只看前缀之下的
第一段；`.agent-team` 认「写明了」；只认相对项目根第一段的 `.agent-team`；写明划给了别人也给「写进你名下」；别人没写明也算归它；前缀不规范化；
`project.json` 不报嵌套的 `.agent-team`；S4 那一句改坏。

存活的两刀：

- 「不折大小写」：`norm` 在 Windows、macOS 上先把路径折成小写，这一刀在那两个系统上与原代码等价；复核在把 `process.platform` 换成 linux 的模拟下
  打红（五条），没在真的 Linux 上跑。
- 「一条前缀都对不上也放行」：两边共用 `restUnder` 之后走不到，是兜底。

第一版里「文件名只认最后一段」那一刀存活，改成哪一段都认（多拒一个叫 `CLAUDE.md` 的目录无害），代码更短。

## 4. 仍然开着的边界

- **`Bash` 写的照旧不管**（§2 的那一族）：执行角色用 `Bash` 在认领的目录下建 `CLAUDE.md`、`.git/hooks/…`，门禁看不见。
- **裸仓库的布局**：认领的目录下用 Write 拼出 `HEAD`、`config`、`objects/`、`refs/`，git 在默认的 `safe.bareRepository` 下把它认成仓库、读里面的
  `config`（复核实测 git 2.50；`core.fsmonitor` 一类的设置能执行命令）。不按文件名拒——`HEAD`、`config` 是常见的文件名。要防，在自己的 git 设置里写
  `safe.bareRepository=explicit`。
- **链接与短文件名**（`docs/25` §4 那一族）：仓库里已有指向别处的目录联接或软链接时，经它的名字写，路径解析之后名字被抹掉，照放行（Write 建不出链接）；
  前缀写成 Windows 的 8.3 短名（`CLAUDE~1/`）时门禁当它写明了，`project.json` 的检查不报。
- **只认这几个名字**：别的会被工具自动读取或执行的位置（`.github/workflows/`、`.vscode/`、`package.json` 的脚本、各语言的构建钩子）不在这一格里——
  它们是项目自己的代码，归认领与审查。
- **大小写不同、平台不加载的名字也拒**（例如 Linux 上的 `.CLAUDE`）：多拒无害。
- **写明了 `.claude/` 的，它里面的 `CLAUDE.md` 还要再写明**：`.claude/CLAUDE.md` 是又一处会被加载的指令。

## 5. 没量到的

- 真实会话里执行角色撞上这一格的拒绝之后照不照出路做（冒泡、项目经理问用户、补写明的前缀）。
  > **收口（M4w，2026-10-10，`docs/58`）**：量到的是另一路——需求里要 `src/CLAUDE.md`，项目经理在 S4 主动问用户、批了之后把这一个文件写明补进 `at-backend`
  > 名下，执行角色照写明的前缀写进去，没撞上拒绝。撞上拒绝、冒泡上来的那一路仍没量到。
- 「不折大小写」那一刀在真的 Linux 上打不打红（模拟下打红）。

## 8. 复核与修订

`31ccc31` 推上去之后一路对抗复核（门禁、正文与文档一起看，变异与探针在仓库外的副本里做）。路径写法——大小写、`..` 与 `.` 段、反斜杠、结尾的点或空格、
流后缀、指向已有文件的 8.3 短名——都被拒或者无害；新建一个字面上叫 `CLAUDE~1.MD` 的文件不会被加载；NTFS 不把 `.gıt` 当成 `.git`；NotebookEdit 走同一个
判定。带日期记录的原话没改，索引点到了本文的 §4、§5。

- **中 1　写明认领的嵌套 `.agent-team` 照样放行**：README 说「谁都不行」、拒绝理由说「不划给任何角色」，门禁却认「写明了」；`project.json` 的检查只看
  第一段；挡着的只有 S4 那一句，那一句没有判据。**改**：`.agent-team` 不认「写明了」、按相对项目根的整条路径查；`project.json` 的检查对任何深度都报；
  S4 那一句钉上。
- **中 2　裸仓库的布局绕开 `.git` 那一格**：复核实测 git 认它、读植入的 `config`；§0、§1 原来写得像 hook 执行这一路整个堵了。**改**：登进 §4（不按
  文件名拒），§0 改成说 `.git` 目录。
- **低**：
  - `guardedBelow` 自己重算前缀、一条都对不上就放行，与 `underAny` 各算一份（去掉它里面的规范化，Windows 上全绿）——两边共用 `restUnder`，对不上不放行，
    补前缀带 `..` 的一格；
  - 宽前缀的角色写别人已经写明认领的位置，拿到的是「写进你名下」——改成说归谁；
  - 已有的目录联接、8.3 短名的前缀——登进 §4；
  - 「五类各拒」报了总数——改成「每一类」；
