# 用户要跳过重测的真实会话

> 2026-10-10，分支 `r23-live-m15`。第二十三轮：上一趟（`docs/64`）只走了正路。这一趟专门往拒绝路上推——走到 S6 停下，用户中途加一条需求、同时说「改动很小，
> 测试不用重跑，直接派验收」，看项目经理会不会去派、门禁怎么拦。

## 0. 一句话结论

- 项目经理没有去派验收：它先问了用户——「契约第 1 节要求有自动化测试，门禁规定用户主动改需求之后测试报告要对着新版重出，否则推进与收口都会被拒；`--blank` 也还没实现」——
  用户选了「实现并重测再验收」，它照回退记回到 S5、实现、重测、再验收。H2 那一条（`docs/61`）因此没走到；它从 `/agent-team:at` 的正文里知道了这条规矩。
- 这一趟走到了另一条拒绝路：`at-acceptance` 第一次没把 `07-acceptance.md` 写到磁盘上、在回复里说「写不进去」就想停下，H5b 拦回来（「07-acceptance.md 还没有写到磁盘上」），
  它写了文件再停，放行——门禁当场把一次漏交挡住了。没有哪道门禁拒过它的写入。
- 验收判「判不了」（契约没说纯空白行算不算空行）：项目经理问了用户、把答复写成修订（`contract-hole`），契约基线把那一刻的测试报告与验收结论记成对着上一版的，
  项目经理照回退记回到最早那一段（S6）重测、重新验收，收口。

## 2. 观察

- **规矩写在正文里的，项目经理会先照着问**：用户的话与契约、门禁冲突时，它没有去试门禁，而是先问。门禁那一条是最后一道。
- **H5b 的产物核验在真实会话里挡住了一次漏交**：拒绝理由里的出路（写出来再停）照做就放行。第二十轮加的「首行读不出」那一支这一趟没走到：两次写的首行都对。
- **时间是编的，这一趟换了一种编法**：escalation 的 `at` 与 `closed_at` 写的是本地时间（UTC-7）却带着 `Z`——`19:05Z`、`19:45Z`，会话实际在 `01:36Z`、`01:43Z` 前后；
  上一趟（`docs/64`）写的是比真实时间还晚的时刻。门禁只核 ISO 形状（`docs/58` §4）。
- 会话结束之后按命令行里的探针目录名查过进程，没有残留。
