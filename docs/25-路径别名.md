# 路径别名

**日期** 2026-09-29 ｜ **口径** 分支 `m3q-path-alias`（`1905eaa`…`607038c`），版本 `0.9.0`；修的是全量审查
（`docs/24-附录-全量审查报告.md`）第 8、9、31 条

## 0. 一句话结论

门禁的「是不是契约、是不是控制文件、在不在 run 目录下、归不归某个角色」，此前全都是字面比较，
所以字面不同、指向同一个物理文件的写法全都漏得过去。没有 Bash 的 at-acceptance 借此能改写契约与
state.json，PM 能清零返工史。现在路径先解析到物理位置再比较；解析不了的写法直接拒；门禁绝不碰
网络路径。两轮独立复核都没有找到还能绕过的写法。

## 1. 问题

门禁判定路径全落在 `hooks/lib/path-norm.mjs` 的 `norm()` 上。它此前只做三件事：resolve、统一分隔符、
Windows 上转小写。审查实测过的漏法：

- **链接**：junction、目录软链接，以及悬空链接（目标还不存在，往里写会把目标建出来）。
- **Windows 8.3 短名**：`.agent-team` 的短名 `AGENT-~1`，文件本身的 `00-CON~1.MD`、`STATE~1.JSO`。
- **Windows 设备前缀**：`\\?\`、`\\.\`；不带盘符的设备路径 `\\?\GLOBALROOT\…`、`\\?\Volume{…}\…`；
  NT 名字空间前缀 `\??\`。
- **网络路径**：本机管理共享 `\\localhost\C$`、`\\127.0.0.1\c$`，以及 `\\?\UNC\…`、`\\.\UNC\…`。
- **流后缀与结尾字符**：`::$DATA`、`:名字`，以及以点或空格结尾的段。
- **macOS 大小写变体**：APFS 默认不区分大小写，而 `norm()` 只在 win32 上转小写。注释里写着
  「POSIX 文件系统大小写敏感」，这是一条错的平台假设。
- **run id**：黑名单放过了单独一个 `.` 与 `r1::$INDEX_ALLOCATION`。

受害最重的是没有 `paths` 条目的角色（at-qa、at-acceptance）：门禁认不出目标是 run 目录，就落到
「未认领，放行」。

## 2. 修法

### 2.1 `norm()` 解析到物理位置

- 已存在的最长前缀做 `realpathSync.native`，把链接、8.3 短名、带盘符的设备前缀、`::$DATA` 都解析
  到物理位置，还不存在的尾巴原样拼回去。
- 找前缀用 `lstat`，不用 `existsSync`：后者跟随链接，会把悬空链接当成「不存在」。悬空链接由门禁
  自己 `readlink` 跟过去，有深度上限。
- **大小写按目录探测，不按平台写死**：把已存在前缀里最后一个带字母的段翻转大小写，比较 dev 与 ino
  是不是同一个对象（`probeFoldsCase`）。探测不了（路径里没有字母可翻）才用平台默认：win32 与
  darwin 折叠。这样能认出 WSL 的 `/mnt/c` 这类 Linux 上不区分大小写的挂载，也不会在大小写敏感的
  APFS 卷、开了按目录区分大小写的 NTFS 目录上误折叠。darwin 上另做 NFC。
- **网络路径与不带盘符的设备路径一次 fs 都不调**，只做字面规范化。原因：门禁在 PreToolUse 上跑，
  早于平台对网络路径的人工确认。它对 `\\server\share` 做一次 `lstat`，就会在用户来得及拒绝之前
  发出 SMB 连接：服务器不通时逼近 hooks.json 的 30 秒超时，慢服务器上实测一次门禁要 2.8 秒，还可能
  泄露 NTLM 凭据。平台自己的 Write 也对网络路径特意跳过 stat。
- 进程内缓存。门禁延迟实测无变化，一次调用约 82 毫秒，大头是起进程。

### 2.2 解析不了的写法直接拒（`exoticPath`，只在 Windows 上）

- **认的形状**：
  - 流后缀；
  - 以点或空格结尾的段；
  - NT 名字空间前缀，以及不带盘符的设备路径；
  - 项目不在同一个共享上时的网络路径；
  - 反过来，项目在网络共享上时的本地盘路径（可能经本机共享绕回项目里的任何文件）。
- **拒在哪里**：
  - H3：写路径判定的最前面，对所有角色（主线程本来就不经 H3）。
  - H4：PM 豁免之后，对所有子代理。
  - H6：只在项目里有 `.agent-team`、且最后一段可能就是 `state.json`（含 8.3 短名）时拒。这是复核
    之后收窄的：H6 挂在每一次 Edit/Write 上，主线程写网络上一个不相干的文件不归它管。
- **为什么结尾带点也要拒**：写入方不同，结果不同。不带 `\\?\` 的 Win32 调用会把点剥掉，写的就是
  真实文件；Node 与 Bun 的 fs 会加上前缀，建出一个字面名字的新文件。门禁不知道写入方怎么处理。

### 2.3 run id 与 `runs/`

- run id 改成白名单 `^[A-Za-z0-9][A-Za-z0-9._-]*$`。命令正文规定的「日期-时刻-slug」是它的子集。
- 指针不在时，`runs/` 只数子目录与链接。`.DS_Store`、`.gitkeep` 这类杂项文件不再被当成「有人建过
  run」；此前它们会让所有非 PM 的写入被拒。

## 3. 两轮复核

**第一轮**（修完主体之后）：四路并行，分别是在本机系统地找绕过、变异扫描、平台事实核对、设计评审。
找绕过的那一路试了几十种写法，对 at-acceptance、at-qa、at-pm、at-frontend 逐个打 H3/H4/H6，
**没有一种能绕过**；反过来也没有新的合法写入被误拦。其余几路确认的问题都在第二轮修掉了：

- `norm()` 会对网络路径做 `lstat`：H6 在没有 `.agent-team` 的项目里会先去连 SMB。
- 大小写折叠按平台写死：WSL 的 `/mnt/c` 等挂载仍能绕过。
- H6 对主线程写任何网络路径都拒。这一条复核里有一位核验者判「不成立」，理由是 H6 的前置拦截是
  认不出的写法唯一的防线。收窄的做法同时满足了两边：只拦最后一段可能是 `state.json` 的写法，
  防线不松，误拦消失。
- 两种形状没认：`\??\` 前缀；项目在网络共享上、却写本地盘路径。
- 判据缺口若干，以及十几处被这一轮变成假话的注释，比如「纯函数」「POSIX 大小写敏感」
  「runs/ 非空就判 unreadable」。

**第二轮**做法同上。几刀关键变异各自打红：
- 网络路径走 canonical；
- 去掉「项目在共享上却写本地盘」这条规则；
- H6 不收窄；
- 去掉 `\??\`；
- 不探测大小写，改回按平台写死。

最后一刀靠一条 Windows 用例钉住：用 `fsutil file setCaseSensitiveInfo` 把一个目录设成区分大小写，
断言 `Ab` 与 `ab` 不折叠。「不碰网络」由 `tests/helpers/no-network.mjs` 钉着：它预加载进门禁进程，
拿网络路径调 fs 就留痕。只断言「拒了」钉不住这一条，因为先 `lstat` 再拒，结论一样。

## 4. 仍然开着的边界

> **更新（2026-09-30，M3u）**：补一条这里漏记的——被认领的前缀若是项目里一个指向项目外的链接（junction、软链），
> 持有者经它写、或直接写链接目标都放行：H3 按物理位置比较，前缀跟着链接走；`project.json` 的形状校验不碰文件系统，
> 报不出来。建链接要 Bash。见 `docs/29` §5。

- **硬链接与 bind mount**：同一个 inode、两条互不相干的路径。只有持 Bash 的角色建得出来，而 Bash
  本来就不经门禁。
- **项目本身在网络共享上**：
  - `norm()` 不碰网络，所以共享里的链接看不穿；
  - 同一台服务器的 FQDN 与 NetBIOS 名（`\\srv` 与 `\\srv.corp.com`）会被当成两个共享，方向是多拦；
  - 本地盘路径一律拒，包括项目之外的临时文件；
  - 项目根写成映射到本机共享的盘符、而写入用本地盘路径的情形没有覆盖。
- **主会话（at-pm）不能用 Write 写网络路径**：H3 对它一视同仁。需要写这些位置时由用户来写。
  README「已知边界」写了这一条。
- **大小写**：两个只差大小写、又分别是不区分大小写挂载的目录叠在一起时，会被当成同一个。只有
  在这种刻意构造的布局下才会发生。Linux 上不做 Unicode 规范化。
- **平台自己的可疑路径检查**覆盖了上面大部分形状，但它在 bypassPermissions 权限模式下失效
  （源码级）。这正是门禁要自带这些判据、不能指望平台的原因。
- **会话中途进 worktree**：见 `docs/24` §4.1，这一轮没有变化。

## 5. 平台事实（源码级，本机 CLI 2.1.283 内嵌源码与官方文档）

- Claude Code 的 Write 走 Bun 的 fs：对带盘符的路径加 `\\?\` 前缀，对 `\??\` 原样透传。写结尾带点
  的路径会建出一个字面名字的新文件；写 `…::$DATA` 时原子写的临时文件名非法，写不进去。
- Write 自己的可疑 Windows 路径检查（设备前缀、冒号、`~` 加数字、结尾点空格、UNC 等）在非 bypass
  模式下要求人工确认，在 bypassPermissions 下被先行放行。
- `realpathSync.native`：Windows 上是 `GetFinalPathNameByHandleW`，解析 8.3、junction、subst 与
  映射盘；macOS 上返回磁盘上的真实大小写；Linux 上不纠正大小写。
- hook 收到的 `file_path` 已经是绝对路径：平台在 PreToolUse 之前把 `~` 与相对路径展开了。

## 6. 没量到的

- 真实的 Linux 不区分大小写挂载（drvfs 之类）、大小写敏感的 APFS 卷：探测逻辑有单测，按目录区分
  大小写的 NTFS 目录有真实用例；前两者没有在真实挂载上量过。
- 没有起真实会话。门禁的判定是夹具实测，平台行为是源码级。
