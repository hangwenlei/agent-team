  H5a 交付物记录（状态行 `记录交付物校验…`）六条。

### 7.3 ⭐ 八道门禁里有五道在九份转录里零足迹 —— 而那是转录的性质，不是门禁的

**只有三道说过话**：H3 写路径门禁、ledger 账本回传、H5a 交付物记录。
**零足迹的五道**：H1 派发白名单、H2 前置产物、H4 契约保护、H6 返工预算、H5b 交付物拦截。

**机制**：**一道静默 exit 0 的 hook 在转录里不留任何记录。** 反证是算术级的：
主线程有 5 次 `Write` + 11 次 `Edit`，光 `PreToolUse` 那三道就是四十八次调用，
而转录里只有**两条** `PreToolUse:Write` 记录；5 次 `Agent` 调用 → H1+H2 十次调用，
`PreToolUse:Agent` 记录**零条**。八道的 `statusMessage` 在九份转录里的出现次数
恰好等于各自的记录条数——`校验派发白名单…`、`校验前置产物…`、`校验契约保护…`、
`校验返工预算…`、`校验交付物…` **全是零次**。

**归类：这五道「转录里就是没有」属于「结构上不可能」**，不是「我没做」
—— 不是我抽错了字段，是**那条记录根本不存在**。

⚠️ **而这本身是一条结论，而且它咬的是这个项目的验证手段**：`docs/19` §11 逐道量到
「八道平台都真的调起来了」，靠的是**让每一道说话**（手工造出会让它开口的状态）。
**在一趟正常的真实 run 里，一道判定为放行且无话可说的门禁，在转录这一层与
「它根本没跑」完全无法区分。** 这一趟因此证明不了那五道跑过——
**也证明不了它们没跑。**

下面五句是**从判据推的，不是从转录读的**（转录里没有它们），写下来只为说明
「今天为什么无话可说」这一侧不必然有问题：H1 七次派发全在花名册白名单内；
H2 每次派发时前置产物都齐（PM 每段都是先推进 `stage` 再派，§7.2 的段序印证）；
H4 对 `isContractWriter` 在读运行上下文**之前**就 exit 0，而这一趟碰 `00-contract.md`
的只有 PM；H6 `rework` 整趟是 `{}`、零返工，没有可减的计数；H5b 七次 `SubagentStop`
时该段产物都已落盘，S5 那一次返回的是协调者 `at-architect`、按 `isCoordinatorFor` 静默。
