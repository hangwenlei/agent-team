# 角色用上本机 skill

> 2026-11-05，分支 `worktree-skills-into-roles`。起因是插件作者自己用下来觉得团队做出来的 UI 不够满意，在 GitHub 上找到了更好用的开源 UI skill，
> 想让 `at-ui` 用上；别的角色同理。设计与实施计划经过一轮头脑风暴、用户批准：`docs/superpowers/specs/2026-11-05-角色用上本机skill-design.md`、
> `docs/superpowers/plans/2026-11-05-角色用上本机skill.md`。

## 0. 一句话结论

- **新命令 `/agent-team:at-skills`**：项目经理经 `Bash` 调插件自带的 `hooks/skills-cli.mjs`（不是门禁），把用户本机装的 skill（用户层、git 克隆的、
  项目层、已装插件带的）整份复制进 `.agent-team/skills/<dir>/`、记进 `.agent-team/skills.json`（分给哪几个角色、来源、指纹、同步时间）。
- **角色怎么用**：九个被派得到的角色同一节「登记给你的 skill」，项目经理一版自己的——开工时读清单、只看用途，用得上才读那份 `SKILL.md`；
  契约里用户点名的必须用；做法上与插件自带的（`at-ui-craft` 等）不一致时照 skill，管不了做什么（契约与产品定义定下的照它们），也盖不过四样（门禁与红线、
  要交哪几份、下游要读的项、开销规矩）；
  用过的记进产物的「用过的 skill」、交付文档汇总。
- **更新**：只在 `/agent-team:at` 起新一趟、建 run 之前比对本机原件与副本，没变不出声，变了问用户再同步；一趟进行中、续跑都不换。
  网上那一层只在用户发起检查时查（git 克隆的 `fetch` 后看落后几个提交，批准了才 `pull --ff-only`）。
- **不授 `Skill`、不加门禁**：角色写不进清单与副本靠现有的写路径隔离（`.agent-team` 不划给任何角色），新判据钉住。

## 1. 起因

用户要两种用法：角色自己判断着用、用户点名用，而且不离开团队。三种做法里选了「登记后复制进项目」（设计 §4）：开 `Skill` 工具要推翻长期决策、
角色看得到本机全部 skill（含管流程的）、带 `context: fork` 的会另起子代理绕开派发白名单（`docs/06`）；改写进插件自带 skill 满足不了「装了就用」。

## 2. 裁定

设计里标「我的裁定」的照设计；实现时另做的裁定：

- 清单的 `source` 多记一个 `ref`，`check` 按它重新认原件——插件升级换了 `installPath`、用户层的目录变成 git 克隆，照样认得。
- 副本目录一律由名字推出（`skillDirName`：`:` 换成 `__`，Windows 不收的字符换成 `_`），**不信清单里记的 `dir`**；推不出一层目录的名字（空、`.`、`..`）
  不复制、不删。起因是提交之后的后台安全审查：清单谁都能用 `Bash` 改，`remove` 原来照清单里的 `dir` 删目录。
- skill 目录里面的软链接（文件的、目录的、Windows 的目录联接）复制与算指纹都不跟；skill 目录本身是链进 `~/.claude/skills` 的照常认。起因同上：
  一份 skill 里放一个指向 `~/.ssh` 的链接，原来会被复制进项目。
- 插件类的网上新版只核本机那份：当前 CLI 没有只读地查插件新版的子命令（`claude plugin --help` 核过），照设计的退路告诉用户可以 `claude plugin update`。
- `/agent-team:at-skills` 开头做门禁自检（它会写 `.agent-team`）；README 两半「安装」一节与 `at-pm` 的「门禁自检」一节点名它。
- `argument-hint` 不以「[」开头：受限写法不许值以 YAML 指示符开头。
- `~/.claude/skills/synced/`（从 claude.ai 同步下来的 skill，多套一层目录）与 skills-dir 形式的插件（`~/.claude/skills/<名>/.claude-plugin`）不认：
  两者在平台上叫什么名字本机核不了，登进 §5。
- **skill 管怎么做、管不了做什么**（实测之后补的，§8）：设计只列了盖不过的四样，没说契约与产品定义定下的东西。探针里登记的 skill 要按钮文字带前缀，
  契约原话与产品定义写的是「订阅」，`at-ui` 照 skill 加了、又只能冒泡问验收按哪个算。各角色那一节补一句「契约与产品定义定下的东西（例如原话里的文案、
  完成定义）照它们」——需求不跑偏是这个插件的头一条好处，一份第三方的做法不该改掉它。

**终审之后的修补**（合并之前请了一个新的审阅者看整条分支，提的应当修的六条与升了一级的一条）：

- **角色正文里不写占位符的字面**：平台把角色正文里的 `${CLAUDE_PLUGIN_ROOT}` 换成本插件的目录（探针里子代理收到的系统提示核到的），原来那句
  「`${CLAUDE_PLUGIN_ROOT}` 指原插件目录」在角色眼里成了一句指着本插件的话。改成清单每一条记一份 `placeholders`（JSON 里的不换）：
  `${CLAUDE_SKILL_DIR}` 与 `${CLAUDE_PLUGIN_ROOT}/skills/<自己>` 指项目里的副本，`${CLAUDE_PLUGIN_ROOT}` 指原插件目录；正文只说「照 `placeholders` 换，长的先换」。
  判据核角色正文里 `${CLAUDE_PLUGIN_ROOT}` 只作为本插件文件的路径前缀出现、不出现 `${CLAUDE_SKILL_DIR}`。
- **两个市场里同名的插件分开列**：`ref` 带上市场（`插件@市场:skill`），名字照旧是 `插件:skill`；同名的几份里恰好一份启用着（用户层、项目层的
  `enabledPlugins`）就认它，不然叫用户挑。本机原来列出的是停用的 superpowers 7.0.0、藏掉了启用着的 7.0.2。
- **插件清单认不出时说出来**：顶层不是对象、版本不是 2（照旧试着读）、某一项不是数组、某一条没有 `installPath`，都进 `errors`。文件不在不算错（没装插件很正常）。
- **`check` 也看副本**：副本的指纹和登记时对不上的报 `copy_changed`（被改过、删了里面的文件）；`sync` 记的指纹改按复制下来的副本算。
- **改分给谁不再顺手换版本**：`assign` 能 `--add`、`--remove`（减到不剩一个拒绝）；已登记、本机那份又变了（或来源换了）的，`sync` 不带 `--update` 拒绝、副本不动。
  命令正文：已登记的只改角色用 `assign`，同步新版用 `sync --update`，且先照第 7 节问过用户。
- **复制时跳过会被自动加载的位置**：`CLAUDE.md`、`CLAUDE.local.md`、`.claude`、`.git`（目录或文件）、`.agent-team`，哪一层都认、不分大小写，不复制也不进指纹，
  `list` 报出跳过了哪几处。名单从 `writepath.mjs` 导出（`AUTOLOADED_NAMES`），与写路径隔离认的是同一份。
- **`/agent-team:at-skills` 里的几问另算**（审阅者标的小问题，按影响升了一级）：照「红线」那一节问用户要不要更新本机，原来会顺着敏感操作的流程往进行中那一趟
  记 escalation、加修订块；命令正文写明不记、不动契约。

## 4. 门禁不核（三样）

角色读没读登记的 skill、照没照做、有没有拿 skill 去盖「改不了的四样」，门禁都看不见。

- **拒绝的判据长什么样**：H5b 在角色停下时读它产物里的「用过的 skill」，契约点名的没出现就拦。
- **它打不红的那一刀**：角色照抄一行「用过的 skill」却没照做；或者照 skill 做了、却顺手少交了一项下游要读的内容。前者门禁分不出，后者要读懂产物。
- **什么会让答案改变**：一趟真实 run 的转录里出现角色点名的 skill 没用、却写了「用过」，或者拿 skill 当理由少交了东西。

## 5. 仍然开着的边界

- 角色照不照登记的 skill 做、盖不盖得过插件自带的做法、四样有没有守住，只靠正文（付了三样，§4）。
- skill 是第三方写的指令，里面可能有叫角色越界的话：写路径隔离照旧挡写入，`Bash` 不挡（不是沙箱，既有边界）。
- 持 `Bash` 的角色能改 `.agent-team/skills.json` 与副本（`Bash` 不受门禁管）；副本目录由名字推出，改清单删不到 skills 目录之外。
- 插件带的 skill 引用插件里别的文件时回原插件目录去读：在项目之外、可能弹读文件确认、不受同步与指纹管；原插件卸了就读不到（`check` 报不出这一种）。
- skill 目录里的软链接一律不复制：靠软链接组织文件的 skill 复制进来会缺东西。
- 插件类的网上新版只核本机那份。
- `~/.claude/skills/synced/` 与 skills-dir 形式的插件不认。
- `installed_plugins.json` 里不是 user 作用域的条目按 `projectPath` 比（终审时在本机一份旧的清单备份里核到 local 条目带的就是它）；不带的照算、标 `scope_unverified`。
- 终审列的小问题没修（见实现记录之外的交付说明）：副本目录名撞车（`ui:p` 与 `ui__p`、只差大小写）、撞名之后按名字同步失败、复制半途出错只做了一半、
  插件升级而 skill 目录没变时来源信息不更新、多行 `description` 只取第一行、`docs/…` 被当成引用、没认 `CLAUDE_CONFIG_DIR`、只写后半截的插件 skill 名认不出。
- 点名的 skill 没用上，推进之前靠项目经理读「用过的 skill」核，门禁不核。

## 6. 没量到的

- 文件软链接那条判据在本机 Windows 上跳过（没开开发者模式，建软链接报 EPERM），红绿只在 CI 的 Linux、macOS 上跑。
- 交互会话里起新一趟之前「同步这几份」那一问、选了同步之后；原话点名一份没登记的 skill 时 S1 那一问；补了「管不了做什么」之后再跑一场（§8）。
- 几 MB、上千个文件的 skill 复制与算指纹要多久。
- macOS、Linux 上真实安装的路径与 `installed_plugins.json` 的形状。

## 8. 变异与实测

**变异**（备份用 `cp` 放仓库外，改完跑、还原）：

- `skillDirsIn` 不认链进来的目录：「skill 目录本身是链进来的」红。
- `writepath.mjs` 里 `.agent-team` 那一道改成 `if (false)`：新的写路径判据红（同文件别的判据都没红——这一格原来没人钉）。
- 安全审查那两条：「清单里被改过的 `dir`」在修之前红；软链接那条在本机跳过（§6）。
- 正文、命令、命令行入口与库一共十六刀（`at-qa` 与 `at-ui`、`at-pm` 那一节各改一句，`at-skills` 两句，`at` 两句，`at-init` 那一句，命令行的角色校验与退出码，
  库的指纹比对、`.git`、软链接、跳过自己、目录名校验、沿用角色）：十三刀第一轮就红。拿掉「跳过软链接」那一行与「空名字、`.`、`..`」那一行是等价变异
  （目录项的类型对软链接本来就既不是文件也不是目录；后面「恰好在 skills 目录下一层」那一道照样挡住），保留它们写明意图；「不带角色时沿用原有的」那一刀
  第一轮没红——判据只核了清单没被改坏、没核这一次确实同步了，补上断言之后红。

终审修补的十三刀（跳过自动加载位置、ref 带市场、挑启用着的、版本与形状报错各一、副本指纹、`--update` 守卫、`--add`、自己目录的占位符、
命令行的 `--update`、角色正文写回占位符字面、`at-skills` 的「另算」、`at` 的 `copy_changed`）全红。

**实测**（CLI 2.1.310，`claude -p --plugin-dir <本工作树>`；探针项目放在仓库外的临时目录，里面一份项目层的夹具 skill `probe-ui` 与一份最小的 `project.json`）：

- 探针目录先放在本工作树下：后台会话起不来（新目录没被信任，信任设置不替用户改），`-p` 能起，但工作树在 `.claude/worktrees/` 下，路径里带 `.claude`，
  平台把探针里每一次写入都当敏感文件拒掉、放行规则也不管用（项目经理照实停下、没有用 `Bash` 绕）。挪到仓库外的临时目录之后正常。
- `/agent-team:at-skills 给 at-ui 加 probe-ui`（$0.14）：项目经理照命令正文调脚本、事后跑 `list` 核磁盘，清单与副本都对，回复里有「skill 是别人写的指令」那句提醒。
- 改了本机原件（加一条「规格末尾写一行 probe-ui v2」）之后起 `/agent-team:at`：建 run 之前跑了 `check`、认出改了 `SKILL.md`；`-p` 会话问不了人，没同步，
  回复里说了哪一份本机有新版——三场里每一场都一样（其中两场因为上面那条权限问题没建起 run）。
- 走到 S2 的一趟（原话没提 skill）：项目经理嫌页面太简单，自己把 `at-ui` 写进了 `trimmed`，这一格没测到 skill。
- 原话点名「UI 用 probe-ui」的一趟（$0.68）：S1 没问（已登记给 `at-ui`）；`at-ui` 读了副本，只出一个视觉方向、首行照写，规格与线框里的按钮都带「◆ 」，
  在「用过的 skill」里写了 sha 前 8 位（`d72f4024`，副本那一版）、改掉的是 `at-ui-craft` 的「视觉方向走两遍」；「至少截 12 张」与截图上限冲突、没照做并冒泡
  （这一场起本机静态服务被拒，一张也没截）；token、状态矩阵、动效、无障碍、响应式照旧写全；规格末尾没有「probe-ui v2」——没同步就没换版本。
  按钮前缀与原话文案对不上那一格引出了 §2 最后一条。`at-product` 在自己的产物里写了「用过的 skill：没有」（正文说没用上不用写，多写一节无害）。
- 没量：交互会话里「同步这几份」那一问与选了同步之后；原话点名一份没登记的 skill 时 S1 那一问；补了「管不了做什么」之后的同一场。
