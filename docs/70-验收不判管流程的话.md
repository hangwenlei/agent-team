# 验收不判管流程的话

> 2026-10-10，分支 `r28-acceptance-process-words`。第二十八轮（从开放边界索引挑）：`docs/69` §4「验收逐条的『不在范围』」。

## 0. 一句话结论

- `agents/at-acceptance.md`「你判什么」：紧跟在「逐条只有三种、不写『部分过』」后面加一句——契约第 1 节里管流程的话（走到哪一段停、要不要收口、先别派谁）不是做出来的
  东西，归项目经理照着走，不列进逐条。门禁不读内容，判据钉那一句的位置。

## 1. 问题

- 真实会话 M17（`docs/69`）：用户原话结尾是「走到收口」，验收把它列成一条，写「流程项，由 S8 完成，本条不在业务验收范围」——过、没过、判不了之外的第四种；第一行照样
  「结论：通过」。上一版刚写明「没有第四种」，这是它在真实会话里的第一个反例：照正文严格判，这一条只能判不了，整份就是「结论：判不了」，门禁会拒推进出 S7——为一句本来
  就不归验收的话回退。
- 原因在正文：「判据逐条来自契约与产品定义里的完成定义」，第 1 节里的每一句都像一条判据，正文没说管流程的话怎么办。

## 2. 修法

- 正文那一句：管流程的话不列进逐条，归项目经理照着走。它们照样留在契约第 1 节里（原话不改），项目经理照着推进与收口。

## 3. 判据与变异

- `tests/acceptance-verdict-prose.test.mjs` 加一条：「你判什么」那一节里那一句紧跟在「逐条只有三种」后面；「管流程的话」在整份里只出现一次。
- 变异（备份在仓库外，每一刀改完逐字节还原）：去掉那一句、改成「列进逐条，写『不在业务验收范围』」、挪到红线那一节、在「哪些算数」里补「管流程的话也可以列进逐条」
  ——每一刀都有判据红。

## 4. 仍然开着的边界

- **哪些算管流程的话，验收自己认**：正文举了三种（走到哪一段停、要不要收口、先别派谁），别的（「先给我看方案」「做完发我」）照它自己的理解；认错了的，要么漏验一条
  要求，要么为一句流程话判不了。门禁不读内容。

## 5. 没量到的

- 真实会话里验收碰上「走到收口」这类话时照新的一句不列进逐条。

## 6. 归属
