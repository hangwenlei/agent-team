- **设置**：CLI 2.1.286，SDK 宿主（`-p` 加 stream-json），`sonnet`，门禁留痕开着；插件是 `main`（v4.4.0）用 `git archive` 导出的副本，经 `--plugin-dir` 加载。项目是
  只有一份 `README.md`、一次初始提交的空 git 仓库。驱动对 `AskUserQuestion` 选第一项。
- **三条消息**：`/agent-team:at-init`；`/agent-team:at 做一个命令行小工具 wordfreq：……要有自动化测试，npm test 能跑。走到 S6、测试报告交了就停下，先别派验收。`；
  `需求加一条：支持 --top N 参数指定输出前几个（不给就是 10）。照流程处理这次改动，一路走到收口，中间要我定的事照常问我。`
- **走法**：
  - 第一趟 S1 到 S6：S2 只派 `at-product`（`at-ui` 照命令行工具裁掉）；S5 架构师前台派 `at-backend`；S6 派 `at-qa`、交了测试报告，项目经理停下。推进出 S1
    时 `contract_sha` 已经记上（推进出第一段那一条没拦）。
  - 改需求：项目经理给契约追加「用户主动提出」的修订块、记上回传给的新 `contract_sha`，门禁的契约基线在那一刻（`revised_at`）记下修订与当时的 `06-test.md`。
    项目经理照回退记回到 S2（`rework_base` 记了 S2 到 S6 的产物），重派 `at-product` 改 PRD；PRD 里有一处取舍（`--top 0` 怎么办、要不要支持 `--top=N`），
    问了用户、记了 `tradeoff` 的 escalation、答复写成第二块修订。
  - 第二趟 S2 到 S6 重走，`at-qa` 重测；S7 派 `at-acceptance`（派之前契约的账对得上，那一条没拦），验收结论第一行「结论：通过」（停下时首行那一条没拦）；
    S8 写交付文档、收口。整趟十四分钟左右。
- **结果**：`state.json` 的 `contract_sha` 与磁盘上的契约相同；`history` 是 S1 到 S6、S2 到 S8，`rework` 里 S2 到 S6 各一轮；派发记录里每一次派发都有放行的停下行；

## 2. 观察

- **没走到的拒绝路**：推进出 S1 时没记账（`docs/63`）、派验证段时账对不上（`docs/60`）、改需求之后不回退就派验收（`docs/61`）、验收结论首行写坏（`docs/62`）——项目经理
  与验收角色都照着做了，这几条一条都没触发。正路上它们都没有误拦。
- **时间又是编的**：`closed_at` 写的是 `02:50Z`，会话实际在 `01:21Z` 前后结束（`docs/58` §4 登着那一条）。

  （`finishedAgents`），不看先后——收口时的【派发】、完成核验都不受影响。
- 回传（additionalContext）不进 stream-json 的转录，这一趟能核的只有落盘的记录（与 `docs/58` 同一个情形）。
- 会话结束之后按命令行里的探针目录名查过进程，没有残留；SDK 宿主的会话自己退出了。
