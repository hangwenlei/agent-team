# 按 agent_id 认 run 与代码基线

> 2026-10-06，M4n，分支 `m4n-agent-run-and-baseline`。第七轮，从 `docs/00-开放边界.md` 挑的两条：全量审查第 24 条剩下的「按 `agent_id` 认 run」
> （`docs/43` §4 第一条，`docs/39` §2.3 判 M、往后放），与第 39 条一直悬着的「S4 记代码基线」（`docs/40` §1.3 说挪到第三轮，之后没人提），连同
> 第 39 条另一半「自检分不出从来没有 run 与 run 被抹掉」的裁定。正文是复核修订之后的样子，两路对抗复核与改了什么在 §8。

## 0. 一句话结论

- **第 24 条**：切走 `current-run` 之后，旧 run 上还在跑的人停下、完成、再往下派人，门禁原来一律按新的这一趟判——停下行记进新 run 的派发记录、
  交付物按新 run 的段核。旧 run 的执行角色恰好也是新 run 当前段的产者时，H5b 会拦下它、叫它交这一趟的产物，它就把那一趟的活写进这一趟的 run 目录
  （写路径隔离放行）。现在按 `agent_id` 认派它的那一趟：当前这一趟的派发记录里没有它、别的一趟里恰好一趟有，就是那一趟的人——H5b 不按这一趟核、
  放它停下、停下行记回那一趟；完成核验告诉项目经理它属于哪一趟；那一趟的协调者再往下派人，H2 在派发那一帧就拒、说清那一趟不是当前 run（H2 读不出
  运行上下文而放行时，H5a 把派发行记回那一趟、回传叫它停下）。
- **第 39 条**：S4 写派发裁决时，在项目根用不改工作树、暂存内容与历史的 git 命令记下代码基线（`04-dispatch.md` 第 6 节）；走过 S5 之后回到 S5 之前，
  照基线列出这一趟（自基线以来）改过、新加、删掉了哪些文件，要不要退回基线照 `sensitive` 问用户——退回会改项目代码，不经用户批准不跑，批准了也只按
  文件退。
- **裁定**：「自检分不出从来没有 run 与 run 被抹掉」不做（§1.3）。

## 1. 修法

### 1.1 第 24 条：按 agent_id 认派它的那一趟

- **认法**：先看当前这一趟的派发记录（`gate.mjs` 的 `elsewhereOf`）——有这个 `agent_id`，照当前这一趟判（与原来一样），不扫别的。没有，再拿
  `runs/` 下每一趟的派发记录（`runLogs`：链接与别名的口径同 runctx；目录名不是合法 run id 的不列——资源管理器复制出来的「r1 - Copy」这类当不了
  `current-run`，里面的派发记录只可能是拷来的；判 run id 与 runctx 认 `current-run` 用同一个 `RUN_ID`）交给 `hooks/lib/completion.mjs` 的
  `elsewhereRunOf`（纯函数）：别的几趟里恰好一趟有，它是那一趟派出去的，取那一趟里对应它的那一行（同一个人记过几行时挑 `tool_use_id` 相同的，
  没给取最后一行）；哪一趟都没有（CLI 的内部分叉、门禁没记下的派发），或者几趟都有（拷来的、伪造的，认不准），照当前这一趟判。
- **H2**（`input.agent_id` 是发起这次派发的人）：发起者是别的一趟的人（那一趟的协调者在切走之后又往下派）——拒，理由说那一趟不是当前 run、
  派出去的人交的东西没人核、改的项目文件还会跟当前这一趟撞在一起，叫它停下来回报。排在这一趟的收口、前置之前：那些说的是这一趟，不是它的。
- **H3**：那一趟的人往那一趟自己的 run 目录写（不是当前 run 的目录，本来就拒）——拒绝理由换成说清那一趟不是当前 run、停下来回报。原来说「没有被
  任何角色认领，由 PM 决定要不要在 paths 里划给谁」，出路是错的（`.agent-team/` 下的一律不补）。拒不拒不变。
- **H5b**（`input.agent_id` 是停下的这个子代理）：认出是别的一趟的，放它停下、不按这一趟核；停下行（`pass`，角色与段原样取那一趟记的那一行）记回
  那一趟；往 stderr 留一行痕，点名它属于哪一趟、记没记下（SubagentStop 上没有到父级的通道）。
- **完成核验**（`input.agent_id` 不在；收件人是项目经理时）：当前这一趟没记它、别的一趟记着——说它是哪一趟派出去的、这一趟不核它、那一趟的产物这一次
  也没人核，出路是把 `current-run` 改回那一趟再跑 `/agent-team:at-resume`；那一趟已经收口的，说它写的东西不计入任何一趟。角色或段认不出的（只伪造
  一边也算），照【派发】的说法（「一条认不出角色或段的派发」）。原来这一格不出声。
- **H5a**（H2 没拦住时的退路：H2 读不出运行上下文就放行）：发起者是别的一趟的人——派的是团队角色、认得出是派发的哪一刻的，派发行记回那一趟（段取
  发起者自己在那一趟的那一段，`caller` 是发起者）；回传【派发】告诉它那一趟已经不是当前 run、叫它不要再往下派、停下来回报，「门禁记回那一趟」只在
  真记下了时说。这一趟的交付物校验、账本比对、契约核对都不发——那些说的是当前这一趟。
- **记回那一趟的口径**（`recordElsewhere`）：只在那一趟明确收了口（`state.json` 读得出、`closed_at` 有值）时不记；`state.json` 读不出、角色或段认不出
  的照样记（角色与段原样抄那一趟自己那一行，不添新值）。与记进当前这一趟的口径不同：当前这一趟收了口不记是安全的，因为 H2 对收了口的 run 拒派一切
  团队角色；别的一趟没有这一层，不记的那几格之后每次写指针都被报成没停。
- 写 `current-run` 时的【派发】与 `/agent-team:at` 第 1 节「放弃」那一支的说法跟着改：门禁认得出它们是那一趟派的、不按新的这一趟核，但那一趟交的东西
  没人核，它们改的项目文件还会跟新的这一趟撞在一起——还在跑的照旧先等它们停下。完成通知到了项目经理这里时回传说它属于哪一趟（交互模式下孙代理的
  通知回到停车的协调者，不一定到项目经理）。
- 【派发】的扫描（`inflightElsewhere`）改用同一个 `runLogs`：名字不是合法 run id 的目录从此也不列。

### 1.2 第 39 条：S4 记代码基线

- `templates/04-dispatch.md` 加第 6 节「代码基线」：在项目根跑，只用不改工作树、暂存内容与历史的 git 命令——`git rev-parse --show-toplevel` 报错的
  写「不是 git 仓库」；`git rev-parse --verify -q HEAD` 的输出（没有输出的写「还没有提交」）；`git --no-optional-locks -c core.quotepath=off status
  --porcelain -uall -- .` 里 `.agent-team/` 之外的条目（没有就写「干净」）。`-- .` 管 monorepo 的子目录（不列项目之外的改动），`-uall` 让未跟踪的
  目录逐个列文件，`core.quotepath=off` 让中文文件名照原样。不 add、不 commit、不打 tag、不 stash：这些会改仓库，要跑先照 `sensitive` 问用户。
  返工轮回到 S4 重写这份文件时照抄上一次记的、不重记；上一次没有这一节的（更早建的 run、漏记了）写「没记」、不补记——走过 S5 之后补记的，会把这一趟的
  改动当成基线。
- `/agent-team:at` 的 S4 那一条把它列进 `04-dispatch.md` 要写的东西。「回退」一节加一段：走过 S5 之后回到 S5 之前的段，代码不跟着回退——在项目根用
  `git -c core.quotepath=off diff --name-status <基线> -- .` 与那一节的 `status` 命令列出这一趟改过、新加、删掉了哪些文件（`diff --stat` 在非终端下按
  80 列截断长路径，不用它），告诉用户，照 `sensitive` 问要不要退回基线（留着让 S5 照新方案改、用户自己退回、批准项目经理退回）。问的时候点明会丢
  什么：基线里已经有改动的路径退回会一起冲掉，基线之后 HEAD 动过的也在列表里。批准退回的只按文件退列出来的那几份（新加的删掉，改过、删掉的用
  `git restore --source=<基线> -- <文件>`），不用 `reset`、`clean`、`checkout`、`stash` 这类整棵树的命令（`.agent-team/` 没忽略或入了库时会把 run 一起
  抹掉或倒回），不碰 `.agent-team/`；批准的那几条命令写进契约的修订记录。同一趟里问过、用户说留着的，再回到 S5 之前照旧列出来告诉用户、不再问。
  「不是 git 仓库」「没记」的照实说退不回去、列出实现记录里写过的文件；「还没有提交」的拿记下的 `status` 与现在的比；回到 S5 本身不用问。
- 项目经理的红线「run 进行中也不自己写项目代码与配置」补一句：用户批准、写进修订记录的退回代码基线不算，照「回退」只按文件退。
- `/agent-team:at-resume` 停在 S4 的核对加一条：`04-dispatch.md` 要有「代码基线」一节，没有就照模板那一节现在补上（还停在 S4、S5 没走过，现在记的
  就是基线）。
- 审查原文的修法 1（S5 开工前由 PM 提交一次或打标签作为检查点、返工时用 git 恢复）不照做：提交、打标签、恢复都会改仓库，第一轮的红线里项目经理不经
  用户批准不跑（`docs/40` §1.1）。基线给得出「这一趟改了什么」，退不退回留给用户。

### 1.3 裁定：自检分不出「从来没有 run」与「run 被抹掉」——不做

`.agent-team/` 没忽略时 `git clean -fd` 就会把它整个抹掉（忽略了也挡不住 `git clean -fdx`、`git stash -a`）；抹掉之后项目里什么都不剩，与从来没跑过
`/agent-team:at-init` 长得一样。

- **拒绝的做法**：门禁在项目之外留一个「这个项目跑过 run」的记号，自检对着它说「run 被抹掉了」。普通仓库的 `.git/` 里是个现成的位置——那里的文件
  经得住 `git clean -fdx`、`git reset --hard`、`git stash -a`、`git gc`，克隆与推送也不带它。不选，因为它只在普通仓库里成立：linked worktree 里 `.git`
  是个文件（门禁得自己解析 gitdir）；monorepo 的几个子项目共用一个 `.git`（记号得按子项目的路径分）；不是 git 仓库的项目没有这个位置，退到用户目录下
  又分不清项目被挪了位置、被重新克隆。为一格三样已有的做法管着的情形（at-init 建议把 `.agent-team/` 加进 `.gitignore`、红线里这些命令要问用户、没有
  run 时派发返回的那一句点出「被 git 清掉或藏起」这个成因，`docs/40` §1.3），多维护一份项目之外、说「有没有 run」的第二个真源。
- **它打不红的那一刀**：用户有意删掉 `.agent-team/` 重新开始——记号照样说「跑过」，自检报「run 被抹掉了」是误报；项目被挪了位置、重新克隆、
  在另一个 worktree 里打开——记号不在，抹掉了照样报不出来。
- **什么会让答案改变**：真实会话里观测到 run 被抹掉之后项目经理把它当成新项目接着跑、没有告诉用户；或者平台给插件一个随项目走、不进版本库、
  worktree 与 monorepo 的子项目各有一份的存储位置。

## 4. 仍然开着的边界

- **切换本身不拦**：`current-run` 的切换门禁不拦（`docs/26` §4 起开着）；切走之后旧 run 的人认回那一趟，但那一趟交的东西没人核。
- **写路径隔离照旧按当前这一趟判**：旧 run 的执行角色往当前这一趟的 run 目录里写它的产物，它也是当前这一趟当前段的产者时，H3 照样放行（往旧 run
  自己的目录写被拒）。H5b 不再叫它去写，但拦不住它自己写。
- **H2 读不出运行上下文时放行**（流程辅助）：那一刻旧 run 的协调者派得出去，靠 H5a 记回那一趟、叫它停下；那一趟已经收口的不记，派出去的人停下时
  按当前这一趟判。前台派发（`-p`、SDK 宿主）下派出去的人的 H5b 早于发起者的 H5a，那一刻哪一趟都没记它，也按当前这一趟判。
- **记回那一趟的停下行一律是 `pass`**：冒泡也记成 `pass`。之后切回那一趟，协调者进度与完成核验按「最后一回停下门禁放行了」说成因（那一刻它不在
  这一段的名单上，或者那时交了、之后又没了），两种都不对。
- **完成那一刻，那一趟的产物照旧没人核**：只告诉项目经理它属于哪一趟，出路是切回那一趟跑 `/agent-team:at-resume`。
- **认法靠派发记录**：门禁不在时派出去的认不回去；几趟都记着同一个人时认不准，照当前这一趟判。派发记录 `Bash` 写得进：删掉自己在当前这一趟的那一行、
  往别的一趟里伪造一行，就能让自己不被当前这一趟核；前台派发下连删那一行都不用（它停下时派发行还没记），只要知道自己的 `agent_id`——与「`Bash` 不经
  门禁」同一族。
- **被放弃的那一趟里门禁始终没见它停下的派发**：之后每一次写指针照旧再报一遍。停下了的不报（M4h 起停下行在所有 run 里认；这一轮起旧 run 的人停下时
  不再被当前这一趟拦下、记成 `block`）。
- **代码基线只在正文里**：门禁不核记没记、不跑 git。基线只记 HEAD 与有改动的路径：S4 之前就有的未提交改动（用户自己的、S2 里 `at-ui` 写进项目的）
  只有路径、没有内容，退回会一起冲掉（正文叫项目经理问的时候点明）；基线之后 HEAD 动过的，列表里混着这一趟以外的改动。`status` 与 `diff` 会刷新
  `.git/index` 的 stat 缓存、短暂占用 `index.lock`（不改工作树、暂存内容与历史；`status` 带了 `--no-optional-locks`，`diff` 没有这个开关）。
- **退回基线靠 `sensitive` 与红线**：项目经理在用户批准之前不跑改项目代码的 git 命令，批准了只按文件退——门禁不看 `Bash`。

## 8. 复核与修订

### 8.1 门禁（两条中、四条低）

- **中-1　旧 run 的协调者派出去的人，有三种情形仍按当前这一趟拦**：那一趟已经收口、`state.json` 读不出（`recordElsewhere` 不记），或者前台派发
  （派出去的人停下早于 H5a 记派发）；这三种情形下 H5a 的回传说「门禁记回那一趟」是假话。H2 也按当前这一趟判：新的这一趟前置齐了就放行，不齐就拿
  这一趟缺的前置说那一趟的协调者，还可能把它引去写新 run 的产物（正文复核中-5 同一件事）。**改**：H2 认出发起者是别的一趟的人就拒（§1.1），三种情形
  在派发那一帧一起关上；H5a 留作 H2 放行时的退路，记回去的口径放宽到只在那一趟明确收了口时不记，回传按记没记下分开说。
- **中-2　回显判据打不到两处**：run 目录名（场景里写死成 `r0`，注释说 Windows 的目录名装不下载荷——不对，行分隔符那几种都是合法目录名），与只伪造
  角色或只伪造段的派发行（把完成核验的「认得出」改成只核一边，判据照绿，那个变异下实测伪造得出受信行）。**改**：`runLogs` 只列名字是合法 run id 的目录，载荷进不了
  run 目录名这一格（过滤由判据钉着）；回显场景补上只伪造一边的两行、各配一条通知。
- **低-3　每次停下都整读所有 run 的派发记录**（200 个 run、34MB 时一次多 280ms）。**改**：先查当前这一趟（`elsewhereOf`）。
