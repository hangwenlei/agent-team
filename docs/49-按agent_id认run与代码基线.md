# 按 agent_id 认 run 与代码基线

> 2026-10-06，M4n，分支 `m4n-agent-run-and-baseline`。第七轮，从 `docs/00-开放边界.md` 挑的两条：全量审查第 24 条剩下的「按 `agent_id` 认 run」
> （`docs/43` §4 第一条，`docs/39` §2.3 判 M、往后放），与第 39 条一直悬着的「S4 记代码基线」（`docs/40` §1.3 说挪到第三轮，之后没人提），连同
> 第 39 条另一半「自检分不出从来没有 run 与 run 被抹掉」的裁定。

## 0. 一句话结论

- **第 24 条**：切走 `current-run` 之后，旧 run 上还在跑的人停下、完成、再往下派人，门禁原来一律按新的这一趟判——停下行记进新 run 的派发记录、
  交付物按新 run 的段核。旧 run 的执行角色恰好也是新 run 当前段的产者时，H5b 会拦下它、叫它交这一趟的产物，它就把那一趟的活写进这一趟的 run 目录
  （写路径隔离放行）。现在按 `agent_id` 认派它的那一趟：当前这一趟的派发记录里没有它、别的一趟有，就是那一趟的人——H5b 不按这一趟核、放它停下、
  停下行记回那一趟；完成核验告诉项目经理它属于哪一趟；那一趟的协调者再往下派人，派发行记回那一趟、回传叫它停下。
- **第 39 条**：S4 写派发裁决时，用只读的 git 命令记下代码基线（`04-dispatch.md` 第 6 节）；回退到 S5 之前，照基线列出这一轮改过、新加了哪些文件，
  要不要退回基线照 `sensitive` 问用户（退回是动工作树的 git 操作，项目经理不自己跑）。
- **裁定**：「自检分不出从来没有 run 与 run 被抹掉」不做（§1.3）。

## 1. 修法

### 1.1 第 24 条：按 agent_id 认派它的那一趟

- **认法**（`hooks/lib/completion.mjs` 的 `elsewhereRunOf`，纯函数）：拿每一趟 run 的派发记录（`gate.mjs` 的 `runLogs`，读 `runs/` 下每个目录的
  `dispatches.jsonl`，链接与别名的口径同 runctx）。当前这一趟的派发记录里有这个 `agent_id`：照当前这一趟判（与原来一样）。没有、别的一趟有：它是那一趟
  派出去的，取那一趟里对应它的那一行。哪一趟都没有（CLI 的内部分叉、门禁没记下的派发）：照当前这一趟判。
- **H5b**（`input.agent_id` 是停下的这个子代理）：认出是别的一趟的，放它停下、不按这一趟核；停下行（`pass`，角色与段取那一趟记的）记回那一趟——那一趟
  没收口、`state.json` 读得出、角色在花名册里、段在阶段链上时，与记进当前这一趟同一个口径；往 stderr 留一行痕，点名它属于哪一趟（SubagentStop 上
  没有到父级的通道）。
- **完成核验**（`input.agent_id` 不在；收件人是项目经理时）：当前这一趟没记它、别的一趟记着——说它是哪一趟派出去的、这一趟不核它、那一趟的产物这一次
  也没人核，出路是把 `current-run` 改回那一趟再跑 `/agent-team:at-resume`；那一趟已经收口的，说它写的东西不计入任何一趟。角色或段认不出的，照【派发】
  的说法（「一条认不出角色或段的派发」）。原来这一格不出声。
- **H5a**（`input.agent_id` 是发起这次派发的人）：发起者是别的一趟的人（那一趟的协调者在切走之后又往下派）——派发行记回那一趟，段取发起者自己在
  那一趟的那一段；回传【派发】告诉它那一趟已经不是当前 run、它派出去的人交的东西没人核、会和当前这一趟撞在一起，叫它不要再往下派、停下来回报。
  这一趟的交付物校验、账本比对、契约核对都不发——那些说的是当前这一趟。
- 写 `current-run` 时的【派发】与 `/agent-team:at` 第 1 节「放弃」那一支的说法跟着改：门禁认得出它们是那一趟派的、不按新的这一趟核，但那一趟交的东西
  没人核，它们改的项目文件还会跟新的这一趟撞在一起——还在跑的照旧先等它们停下。旧 run 的人停下之后停下行记回那一趟，之后写指针时不再把它报成没停。
- 【派发】的扫描（`inflightElsewhere`）改用同一个 `runLogs`，行为不变。

### 1.2 第 39 条：S4 记代码基线

- `templates/04-dispatch.md` 加第 6 节「代码基线」：只读的 git 命令记 `git rev-parse HEAD` 的输出与 `git status --porcelain` 里 `.agent-team/` 之外的
  条目（没有就写「干净」）；不是 git 仓库的写「不是 git 仓库」；不提交、不打标签、不暂存（动工作树或历史的 git 命令）；返工轮回到 S4 重写这份文件时照抄
  上一次记的、不重记。
- `/agent-team:at` 的 S4 那一条把它列进 `04-dispatch.md` 要写的东西；「回退」一节加一段：回到 S5 之前的段，代码不跟着回退——照基线用只读命令
  （`git diff --stat <基线>`、`git status --porcelain`）列出这一轮改过、新加了哪些文件，告诉用户，照 `sensitive` 问要不要退回基线（留着让 S5 照新方案改、
  用户自己退回、批准项目经理退回——批准的那一步写进契约的修订记录）；不是 git 仓库的照实说退不回去、列出实现记录里写过的文件；回到 S5 本身不用问。
- 审查原文的修法 1（S5 开工前由 PM 提交一次或打标签作为检查点、返工时用 git 恢复）不照做：提交、打标签、恢复都是动工作树或历史的 git 命令，第一轮的
  红线里项目经理不自己跑（`docs/40` §1.1）。只读的基线给得出「这一轮改了什么」，退不退回留给用户。

### 1.3 裁定：自检分不出「从来没有 run」与「run 被抹掉」——不做

`git clean -fdx` 之类把整个 `.agent-team/` 抹掉之后，项目里什么都不剩，与从来没跑过 `/agent-team:at-init` 长得一样。

- **拒绝的做法**：门禁在项目之外（`.git/` 里、用户目录下）留一个「这个项目跑过 run」的记号，自检对着它说「run 被抹掉了」。插件不往项目之外写东西；
  `.git/` 里写的东西会被 git 自己的操作清掉或跟着仓库走，用户目录下的记号又分不清同一个项目被挪了位置、被重新克隆。
- **打不红的那一刀**：用户在 `.agent-team/` 没进 `.gitignore` 的仓库里跑 `git clean -fdx`，再起一个会话——自检照样「在线」、派发返回说没有 run。
  第一轮已经做的三样接着管它：at-init 建议把 `.agent-team/` 加进 `.gitignore`、红线里这些命令要问用户、没有 run 时派发返回的那一句点出「被 git 清掉或藏起」
  这个成因（`docs/40` §1.3）。
- **什么会让答案改变**：真实会话里观测到 run 被抹掉之后项目经理把它当成新项目接着跑、没有告诉用户；或者平台给插件一个项目级、随项目走而不进版本库的
  存储位置。

- 没起真实会话：切指针时旧 run 还有派发在跑这一格要两个会话或后台派发配合，判据的输入形状照 CLI 2.1.286 实测（`docs/37` §1.2、`docs/38` §1.3）。

## 4. 仍然开着的边界

- **写路径隔离与就绪门禁照旧按当前这一趟判**：旧 run 的执行角色自己往当前这一趟的 run 目录里写它的产物，当前这一趟也在那一段、它也是这一段的产者时，
  H3 照样放行（核过：往旧 run 的目录写被拒，往当前这一趟的写放行）；旧 run 的协调者再往下派人，H2 按当前这一趟的前置判。H5b 不再叫它去写，但拦不住
  它自己写。
- **认法靠派发记录**：门禁不在时派出去的（读不出派发记录的 run、门禁没装好时的派发）认不回去，照当前这一趟判。派发记录 `Bash` 写得进：删掉自己在
  当前这一趟的那一行、往别的一趟里伪造一行，就能让自己不被当前这一趟核（与「`Bash` 不经门禁」同一族）。
- **被放弃的那一趟里门禁始终没见它停下的派发**：之后每一次写指针照旧再报一遍——停下了的才记回那一趟、不再报。
- **代码基线只在正文里**：门禁不核记没记、不跑 git；基线只记 HEAD 与工作树里有改动的路径，S4 之前就有的未提交改动在基线里只有路径、没有内容。
- **退回基线靠 `sensitive` 与红线**：项目经理在用户批准之前不跑动工作树的 git 命令，门禁不看 `Bash`。

## 5. 没量到的

- 真实会话里切走指针时旧 run 还有派发在跑：停下、完成通知、旧 run 的协调者再派人，只有子进程判据。
- 代码基线那几句，真实会话里项目经理照不照做（S4 记没记、回到 S5 之前列没列、问没问）。
