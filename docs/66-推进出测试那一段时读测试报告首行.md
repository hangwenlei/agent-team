# 推进出测试那一段时读测试报告首行

> 2026-10-10，分支 `r24-test-verdict-line`。第二十四轮（从开放边界索引挑）：`docs/46` §4「测试报告的结论不读」。`/agent-team:at` 第 3 节一直写着「推进之前读结论：
> `06-test.md` 判不通过的照回退处理，不要推进」，门禁只核测试报告在不在、空不空、是不是这一轮的。

## 0. 一句话结论

- 测试报告（插件自带的链上是 `06-test.md`）的第一个非空行固定写「结论：通过」「结论：不通过」「结论：跑不起来」之一，不通过、跑不起来后面可以接冒号写原因
  （「结论：不通过：缺测试」）。推进出测试那一段的那一次 H6 读它：不通过的拒（回退到实现那一段）、读不出的拒（同段重派 `at-qa` 照格式写）；跑不起来的放行——
  那是正文里 `env-blocked` 那一问，用户定。`at-qa` 在测试那一段停下时首行读不出，H5b 拦它当场改；【阶段】在测试那一段齐了、首行不通过或读不出时补一句。

## 1. 问题

- 测试结论只在正文里：项目经理没照着读、带着一份「不通过」推进出 S6，门禁不拦——之后要等验收角色自己发现，或者整段验收被裁掉时一路收口。
- 验收结论在 `docs/46` 已经有了固定首行与门禁读它的一套；测试报告没有。

## 2. 修法

- 新模块 `hooks/lib/test-verdict.mjs`（单一真源，纯函数）：
  - `testVerdict(bytes)`：第一个非空行按 NFKC 之后匹配，「通过」严格（后面只容许强调、空白、句末标点），「不通过」「跑不起来」按前缀认；回 `'pass'` `'fail'` `'env'`，
    读不出回 null。与验收结论的认法（`verdict.mjs` 的 `acceptanceVerdict`）同一路写法。
  - `testStageOf(stages)`：阶段链上第一个产者里有 `at-qa` 的验证段、它的第一份产物、它之前最近的执行段（测试没过回到那里）。从 `stages.json` 派生。
  - `testBlock`：测试那一段整段裁掉、谁都没叫过的不拦；报告不在、空的交给别的判据；首行通过、跑不起来不拦。
  - `decideTestVerdict`：只管推进出测试那一段的那一次（写入前停在测试那一段、写入后到了后面的段）。不在之后的推进与收口读——之后由验收结论管，已经走过测试
    那一段的旧 run 不受牵连。
  - 文案：不通过——「照 /agent-team:at 第 3 节的『回退』记回到 S5（测试没过、缺测试都回那里），修好之后重新走到这里」；读不出——列出三种写法，「在 S6 里同段
    重派 at-qa，让它把第一行照格式写（同一段里重派不计返工）」。
- `hooks/gate.mjs`：
  - H6：排在验收结论判据之前接上 `decideTestVerdict`。
  - 【阶段】：测试那一段齐了、首行不通过或读不出时补一句（与验收那一句同一个位置——两段不会同时是当前段）：写者是 `at-qa`、读不出的叫它把第一行改好再停；写者是
    `at-qa`、不通过的说推进会被拒、回报时照实说；别的写者照 H6 的拒绝理由给出路。
  - H5b：`at-qa` 在测试那一段停下、报告首行读不出——拦，理由是【阶段】给写者的那一句加冒泡的尾巴（S5 没交齐、红线里的敏感操作才冒泡）。与验收角色那一支
    （`docs/62`）同一个写法、同一个 `isBubbleStop`。
- 正文：`agents/at-qa.md` 写明第一行的三种写法与判法；`/agent-team:at` 第 3 节加「S6 测试报告的第一行」一条。
- 牵连的旧判据：`tests/gate-contract-base.test.mjs` 的测试报告夹具推进出 S6 时首行不是三种之一，改成「结论：通过」打头；`tests/gate-stop-verdict.test.mjs` 里「at-qa 的
  测试报告不核首行」那一格改成只断言不说验收结论那一句（它自己的测试报告现在另有一条）。

## 3. 判据与变异

- `tests/gate-test-verdict.test.mjs`：
  - `testVerdict` 的认法（通过严格、不通过与跑不起来按前缀、全角冒号与强调、标题打头读不出）。
  - 推进出 S6：通过、跑不起来放行；不通过拒（回退到 S5）；读不出拒（列出三种写法、同段重派 `at-qa`）。
  - 只在推进出 S6 的那一次读：S6 里原地重写不读，已经走过 S6、停在 S7 推进到 S8 的不按测试报告拦；S6 整段裁掉、磁盘上留着一份报告也不读。
  - H5b：`at-qa` 在 S6 停下、首行读不出——拦、带冒泡的出口；三种之一照常放行；不在测试那一段停下的不核。
  - 【阶段】：`at-qa` 写的读不出——叫它改；项目经理在 S6 齐了、不通过时写 `state.json`——说推进会被拒；通过的不说。
  - 正文两句在。
- 变异（备份在仓库外，每一刀改完逐字节还原）：H6 不读测试报告、跑不起来当不通过、跑不起来也拦、通过不严格、之后的推进也读、不通过不说回退、读不出不说同段重派、
  H5b 不核测试报告、H5b 不看是不是测试那一段、【阶段】不补测试那一句、`at-qa` 写的读不出也给项目经理那一句、整段裁掉也读——每一刀都有判据红。「还旧的也按首行拦」
  存活：还旧的报告在 H6 里由排在前面的推进判据先拒，【阶段】那一侧也不判齐——那一行走不到，删掉了。
- 没起真实会话：H6、H5b、【阶段】的判定在子进程里全走到了。

## 4. 仍然开着的边界

- **跑不起来的放行**：环境阻塞要用户定（`env-blocked`）；问过之后照现状交付的批准仍绑在验收结论上（`docs/46`）。验收那一段整段裁掉、测试又跑不起来时，收口不读任何
  结论（`docs/46` §4 那一条剩下的一半）。
- **只核首行**：首行写「通过」、下面写着有用例挂了，门禁照通过算——与验收结论那一条同一档。
- **已经走过测试那一段的旧 run**：不回头读。
