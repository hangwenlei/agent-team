# 单个微调 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新命令 `/agent-team:at-tweak <要改什么>` 起一趟微调：门禁按一条短链判（S1 记原话 → S4 派发 → S5 来回改 → S6 跑测试 → S8 交付），项目经理直接派负责的开发角色，用户点「可以了，收尾」才出 S5。

**Architecture:** 微调是一趟 `state.json` 里 `kind` 为 `tweak` 的 run，照旧用 `current-run` 指着（按会话认、不写指针是第三步的事）。阶段链与派发白名单按 `kind` 选：短链在插件根的 `stages.tweak.json`，白名单是在花名册上把项目经理两行的可派名单换成短链里实现段的产者（`hooks/lib/tweak.mjs` 现算，不另放一份花名册）。测试段由项目经理产出、靠阶段上的 `"test": true` 认；短链没有验收段，收口照「验收整段裁掉」那一套读测试报告。「可以了，收尾」经两个批准记录器记进 `approvals.jsonl`，绑在那一刻的契约 sha 上，H6 推进出 S5 时核。

**Tech Stack:** Node（`MIN_NODE` 起），零 npm 依赖，`node --test`。

**Spec:** `docs/superpowers/specs/2026-11-05-边看边改微调与会话归属-design.md`（§5.3–§5.5、§5.8、§8 第 2 条；第一步的实现与裁定在 `docs/103`）

## Global Constraints

- 零 npm 依赖；`hooks/` 不用晚于 `MIN_NODE` 的内建；门禁子进程经 `tests/helpers/gate-runner.mjs` 起；裸 `node --test`。
- 运行时正文（命令、角色正文、`stages.produces.md`、门禁回传与拒绝理由）只写现行规则，不写开发史、不指向 `stages.README.md`。
- 正常的一趟一个字不变：没有 `kind` 或 `kind` 为 `full` 的 run，阶段链、花名册、每一道判定与今天相同（配「上一版状态的夹具」判据）。
- 外部值引法照 `trusted.mjs`；特殊字符用 `String.fromCharCode`；锚串替换 `split/join` 并断言命中数；落盘后扫控制字节与行尾。
- 插件会加载的文件加了 `stages.tweak.json`：进 `scripts/lib/version-bump.mjs` 的 `PLUGIN_LOADED`。
- 发版 `7.9.0`，`CHANGELOG.md` 最上面一行；先推功能分支、CI 全绿再合 main。
- 规范标签逐字：`可以了，收尾`（单一真源 `hooks/lib/tweak.mjs` 的 `DONE_LABEL`）；`kind` 的取值 `full`、`tweak`。

## Review Focus

1. 旧 run（没有 `kind`）被升级之后的门禁读：照正常链判，不因 `kind` 缺失走错链。→ Task 1、2 的「上一版状态」判据。
2. `state.json` 写坏了 `kind`（拼错、类型不对）：`validateState` 报；运行上下文按正常链读（不让一个坏值把整趟判坏）；H6 不许建好之后改 `kind`。→ Task 1、2。
3. 微调里用户点了「可以了，收尾」之后又提一轮改动（改了契约）：那条记录作废，再推出 S5 要重新问。→ Task 5。
4. 微调里测试报告「跑不起来」或「不通过」：推出 S6 时不通过拒；收口时跑不起来要用户批准照现状交付（没有验收段）。→ Task 4。
5. 微调里项目经理派产品、架构、测试、验收：H1 拒；正常一趟里项目经理派开发角色：照旧拒。→ Task 3。

## Rulings 预置

- 微调照旧用 `current-run`：第二步只做单个微调，按会话认这一趟、微调不写指针、互斥与认领都在第三步。代价：第二步里微调与完整的一趟互斥靠第 1 节「上一趟没走完」那一问（同今天）。
- 放弃（完整一趟与微调的「放弃」收尾）挪到第三步：照旧用 `current-run` 时，切走指针就等于放弃（与今天相同），显式的放弃收尾要等微调离开指针才有用。
- 短链沿用正常链的段号与产物名（设计 §5.3）；S6 加 `"test": true` 让测试段认得出，正常链的 S6 不加（它靠 `at-qa` 认，行为不变）。
- 白名单不另放文件：`tweakRoster(roster, tweakStages)` 只改项目经理两行（`__main__`、`at-pm`）的 `can_delegate_to`，别的行与别的花名册用处（触达表、覆盖、项目校验）照旧用 `roster.json`。
