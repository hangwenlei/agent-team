# M3a：`roster` 的洞 —— 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 让「一个 `producers` 里的角色从来没被派」这件事不再是静默的，并把 `unrecorded` 还给它自己声明的用途。

**Architecture:** 三条互相独立的改动 —— `state.json` 多一个 `trimmed` 字段（把已有的裁剪决定变成可机器读的）、一条新的纯函数判据在阶段推进后报出没有交代的产者、`compareArtifacts` 的 `unrecorded` 脱离 `roster` 收窄。三条都不拦截，只报。

**Tech Stack:** Node 内置模块，零运行时依赖，`node:test`。

**Spec:** `docs/superpowers/specs/2026-09-20-M3a-roster的洞-design.md`

## Global Constraints

- **零运行时依赖，不得创建 `package.json`**
- **裸 `node --test`**（仓库根，**不带路径参数**）。带路径会报一个假的 `pass 0 / fail 1`。基线 **639 / 0**
- **一条断言一个 `test()`**；**否定式断言必须有正向自检锚**，**锚要钉在判据真正迭代的那一层**；**判据每加一次收窄，锚就跟着往里挪一层**
- **今天执行 0 次断言的判据，锚不能用「派生集合非空」那一款**，要用**已知违规样本**那一款（`docs/16` §3.3）
- 变异一律 `cp` 备份与还原，**不用 `git checkout` / `git restore`**，**按行号定位**
- **临时文件与备份放仓库外的会话 scratchpad**，不要在仓库里建 `scratchpad/`（不在 `.gitignore`，且裸 `node --test` 会从仓库根递归收集 `*.test.mjs`）
- `git commit -F - <<'MSG'`，一条命令里只放一个 heredoc，**正文里不要出现 ASCII 单引号**
- **要写出转义文本本身时一个反斜杠字面量都不要写**，用 `chr(92)` 拼；**落盘后扫一遍控制字节**（`docs/16` §3.8）
- **任何角色的 `tools:` 里都不得出现 `Skill` / `SendMessage` / `ListAgents`**
- **不改 `docs/11` 的 §1–§4**；跨文件引用**引名字不引编号**（`docs/16` Ruling 30）

### Task 2：阶段推进后的产者交代判据

**Files:** Create `hooks/lib/coverage.mjs`；Modify `hooks/gate.mjs`；Test `tests/coverage.test.mjs`、`tests/gate-ledger.test.mjs`

**Interfaces:**
- Consumes：Task 1 的 `state.trimmed`；`hooks/lib/stages.mjs` 的 `stageRoles`
- Consumes（Ruling 2 补）：`project.json` 的 `available_roles`
- Produces：`decideCoverage({ stages, state, availableRoles })` → `{ gaps: [{ stage, role }], narrowed }`，`gaps` 为空表示没有没交代的

- [ ] **Step 1：先写判据的定义，再写代码**

「**已经走过的阶段**」= 出现在 `state.history` 里、**且不等于 `state.stage`** 的阶段。
（返工会让一个阶段重新成为当前阶段，那时它不算走过。）

对每个走过的阶段 `S`，**`stageRoles(S) ∩ available_roles`** 里每个角色必须在
`state.roster` **或** `state.trimmed` 里。两边都不在 → 一条 gap。

> ⚠️ **`∩ available_roles` 是 Ruling 2 在实现期加的收窄，本计划初稿没有它**
> （初稿写的是「`stageRoles(S)` 里每个角色」）。实测信噪比 1:3：不收窄时报出来的
> 多数不是漏派，是**这个项目根本没用过那个角色**——那不是决定，谈不上「把已经存在的
> 决定变成可机器读的」。完整理由与 `at-pm` 那一格为什么承重，见设计 §3.2 的裁定块。
> **复述这条判据时不要略掉这层交集**：略掉之后的字面读法，正好指向把 `at-pm` 写进
> `trimmed` 这个被判过「确确实实错」的修法。
>
> ⚠️ **下面 Step 2 那段示例代码按初稿口径写，它的期望值只在收窄之后才对**——实跑核过：
> 同一份 `state` 不传 `availableRoles` 时，`gaps` 是
> `[{S1, at-pm}, {S2, at-ui}]`，**多出来的那条正是 `at-pm`**；传了模板的
> `available_roles` 才是示例写的 `[{S2, at-ui}]`。
> **那段示例因此正好是这条陷阱的实物**：照它字面走，第一条 gap 就是 `{S1, at-pm}`，
> 而它紧挨着的 Step 7 教你「真要裁剪就写进 `trimmed`」。
> 落地的测试已经把 `availableRoles` 显式传进去了，示例代码这里**保留初稿原样**
> （它是当时下发的那一份），只在这里标明它少了哪个参数、期望值差在哪一条。

- [ ] **Step 2**：先写失败的测试 —— M2b 那一趟的真实形状

```js
// docs/15 §5.1 记的那一趟：S2 走过了，at-ui 既不在 roster 也不在 trimmed
const state = {
  stage: 'S3',
  history: [{ stage: 'S1' }, { stage: 'S2' }, { stage: 'S3' }],
  roster: ['at-product', 'at-architect'],
  trimmed: {},
}
assert.deepEqual(decideCoverage({ stages, state }).gaps, [{ stage: 'S2', role: 'at-ui' }])
```

- [ ] **Step 3**：跑它，确认红（函数还不存在）
- [ ] **Step 4**：写 `decideCoverage`。**纯函数，不碰文件系统**，与 `readiness.mjs` / `deliverable.mjs` 同一层
- [ ] **Step 5**：跑它，确认绿
- [ ] **Step 6**：补这几条，**各一个 `test()`**
  - `at-ui` 写进 `trimmed` → `gaps` 为空
  - `at-ui` 写进 `roster` → `gaps` 为空
  - **当前阶段不算走过**：`stage: 'S2'` 时 S2 不产生 gap
  - **返工**：S5 在 history 里出现两次、且是当前阶段 → 不产生 gap
  - 退化输入：`state` 不是对象 / `history` 不是数组 / `trimmed` 缺失 / `roster` 不是数组 —— **一律不抛**
  - **正向自检锚**：上面那些「gaps 为空」的断言，要有一条证明同一组夹具在**该报的时候真的报**
- [ ] **Step 7**：接线到 `hooks/gate.mjs`。**与 H5a 同一档：`additionalContext` 报，不 deny**。文案要点名**是哪一段的哪个角色**，并写清两条出路（真要裁剪就写进 `trimmed`；不是裁剪就去补派）
- [ ] **Step 8**：子进程级测试 —— 真实 gate 跑一遍，确认那条文案出现在 stdout
- [ ] **Step 9**：变异
