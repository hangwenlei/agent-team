# 角色用上本机 skill —— 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户能用 `/agent-team:at-skills` 把本机装的 skill 登记给角色（整份复制进项目），角色按清单读来用；起新一趟前发现新版就问用户再同步。

**Architecture:** 一个零依赖的 Node 模块（`hooks/lib/skills.mjs`）做找、算指纹、复制、比对，一个薄 CLI（`hooks/skills-cli.mjs`）给项目经理经 `Bash` 调用；角色只多一节正文（读 `.agent-team/skills.json` 与副本），门禁一行不改。

**Tech Stack:** Node（下限 `hooks/boot.mjs` 的 `MIN_NODE` = 16.9.0）、`node --test`、Markdown 正文。

**Spec:** `docs/superpowers/specs/2026-11-05-角色用上本机skill-design.md`（已批准）。执行前两份都读。

## Global Constraints

- 零 npm 依赖，不建 `package.json`。
- `hooks/` 下的代码不用晚于 `MIN_NODE`（16.9.0）的内建（`fs.cpSync` 不用，自己递归复制）。
- 不给任何角色加 `Skill`、`SendMessage`、`ListAgents`；不改任何门禁的判定。
- 运行时正文（角色、命令、模板）只写现行规则：不写 docs 编号、里程碑、「上一版」（`tests/runtime-prose.test.mjs`）。
- 子进程一律经 `tests/helpers/gate-runner.mjs` 起（`tests/gate-runner.test.mjs` 钉着）。
- 锚串替换用 `split(a).join(b)` 并断言命中数；写完扫控制字节与行尾。
- 裸 `node --test`（仓库根，不带路径）。
- 版本 7.6.0 → 7.7.0，`CHANGELOG.md` 最上面加一行；推 main 之前先推功能分支、CI 全绿。
- 在隔离的 worktree 里做（主工作树上有别人没提交的改动，不碰）。

## Review Focus

1. `installed_plugins.json` 缺失、不是 JSON、版本号不认识：`list` 照样列出用户层与项目层的 skill，插件那一块进 `errors`，不崩（Task 1 的 `discover tolerates broken plugin list`）。
2. `SKILL.md` 没有 frontmatter 或没有 `description`：照样列出，`description` 为空串（Task 1 的 `meta without frontmatter`）。
3. 用户手改坏了 `.agent-team/skills.json`：任何子命令都不覆盖它，报错退出码 2（Task 2 的 `cli refuses broken registry`）。
4. 项目里的副本被人删了、清单还在：`check` 报 `copy_missing`，不当成「没变」（Task 1 的 `check reports deleted copy`）。
5. 插件升级换了目录（`installPath` 带版本号）：`check` 按插件名认到新目录，内容变了报 `changed` 并带新旧版本号，不报 `missing`（Task 1 的 `check follows plugin upgrade`）。

  - `discoverSkills({ home: string, projectRoot: string, selfPlugin?: string }): { installed: Installed[], errors: Array<{ source: string, message: string }> }`
    - `Installed = { name, ref, kind: 'user'|'git'|'project'|'plugin', path, plugin?, version?, plugin_root?, ...readSkillMeta }`
    - 用户层：`<home>/.claude/skills/*/SKILL.md`，目录里有 `.git` 的 `kind` 为 `git`；`name` = 目录名，`ref` = `user/<目录名>`
    - 项目层：`<projectRoot>/.claude/skills/*/SKILL.md`，`ref` = `project/<目录名>`
    - 插件：读 `<home>/.claude/plugins/installed_plugins.json`（`version: 2`），每条的 `installPath/skills/*/SKILL.md`；`name` = `ref` = `<插件名>:<skill 目录名>`；`selfPlugin`（默认 `'agent-team'`）跳过；`scope` 为 `user` 的都算，别的作用域只在条目的项目路径字段（实现前先在一份真实的 local 安装上核字段名）等于 `projectRoot` 时算，核不出字段的照算并带 `scope_unverified: true`
  - `readRegistry(agentTeamDir: string): { skills: Record<string, Entry> }`——文件不在返回 `{ skills: {} }`；不是合法 JSON 或形状不对抛 `Error`，消息以 `skills.json 读不出来：` 开头
  - `Entry = { dir, description, roles: string[], source: { kind, path, plugin?, version?, plugin_root? }, sha, synced_at }`
  - `syncSkills({ agentTeamDir, installed, names, roles, now }): { synced: Array<{ name, dir, sha }>, errors: Array<{ name, message }> }`——`names` 里可以写 `name` 或 `ref`；一个 `name` 对上几条 `installed` 的进 `errors`（消息列出各条 `ref`）；`roles` 为 `null` 时沿用清单里原有的；整份复制到 `.agent-team/skills/<skillDirName(name)>/`（先删旧副本，跳过 `.git`），写清单
  - `assignRoles({ agentTeamDir, names, roles }): { assigned: string[], errors }`——只改 `roles`，不复制
  - `checkSkills({ agentTeamDir, installed }): { unchanged: string[], changed: Array<{ name, files, source_path, copy_path, version_from?, version_to? }>, missing: string[], copy_missing: string[] }`——按 `source.kind` 与名字在 `installed` 里重新认原件（插件按插件名加 skill 名，不按路径）；原件指纹 ≠ 清单 `sha` 为 `changed`，`files` 由 `diffSkillDirs(副本, 原件)` 给
