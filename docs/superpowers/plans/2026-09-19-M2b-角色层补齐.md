> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 M2a 建的五个占位 agent 写成真正文，并补上写真正文才发现必须先有的东西——`at-pm` 的派发宇宙、花名册边、以及 S2 的多产者槽位。

**Architecture:** `produces` 增加第二种形式（按角色映射的对象），落点收在 `hooks/lib/stages.mjs` 的 `expandProduces` 一处——它已经是全部消费方共用的单一真源。`at-pm.md` 的 `Agent(...)`（整个会话的 agent 宇宙）先扩到九个角色，再加花名册边，顺序反了必红。加 `at-pm → at-qa` 会逼 H5a 的静默集合第三次重算。

## Global Constraints

- **零运行时依赖**：只用 Node 内置模块，**不得创建 `package.json`**。
- **跑测试一律裸 `node --test`**（仓库根，不带任何路径参数）。本机实测 `node --test tests/` **不会发现**测试文件，只报幻影的 `pass 0 / fail 1`。
- **基线 pass 509 / fail 0**。只许加测试，**不得有任何一条从绿变红**。
- **任何角色的 `tools:` 一律不得含 `Skill` / `SendMessage` / `ListAgents`**（主规格 §6.1）。frontmatter 的 `skills:` 键是允许的，与 `Skill` 工具是两回事。
- **插件自带的 skill 绝不能声明 `context: fork`**。
- **受信前缀 `agent-team 账本回传` 的单一真源是 `hooks/lib/trusted.mjs`**；新增任何 `additionalContext` 回传路径必须走 `trustedBlock(...)`。`templates/` 里不得出现该前缀。
- **`at-outsider` 永远不进 `at-pm` 的 `Agent(...)` 宇宙**，也不进任何角色的 `can_delegate_to`——它是「任何角色都不应能派发它」这条不变量的测试替身。
- **不要动 master**；分支 `m2b-roles`。
- **提交用 `git commit -F - <<'MSG'`**，**一条命令只放一个 heredoc**。不要用 `git commit -m "$(cat <<'EOF' ...)"`——本机 git-bash 实测报 `unexpected EOF`。
- commit trailer 一律 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`。运行时提醒可能说你是别的模型；这个仓库把指挥与裁定的那个会话当作者，历史里这一行 170+ 条、别的 0 条。**不要自己重新判断。**
- **变异验证用 `cp` 备份到临时目录再改回来，不要用 `git checkout` / `git restore`**——本项目被它毁过两次未提交的工作。
- **同构字符串做变异要按行号定位，不要按内容**——M2a 期间用 `rfind` 打中过错误的那一处，零红，差点误判。
- **写含正则的测试代码用 Write 工具，不走 heredoc**（backslash 会被吞掉导致正则失效、测试假绿）。

### 两条测试硬规矩（`docs/11` §3.3，**brief 给的测试代码不豁免**）

1. **一条断言一个 `test()`**——多条**检验不同侧面**的固定断言要拆开。例外：同一断言形状遍历互不耦合的数据点可共块，**但失败消息必须点名具体数据点**。

### 三条 M2a 打出来的教训，直接适用

1. **「补锚时要问这条锚钉的是哪一半」**（Task 5）：那一轮补了三条回归，三条**全部锚在同一个半边**上，新写的另一半裸着、变异后零红。

- [ ] **Step 3: 实现**

把 `expandProduces` 整个替换成：

```js
/** produces 的两种形式（规格 §4 的 M2b 注记）：
 *
 *   数组 `["05-impl/<role>.md"]`  —— 所有产者交同一个模式的东西（S5）。
 *                                    <role> 按 roles 逐个展开；不含占位符的条目
 *                                    原样保留**一次**（否则 S1 的 00-contract.md
 *                                    会随角色数量翻倍）。
 *   对象 `{"at-ui": ["02-ui-spec.md", ...]}` —— 各交各的（S2）。按 roles 取它们
 *                                    各自那几份，不在映射里的角色不产出。
 *
 * ⚠️ 这个函数是全部消费方的单一真源（清单见规格 §4 那张表）。两种形式都要有变异验证
 * 各自钉住——只钉一种的话，另一种可以被改坏而全绿。 */
export function expandProduces(stage, roles) {
  const out = []
  if (!isPlainObject(stage)) return out
  const list = Array.isArray(roles) ? roles.filter((r) => typeof r === 'string') : []

  // 对象形式：按角色取各自的产物。
  if (isPlainObject(stage.produces)) {
    for (const r of list) {
      const own = stage.produces[r]
      if (!Array.isArray(own)) continue
      for (const p of own) if (typeof p === 'string') out.push(p)
    }
    return out
  }

  // 数组形式：<role> 模式展开。
  if (!Array.isArray(stage.produces)) return out
  for (const p of stage.produces) {
    if (typeof p !== 'string') continue
    if (!p.includes(ROLE_TOKEN)) { out.push(p); continue }
    for (const r of list) out.push(p.split(ROLE_TOKEN).join(r))
  }
  return out
}
```
