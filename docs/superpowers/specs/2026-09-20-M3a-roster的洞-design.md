# M3a：`roster` 的洞 —— 设计

**入口条件**：`docs/11` §5.16（数据到了、候选方案被证伪）与 §5.18 C2（同一个决定的正文侧那一半）。
**数据来源**：`docs/15-M2b-实测结论.md` §5.1 / §5.1bis / §6.1，全部记录级，一趟走完 S1→S8 的真实 run。

---

## §1 这个洞是什么

**一句话**：`roster` 决定「这一趟该有什么」，而 `roster` 是 PM 在**派发并核实之后**才写的
——所以**从来没被派的角色，就从来不被期待，它的缺席因此不可见**。

M2b Task 5 在真实环境里观测到它的**两种形状**：

### 形状 A（S2）：从来没写

`at-product` 自决不派 `at-ui`，PM 复核后同意，并在 `04-dispatch.md` 里把它写成一条裁决
（**磁盘文件，不是转述**）：「不是漏派，是按需组队后的主动裁剪」。

于是 S2 一半的产物（`02-ui-spec.md`、`02-wireframe.html`）整趟没有产出，而：

- `stageRolesInRun(S2, roster)` = `["at-product"]` → `expandProduces` 只剩 `01-prd.md`
- **`isStageDone(S2)` 为真**
- `expectedArtifacts` 里根本没有那两个名字，`compareArtifacts` 只遍历 `expectedArtifacts`
  → **那两份既不算 `missing` 也不算 `unrecorded`，连查都没被查**

**八道判据一条都没响。**

> ⚠️ **上面第三个圆点的机制那一半，本设计 §3.3 落地之后不再成立
> （2026-09-20，M3a Task 5 补标）。** 这一段记的是 M2b 那一趟的形状，
> **结论（那两份什么都不算）一个字不动**，变的是理由：
> `unrecorded` 现在走 `producedNames(stages)`、**不按 `roster` 收窄**，
> 所以那两个名字**是被查了的**——只是磁盘上从来没有它们，`artifactBytes` 返回 `null`，
> 于是仍然什么都不是。
> **这一句被 `hooks/lib/coverage.mjs` 头部逐字引为「原文」并且在那边标过**，
> 同族的另外几份在 `docs/15` 与 `docs/11` §5.11/§5.13 也标过
> ——**独这一份没标，而这份正是被引的那个源**。

### 形状 B（S5）：写晚了

S5 的实现记录落盘之后、PM 把 `at-backend`/`at-frontend` 写进 `roster` **之前**，
`compareArtifacts` 对它们同样是瞎的。

**而 `hooks/lib/artifact-drift.mjs` 的头部注释写着 `unrecorded` 是
「`Bash` 绕过 H3 的直接表征」** —— 一个**按 `roster` 收窄**的 `unrecorded`
**看不见一个还没进 `roster` 的角色写出来的任何东西**。**判据与它自己声明的用途矛盾。**

## §2 两个被排除的方案，以及为什么

### 排除 1：「`roster` 只许追加，不许删」（§5.7 当年列的候选）

**被同一份数据证伪**：观测到的形状是「**从来没写**」，而单调增长的 `roster` 一次都不会
触发「只许追加」。`docs/14` 记的「131 次快照没有出现缩短」不是好消息——
**真正要防的那个形状根本不经过「缩短」这个动作。**

### 排除 2：「不管 `roster`，所有 `producers` 一律期待」

**会打死一个有意的设计**：`roster` 存在的理由就是「按需组队」——只派两个执行角色的 run
不该被要求交五份实现记录（`hooks/lib/state.mjs` 的 `isStageDone` 注释记着，
静态列全五个会让整条链卡死）。

**而且观测到的那次裁剪是合法的**：PM 复核过、写成了磁盘上的裁决。
**问题不在「裁剪」，在「裁剪不可机器读」。**

## §3 设计：三条改动

### 3.1 `trimmed` 进 `state.json`，裁剪从散文变成声明

```json
"trimmed": { "at-ui": "S2" }
```

键是角色名，值是**在哪一段被裁掉的**。

**它把一个已经存在的决定变成可机器读的**——那次裁剪本来就被 PM 写进了 `04-dispatch.md`，
**只是没有任何判据能读它**。

⚠️ **不要求写理由**。理由已经在 `04-dispatch.md` 里，再要一份就是第二份拷贝
（`docs/16`「同一份知识只留一处」）。`trimmed` 只回答「谁、在哪一段」。

### 3.2 阶段推进时核：这一段的 `producers` 每一个都得有交代

**判据**：`state.stage` 从 `S_n` 推进出去时，
**`stageRoles(S_n) ∩ available_roles`** 里的每一个角色**必须在 `roster ∪ trimmed` 里**。
两边都不在 = 静默漏掉 → **报**。

这正是数据指出的那个方向（「当前阶段的 `producers` 里有人不在 `roster`」），
**修正成允许「已声明的裁剪」**。

> ⚠️ **上面那个 `∩ available_roles` 是实现期加的（Ruling 2），这份设计的初稿没有它**
> ——初稿写的是「`stageRoles(S_n)` 里的每一个角色」。**实现者拿真实终局数据实跑，
> 报出来的那几条里 `at-ios` 与 `at-android` 不是漏派，是按需组队本身**
> （那一趟的 `available_roles` 里根本没有它们）——要它们闭嘴，PM 得把这个项目根本没
> 用过的角色写进 `trimmed`，而**没有决定，也就谈不上「把已经存在的决定变成可机器读的」**，
> 直接打在 §3.1 的立论上。收窄之后剩下的全是**同一个角色 `at-ui` 的同一个决定**
> （`S2` 与 `S5` 各一条，它在两段都是产者），写一行 `trimmed` 一起消失。
>
> ⚠️ **这里不报总数**（`docs/16`「列举，不报总数」）。这一段初稿写的是「判据报四条、
> **信噪比 1:3**，其中**三条**不是漏派」——**两个数字都错**：实测那一类是 `at-ios` 与
> `at-android` **两个角色**，而且它逐字抄自 `hooks/lib/coverage.mjs` 的注释，
> **那句原话本身就自相矛盾**（「四条里有三条是这种；收窄之后是两条」，4 − 3 = 1 ≠ 2）。
> **本轮把一句没重核的话搬进了 tracked 文档——这正是 F1 的形状**，定向复评抓出来的，
> 三处（`coverage.mjs` 注释、这里、计划）一起改成列举。
>
> `available_roles`（`project.json`，「这个项目用得上哪些执行角色」）是仓库里**现成的**
> 那个概念。收窄之后 `at-pm` 也自动退出宇宙——`templates/project.json` 有一条不变量
> 「`available_roles` 不得含 `at-pm`」，理由逐字是「**它是这一趟的驱动者，不参与
> 『有没有被叫到』的统计**」，**与这条判据要的理由是同一句话**，不用开特例。
>
> ⚠️ **`at-pm` 那一格是承重的，不是顺带**：它**是** S1/S4/S8 的 `role`，所以按初稿口径
> 会被点名，而 **`{"at-pm": "S1"}` 会被 `validateState` 放行**（形状挑不出毛病），
> 且 `trimmed` 按角色名判、**一条记录盖住那个角色的每一段**。
> 正文里任何一句复述这条判据而略掉 `∩ available_roles` 的话，**字面读法都指向这个错修法**。
>
> **口径读不到时（`project.json` 缺失或 `available_roles` 不可用）不收窄、并留痕**
> ——收窄成空集合会让「把 `available_roles` 删掉」变成一条静默通道。
>
> 这条裁定**当时只写进了会话账本，没有回改这份设计与那份计划**，M3a Task 4 的评审把它
> 捞了出来。教训与本文件 §4 那条是同一句：**一次裁定要落到它改掉的每一处断言上。**

**为什么触发点选「推进出去时」**：`commands/at.md` 第 4 步在**派发并核实之后**才累加
`roster`，而推进在更后面——**推进那一刻 `roster` 对这一段已经是完整的**，
不会撞上形状 B 那个窗口。

**失败策略：报，不拦。** 与 H5a 同一档（`additionalContext`），不是 deny。
理由：裁剪是合法动作，判据只负责**把沉默变成一句话**；把它做成 deny 会在
「PM 还没来得及写 `trimmed`」时卡死整条链，而那是形状 B 那个窗口的同族误报。

### 3.3 `unrecorded` 不再按 `roster` 收窄

`compareArtifacts` 现在遍历 `expectedArtifacts(stages, roster)` 算三个清单。改成：

- **`drifted` / `missing` 仍按 `roster` 收窄** —— 它们问的是「**这一趟**该有的对不对得上」，
  roster 是对的口径
- **`unrecorded` 改走 `producedNames(stages)`**（roster 无关）—— 它问的是
  「**磁盘上有谁没交代的东西**」，**这个问题从来就不该被 `roster` 闸住**

**这一条是三条里最硬的**：不是加功能，是**让一条判据回到它头部注释已经写明的用途**。
形状 B 因此自动消失。

## §5 不做的

- **不给 `trimmed` 加写时强制**（H6 那种）。先让它存在、被判据读到；
  写时强制要等下一次真实 run 的误报率数据——**这正是 §5.7 当年该做而没做的那一步，
  不要在同一个地方再犯一次**。
- **不改 `isStageDone`**。它按 `roster` 收窄是对的（它答的是「这一趟这一段齐了没」）；
  形状 A 由 3.2 那条推进判据接住，不是由它。
- **不补 S6–S8 的逐段正文**（`docs/11` §5.18 C1 已裁定，会造出第二份阶段链）。
