# 契约读不出的判据三个系统都跑

> 2026-10-11，分支 `r42-unreadable-contract-tests`。第四十二轮（从开放边界索引挑）：`docs/37` §5「『契约在、却读不出』只在 POSIX 上有子进程判据」，
> 也是 `docs/60` §4「『契约在、却读不出』在 Windows 上没有自动判据」。只动判据与文档。

## 0. 一句话结论

- 那两条判据原来用权限位（`chmod 000`）造「在、却读不出」的契约，Windows 上造不出那种文件，只能跳过、靠手工复现。现在用预加载脚本（`tests/fixtures/fail-read.cjs`，
  门禁子进程以 `node -r` 加载）让读某个文件名时抛 EBUSY，三个系统都造得出；两条判据不再跳过。`docs/83` 为 `project.json` 被占用写的那一份推广成按文件名读失败，
  共用的帮手在 `tests/helpers/fail-read.mjs`。

## 1. 问题

- `tests/gate-contract-sha.test.mjs` 的「契约在却读不出 → 【契约】说读不出、没核，不说它不在」与 `tests/gate-readiness-contract.test.mjs` 的「H2：契约在却读不出——不拦、
  留痕」在 Windows 上 `skip`；本机就是 Windows，这两格平时一次都不跑，CI 的 Windows 作业也不跑。root 下 `chmod` 不起作用，POSIX 上以 root 跑也形同跳过。

## 2. 修法

- `tests/fixtures/fail-read.cjs`（由 `fail-project-read.cjs` 改名推广）：`AGENT_TEAM_TEST_FAIL_READ_NAME` 是文件名（不给是 `project.json`）、`AGENT_TEAM_TEST_FAIL_READS`
  是失败几次（不给就一直失败）；只碰文件名正好是它的读，正反斜杠都认。
- `tests/helpers/fail-read.mjs` 的 `failRead(name, times)`：给 `run` 的第五、六个参数（环境与 `nodeArgs`）。
- 两条判据改用它、去掉 `skip` 与 root 那一句；`tests/reach-unchecked.test.mjs` 改用同一个帮手。

## 3. 判据与变异

- 本机（Windows）上两条判据从「跳过」变成跑；全量跳过的条数少了两条。
- 变异（备份在仓库外，改完逐字节还原）：把门禁「契约在、却读不出」那一支改成按「不在」处理（`gate.mjs` 的 `contractCmp`），两条判据在 Windows 上都红。

## 4. 仍然开着的边界

- **预加载模拟的是 `readFileSync` 抛错**：门禁换一种读法（例：`openSync` 加 `readSync`）时这条模拟就不生效，判据会因为读到了契约而红——方向安全，到时候跟着改。

## 5. 没量到的

- 无（这一轮只动判据）。

## 6. 归属

- `tests/fixtures/fail-read.cjs`、`tests/helpers/fail-read.mjs`；改动的判据在 `tests/gate-contract-sha.test.mjs`、`tests/gate-readiness-contract.test.mjs`、`tests/reach-unchecked.test.mjs`。
