# 契约读不出的判据三个系统都跑

> 2026-10-11，分支 `r42-unreadable-contract-tests`。第四十二轮（从开放边界索引挑）：`docs/37` §5「『契约在、却读不出』只在 POSIX 上有子进程判据」，
> 也是 `docs/60` §4「『契约在、却读不出』在 Windows 上没有自动判据」。只动判据与文档。

## 0. 一句话结论

- 两条判据原来用权限位（`chmod 000`）造「在、却读不出」的契约，Windows 上造不出那种文件，只能跳过、靠手工复现。现在用预加载让门禁子进程读契约时抛错，三个系统都跑、
  不再跳过；项目经理写 `state.json` 时那一支原来在任何系统上都没有判据，补了一条。预加载用仓库里已有的两份（`tests/helpers/inject-throw.cjs` 的 `read:<后缀>`、
  `tests/helpers/project-reads.cjs`），由 `tests/helpers/fail-read.mjs` 的 `failRead` 包一层；`docs/83` 为 `project.json` 被占用另写的那一份删了（复核之后，§8）。

## 1. 问题

- `tests/gate-contract-sha.test.mjs` 的「契约在却读不出 → 【契约】说读不出、没核，不说它不在」与 `tests/gate-readiness-contract.test.mjs` 的「H2：契约在却读不出——不拦、
  留痕」在 Windows 上 `skip`；本机就是 Windows，这两格平时一次都不跑，CI 的 Windows 作业也不跑。root 下 `chmod` 不起作用，POSIX 上以 root 跑也形同跳过。
- 项目经理写 `state.json` 时账本那一支（`contractUnreadable`，`docs/37` §2.5）一条判据都没有：把它改成恒假，回传就成了「需求基线不在了、告诉用户」，全量照绿。

## 2. 修法

- `tests/helpers/fail-read.mjs` 的 `failRead(name, times)`：给 `run` 的第五、六个参数（环境与 `nodeArgs`）——`project.json` 走 `project-reads.cjs`（按次数抛 EBUSY），
  别的文件走 `inject-throw.cjs` 的 `read:<后缀>`（一直抛）。两份都调 `syncBuiltinESMExports`，门禁里 `import { readFileSync }` 的具名导入看得到替换后的函数。
- 两条判据改用它、去掉 `skip` 与 root 那一句；H2 那一条要求放行（原来的断言放得过「读不出就拒派」）。新加「项目经理写 `state.json`、契约在却读不出」一条。
  `tests/reach-unchecked.test.mjs` 改用同一个帮手。

## 3. 判据与变异

- 本机（Windows）上两条判据从「跳过」变成跑，再加一条；全量跳过的条数少了两条。
- 变异（备份在仓库外，改完逐字节还原）：把门禁「契约在、却读不出」那一支改成按「不在」处理（`gate.mjs` 的 `contractCmp`），两条判据在 Windows 上都红。复核之后：
  读不出就拒派、写 `state.json` 那一支不认读不出、帮手不加载预加载（契约那一份、`project.json` 那一份）——每一刀都有判据红。

## 4. 仍然开着的边界

- **预加载模拟的是 `readFileSync` 抛错**：门禁换一种读法（例：`openSync` 加 `readSync`）时这条模拟就不生效，判据会因为读到了契约而红——方向安全，到时候跟着改。

## 5. 没量到的

- 无（这一轮只动判据）。

## 6. 归属

- `tests/helpers/fail-read.mjs`（包的是 `tests/helpers/inject-throw.cjs`、`tests/helpers/project-reads.cjs`）；改动的判据在 `tests/gate-contract-sha.test.mjs`、
  `tests/gate-readiness-contract.test.mjs`、`tests/reach-unchecked.test.mjs`。

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：预加载在三个系统、Node 16.9／22／24 上都真的生效；预加载什么都不做、去掉反斜杠匹配、忽略文件名都会让判据红，不会假绿；
用 `FileShare.None` 锁住文件实测，stat 成功、读抛 EBUSY，与模拟一致。两个中等、四个小问题：

- **中 1：H2 那一条没钉住「不拦」**——把读不出改成拒派，全量照绿。→ 要求放行。
- **中 2：项目经理写 `state.json` 时那一支没有判据**，索引却把这一族写成关了。→ 补一条。
- **低**：仓库里本来就有两份伪造读失败的预加载，又另造了一份，语义、位置都不一样（→ 删掉新造的，帮手包已有的两份）；新造的那份没调 `syncBuiltinESMExports`、靠 Node 的
  内部时序，与姊妹文件的说法相反（→ 随它删掉）；看板第 44 项还列着关上了的这一条（→ 删了）；`docs/83` 引用了已删的文件（→ 写了订正）。
