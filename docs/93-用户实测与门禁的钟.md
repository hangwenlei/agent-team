# 用户实测与门禁的钟

> 2026-10-12，分支 `r49-gate-clock`。`docs/91` §2.2 交给用户的两场跑回来了；照结果修一处——`state.json` 里的时间是项目经理估的。动门禁的两句回传
> （自检、【阶段】）与 `/agent-team:at` 的正文。

## 0. 一句话结论

- **U1（桌面端粘贴长需求）过了**：粘贴的整段进了命令参数（不是占位），门禁记下的原话与契约第 1 节对得上，契约基线照新口径记了整段原话，从 S1 走到收口，
  门禁除了每轮的自检没拒过一次。
- **U2 没量到它要量的**：用户是在桌面端、auto 模式下跑的，不是交互终端的默认权限模式。它与 U1 一起说明桌面端加 auto 模式这条路走得通；终端那一格照旧开着，
  不再交给用户（§3）。
- **时间多半是估的**：七场真实会话（`docs/92` 五场、这里两场）里 `history` 的 at 与 `closed_at` 多半是项目经理估的——U2 九个全是估的、越写越往后，
  写下的收口时间在会话结束之后一刻钟；U1 跑过四次 `date`，那四个准，另外五个是估的。门禁在自检的回复与【阶段】里带上门禁此刻的时间，正文叫项目经理照最近
  拿到的那一个写、不要估。

## 2. 观察

- **桌面端的派发是前台的**（`run_in_background: false`，派发记录里是 foreground），与 SDK 宿主一样；角色交回来时，平台把它的回报当成一条消息递给项目经理，每一条
  都触发一次「先自检」的提醒。门禁在派发正常交齐时不说话，所以派出去的角色交产物的那几段，项目经理推进之前收不到【阶段】——它拿得到门禁时间的地方是自检的回复。
- **时间越写越偏**：U2 里项目经理九次写时间（`history` 八条、`closed_at` 一条），写下的时间比写入那一刻依次差 −5 秒、+54 秒、+88 秒、+2.5 分、+4.6 分、+7 分、
  +10 分、+12 分、+15 分。第一条照着真时间写（建 run 时它取过一次时间），之后都是估的。U1 里项目经理在 S1、S3、S7、S8 推进前各跑过一次 `date -u`，那四个与
  写入时刻差几秒；另外五个（S2、S4、S5、S6 的推进与收口）偏 +1 到 +6 分钟。`docs/92` 五场的 `closed_at` 都不是收口那一刻。拿得到真时间就照着写，拿不到就估——
  门禁不拿这些时间判任何事（`docs/33` 不用 `history.at`；收口标记只核形状），所以没出过错，错的是记录本身。
- **at-init 在空目录里照模板写占位**（TypeScript、`npm run build`、`npm test`），U1 收尾时项目经理照正文提醒用户重跑 at-init——照设计。
- **契约模板第 4 节注释里的两条示例修订块标题记进了基线的 `revisions`**：记基线那一刻就在，之后不算新加的，不影响判断（之前的版本同样如此）。

## 3. 裁定、修法与判据

- **修时间**：项目经理有 Bash，却没有可靠的钟（估出来的偏差越积越大）；每次推进都先跑 `date` 在默认权限模式下要多弹一次窗。门禁在项目经理写 `state.json`
  之前总会说话的两处带上门禁此刻的时间（`hooks/lib/closing.mjs` 的 `gateClock`：到秒的 UTC、以 Z 结尾）：
  - 自检的回复（`gate-check.mjs` 的 `gateCheckReason`）：「门禁此刻的时间是 …（UTC）：state.json 的 history 里的 at、closed_at 照门禁回传给的这种时间写，不要估。」
  - 【阶段】（`ledger.mjs`）：推进那一句 history 那一条直接带时间（原来是占位 `<ISO 时间>`），收口那一句说 closed_at 写门禁此刻的时间。
  - `/agent-team:at` 正文：建 run 那一段加一句——`state.json` 里的时间（`history` 与 `escalations` 每一条的 at、`closed_at`）和契约的冻结时间用这次写入之前
    最后拿到的门禁时间写、不要估；拿到之后又等过用户或角色的，先再做一次门禁自检取一次（自检那次写入总被门禁拒掉，不弹权限窗）。四处占位与契约模板的冻结时间
    改成「门禁给的时间」。
  - 门禁叫项目经理重写时间的几处——history 新条目形状不对（H6）、`closed_at` 不是时间（H6 与账本的状态校验）——也带门禁此刻的时间，不再只给占位或一个固定的样例。
  门禁照旧不核这两个时间（不拿它们判事，核了也只能拦掉、不能让它变准）。
- **不修**：at-init 的占位（照设计）；U2 那一格——交互终端里权限弹窗怎么出、后台角色会不会被自动拒是平台的行为，插件改不了，量到了最多补 README 一句；维护者
  够不着交互终端的弹窗（终端面板只能敲一行命令），用户平时用的是桌面端加 auto 模式。照旧登在开放边界（第 44 条）。

- **判据** `tests/gate-clock.test.mjs`：钟的格式过得了收口标记的形状、换了时区照样是 UTC；自检的回复（整句）、【阶段】推进与收口带注入的时间；门禁子进程里两处带的
  是跑的那一刻的时间；三处拒绝理由与报错带门禁此刻的时间；正文那一句在，三处 history 那一条、收口那一步、契约模板的冻结时间逐处是「门禁给的时间」。
- **变异**（备份在仓库外，改完逐字节还原，每刀跑全量），每一刀都红：钟带毫秒、自检不带时间、自检不用注入的钟、推进还是占位、推进不用注入的钟、收口不带时间、
  正文去掉那一句、正文推进那一处还是占位；复核之后：钟用本地时间冒充 UTC、三处拒绝理由与报错不带时间、正文回退那一处与收口那一步退回旧写法、契约模板退回占位。

## 4. 仍然开着的边界

- **门禁不核这些时间**：项目经理照旧可以不照抄（只靠回传与正文）。
- **拿到的时间会过时**：门禁的时间只在两个时刻给——每一轮第一次写 `.agent-team` 之前的自检、项目经理自己的一次写入让这一段判齐时的【阶段】。之后同一轮里等过
  用户（开头问续跑还是另起、`AskUserQuestion` 的答复在同一轮返回）或角色（前台派发在同一轮返回的宿主上）、又没照正文再自检的，照抄下来的是等之前那一刻，
  早多少没有上限。桌面端（2.1.295）与 SDK 宿主（2.1.286）里每个角色交回来都开新的一轮、重新自检，这两处没有这个问题。
- **修订块标题里的日期**（`### <日期> · …`）不在其内：日期项目经理从会话里拿得到。
- **交互终端的默认权限模式**（第 44 条）：照旧没量。

## 5. 没量到的

- 真实会话里项目经理拿到门禁的时间之后照不照抄（下一次真实会话时，对着转录里写入的时刻看 `history` 的 at 与 `closed_at`）。

## 8. 复核与修订

第一版（2792dc6）推上分支之后起了一个对抗复核的子代理。下面这些核过了：时间只进账本与自检两处回传，去重指纹（完成核验的 told）不受影响；不是外部值、
不触发 trusted-echo；Node 下限之内、import 不成环；门禁确实不拿这些时间判事；每个角色交回来都重新自检（桌面端、SDK 宿主）；U2 的数据与转录对得上。没有高，两个中、
几个低：

- **中 1：拿到的时间会过时**——同一轮里等过用户或角色、再写 `state.json`，照抄下来的是等之前那一刻；正文与自检回复都没说用最近的那一个。→ 正文写明用这次写入之前
  最后拿到的、等过就再自检取一次；自检回复说「照最近一次门禁回传给的时间写」；§4 写清几种情形。
- **中 2：`docs/92` §5 的原话被就地改了**。→ 改回去，收口写在底下。
- **低**：U1 跑过四次 `date`，「七场全是估的」与 CHANGELOG 说过了头（→ 如实写）；`escalations` 的 at、契约的冻结时间、几处拒绝理由里的占位与固定样例没跟上（→ 跟上，
  修订块标题的日期登在 §4）；判据打不红的几刀——收口那一步与回退那一处退回旧写法、自检回复少半句、钟用本地时间（CI 的 runner 是 UTC）（→ 逐处核、整句钉、换时区测）；
  `docs/00` 里 `docs/92` §5 那一行读起来像 U2 关了（→ 写准）；§3 的体例（→ 并成一节）。
