# 用户实测与门禁的钟

> 2026-10-12，分支 `r49-gate-clock`。`docs/91` §2.2 交给用户的两场跑回来了；照结果修一处——`state.json` 里的时间是项目经理估的。动门禁的两句回传
> （自检、【阶段】）与 `/agent-team:at` 的正文。

## 0. 一句话结论

- **U1（桌面端粘贴长需求）过了**：粘贴的整段进了命令参数（不是占位），门禁记下的原话与契约第 1 节对得上，契约基线照新口径记了整段原话，从 S1 走到收口，
  门禁除了每轮的自检没拒过一次。
- **U2 没量到它要量的**：用户是在桌面端、auto 模式下跑的，不是交互终端的默认权限模式。它与 U1 一起说明桌面端加 auto 模式这条路走得通；终端那一格照旧开着，
  不再交给用户（§3）。
- **时间是估的**：七场真实会话（`docs/92` 五场、这里两场）里 `history` 的 at 与 `closed_at` 全是项目经理估的，越写越往后——U2 写下的收口时间在会话结束之后
  一刻钟。门禁在自检的回复与【阶段】里带上门禁此刻的时间，正文叫项目经理照抄、不要估。

## 2. 观察

- **桌面端的派发是前台的**（`run_in_background: false`，派发记录里是 foreground），与 SDK 宿主一样；角色交回来时，平台把它的回报当成一条消息递给项目经理，每一条
  都触发一次「先自检」的提醒。门禁在派发正常交齐时不说话，所以派出去的角色交产物的那几段，项目经理推进之前收不到【阶段】——它拿得到门禁时间的地方是自检的回复。
- **时间越写越偏**：U2 里项目经理九次写时间（`history` 八条、`closed_at` 一条），写下的时间比写入那一刻依次差 −5 秒、+54 秒、+88 秒、+2.5 分、+4.6 分、+7 分、
  +10 分、+12 分、+15 分。第一条照着真时间写（建 run 时它取过一次时间），之后都是估的。U1 与 `docs/92` 的五场同样。门禁不拿这些时间判任何事（`docs/33`
  不用 `history.at`；收口标记只核形状），所以没出过错——错的是记录本身。
- **at-init 在空目录里照模板写占位**（TypeScript、`npm run build`、`npm test`），U1 收尾时项目经理照正文提醒用户重跑 at-init——照设计。
- **契约模板第 4 节注释里的两条示例修订块标题记进了基线的 `revisions`**：记基线那一刻就在，之后不算新加的，不影响判断（之前的版本同样如此）。

## 3. 裁定与修法

- **修时间**：项目经理有 Bash，却没有可靠的钟（估出来的偏差越积越大）；每次推进都先跑 `date` 在默认权限模式下要多弹一次窗。门禁在项目经理写 `state.json`
  之前总会说话的两处带上门禁此刻的时间（`hooks/lib/closing.mjs` 的 `gateClock`：到秒的 UTC、以 Z 结尾）：
  - 自检的回复（`gate-check.mjs` 的 `gateCheckReason`）：「门禁此刻的时间是 …（UTC）：state.json 的 history 里的 at、closed_at 照门禁回传给的这种时间写，不要估。」
  - 【阶段】（`ledger.mjs`）：推进那一句 history 那一条直接带时间（原来是占位 `<ISO 时间>`），收口那一句说 closed_at 写门禁此刻的时间。
  - `/agent-team:at` 正文：建 run 那一段加一句「`history` 里的 at 与 `closed_at` 写真实的时间：照这一轮门禁自检或【阶段】回传里给的门禁时间写，不要估」，四处占位改成
    「门禁给的时间」。
  门禁照旧不核这两个时间（不拿它们判事，核了也只能拦掉、不能让它变准）。
- **不修**：at-init 的占位（照设计）；U2 那一格——交互终端里权限弹窗怎么出、后台角色会不会被自动拒是平台的行为，插件改不了，量到了最多补 README 一句；维护者
  够不着交互终端的弹窗（终端面板只能敲一行命令），用户平时用的是桌面端加 auto 模式。照旧登在开放边界（第 44 条）。

- `tests/gate-clock.test.mjs`：钟的格式过得了收口标记的形状；自检的回复、【阶段】推进与收口带注入的时间；门禁子进程里两处带的是跑的那一刻的时间；正文那一句在、
  不再有只写占位的地方。
- 变异（备份在仓库外，改完逐字节还原，每刀跑全量），每一刀都红：钟带毫秒、自检不带时间、自检不用注入的钟、推进还是占位、推进不用注入的钟、收口不带时间、正文去掉
  那一句、正文推进那一处还是占位。

## 4. 仍然开着的边界

- **门禁不核这两个时间**：项目经理照旧可以不照抄（只靠回传与正文）；推进晚于回传的，照抄下来的是收到回传那一刻、不是推进那一刻（通常差不到一分钟）。
- **交互终端的默认权限模式**（第 44 条）：照旧没量。

## 5. 没量到的

- 真实会话里项目经理拿到门禁的时间之后照不照抄（下一次真实会话时，对着转录里写入的时刻看 `history` 的 at 与 `closed_at`）。
