# 没叫过的产者被当前置时推进也要

> 2026-10-11，分支 `r47-uncalled-producer-prereq`。第四十七轮（从开放边界索引挑）：`docs/81` §4「推进那一侧对 `[]` 照旧放行」，也是 `docs/77` §4
> 「`stage_roles` 记成 `[]`」那一格的 S2 那一半。动门禁判据（推进与判齐）、`/agent-team:at` 的一句与判据。

## 0. 一句话结论

- 随参与者展开的段（S2、S5），离开时原来只要叫到的人那几份：S2 记成 `[]`、谁都没裁，`01-prd.md` 不在也放行推进，到 S3 派人时 H2 才按前置拒。现在这一段
  没叫过、也没在这一段裁掉的产者，它被后面某段当前置的产物（S2 的 `01-prd.md`）照样要——推进（`advance.mjs` 的 `departureNeeds`）与判齐（`state.mjs` 的
  `isStageDone`，【阶段】用它）同一个口径；出路是派它、或者把它写进 `trimmed`。不是前置的（`02-*`、`05-impl/*`）没叫就不要，照旧。

## 1. 问题

- 「叫到」只看 `stage_roles` 与派发记录：S2 一个产者都没叫、也没裁，推进那一次核的是空集，放行；`01-prd.md` 是 S3、S4、S7 的前置，到 S3 派架构师时 H2 才拒，
  出路要回头补 S2——推进那一刻本可以说清。只叫了 `at-ui` 的 S2 同样：【阶段】说 S2 齐了（02-* 都在）、推进放行，`01-prd.md` 照样缺。

## 2. 修法

- `hooks/lib/advance.mjs` 的 `departureNeeds`：随参与者展开的段，叫到的人那几份之外，再要没叫过、也没在这一段裁掉（`trimmedAt`）的产者被后面某段当前置
  （`!mayWaive`）的那几份；拒绝理由走「这一趟还没叫过 X——派它；不叫它就写进 trimmed」那一支，随参与者展开的段说「裁掉它」、不说「整段裁掉」。
- `hooks/lib/state.mjs` 的 `isStageDone`：同一条（传了 `state` 时，调用方都传）。
- `commands/at.md` 第 3 节「推进那一次，H6 核离开的这一段交齐了没有」：补「再加上这一段没叫过、也没裁掉的产者被后面某段当前置的那几份（`S2` 的 `01-prd.md`：
  不叫 `at-product` 就把它写进 `trimmed`）」。
- 判据：`tests/advance.test.mjs` 一条（S2 记成 `[]`、只叫了 `at-ui`、裁掉了、记在别的段的 trimmed、S5 记成 `[]`；H6 接线的拒与放行、「裁掉它」的说法）；
  `tests/stage-trim-done.test.mjs` 一条（`isStageDone` 的同一组情形）；`tests/advance-completion-prose.test.mjs` 那一段的关键词补两样；`tests/gate-rework.test.mjs`
  「正常推进」那一条的夹具补上 `01-prd.md`（它停在 S2、一个产者都没叫，正是这一轮要拒的情形，夹具比真实会话少了这份产物）。

## 3. 判据与变异

- 变异（备份在仓库外，改完逐字节还原，每刀跑全量），每一刀都红：推进那一侧去掉新那一圈、不看是不是前置、不看 `trimmed`、一律说整段裁掉；判齐那一侧去掉新那一圈、
  不看 `trimmed`、不看是不是前置；`/agent-team:at` 删掉新加的那半句。

## 4. 仍然开着的边界

- **记成 `[]` 而前置产物都在时【阶段】照旧不说齐了**：`isStageDone` 对参与者展开出来是空集的段照旧算没齐（推进放行）——`docs/77` §4 那一格的另一半，没动。
- **S5 记成 `[]`、S6 整段裁掉**：照旧推进放行而【阶段】不发（`05-impl/*` 不是前置）。
- **裁掉 `at-product`、只叫了 `at-ui` 的 S2**：推进放行；S3 派人时 H2 照前置拒（S2 不算整段裁掉），出路要么补 PRD、要么连 S3 起一起整段裁掉——与原来一样。

## 5. 没量到的

- 真实会话里推进出 S2 被这一条拒之后，项目经理派 `at-product` 还是写 `trimmed`。

## 6. 归属

  `tests/stage-trim-done.test.mjs`、`tests/advance-completion-prose.test.mjs`、`tests/gate-rework.test.mjs`。
