# 一趟真实 run 的开销与三条修改

> 2026-10-16，分支 `claude/trial-cost-fixes-089ac9`。用户在自己的 VPS Airport 项目的一个试验 worktree 里装了 7.4.0（local 作用域），跑了一整趟真实 run
> （需求「节点页面加个筛选」，run `20261016-1552-node-filter`）。功能都对，`docs/95`–`docs/99` 新做的五样（问需求、S6 审查、`at-ui` 截图自检、auto 模式交回、
> 交付文档的改动清单）都照设计工作，但太慢、太费 token。主会话复盘之后，用户批准三条修改：子代理不再自动带项目的 `CLAUDE.md`；`at-qa` 判「缺测试」的口径写死；
> 管住截图、大文件与长输出。不重跑整趟 run（用户对 token 敏感），只做探针量第一条；试验 worktree 是证据，只读。

## 0. 一句话结论

- **开局就背着一份交接文档**（§1.1）：试验项目的 `CLAUDE.md` 用 `@HANDOFF.md` 引了 279KB 的交接文档，平台把它放进主会话与每个子代理的开局上下文，每个子代理
  第一次调用就是 135k–147k token，之后每一次调用都再带一遍。改成被派得到的角色一律 `omitClaudeMd: true`（§3.1）。实测（§2）：同一份引进来的 60KB 文件，不带键的对照角色开局 35,023 token、看得到两个暗号；带键的 `at-qa` 16,590、一个都看不到；主会话带了键照样看到——平台说的「对主会话不起作用」成立。照同一个量折算，试验里每个子代理的开局会从 14 万上下掉到两三万。README 那句「用 `claudeMdExcludes` 排除」也量过：只排除引进来的那一份，项目的 `CLAUDE.md` 照常读。
- **返工的成因要分开看**（§1.2）：两次回退点名的都是契约第 4 节用户裁决「始终显示」这类整条新行为——把它去掉，整套测试一条都不红。新口径（§3.2）把用户点名的
  每一种情形各算一条新行为、碰没碰到靠读测试判，照它这两条仍算缺测试，那两次回退本身判对了。费的是变异本身：交接文档里「变异」67 处、`at-qa` 正文里 0 处，
  架构方案把「变异验证」写进执行角色的完成定义，`at-qa` 三轮做了 84、105、186 条；看得出是在做变异的调用至少占全趟 token 的 17.8%。新口径把「缺测试」写死成
  没有测试、测试碰不到这条新行为两种，断言偏弱、用户没点名的边界没测全、变异没杀死的只进审查、最多「应当修」，变异测试只在契约里用户要了才做。
- **单个角色的上下文涨到六七十万**（§1.3、§1.4）：整份读的大文件与测试输出，留在上下文里的图（四个角色合计 80 张）；各占多少没有拆开量。改成浏览器里的页面
  归 `at-ui`、原生界面归各端、每轮有数，验证段的角色不截图不读图；持 `Bash` 的角色同一节读文件与看输出的做法（§3.3、§3.4）。都只在正文里，门禁不核（§5）。

## 2. 实测：`omitClaudeMd`

### 2.1 源码里的几件事（CLI 2.1.301）

- agent 定义的 frontmatter 认 `omitClaudeMd`，schema 说明的大意：子代理运行时不带用户、项目与本地的 `CLAUDE.md` 指令文件，托管的策略文件保留；
  对主会话的 agent 不起作用（原文 No effect on the main session agent）。内置的 Explore、Plan 两个子代理就带着它。
- Claude Code 的更新记录里，这个键是 2.1.271 加的（「letting custom and plugin subagents run without user, project and local CLAUDE.md files」），README 写的下限 2.1.276 在它之后：支持的版本都认。
- 读插件 agent 的那一段：值是布尔 `true` 或字符串 `"true"` 才开，别的一律当没写、不报错；键名不做归一化（`omitclaudemd`、`omit-claude-md` 都不认）。
- 派子代理时：带这个键的，把开局上下文里的 `claudeMd` 换成只有托管文件的那一份（没有托管文件就整份去掉）。

### 2.2 做法

照 `docs/98`、`docs/99` 的做法起 `claude --bg`（CLI 2.1.301），工作目录是本工作树下的临时子目录。探针目录里放一份 `CLAUDE.md`：一行暗号，再用 `@big.md`
引一份 60KB 的大文件（末尾另一个暗号）。

| 场 | 会话 | 做法 |
|---|---|---|
| 一 | `420bd109` | 工作目录 `probe-100/`，`--settings` 带 `bgIsolation: "none"` 与排除本仓库、上一层 `CLAUDE.md` 的 `claudeMdExcludes`。项目经理先不调工具回答看没看到暗号，再派 `at-qa`、`at-acceptance` 各一次，派发提示叫它们不读不写不跑命令、直接回答 |
| 二 | `4980d221` | 工作目录 `probe-100b/`（同样两份文件），不带 `--settings`：项目的 `.claude/settings.local.json` 里写 `bgIsolation` 与 `claudeMdExcludes`（本仓库、上一层的 `CLAUDE.md`，外加 `**/probe-100b/big.md`）。项目经理不调工具、只回答看没看到暗号——量 README 那句建议 |

- 两场都用 `--permission-mode auto`，插件用工作树当前插件文件的一份拷贝（放在维护者的临时目录里，免得为探针改仓库）：拷贝上给 `at-pm` 加了键，
  把 `at-acceptance` 的键去掉作对照，`at-qa` 照仓库里的样子带着。没有 `.agent-team`：派发门禁、就绪门禁在没有 run 时放行（起会话之前拿门禁本身模拟过），
  项目经理的门禁自检照样回「在线」。
- 量法：转录里每个会话第一次调用的 usage（`input_tokens` 加两种缓存）；看没看到暗号照它们自己的回答（子代理是交回的报告原文）。
- 第一次起会话时本机命令行的登录过期了（OAuth refresh 400），那一场一次调用都没发出去，`stop`、`rm` 掉；用户重新登录之后再起这两场。

### 2.3 结果

| 场 | 会话、角色 | 带不带键 | 第一次调用的上下文 | 看到的暗号 |
|---|---|---|---|---|
| 一 | 主会话（`at-pm`） | 带 | 47,566 | 甲、乙 |
| 一 | `at-qa` | 带 | 16,590 | 没看到 |
| 一 | `at-acceptance` | 不带（对照） | 35,023 | 甲、乙 |
| 二 | 主会话（`at-pm`），本地设置排除 `big.md` | 带 | 24,674 | 只有甲 |

- **子代理带了键就不带项目的 `CLAUDE.md`，连同它引进来的文件**；不带的照旧都带。
- **主会话带了键照样带**：平台的说明成立。项目经理不加这个键（§3.1）。
- **引进来的 60KB 约 2.29 万 token**：第一场主会话减第二场主会话（两份给项目经理的话长短不一样，差几百）。对照的 `at-acceptance` 35,023 ≈ 底数约 1.2 万加这一份；
  `at-qa` 带键 16,590——它的正文比验收长、多一个 `Bash`，底数大一些。
- **`claudeMdExcludes` 写在项目的 `.claude/settings.local.json` 里，排得掉 `@` 引进来的那一份**，项目的 `CLAUDE.md` 照常读：README 那句建议成立。
- 两个子代理都只调了交回；项目经理做了门禁自检、派了两次，最后原样抄出两份报告。

### 2.4 收尾

两场都 `claude stop`、`claude rm`；按起会话之前的进程基线核过，三个 `claude` 进程都已退出，多出来的一个 Chrome 渲染进程是用户自己浏览器的扩展进程
（父进程在基线里）；`~/.claude.json` 里没有这两个临时目录的条目；探针目录删掉。转录留在 `~/.claude/projects/` 下，是证据。

## 3. 裁定

### 3.1 子代理不带项目的 `CLAUDE.md`（第一条）

- **被派得到的角色一律 `omitClaudeMd: true`**：从 `roster.json` 的 `can_delegate_to` 派生（测试替身 `at-outsider` 谁都派不到，不加）。
- **`at-pm` 不加**：平台对主会话不认这个键（§2）；主会话也要项目里的约定（分支规范、上线规矩这类，用户的项目里就写在 `CLAUDE.md`）。主会话那一份照旧
  整份读，README 两半各一句：引了很大的文档时，在项目的 `.claude/settings.local.json` 里用 `claudeMdExcludes` 排除（只对自己生效）。第二场量过：只排除引进来的那一份，项目的 `CLAUDE.md` 照常读（§2.3）。
- **项目里的约定改由角色自己取**：每个带这个键的角色加同一节「项目自己的约定」——开工时 `Read` 项目根的 `CLAUDE.md` 这一份，里面用 `@` 引的文件不跟着读，
  除非与这一次的任务直接相关，要读也先 `Grep` 再按段读；里面的约定照做，与角色正文冲突的照正文（它改不了正文定的判法与红线）；测试、构建的命令照旧从
  `project.json` 与交接包来。只读根上那一份：它是项目自己写给每个会话看的那几条；`@` 引的东西多半是背景，整份带上就是这一趟的开销来源。
  `CLAUDE.local.md`、用户自己的 `~/.claude/CLAUDE.md`、`.claude/rules/` 也随这个键一起不带了，角色不去读（§5）。
- **受限写法开一个窄口**：`tests/frontmatter-subset.test.mjs` 不许布尔值、键名只许小写与连字符；`omitClaudeMd` 两条都撞。只对逐字的 `omitClaudeMd: true`
  一行放行：YAML 把它读成布尔 true，平台照开；走「给值补引号再解析」那条退路时读到字符串 `"true"`，照样开。`True`、`TRUE`、带引号的 `"true"` 平台也开，
  按行读的判据却看见另一个字；`yes`、`on` 平台静默不开——两边读出的东西不一样，一律挡。顶层键白名单（`tests/agents.test.mjs`）加它：它不把子代理挪出这棵
  工作树、不改权限，那条不变量不受影响。

### 3.2 `at-qa` 判「缺测试」的口径（第二条）

- **「缺测试」只认两种**：一条新行为一个测试都没有；或者有测试，却碰不到这条新行为——没跑到它，或者只断言替身、什么都不断言。
- **用户点名的情形各算一条**：契约第 1 节原话、第 4 节修订块里用户的原话或裁决点名的每一种情形（试验里的「节点很少时也照常显示」）各算一条新行为，没有一个测试
  造出那种情形、断言它的结果，就是碰不到。复核指出没有这一句时，界线正好落在试验里判对的那一类上：工具栏有测试、只是没造出节点很少的情形，照字面会落进
  「边界没测全」，用户的裁决没有任何测试守着就交出去。用户没点名的边界与分支没测全，才只进审查。
- **碰没碰到靠读测试判，不靠变异**；测到了这条新行为、断言了它的结果，只是断言偏弱、用户没点名的边界与分支没测全、变异没杀死的，不算缺测试：写进「审查」，
  不改第一行，不因此回退。
- **测试本身的毛病最多「应当修」**：项目经理只对「必须修」回退（`/agent-team:at` 的 S6 审查那一条），`at-qa` 把一条弱断言定成「必须修」就又绕回返工。
  测试的毛病不直接让使用者拿到错的结果，照「按对使用者的影响定级」最多到「应当修」；顺着它读出代码真有错的，那是代码的问题，照代码定级。项目经理那一侧
  也补一句：审查里报的是测试本身的毛病的，定的哪一级都不回退。
- **变异测试不是 S6 的默认动作**：只有契约第 1 节用户原话或第 4 节修订块里用户的原话或裁决要了才做；架构方案、产品定义、派发提示、项目的 `CLAUDE.md` 与它引的
  文件要的都不算（与「用户说了不要测试」同一个口径：被验的一方与转述的一方都不能单方面加码）。要做也只用项目里已经配好的变异测试工具、照它的命令跑；没配的
  不装、不改代码、不拷副本手改，在审查里写明没做——`at-qa` 没有 `Edit`、`Bash` 只许装依赖编译跑测试，试验里那套拷副本、写脚本的做法本来就不合它的正文（§1.2）。
  做了的，结果同样只进审查。
- 这一条不靠第一条：第一条之后，项目自己的方法论不再自动进 `at-qa` 的上下文；口径写死在正文里，「项目自己的约定」那一节也写明它改不了正文定的判法。

### 3.3 截图（第三条之一）

- **看渲染效果归一个人**：浏览器里的页面归 `at-ui`——这一趟 `S5` 叫了它的，看页面那一步排在实现页面的产者交齐之后，架构师照这个顺序派（它先交了自己那一份的，
  同段再派它一次；同一段里重派 H2 不拦）；`S5` 没叫它的，归实现页面的那个产者（试验里就是 `at-frontend`）。iOS、Android 的原生界面归实现它的那个端：
  `at-ui` 手里只有浏览器。轮不到的不截图、不看图，要亲眼看的条目落进「没核」、写明归谁看。复核指出原来写成「叫了 `at-ui` 就只归它」时两处没人看：并发派时
  `at-ui` 先交、页面还没做出来；原生界面它看不了，两个端原来能在模拟器上自己看，那样写反而不许看了。
- **没有浏览器工具的怎么看**：只用项目里已有的截图测试、模拟器或真机（架构方案里列了的截图脚本也算），不为看页面另加依赖、另写脚本。
- **每轮有数**：每种情形一张，一轮通常不超过 4–6 张；页面没改动不重截；看完把结论写进记录就停。写在 `at-ui` 正文、`at-ui-craft` 的 SKILL.md 自检一节与
  `references/self-check.md`（后者不挂在「有那组浏览器工具」的条件下：三个端用模拟器、截图测试看，读进来的图一样留在上下文里）。
- **验证段不截图、不读图**：`at-qa`、`at-acceptance` 读实现记录「设计自检」里「看过」那一栏的结论；所以那一栏写看到了什么、对不对，不只列截了哪几张。
  `at-qa` 跑项目自己会生成截图的测试，照测试过没过判、不打开图；审改动时新文件里的图片只列路径。
- **验收那一种判不了的出路**：「看过」那一栏没看过、又只有亲眼看才判得了的，验收照判不了写、写明归谁看——这一种不是补跑测试，不回 S6（回去也没人看，
  S6、S7 白转）。项目经理照记录看那个人手里有没有办法看：有办法、却没看的，回 S5 由它补看（S5、S6、S7 各记一轮）；没办法看的，问用户要不要照现状交付，
  收口时交付文档写明哪些没验证。`/agent-team:at` 的回退、照现状交付、收口三处一起补。

### 3.4 大文件与长输出（第三条之二）

持 `Bash` 的角色（从 `tools:` 派生：`at-pm` 与六个执行、测试角色）加同一节「读文件与看输出」：大文件先用 `Grep` 找到要看的地方，再用 `Read` 带 `offset`、`limit`
只读那几段，要整份逐行看的才整份读（`at-qa` 审新加的文件就是这种）；跑测试、构建时命令前面加 `set -o pipefail;`、后面接 `2>&1 | tail -n 60`，只看结尾的汇总
与失败，失败多到结尾列不全的，重跑时接 `grep` 只留失败的那几行，要看哪一条失败的详情就单跑那一条；已经读过、之后没人改过、内容也还在上下文里的文件不重读，
拿不准的照读（项目经理照规矩逐份去磁盘核产物，这一句不压过它）。不往文件里重定向输出：执行角色的正文本来就不许用 `Bash` 写文件。

## 5. 仍然开着的边界

- **主会话照旧整份读项目的 `CLAUDE.md`**：平台对主会话不认这个键；README 两半写了怎么排除（有意：主会话要项目里的约定，排不排、排哪几份由用户定）。
- **角色只读根上那一份 `CLAUDE.md`**：`CLAUDE.local.md`、用户的 `~/.claude/CLAUDE.md`、`.claude/rules/`、子目录里的 `CLAUDE.md` 角色都不再自动带、也不去读；
  用户写在那几处、要团队角色照办的话到不了它们（真实里出现一份因此出错的转录时，再定读不读）。「与正文冲突的照正文」也只靠正文。
- **架构方案还写得出「执行角色必须做变异验证」**：`at-qa` 不再照它做，S5 的执行角色照完成定义办（试验里 S5 的变异调用比 S6 还多，§1.2）；架构师正文没改。
  第一条之后，项目的方法论不再自动进架构师的上下文，写出这一句的源头没了一半。
- **看页面的先后靠架构师排**：`at-ui` 在 S5 要看的页面排在产者交齐之后、同段再派一次，只在正文里；排错了 `at-ui` 看到的是半成品，门禁不核。
- **验收那一种判不了，「有办法看却没看」靠项目经理读记录判**：记录里没写为什么没看的，项目经理分不出该回 S5 还是该问用户。
- **截图张数、读文件、看输出只靠正文，门禁不核**（付三样）：拒绝的判据要按派发数图片工具结果、`Read` 的范围与 `Bash` 的输出长度，H5b 停下时读转录才数得出；
  它打不红的那一刀是角色照样整份读、整份灌——正文判据钉得住字，钉不住做；会让答案改变的是一份照新正文跑、上下文还是涨到几十万的转录。
- **不持 `Bash` 的角色（`at-architect`、`at-product`、`at-acceptance`）没加「读文件与看输出」**：这一轮只照批准的范围给持 `Bash` 的；试验里架构师最大上下文也到了 537k。
