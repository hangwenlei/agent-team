## 0. 一句话结论

1. **分叉带的是主线程的 `agent_type`，不是它从谁身上分出来的。** 给 `at-product` 写进度摘要的
   `agent_summary` 分叉，六次停下六次都带着 `agent-team:at-pm`；主线程没有被钉成任何角色时，
   分叉带的是空串 `""`（一次）。**这是交待下来的两种可能之外的第三种**（§1、§3）。
2. **所以 H5b 把每一个分叉都当成 `at-pm` 在收尾。** 在 `at-pm` 自己是产者的阶段（S1 / S4 / S8）、
   PM 的产物还没落盘时，**H5b 真的拦了分叉**：S4 两次 `exit 2`，原文
   「`at-pm 在 S4 应当产出 04-dispatch.md，但 04-dispatch.md 还没有写到磁盘上。……`」（记录级，§5）。
3. **在量到的这一种分叉上，这次误拦的代价是零**：`agent_summary` 的 `maxTurns` 是 1，被拦之后
   不重试（每个分叉恰好一次 API 请求）、摘要照发、任何一份转录里都没有痕迹。**会让它有代价的是
   `maxTurns` 大于 1 的那几种分叉**（`prompt_suggestion` 与 `auto_dream` 缺省 50、`extract_memories` 5）
   ——那一半是源码级的，本轮在 `--bg` 下量不到（§6、§10）。
4. **hook 输入里没有「这是分叉」的字段**：十一次 `SubagentStop` 的键集合逐次相同。本轮十一次里
   有三个字段把分叉与真子代理分得开——`agent_type`（主线程身份）、`agent_transcript_path` 指的文件
   不存在、`background_tasks` 不列它自己——但三个各有各的前提（§7）。
5. **修法要动 H5b 的判定逻辑，按本轮的交待先报方案、没改 `hooks/`**（方案在 §8）。

## 1. 问题与出处

`docs/11` §5.35（M3l 合入复核）：`docs/21` §5.5 量到一趟里 H5b 跑了七次，五次是 CLI 内部分叉停下时
触发的，全部放行。H5b 按 `agent_type` 决定去核谁的产物，它隐含的前提是
「**每一次 `SubagentStop` 都是一个团队角色干完了它那一段**」。§5.35 把分叉带进来的 `agent_type`
写成两种可能：

- 不带、或带一个不在任何阶段 `producers` 里的名字 → 放行，与观测一致；
- **继承父代理的名字**（从 `at-backend` 分出来的摘要分叉带着 `agent-team:at-backend`）→ 产物不在就被拦。

并写道：今天的观测分不开这两种，因为「执行角色停下时它的产物已经在盘上」。

⚠️ **与交待下来的框架不一致的一处，核过了**：`docs/21` §5.5 最后一段逐字记着
**前三次 `agent_summary` 停下时 `01-prd.md` 还不在盘上**（它 11:56:36 才落盘），而那三次都放行了、
同一时段 `at-product` 自己要停就被拦了——那一段当时就据此写下「分叉代理进来的 `agent_type`
**不是** S2 的执行角色；也不是缺失」。也就是说：**「继承父代理」在 M3l 自己的记录里已经被排除了**，
「今天分不开」那句与它隔壁的记录冲突。**缺的从来不是「是不是第二种」，是「那到底是什么」**
——而答案不在两个选项里（§3）。

## 2. 探针、夹具与会话

**探针 hook**（不到一百行的 node 脚本，只存在于探针工程）：挂在 `SubagentStop` 上，每次运行
① 把 stdin **原样**追加进一个旁证文件；② 在 hook 运行的那一刻采样两样东西——`agent_transcript_path`
指的文件在不在、`background_tasks` 里有没有这个 `agent_id`；③ 把同一份 stdin 原样喂给工作树里的

## 4. 为什么是这样（源码级）

- **hook 输入的公共部分**由一个函数统一拼：`agent_type` 取「这次事件所属那个上下文的 `agentType`，
  没有就取**主线程的 agent 类型**」——`let g=s?.agentType??dv()`，而 `dv()` 读的是
  `mainThreadAgentType`。
- **`SubagentStop` 与 `Stop` 是同一个函数发的**：上下文**有 `agentId`** 就发 `SubagentStop`，
  `agent_type` 是 `w??ve.agent_type??""`（`w` 就是那个上下文的 `agentType`）。**空串就从这里来。**
- **分叉的上下文是新造的**：`agentId: n?.agentId ?? kh()`（新 id——所以它发的是 `SubagentStop`，
  不是 `Stop`）、`agentType: n?.agentType`（**只取调用方显式传进来的，不从父上下文继承**）。
- **CLI 里十一处起分叉的调用点**（`agent_summary`、`prompt_suggestion`、`compact`、`reactive-compact`、
  `away_summary`、`side_question`、`rename`、`extract_memories` 两处、`auto_dream`、`plugin_model_fork`）
  **没有一处传 `agentType`**。于是分叉的 `agentType` 恒为空，hook 输入回落到 `dv()`——**主线程是谁，
  分叉就是谁**，从谁身上分出来不相干。本插件用 `settings.json` 的 `agent` 键把主线程钉成 `at-pm`，
  所以它们一律是 `agent-team:at-pm`。
- 顺带：`SubagentStop` 的 `matcher` 比的就是 `agent_type`（源码里 `case"SubagentStop":return e.agent_type`）。

各种分叉的 `maxTurns`（决定被 H5b 拦下之后会不会再跑一轮，§6）：

| 分叉 | `maxTurns` |
|---|---|
| `agent_summary`、`compact`、`reactive-compact`、`away_summary`、`side_question`、`rename` | 1 |
| `extract_memories` | 5（另一条路径由调用方给） |
| `plugin_model_fork` | 由调用方给 |
| `prompt_suggestion`、`auto_dream` | **不给，缺省 50** |

## 6. 代价：量到的一半与推的一半

**量到的（记录级）**：被拦的分叉多出来的**只有一条 `user` 消息**（调试日志记下的是它的类型；
它的内容是那段拒绝原文——这一半是源码级的：阻断错误被转成一条 meta 的 user 消息注回循环）
——没被拦的分叉是 `types=[assistant, progress, progress, progress, attachment, attachment, system]`，
被拦的是 `[assistant, progress, progress, progress, user, attachment, system, attachment]`，
**`assistant` 仍然只有一条**。`source=agent_summary` 的 API 请求数逐趟等于分叉数（s2 四对四、s4 二对二）
——**被拦之后没有再跑一轮**，因为 `maxTurns` 是 1。摘要照发（上面那条 `Summary result`，与第一条
`assistant` 同一句话）。**所以在这一种分叉上，这次误拦对用户、对模型、对账单都没有可见的后果。**

**推的（源码级，本轮没量到）**：`maxTurns` 大于 1 的分叉被拦之后会带着那段拒绝原文**再跑一轮**，
再停、再被拦，直到平台的重试上限或 `maxTurns`。其中最常见的一种是 `prompt_suggestion`：它把
**所有** `assistant` 文本都收成候选（源码：逐条 `messages` 取 `type==="assistant"` 的文本推进候选数组），
于是在交互会话里、提示建议开着时，PM 在 S1 / S4 / S8、自己的产物落盘之前每结束一轮，都可能多出几次模型调用、
外加几条围着「把 `04-dispatch.md` 写出来」打转的候选。**这一半本轮一次都没有量到**
——`prompt_suggestion` 在两个 `--bg` 会话里都没有出现（§10 第 1 条）。`docs/11` §5.35 写的
「在 8 到 10 次重试里反复要它把产物写出来」**对 `agent_summary` 不成立**（量到了：零次重试），
对 `maxTurns` 大于 1 的那几种是否成立，本轮不知道。

> ⭐ **收口（M3n）：推的那一半不再需要量——不是量过了。** §8 落地之后（§14），带着 `at-pm`
> 进来的分叉在 H5b 那里直接放行，一次都不会被拦，「被拦之后跑几轮」这个问题在主线程钉成
> `at-pm` 的路径上不复存在。**它从来没有被量过**；仍然可能遇到它的只剩 §8「盖不住的」那一格
> （用户用 `--agent` 把主线程钉成别的团队角色）。

## 9. 什么会让本文件的结论变假（可观测，不是数字）

   （它不是任何阶段的产者），**唯一的差别**是读不到运行上下文时不再写那行 failOpenNotice。
3. **前提的插件侧那一半由 `tests/roster-closure.test.mjs` 钉着**（花名册里没人能派 `at-pm`）——
   `hooks/gate.mjs` 那一行上方的注释点名它，**没有另抄一份判据**。

### 14.2 改了什么

`hooks/gate.mjs` 的 H5 共用分支里，`const role = stripPluginPrefix(rawTarget)` 之后、读运行上下文之前，一行：

```js
if (CHECK === 'stop-gate' && isContractWriter(rawTarget)) process.exit(0)
```

上方一段注释：实测出处、前提的两半（平台侧付三样在 §9；插件侧点名 `tests/roster-closure.test.mjs`）、
MAIN 那一半为什么够不着、为什么只对 `stop-gate`、为什么排在读上下文之前、为什么走 `process.exit(0)`、
盖不住的那一格。**判定逻辑别处一个字没动。**

**与 §8 的一处差别**：谓词吃的是 `rawTarget`（原始的 `agent_type`），不是剥过前缀的 `role`。
`isContractWriter` 自己经 `callerOf` 剥一次前缀；喂它 `role` 会剥两次（`agent-team:agent-team:at-pm`
会被认成 PM）。吃 `rawTarget` 与 H4 的短路 `isContractWriter(input?.agent_type)` 逐字同一个口径。
§8 那份 scratch 预演用的是 `role`；预演表里除「S2、`agent-team:at-pm`」那一格（改前改后都是静默放行，
没进判据）以外，每一格落地版本的输出都由 §14.3 的判据钉着，与预演一致。

**行为全表**（`stop-gate`；H5a 一格都没变）：

| 输入 | 修之前 | 修之后 |
|---|---|---|
| `agent_type` 为 `at-pm` / `agent-team:at-pm`，当前阶段是 PM 的（S1 / S4 / S8），PM 的产物不在 | `exit 2`，要求把产物写出来 | **静默 `exit 0`** |

| 同上，读不到运行上下文（没有 run、丢指针、`state.json` 坏了） | `exit 0` + stderr 一行 failOpenNotice | **静默 `exit 0`** |
| `agent_type` 缺失、`null`、空串 | `exit 0` + stderr「没有可判定的目标角色」 | 不变 |
| 其余一切 `agent_type` | —— | 不变 |
