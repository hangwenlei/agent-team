# 叫到之后又裁掉的那一段判齐

> 2026-10-11，分支 `r34-trimmed-stage-done`。第三十四轮（从开放边界索引挑）：`docs/32` §4「叫到之后又裁掉（预算耗尽之类）：`isStageDone` 仍等它的产物，【阶段】不发」。

## 0. 一句话结论

- `isStageDone`（【阶段】判齐、交付物核验判「停在旧阶段」、协调者返回时报进度都用它）多收一个 `state`：叫到之后又裁掉的角色——`trimmed` 里记着它、值就是这一段——那几份
  产物里 `mayWaive` 许的（按叫到的人展开产物的段、不被任何段当前置、不是验证段；不随参与者变的固定产物不免）不再等。与推进判据（`advance.mjs` 的 `departureNeeds`）
  同一个口径：叫到之后又裁掉的这一格，推进放行的时候【阶段】也说齐了。`hooks/gate.mjs` 里三处调用都传 `state`。
- 复核之后（§8）：两格不免——免掉的那份还是上一轮的（`artifactStale`：H6 照样按还旧拒）、那个角色在这一段还在跑（`running`：派出去了、门禁还没见它停下——裁掉之后又派
  回来时 `trimmed` 不会自己清掉）。`/agent-team:at` 第 3 节补一句「裁掉之后又把它叫回来的，派它那一次就从 `trimmed` 里拿掉它」。

## 1. 问题

- 推进判据在 `docs/38` 起就免掉叫到之后又裁掉的那几份（`mayWaive`），`isStageDone` 没跟：S5 里派过 `at-frontend`、后来决定这一趟不要它（写进 `trimmed`），别的执行角色
  都交了——推进出 S5 门禁放行，【阶段】却一直不说「S5 的产物已经齐了」，项目经理拿不到「可以推进了」那一句，交付物核验与协调者返回的进度也按「没齐」报。

## 2. 修法

- `hooks/lib/state.mjs` 的 `isStageDone({ …, state })`：`state` 给了时，参与者里 `trimmedAt(state, r, stage)` 的角色，它那几份产物里不是固定产物、`mayWaive(stages, stage, n)`
  许的，免掉；别的照旧要在。不给 `state` 的照旧。`hooks/lib/advance.mjs` 的 `trimmedAt` 导出给它用（同一份判断）。
- `hooks/gate.mjs`：账本（【阶段】）、协调者返回报进度、交付物核验三处调用都传 `state: ctx.state`。复核之后三处再传 `artifactStale: fresh.isStale` 与
  `running: runningRolesIn(ctx, ctx.state?.stage)`（`runningRolesIn`：这一趟派发记录里在这一段派出去、最后一回停下不是放行也不是冒泡的角色；读不出给空集）。
  H6 那一侧不看还在跑——中断的子代理永远没有停下行，按它拦会一直拒（`docs/51` §1.2 同一个理由），只在提示这一侧不催。

## 3. 判据与变异

- `tests/stage-trim-done.test.mjs`：S5 里叫到之后又裁掉 `at-frontend`、`at-backend` 交了——传了 `state` 判齐，不传、或者 `trimmed` 记的是别的段、或者别人也没交，照旧不齐；
  验证段（S6）叫到 `at-qa` 之后又裁掉的不免；S2 里裁掉 `at-product` 时 `01-prd.md`（S3 的前置）不免、裁掉 `at-ui` 时 `02-*` 免；自造的一段里不随参与者变的固定产物不免；
  【阶段】在项目经理写 `state.json` 时说 S5 齐了；`hooks/` 下每一处 `isStageDone` 调用都传 `state`。复核之后：还旧的、还在跑的不免（纯函数与【阶段】各一格）；旧 run
  没有 `stage_roles` 照样免；调用点判据核值（`state: ctx.state`、`artifactStale: fresh.isStale`、`running: runningRolesIn(…)`），认任何写法的调用、跳过定义与注释，
  列举调用所在的文件（只在 `hooks/gate.mjs`）。
- 变异（备份在仓库外，每一刀改完逐字节还原）：不看 `state`、不问 `mayWaive`（补了 S2 那一格才红：S6 的测试报告是固定产物，挡它的是「固定产物不免」）、固定产物也免（插件自带的
  链上碰不到，补了自造的一段才红）、不看裁在哪一段、账本那一处不传——每一刀都有判据红。复核之后又加了：不看还旧、不看还在跑、`runningRolesIn` 永远空、交付物核验那处
  传 `state: null`（起初的判据只认键，打不红）、进度那处少传 `running`——每一刀都有判据红。

## 4. 仍然开着的边界

- **判齐不等于推进放行**：推进那一次还核别的（返工预算、契约、测试报告首行……）；【阶段】说齐了只说明产物齐了。与原来一样。
- **只认 `trimmed` 记的那一段**：一个角色在 `trimmed` 里只记一段（`/agent-team:at` 第 3 节写着），记了别的段的不算这一段裁掉（与推进同一档）。
- **中断的子代理永远算还在跑**：它没有停下行，那几份一直不免，【阶段】对那一段不说齐了（推进照样放行，H6 不看还在跑）。
- **裁掉之后又派回来、还在跑时 H6 照样放行推进**（`trimmed` 不分轮次，`docs/38` §5 那一条）：这一轮只让提示不催，正文叫项目经理派它那一次就从 `trimmed` 拿掉。
- **改动前就有的几格对不上**：S5 的 `stage_roles` 记成 `[]`、S6 整段裁掉——推进放行而【阶段】不发；派发记录里有、`stage_roles` 没记、也没裁——【阶段】说齐而推进被拒。
- **协调者进度不认 `trimmed`**：已经裁掉的那个人，进度里仍列成「还没有」、尾句仍叫项目经理写 `trimmed`。
- **非项目经理的写者收到的那句「这一段的产物都在磁盘上了」**：免掉的那一份其实不在磁盘上。很轻。

> 收口（2026-10-11，`docs/77`，v5.5.0）：「改动前就有的几格对不上」里派发记录里有、`stage_roles` 没记的那一格关上了——`isStageDone` 在这一段记了账时并上派发记录，
> 与推进同一个「叫到」；`stage_roles` 记成 `[]`、S6 整段裁掉那两格没动。「协调者进度不认 `trimmed`」关上了：裁掉、已经停下的人那几份写成免了。「非项目经理的写者
> 收到的那句」改成「这一段要交的产物都在磁盘上了」。

## 5. 没量到的

- 真实会话里项目经理叫到一个执行角色之后又裁掉它、【阶段】说齐了之后推进。

## 6. 归属

## 8. 复核与修订

第一版推上分支之后起了一个对抗复核的子代理：主情形与几种边界（旧 run、只在派发记录里有又裁掉、叫到的全裁掉、裁掉的那份是空文件）子进程里按真实顺序走过，【阶段】与 H6 一致；
收口不受影响（最后一段是固定产物的验证段）。没有高的，三个中等、几处小问题：

- **中 1：裁掉之后又派回来时，门禁改成催推进了**（退步）——返工轮回到 S5、架构师重派了 `at-frontend`、它还在跑，交付物核验改报「停在旧阶段……当前阶段的产物已经全部齐备……
  推进」，【阶段】说齐了。→ 还在跑的不免（只在提示这一侧）；正文补「又叫回来的从 `trimmed` 拿掉」；H6 那一侧的洞登在 §4。
