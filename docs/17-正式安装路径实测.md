# M2d · 正式安装路径实测 —— `docs/15` §8.1 那条「环境不允许」了掉了

## 0. 一句话结论

**`claude plugin install --scope local` 装上的 agent-team，与 `--plugin-dir` 加载的那一份，
在本轮量到的七条上全部同形**：主会话同样被钉成 `at-pm`、命令与角色同样解析得到、
九个可派发角色的工具面**逐字一致**（`at-pm` 自己只有模型自述这一层，结果同样相同）、
六道门禁同样触发、`uninstall` 之后新会话同样干净。
唯一不同的是**续会话失效的触发条件**：`--plugin-dir` 下是「忘了带那个参数」，
正式安装下是「换了工作目录」——**后果一模一样，而后者更难察觉，因为没有参数可忘**。

**`docs/15` §8.1 把这件事记成「环境不允许」，那条归因把范围划宽了。**
真正的情况是「当时没找到安全的做法」：`install` 与 `marketplace add` 都支持
`--scope local`，整件事可以完全关在一个探针目录里做，全程不碰 `enable` / `disable`、
不碰 user 作用域、不碰机器上已装的任何插件。处置见 §7。

### 安全边界的执行记录（逐条）

1. **全程 `--scope local`。** `marketplace add`、`install`、`uninstall`、`marketplace remove`
   四条命令全部显式带 `--scope local`，一次都没用过 `user` / `project`。
2. **全程未使用 `claude plugin enable` / `disable`**（本项目纪律，`docs/04` §9 ③）。
3. **未碰机器上已装的任何插件。** 收尾逐行比对见 §6。
4. **探针目录全部在会话 scratchpad 的 `m2d-probe/` 下**，不在本仓库、不在 `/tmp`。
   本仓库文件一个都没动（除本文件与 §7 列出的那几处）。

### ⚠️ `agent-team@skills-dir` 是一个指向**本工作树**的符号链接——记录级

本轮开工前就知道这台机器上有一个 user 作用域、`✘ disabled` 的 `agent-team@skills-dir`，
纪律是「绝不碰它」。**收尾复核时才量清楚它到底是什么**：

    $ ls -la ~/.claude/skills/
    lrwxrwxrwx 1 82370 197609 33 Sep 16 00:39 agent-team -> /c/Users/82370/Desktop/Agent-Team

    $ readlink -f ~/.claude/skills/agent-team
    /c/Users/82370/Desktop/Agent-Team

**它不是一份副本，是一条软链，直接指着这个仓库的工作树。**
`claude plugin list` 给它报的 `Version: 0.1.0` 就是从链接那头读出来的
——**也就是 M2c 刚把 `0.0.1` 改成 `0.1.0` 的那个值**，不是某个历史快照。

**由此成立的一条**：一旦有人 `enable` 它，加载的是**当前工作树，包括未提交的改动**。
今天它是 `disabled`，所以无害。但这解释了两件此前只当成约定来守的事：

1. **为什么两份 README 里当年那条 `agent-team@skills-dir` 收场命令写得出来**
   ——开发期根本不需要装，软链一挂就等于装上了；
2. **为什么「绝不碰它」这条纪律比它看起来更要紧**——碰的不是一个装好的插件，
   是**这个仓库本身**。`enable` 它等于把一个还在改的工作树按 user 作用域挂到
   **这台机器上此后开的每一个新会话**上（两份 README 的「已知边界」写的正是这个后果）。

**它与 §3.1.2 那条命名撞车是同一件事的两头**：装上之后平台打的那句
`Give the plugin at ~\.claude\skills\agent-team a different "name"`，
指的就是这条软链的那一头——而「给它改个名字」意味着去改**本仓库的 `plugin.json`**。
本轮当然没有那么做。

## 3. 逐条

### 3.1 第 1 条：装得上——**记录级**

两条命令都在探针工程目录下执行，都带 `--scope local`：

    $ claude plugin marketplace add "<...>/m2d-probe-plugin" --scope local
    ✔ Successfully added marketplace: agent-team-marketplace (declared in local settings)

    $ claude plugin install agent-team@agent-team-marketplace --scope local
    ✔ Successfully installed plugin: agent-team@agent-team-marketplace (scope: local)

探针工程下 `claude plugin list`：

      ❯ agent-team@agent-team-marketplace
        Version: 0.1.0
        Scope: local
        Status: ✔ enabled

`claude plugin details agent-team@agent-team-marketplace` 把整份组件清单都解出来了：

    Skills (7)  at, at-api-contract, at-contract-format, at-handoff-package, at-init, at-resume, at-status
    Agents (11)  at-acceptance, at-android, at-architect, at-backend, at-frontend, at-ios, at-outsider, at-pm, at-product, at-qa, at-ui
    Hooks (3)  PreToolUse, SubagentStop, PostToolUse  (harness-only — no model context cost)
    MCP servers (0)

那 7 个 "Skills" = `commands/` 下的四条命令 + `skills/` 下的三份，与 `docs/11` §5.2
记的「skill 也被平台曝露成同名 slash command」是同一件事的另一面：**平台在这份清单里
不区分命令与 skill**。

#### 3.1.1 `--scope local` 到底关住了什么——**它只关住一半**

**关住的**：`enabledPlugins` 与 `extraKnownMarketplaces` 两个键都只写进探针工程的
`.claude/settings.local.json`。`~/.claude/settings.json` 全程**逐字节未变**
（安装后与基线 `diff` 零差异）。

**没关住的**（三处，都在 user 作用域的路径下）：

| 落点 | 内容 | 收尾是否自动清掉 |
|---|---|---|
| `~/.claude/plugins/known_marketplaces.json` | 多出 `agent-team-marketplace` 一条 | **会**，`marketplace remove --scope local` 一起清掉了 |
| `~/.claude/plugins/installed_plugins.json` | 多出一条带 `"scope":"local"` 与 `"projectPath"` 的记录 | **会**，`uninstall --scope local` 之后与基线零 diff |
| `~/.claude/plugins/cache/agent-team-marketplace/agent-team/0.1.0/` | 插件的一份完整副本 | **不会**，`uninstall` 之后仍在盘上，本轮手工删的（§6） |

**由此带来的一条可观察后果**：`claude plugin list` 的**清单是全机器的，状态才是按目录的**。
在本仓库目录下跑同一条命令，看到的是

      ❯ agent-team@agent-team-marketplace
        Scope: local
        Status: ✘ disabled

——**列出来了，但没启用**。所以「`--scope local` 之后别的目录完全看不见它」是假的；
真正成立的是「**别的目录不会加载它**」。这两句话的差别在排查时很贵。

#### 3.1.2 命名撞车真的发生了，而且 `uninstall` 的回执不说它卸了哪一个

这台机器上本来就有一个 user 作用域、`✘ disabled` 的 `agent-team@skills-dir`。
装上之后，**在探针目录下**它的那一行变成：

    ❯ agent-team@skills-dir: ✘ Not loaded — the name "agent-team" is already taken by an
      installed plugin (agent-team@agent-team-marketplace), which takes precedence. Give the
      plugin at ~\.claude\skills\agent-team a different "name" (in plugin.json or SKILL.md
      frontmatter) to load this copy.

**这只是显示层的后果，不是状态改变**：同一时刻在本仓库目录下跑 `plugin list`，
那一行仍然是 `Scope: user / Status: ✘ disabled`，`~/.claude/settings.json` 里
`"agent-team@skills-dir": false` 一个字没动。卸载之后它在探针目录下也立刻变回
`user / ✘ disabled`。

⚠️ **但卸载的回执值得记一笔**：

    $ claude plugin uninstall agent-team@agent-team-marketplace --scope local
    ✔ Successfully uninstalled plugin: agent-team (scope: local)

**命令里给的是全限定名，回执里回的是裸名 `agent-team`。** 回执本身**不足以确认卸掉的是
哪一个**——在这台机器上有两个都叫 `agent-team` 的插件，而回执对它们不作区分。
本轮是靠卸载前后各一次 `plugin list` 的逐行比对确认的，不是靠这句回执。
**凡是机器上存在同名插件的场合，这句回执不能当证据用。**

### 3.2 第 2 条：主会话被钉成 `at-pm`——**记录级**

正式安装臂的转录里有 `type: "agent-setting"` 的记录，值是

    "agentSetting":"agent-team:at-pm"

`--plugin-dir` 对照臂同一位置同一值。CLI 自己的会话抬头也印着 `@agent-team:at-pm`。

⚠️ **一处与 `docs/15` §3.0 的措辞出入**：§3.0 写的是「会话的转录里**每一条**都带
`"agentSetting":"agent-team:at-pm"`」。在 2.1.278 上不是这样——`agentSetting`
只出现在专门的 `type: "agent-setting"` 记录上，正式安装臂 23 行的转录里只有 2 条带它。
**结论（被钉成 at-pm）不变，判据的形状变了。** 更要紧的是这条判据在续会话下会给出
假阳性，见 §4.2。

### 3.3 第 3 条：命令与角色都解析得到——**记录级**

**先说一条方法论上的坑，它差点让这一条被误判。**

主探针会话里，`at-pm` 面对「执行 `/agent-team:at-status`」的要求时**没有执行它**，
而是老实说了一句（对照臂原话）：

    我没有工具能真正"执行" /agent-team:at-status，无法产生它的真实回答，也不会伪造一个。

原因是 `at-pm` 的 `tools:` 里没有 `SlashCommand`——斜杠命令是**用户输入层**展开的，
不是模型能调用的函数。正式安装臂的 `at-pm` 更进一步：它用 `Glob` 在磁盘上**找到了**
`commands/at-status.md` 并照着正文手工执行了一遍。**那个回答看起来完全像命令解析成功了，
但它证明的只是「这个角色会读文件」。**

所以这一条**另起了一个会话**，把 `/agent-team:at-status` 直接作为会话的**第一条用户消息**。
正式安装臂的转录里拿到的是命令展开本身：

    <command-message>agent-team:at-status</command-message>
    <command-name>/agent-team:at-status</command-name>

紧跟着是 `commands/at-status.md` 的正文，而且 `${CLAUDE_PLUGIN_ROOT}` **已经被展开**：

    插件的 `C:/Users/.../m2d-probe/m2d-probe-plugin/stages.json`（阶段链）

对照臂同一位置展开成**同一个路径**。`at-pm` 随后按命令正文第 1 节的规则正确地报了
「当前没有进行中的 run。」

**角色解析**：主探针里 `Agent(subagent_type: "agent-team:at-product")` 真实派发成功
（`Async agent launched successfully`），子代理完成并回报。

#### 3.3.1 `CLAUDE_PLUGIN_ROOT` 指的是市场源目录，不是 `~/.claude/plugins/cache` 里那份副本

上面那个展开路径是 `m2d-probe-plugin`，也就是 `marketplace add` 时给的那个源目录，
**不是** §3.1.1 表里那份 cache 副本。H5b 顶回子代理时打出的 hook 命令行是第二份独立证据：

    [node C:\Users\...\m2d-probe\m2d-probe-plugin/hooks/gate.mjs stop-gate]

**推论（不是实测）**：`source: "directory"` 这种市场装出来的插件是**活连**到源目录的，
删掉或改动源目录会直接作用到"已安装"的那一份。本轮没有去改源目录验证这一点，
所以它只是推论；但两处独立的路径原文都指向源目录，这一点是实测的。

### 3.4 第 4 条：工具面两臂逐字一致——**记录级**

这一条原本只打算收模型自述，实测时发现**平台自己把每个角色的 `tools:` 注入进了会话**
（"Available agent types" 那份清单），于是升级成记录级。两臂各自抠出来的九行：

    agent-team:at-acceptance   Read, Glob, Write
    agent-team:at-android      Bash, Read, Glob, Write, Edit
    agent-team:at-architect    Agent(agent-team:at-backend, agent-team:at-frontend, agent-team:at-ui, agent-team:at-ios, agent-team:at-android), Read, Glob, Write
    agent-team:at-backend      Bash, Read, Glob, Write, Edit
    agent-team:at-frontend     Bash, Read, Glob, Write, Edit
    agent-team:at-ios          Bash, Read, Glob, Write, Edit
    agent-team:at-product      Agent(agent-team:at-ui), Read, Glob, Write
    agent-team:at-qa           Bash, Read, Glob, Write
    agent-team:at-ui           Bash, Read, Glob, Write, Edit

**三方比对的结果**：正式安装臂 == `--plugin-dir` 对照臂（`diff` 零差异），
且两者都 == `agents/*.md` 各自的 `tools:` 声明（逐份相同，不一致条数 0）。

**清单里没有的两个**：`at-pm`（主线程角色，不在可被派发之列）与 `at-outsider`
（测试替身，两臂都不在清单里——与 `docs/15` §8.5 的预期一致）。

`at-pm` 自己的工具面只有模型自述这一层，两臂各报一次，**结果相同**：

    Agent / AskUserQuestion / Bash / Edit / Glob / Read / Write

与 `agents/at-pm.md` 的 `tools:` 声明相同。

**一条阴性样本**：`at-product` 两臂都报「我的工具表里没有 Bash」，正式安装臂那一份
还补了理由——「系统提示里明确列出了 `agent-team:at-product` 可用的工具是
`Agent(agent-team:at-ui), Read, Glob, Write`，不包含 Bash」。同一个子代理**成功**用
`Read` 读到了 `README.md` 第一行（记录级 `tool_use` + `tool_result`），
所以这不是「它什么都干不了」，是「它只有声明里那几样」。

### 3.5 第 5 条：六道门禁全部触发——**记录级**

平台把每一次 hook 执行都写成一条带 `attachment.hookName` 的转录记录，本节的计数取自它。

| 门禁 | 事件 | 形态 | 观测 |
|---|---|---|---|
| H1 派发白名单 | `PreToolUse:Agent` | fail-closed 拒绝 | 1 次，子代理**根本没启动** |
| H2 就绪门禁 | `PreToolUse:Agent` | fail-open 告警 | 2 次，`exitCode: 0`，`command: 校验前置产物…` |
| H3 写路径隔离 | `PreToolUse:Write` | fail-closed 拒绝 | 1 次 |
| H4 契约保护 | `PreToolUse:Write` | fail-closed 拒绝 | 1 次 |
| H5a 交付物校验 | `PostToolUse:Agent` | `additionalContext` | 2 次 `hook_success` + 1 次 `hook_additional_context` |
| H5b 停止门禁 | `SubagentStop` | 以 user 消息顶回子代理 | 1 次 |
| 账本回传 | `PostToolUse:Write` | `additionalContext` | 1 次 `hook_success`，`command: 回传契约哈希与触达表…` |

拒绝原文（正式安装臂，**与 `docs/04` §9 记的 `--plugin-dir` 下那几条逐字相同**）：

**H1**

    PreToolUse:Agent hook error: 角色 at-pm 不得派发给 at-backend。它可以派发的角色是：
    at-product、at-architect、at-qa、at-acceptance。如果这项工作确实需要 at-backend，
    把它冒泡给上级，不要绕过花名册。

**H3**

    PreToolUse:Write hook error: at-product 不得写 C:\...\m2d-probe-app\src\web\m2d-probe.ts
    ——这条路径归 at-frontend。跨角色的改动要经上级协调，不要直接动别人的地盘。

**H4**

    PreToolUse:Write hook error: 不得写 00-contract.md。契约是这趟 run 唯一的需求基线，
    只能由用户改、经 PM（项目经理）在主会话里转写——任何 subagent 都不能碰它。……

**H5b**

    Stop hook feedback:
    [node C:\...\m2d-probe-plugin/hooks/gate.mjs stop-gate]: at-product 在 S2 应当产出

⚠️ **探针会话并没有与机器上别的插件隔离。** 两臂的转录里都有一条

`superpowers@claude-plugins-official`，**不是 agent-team 的**。

两臂同时受它影响，所以它不干扰 A/B 比较，但写进报告时不能把它算成 agent-team 的第七道 hook。

### 3.6 第 6 条：`claude --resume` —— **两边确实不一样，这是本轮唯一的新结论**

三个臂，同一份续会话探针指令：

| 臂 | 起会话的方式 | 续会话的 cwd | 结果 |
|---|---|---|---|
| **6a** | 正式安装 | **同一个**（`m2d-probe-app`） | **全保住** |
| **6b** | 正式安装 | **换到** `m2d-probe-neutral` | **全掉光** |
| **6c** | `--plugin-dir` | 原 cwd，但**故意不带 `--plugin-dir`** | **全掉光** |

**6a**：`agentSetting` 仍是 `agent-team:at-pm`，工具面仍是那七个
（`Agent / AskUserQuestion / Bash / Edit / Glob / Read / Write`），四条 `/agent-team:` 命令仍在，
转录里**没有**任何降级告警。**续会话什么参数都不用带。**

**6b 与 6c 拿到的是同一句告警**（`type: "system"`、`subtype: "informational"`、
`level: "warning"`，2.1.278 原文）：

    This session was running agent 'agent-team:at-pm', which is no longer available
    (no agent by that name in <cwd>). Continuing with the default tools and system prompt
    — the agent's tool restrictions no longer apply. To restore it, re-create the agent,
    or resume with an explicit --agent <name>.

两臂的 `<cwd>` 各自填的是自己那一轮的工作目录。随后两臂都：
掉到默认工具面（多出 `ToolSearch`、`ScheduleWakeup` 等）、`/agent-team:*` 命令全部消失、
`agent-team:at-*` 九个角色被平台明确标成 "no longer available"。

**三条要记的**：

1. **触发条件变了，后果没变。** `--plugin-dir` 下触发它的是「忘了带参数」；
   正式安装下**没有参数可忘**，触发它的是「换了工作目录」。`--scope local` 把插件
   绑在 `<工程>/.claude/settings.local.json` 上，而 `--resume` **不跟着原会话的 cwd 走**。
   告警里那半句 `no agent by that name in <cwd>` 就是机制本身：解析是按 **cwd** 做的。
2. **这条比 `--plugin-dir` 那条更难察觉。** 忘带参数是一个看得见的动作差异；
   「在另一个目录里续会话」看起来完全正常，而且 `--resume` 本来就常被用来「换个地方接着干」。
3. **2.1.278 的原文比 `docs/11` §5.5 记的长。** §5.5 与两份 README 引的那一句，
   逐字出现在本轮这一整句的**中段**；它前面还有一句
   `This session was running agent '...', which is no longer available (no agent by that
   name in <cwd>).`，后面还有一句 `To restore it, re-create the agent, or resume with an
   explicit --agent <name>.`——两头这两句都是 §5.5 当时没有记的。
   **前面那一句尤其值钱**：它把机制（按 cwd 解析）写在了脸上。
   两份 README 现有的逐字引用因此仍然成立，不需要改（`tests/readme-sync.test.mjs`
   里比对那句原话的两条判据全绿）。

**6c 顺带把 `docs/15` §8.2 结清了**：§8.2 把「`claude --resume` 不带 `--plugin-dir`
会掉工具面」记成「我没做（照纪律规避了）」。本轮在一个一次性探针工程里**故意**做了一次，
在 CLI 2.1.278 上复现了 `docs/11` §5.5 的结论。

### 3.7 第 7 条：`uninstall` 之后的新会话完全干净——**记录级**

`uninstall --scope local` 之后，在**同一个探针工程目录**下起一个全新会话：

- **`agent-setting` 记录零条**（装着的时候是 2 条）——`settings.json` 的 `agent` 键不再生效；
- 平台的 agent 类型清单里 `agent-team:at-*` **一个都没有**，只剩宿主内置的那几个；
- 会话自述「我是默认会话，没有插件角色」、`/agent-team:` 命令「看不到」；
- 工具面回到默认（含 `Skill`——而 `Skill` 正是规格 §6.1 禁止任何角色持有的那一个，
  它的出现本身就是"插件不在了"的旁证）。

**这与 `docs/04` §9 ③ 记的 `disable` 不是一回事，两者并不矛盾**：§9 ③ 说的是
`disable` 不恢复**正在运行的**会话的工具面（会话的工具面在其生命周期内固定）。
本条说的是 `uninstall` 之后**新起的**会话——那是一个全新的生命周期，所以它干净。
**本轮没有验**「`uninstall` 能不能恢复一个正在运行的会话」，按 §5 记成「我没做」。

## 4. 本轮新出的两条

### 4.1 `--scope local` 是「第三条路」，而两份 README 此前只描述了两条

两份 README 的「已知边界」写的是一个二选一：`--plugin-dir`（波及面限定在你自己带那个
参数起的会话）对比"把插件按机器全局启用"（作用到这台机器上此后开的每一个新会话）。

**实测下来还有第三条**：`install --scope local`，波及面限定在**一个工程目录**。
它比 `--plugin-dir` 更省事（续会话不用带参数、命令能正常解析），又不像 user 作用域
那样作用到全机器。代价是 §3.1.1 那三处 user 作用域落点，以及 §3.6 那条更隐蔽的续会话陷阱。

这一条已经写进两份 README（§7）。

### 4.2 ⭐ `"agentSetting":"agent-team:at-pm"` **在会话已经掉了工具面之后仍然继续写**

`docs/15` §3.0 用「转录里有 `"agentSetting":"agent-team:at-pm"`」当作
「主会话确实被钉成了 `at-pm`」的记录级判据。本轮这条判据被**证伪为充分条件**。

在 6b 那份转录（`de957493`）里：

- 第 46 行是那条降级告警（`...the agent's tool restrictions no longer apply.`）；
- 而 `type: "agent-setting"`、值为 `"agent-team:at-pm"` 的记录出现在**第 4、57、68 行**
  ——**其中两条在告警之后**；
- 三条的 `sessionId` 都是**这一轮新会话自己的 id**，不是被续的那个原会话的。

6c（`98b73055`）是同一个形状：告警在第 47 行，`agent-setting` 记录在第 58、69 行。

**也就是说**：一个已经掉回默认工具面、`/agent-team:*` 全部解析不到、九个角色都被标成
"no longer available" 的会话，它的转录**仍然一条接一条地写着**
`"agentSetting":"agent-team:at-pm"`。

**为什么这值得单独记一条**：这正是 `docs/11` §5.13 那个形状的又一个实物——
**判据在它所断言的性质已经为假时仍然是绿的**。而这一次它出现在**实测方法**这一层，
不是在测试套件里：§3.0 那条判据今天仍然对"新起的会话"成立，但**把它用在续会话上会给出
假阳性**，而"续会话"恰恰是这条判据最需要被用到的场合（因为那正是工具面最可能已经掉了的场合）。

**可照做的判据**：判「这个会话此刻是不是还被钉着」不能只看 `agent-setting`，
要同时看**有没有那条降级告警**（`type: "system"` / `level: "warning"`）。
本轮 §3.6 三个臂用的就是这个口径——两条一起看，6a 与 6b/6c 才分得开。

**裁定：这一条不配机械判据，它作为一个有名字的形状记进 `docs/16` §3.9**
（连同「为什么不配」的理由：这条判据活在**实测方法**那一层，不在代码里，
硬造一条只会造出一个不守任何东西的绿测试）。

**还有一层**：这条告警**模型自己看不到**。6c 的会话被直接问「CLI 有没有提示过
『工具限制不再适用』之类的话」，它逐字核对后回答「没有」——同时它又从角色清单的变化
推断出自己大概已经不是 `at-pm` 了。**告警只在转录里，不在模型的上下文里。**
所以这一条只能靠记录级证据判，问会话本身是问不出来的。
**这一层单独成一条形状，记在 `docs/16` §3.10**：「问 agent」与「读转录」
不是可替换的两种手段——而且那个「没有」是诚实的，它并没有说谎，是它拿不到那个事实。

### 5.3 「`uninstall` 对正在运行的会话有没有效」——**我没做**

§3.7 验的是 `uninstall` 之后**新起的**会话。`disable` 那一半（`docs/04` §9 ③）说的是
正在运行的会话，本轮没有去试 `uninstall` 在这个方向上的行为——试它要在一个活会话中途

### 5.4 「非 `directory` 源的市场（GitHub / npm）装出来是不是同一个样子」——**我没做**

本轮的市场源是 `source: "directory"`，§3.3.1 那条「`CLAUDE_PLUGIN_ROOT` 指向源目录」
很可能是这个源类型特有的。GitHub 源会先 clone 进 `~/.claude/plugins/marketplaces/`，
届时 `CLAUDE_PLUGIN_ROOT` 指哪里**没验过**。

### 5.5 「交互终端（真人手里那种）下的复核」——**需要人来操作**

与 `docs/15` §8.3 同。本轮全程 `--bg` 常驻后台会话。

### 5.6 「`--scope project` 会怎样」——**环境不允许（这一次是真的）**

`project` 作用域写的是 `<工程>/.claude/settings.json`，那是要提交进版本库的文件。
在探针工程里试它本身没有风险，但它**不能回答任何本轮的问题**（它与 `local` 的差别只在
写进哪个文件），而本轮的安全边界明写了「绝不 `project`」。**没试，也不打算试。**
