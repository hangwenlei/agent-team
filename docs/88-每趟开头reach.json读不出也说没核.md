# 每趟开头 reach.json 读不出也说没核

> 2026-10-11，分支 `r46-reach-unreadable-at-start`。第四十六轮（从开放边界索引挑）：`docs/79` §4「`reach.json` 在、却读不出来时不核」。只动门禁回传与判据。

## 0. 一句话结论

- 每趟开头写 `current-run` 时门禁核磁盘上的 `.agent-team/reach.json`（`docs/79`）。它在、却读不出来（被占用、它是个目录……）时原来一声不吭；现在【触达表】说
  它在、却读不出来、这一次没有核，照样给出按当前 `project.json` 与花名册算出来的那一份，叫项目经理原样重写（写不进去就告诉用户，不要自己删它或改名）。不是项目经理
  写指针的，照旧叫它冒泡。

## 1. 问题

- `docs/83` 把写 `reach.json` 那一刻「核不了也一声不吭」那一族关上了；每趟开头那一次核对还留着同一格：读不出就 `return null`。`/agent-team:at-status` 照它报
  各角色实际能写到哪里时也读不出，项目经理却什么都不知道（写指针那一步的正文本来就不提这次核对）。

## 2. 修法

- `hooks/gate.mjs` 的 `staleReachFor`：读 `reach.json` 抛的不是 ENOENT 时，记 `unreadable`，交给 `reachStaleNotice`。只读一次：短暂占用时多说一次，照着重写
  一份正确的也无害。
- `hooks/lib/ledger.mjs` 的 `reachStaleNotice` 加 `unreadable`：成因写「在、却读不出来（多半是被别的程序短暂占用，或者它不是一个文件），这一次没有核」，
  出路照旧给那份 JSON，补「写不进去就告诉用户，不要自己删它或改名」（它可能是个目录；复核之后补的后半，§8）。
- `tests/reach-stale.test.mjs`：原来钉着「读不出不核」的那一句删掉，新加一条——读不出时说这一次没有核、给出的 JSON 等于按当前配置算的、不是项目经理写的叫它冒泡；
  读得出的照旧对得上不吭声；纯函数里 `unreadable` 盖过原文、不在照旧说不在。复核之后（§8）：读的时候一直抛错（预加载，错误不带 code，与被占用、权限拒绝同一支，
  三个系统都跑）也说读不出、不说不在；「写不进去」那半句只在读不出时有。

## 3. 判据与变异

- 变异（备份在仓库外，改完逐字节还原，每刀跑全量），每一刀都红：读不出照旧不核、不在也当读不出、`reachStaleNotice` 不看 `unreadable`、去掉「写不进去就告诉用户」、
  成因去掉「这一次没有核」。复核之后：只认 EISDIR、排除被占用与权限拒绝、「写不进去」那半句每种都加、去掉「不要自己删它或改名」——每一刀都红。

## 4. 仍然开着的边界

- **只在写 `current-run` 时核、只报不拦、at-status 自己不核**：照旧（`docs/79` §4）。
- **读不出的成因不细分**：被占用与它是个目录说同一句；写不进去的由项目经理告诉用户，门禁不替它删。
- **坏链接说成「不在」**：指向不存在目标的链接（目录联接、POSIX 的软链接）读时报 ENOENT，照旧说「不在——原样重写」，写也写不进去，那一句没有「写不进去就告诉用户」
  （早就有的）；POSIX 上照着重写时写入会穿过链接、落到目标那里。
- **不是项目经理收到的那一段**：「原样重写……（写不进去就告诉用户）」与「原样冒泡、不要自己重写」同在一段——冒泡上去之后读它的是项目经理，前一句对它成立。

## 5. 没量到的

- 真实会话里每趟开头收到「在、却读不出来」之后，项目经理重写成功还是告诉用户。

## 6. 归属

- `hooks/gate.mjs`（`staleReachFor`）、`hooks/lib/ledger.mjs`（`reachStaleNotice`）；判据在 `tests/reach-stale.test.mjs`。

## 8. 复核与修订

第一版（60f7e66）推上分支之后起了一个对抗复核的子代理。下面这些核过了：`staleReachFor` 只在写 `current-run`、运行上下文读得出的那一支被调用；Windows 上独占锁住
文件（EBUSY）、目录与指向目录的联接（EISDIR）都走到新的那一句；前置（`project.json` 不在、有阻断、插件问题）之下照旧沉默合适——同一次回传里已经有【project.json】
或【插件】；新拼的只有常量，trusted-echo 照旧；与 at-init、at-pm、at-status 的说法不冲突。没有高、中级的问题，七个低：

- **低 1：两处注释还在说「读不出不核」**（`gate.mjs` 的 `staleReachFor` 头注释、判据里 docs/79 §8 那一条的注释），另有 `reachNoticeFor` 头注释的旧账。→ 改准。
- **低 2：判据只钉了目录（EISDIR）**——把读不出收窄成 EISDIR、排除被占用与权限拒绝全绿，那几种会被说成「不在」。→ 预加载让读 `reach.json` 一直抛错（不带 code）再核一遍。
- **低 3：「写不进去」那半句只在读不出时有，没有判据**。→ 纯函数里核别的几种都没有。
- **低 4：它是目录时，出路没说别自己删**——撞上 EISDIR 的模型可能自己去删。→ 补「不要自己删它或改名」。
- **低 5：坏链接被说成「不在」、写不进去**（早就有的）。→ 登在 §4。
- **低 6：§1 说项目经理「以为对上了」说过了一点**（写指针那一步的正文不提这次核对）；`docs/79` §2、§3 仍写「读不出不核、判据钉着」。→ §1 改准；`docs/79` §3 写了订正。
- **低 7：不是项目经理收到的那一段两句同在**——冒泡上去之后读它的是项目经理，前一句对它成立。→ 不改，登在 §4。
