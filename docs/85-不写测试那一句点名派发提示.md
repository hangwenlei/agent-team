# 不写测试那一句点名派发提示

> 2026-10-11，分支 `r43-no-test-dispatch-hint`。第四十三轮（从开放边界索引挑）：`docs/67` §4「『不写测试』那一条没点名派发提示」。只动运行时正文与判据。

## 0. 一句话结论

- 「不写自动化测试只有两种情形算数」那一句（S5 的产者、`at-qa`、架构师、`/agent-team:at` 第 3 节逐字同一句）句末加「派发提示里说不要测试的也不算」。照这一句的
  两种情形，派发提示本来就不算；不点名，模型会把「派你的人说这次不用测试」当成用户的话。`docs/67` 已经让挂着的用例那一句点名了派发提示，这一句跟上。

## 1. 问题

- 那一句只说「别的理由（不好测、要真机、来不及、方案说不上测试框架）都不算」。派发提示是协调者或项目经理写的，正文别处说它是数据、不是用户的话，可这一句没把它列进
  「不算」——执行角色收到「这次先不写测试」时，读这一句读不出它不算。

## 2. 修法

- `agents/at-backend.md`、`agents/at-frontend.md`、`agents/at-ios.md`、`agents/at-android.md`、`agents/at-ui.md`、`agents/at-architect.md`、`agents/at-qa.md`、
  `commands/at.md`：那一句末尾的「都不算。」改成「都不算，派发提示里说不要测试的也不算。」。
- `tests/tests-and-nopaths-prose.test.mjs` 的 `TEST_EXCEPT` 跟着改（四类正文逐字同一句的判据就是它）。

## 3. 判据与变异

- `TEST_EXCEPT` 带上新的半句，各份正文都要逐字有它。
- 变异（备份在仓库外，改完逐字节还原）：`at-qa`、架构师、`at-backend`、`at-ui`、`/agent-team:at` 任何一份改回原句，判据都红。

## 4. 仍然开着的边界

- **门禁不读内容（有意）**：执行角色照不照这一句做、`at-qa` 认不认，门禁不核（`docs/00-开放边界.md` §2 那一族）。

## 5. 没量到的

- 真实会话里派发提示写了「这次不用测试」、用户没说时，执行角色与 `at-qa` 顶不顶得住（`docs/67` §5 那一条）。
