## 1. 裁定

- **必修**：用户原话里带编号节标题时契约的节认错——第 1 节切成空串、第 4 节认成原话里的那一节，改需求与照现状交付的判据整条失效。用户贴结构化需求很常见，
  失效又是静默的。`docs/90` 修了；复核时还挑出它会让升级中途的 run 卡死，同一轮补了兼容（旧基线照旧口径算）。
- **升级中途单独定规矩**（不归「不处理」）：推 main 就是发布，用户在一趟进行中更新是正常路径。发布纪律加一条——新版不许让进行中的 run 新增失败，门禁专属
  文件的算法或格式变了的，新记的带版本标记、旧的照旧口径算，配一条上一版状态的夹具判据（HANDOFF）；README 写明更新最好放在两趟之间、被拦得没有出路就另起一趟。
  已经登记的旧 run 格子（没有 `stage_roles`、没有派发记录、停在旧终态的）照旧不追：它们是更早版本留下的，出路都是另起一趟。
- **不处理**，理由按类：
  - **有意的设计**：`Bash` 不经门禁（靠权限模式与正文红线）、门禁不读内容（只认在不在、空不空、首行）、只报不拦的提示、时序、`current-run` 的切换不拦、
    收口不拦还在跑的派发、共用工作树不强制串行。改了就是另一套设计，风险大于收益。
  - **极少碰到的环境**：超大产物（512MB 以上）、硬链接与 bind mount、网络共享与 8.3 短名、不区分大小写的 Linux 挂载、指向项目外的链接、项目放在名叫
    `.agent-team` 的目录里、UTF-16 写成的 `state.json`、同形字与私用区字符。
  - **防改正文的反向判据认字面**：拆成两句、换说法、改小节标题、包进注释的放宽认不出——防的是维护者手滑，不是用户的使用路径；已经钉住的承重句够用。
  - **措辞小瑕疵**：拒绝理由括号里多列了项目经理自己的段、提醒语里几个词没定义——不影响出路。
  - **下限之外、源码级推断、平台事实**：早于支持下限的 Claude Code 与 Node、平台自己的拦截与回传形状——门禁改不了。
- **要真实会话才量得到**：`docs/00-开放边界.md` 里 77 行「没量到的」，绝大多数是「项目经理、执行角色收到某条回传之后实际怎么做」。它们挑不出 bug，只能看
  真实行为；下面按覆盖面挑场景，一趟能顺带量很多条。能用后台会话驱动的由维护者自己跑，只有用户的界面上才有的才交给用户。

### 2.2 交给用户（只有用户的界面上才有）

> **跑了（2026-10-12，`docs/93`）**：U1 过了（粘贴的整段进了命令参数，门禁照原话记、没拦过）；U2 是在桌面端、auto 模式下跑的，没量到交互终端的默认权限模式，
> 不再交给用户（理由在 `docs/93` §3）。

- **U1 桌面端粘贴长需求**（为什么要人：粘贴时输入框会不会把长文本收成「粘贴的文本」小块、命令参数里带的是原文还是占位，只在桌面端的输入框里发生）：
  - 新建空目录 `at-trial-u1`。先在终端里进到这个目录、装插件（6.7.0 或更新）——要在这个目录里跑，插件是装在这个项目上的：

    ```
    claude plugin marketplace add hangwenlei/agent-team --scope local
    claude plugin install agent-team@agent-team-marketplace --scope local
    ```

  - 装好之后，桌面端新开一个 Code 会话指向这个目录（装之前就开着的会话里没有插件），模型与权限模式照平时用的。先 `/agent-team:at-init`，再输入
    `/agent-team:at `、然后**粘贴**下面这段（不要手打），照常回答问题，让它走到收口：

    ```
    ## 1. 背景
    我想要一个命令行记账小工具，用 Node.js 写，不引入第三方依赖。平时在终端里随手记一笔，月底看总数。

    ## 2. 功能
    - add <金额> <备注>：记一笔支出，金额可以带两位小数
    - list：列出全部记录，每行是序号、日期、金额、备注
    - total：输出总金额，保留两位小数
    - delete <序号>：删掉一笔，序号不存在时报错
    - 数据存在当前目录的 ledger.json，文件不在时自动建

    ## 3. 不做的
    - 不做图形界面，不做多用户，不做云同步
    - 不做分类与预算

    ## 4. 验收标准
    - 新记的一笔 list 能看到，total 跟着变
    - 金额不是数字时报错，退出码不是 0
    - delete 之后 list 里没有那一笔
    - ledger.json 被删掉之后再 add 能自动重建
    - 有自动化测试，node --test 能跑通
    ```

  - 发回来：项目目录的路径；粘贴之后输入框里有没有出现「粘贴的文本」这样的小块；有没有在推进出 S1 时被【契约】拦住；用的什么模型。其余（`.agent-team/runs/`
    与会话转录）在这台机器上，由维护者读。
- **U2 交互终端的默认权限模式**（为什么要人：权限弹窗要有人看、要有人点「拒绝」；审查第 44 条）：
  - 新建空目录 `at-trial-u2`，在终端里进这个目录、装插件（同上），再在同一个目录里用 `claude` 交互启动（用默认权限模式，每次写文件、跑命令都会问你，不要用跳过
    权限的模式）。
  - 先 `/agent-team:at-init`，再 `/agent-team:at 写一个输出 hello 的 Node.js 脚本，带一个自动化测试。`；中途拒掉一次写文件的权限请求，之后照常同意。
  - 发回来：目录路径；后台角色的权限请求是怎么弹出来的（会不会被自动拒、要不要切到别的会话去点）；拒掉的那一次之后它怎么走。
