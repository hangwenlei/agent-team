# 遗留项裁定与实测清单

> 2026-10-12。`docs/00-开放边界.md` 记着 145 行、74 份记录的开放项，每一轮都在涨（10-06 是 55 行），「每轮从索引挑一条」的做法清不完它。这一份按专家判断
> 把它们分成三类：必修（做了，`docs/90`）、不处理、要真实会话才量得到（下面的实测清单）。之后不再一轮一轮从索引挑；跑完实测、照结果修补、回归。

## 1. 裁定

- **必修（只有一项）**：用户原话里带编号节标题时契约的节认错——第 1 节切成空串、第 4 节认成原话里的那一节，改需求与照现状交付的判据整条失效。用户贴
  结构化需求很常见，失效又是静默的。`docs/90` 修了。
- **不处理**，理由按类：
  - **有意的设计**：`Bash` 不经门禁（靠权限模式与正文红线）、门禁不读内容（只认在不在、空不空、首行）、只报不拦的提示、时序、`current-run` 的切换不拦、
    收口不拦还在跑的派发、共用工作树不强制串行。改了就是另一套设计，风险大于收益。
  - **极少碰到的环境**：超大产物（512MB 以上）、硬链接与 bind mount、网络共享与 8.3 短名、不区分大小写的 Linux 挂载、指向项目外的链接、项目放在名叫
    `.agent-team` 的目录里、UTF-16 写成的 `state.json`、同形字与私用区字符。
  - **旧 run 与升级中途**：没有 `stage_roles`、没有派发记录、停在旧终态、旧格式的测试报告——出路都是另起一趟。
  - **防改正文的反向判据认字面**：拆成两句、换说法、改小节标题、包进注释的放宽认不出——防的是维护者手滑，不是用户的使用路径；已经钉住的承重句够用。
  - **措辞小瑕疵**：拒绝理由括号里多列了项目经理自己的段、提醒语里几个词没定义——不影响出路。
  - **下限之外、源码级推断、平台事实**：早于支持下限的 Claude Code 与 Node、平台自己的拦截与回传形状——门禁改不了。
- **要真实会话才量得到**：`docs/00-开放边界.md` 里 77 行「没量到的」，绝大多数是「项目经理、执行角色收到某条回传之后实际怎么做」。它们挑不出 bug，只能看
  真实行为；下面五个场景按覆盖面挑，一趟能顺带量很多条。

## 2. 没量到的：实测清单

每个场景都在一个新建的空目录里跑（不要在本仓库里跑）。插件先装或更新到包含 `docs/90` 的版本（6.7.0 或更新）：

```
claude plugin marketplace add hangwenlei/agent-team --scope local
claude plugin install agent-team@agent-team-marketplace --scope local
```

已经装过的目录用 `claude plugin update agent-team@agent-team-marketplace --scope local`。跑完把**项目目录的路径**和大概经过（卡在哪、哪句话看着不对）发过来就行：
`.agent-team/runs/` 下的记录与会话转录在这台机器上，分析由维护者做，不用截图、不用整理日志。

### A. 完整一趟：带编号节标题的长需求，中途看一次 at-status（最重要）

- 目录：`at-trial-a`。桌面端的 Code 会话，权限模式照平时用的。
- 步骤：
  1. `/agent-team:at-init`，照它问的答。
  2. 输入 `/agent-team:at `，然后**粘贴**下面这段（用粘贴，不要手打；输入框把它收成一个「粘贴的文本」小块也照常发出，那正是要测的）。
  3. 一路照项目经理的问题答；看到它派执行角色写代码（S5）时，输入一次 `/agent-team:at-status`。
  4. 让它走到交付、收口。
- 粘贴的需求：

  ```
  ## 1. 背景
  我想要一个命令行记账小工具，用 Node.js 写，不引入第三方依赖。

  ## 2. 功能
  - add <金额> <备注>：记一笔支出
  - list：列出全部记录，带序号与日期
  - total：输出总金额
  - 数据存在当前目录的 ledger.json

  ## 3. 不做的
  - 不做图形界面，不做多用户

  ## 4. 验收标准
  - 新记的一笔 list 能看到
  - 金额不是数字时报错，退出码不是 0
  - 有自动化测试，node --test 能跑通
  ```

- 量的是：粘贴的长原话门禁记下的是原文还是占位（是占位的话，推进出 S1 会被【契约】拦住说第 1 节对不上——要知道是不是这样）；带编号节标题的原话在
  真实会话里从 S1 走到收口（`docs/90` 的回归）；at-status 的报法第一次在真实链上跑（交接看板第 5 项）；当前版本整条链、桌面端权限模式下有没有卡住、
  反复被拒的地方。

### B. 不要测试、中途改需求

- 目录：`at-trial-b`。
- 步骤：
  1. `/agent-team:at-init`。
  2. `/agent-team:at 做一个把 Markdown 文件的标题列成目录的命令行小工具，Node.js，不引入第三方依赖。这一趟不要写自动化测试。`
  3. 架构方案出来之后（项目经理说进到 S4 或开始派执行角色时），在对话里发：`再加一个功能：支持 --depth 参数，只列到第几级标题。`
  4. 让它走到收口。
- 量的是：用户说了不要测试时，执行角色不写、`at-qa` 不判「缺测试」、验收不退回 S5（`docs/85`、`docs/86`）；用户主动改需求之后项目经理写不写修订块
  （带「用户原话」一栏）、测试与验收是不是对着新契约重出（`docs/45`、`docs/61`）。

### C. 中断与续跑

- 在 A 或 B 跑到 S5、执行角色在后台跑的时候，直接停掉那个会话（关窗口或点停止），新开一个会话进同一个目录，输入 `/agent-team:at-resume`。
- 量的是：续跑认不认得出当前段、会不会重派已经交了的人、旧会话里没停下的派发怎么报（`docs/11` §5.37、`docs/43`、`docs/49`、`docs/56`）。

### D. 默认权限模式（审查第 44 条）

- 在终端（不是桌面端）进一个新目录 `at-trial-d`，用 `claude` 交互启动，**用默认权限模式**（每次写文件、跑命令都会问你），跑一个最小的需求：
  `/agent-team:at 写一个输出 hello 的 Node.js 脚本，带一个自动化测试。`
- 中途随便拒一次权限请求（例如拒掉一次写文件），看它怎么走。
- 量的是：后台角色的权限请求怎么弹、会不会被自动拒、拒一次之后整趟停在哪——决定 README 要不要写推荐的权限模式。

### E. 可选：git 仓库里用 `--bg` 起一趟（交接看板第 21 项）

- 新目录里 `git init`，用 `claude --bg` 在后台起一趟最小需求，看起不起得来。起不来就把报错发过来；跳过也行。
