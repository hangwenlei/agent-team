## 1. 门禁留痕怎么判读

开关是 `AGENT_TEAM_GATE_TRACE=1`（默认关），打开后每道门禁每次 `exit 0` 往 stderr 写一行
`agent-team gate-trace check=<检查项> main=<entered|not-entered> exit=0`。来历、机制与它能证明什么、不能证明什么在 `docs/21`。

**第一步：起会话时把开关打开。** 后台会话只能走 `--settings`（在 shell 里 export 传不到 hook）：

```sh
claude --bg --plugin-dir /path/to/agent-team \
  --settings '{"env":{"AGENT_TEAM_GATE_TRACE":"1"}}' "<提示词>"
```

不要把它写进项目的 `.claude/settings.local.json`：那是持久配置，那个项目此后每一个会话都开着。

**第二步：找到这一趟的全部转录。** 主转录是 `~/.claude/projects/<cwd 编码>/<session-id>.jsonl`；子代理的在
`~/.claude/projects/<cwd 编码>/<session-id>/subagents/agent-*.jsonl`。两处都要扫：`SubagentStop`（H5b）的记录只在子代理那份里，
子代理发起的 `Write` / `Agent`（H3、H4、H6、ledger、下一层的 H1、H2、H5a）也在子代理那份里。

**第三步：数。**

```sh
D=~/.claude/projects/<cwd 编码>; S=<session-id>
grep -rhoE 'agent-team gate-trace check=[a-z-]+ main=[a-z-]+' "$D/$S.jsonl" "$D/$S/" | sort | uniq -c
```

**第四步：判读。** 每道门禁对应一个 `check` 值、一句 statusMessage（记录里的 `command` 字段）。这张表逐行等于 `hooks/hooks.json`
里的（检查项, statusMessage），`tests/gate-trace.test.mjs` 钉着——加一道门禁或改一句 statusMessage，这里跟着改：

| 门禁 | `check=` | 记录的 `command` | 挂在 | 每发生一次这个事件，应当有 |
|---|---|---|---|---|
| H1 派发白名单 | `delegation` | `校验派发白名单…` | `PreToolUse:Agent` | 一行（被拒的那次除外，见下） |
| H2 就绪门禁 | `readiness` | `校验前置产物…` | `PreToolUse:Agent` | 一行（被拒的那次除外） |
| H3 写路径 | `writepath` | `校验写路径归属…` | `PreToolUse:Edit/Write/NotebookEdit` | 一行（被拒的那次除外） |
| H4 契约保护 | `contract` | `校验契约保护…` | 同上 | 一行（被拒的那次除外） |
| H6 返工预算 | `rework` | `校验返工预算…` | 同上 | 一行（被拒的那次除外） |
| H5a 交付物记录 | `deliverable` | `记录交付物校验…` | `PostToolUse:Agent` | 一行 |
| H5b 交付物拦截 | `stop-gate` | `校验交付物…` | `SubagentStop`（**子代理那份转录**） | 放行时一行；拦截（exit 2）时没有这一行，有平台写的 `Stop hook feedback` |
| 账本回传 | `ledger` | `回传契约哈希与触达表…` | `PostToolUse:Edit/Write/NotebookEdit` | 一行 |
| 返工批准（问答） | `approval-ask` | `记录返工批准…` | `PostToolUse:AskUserQuestion` | 一行 |
| 返工批准（对话） | `approval-prompt` | `核对返工批准…` | `UserPromptSubmit`（每条用户消息，含 task-notification） | 转录里没有（见下）；调试日志里一行 |
| 交付物核验（完成通知） | `completion` | `核对子代理交付…` | `UserPromptSubmit`（每条用户消息，含 task-notification） | 转录里没有（见下）；调试日志里一行 |
| 原话记录 | `user-words` | `记下需求原话…` | `UserPromptExpansion`（`/agent-team:at` 展开时） | 转录里没有（见下）；调试日志里一行 |

- **某个 `check` 一行都没有**：先看这一趟有没有发生过它挂的那个事件（没有 `Agent` 调用，H1、H2、H5a 就该是零）。事件发生过而这一行
  没有，那才是「没跑」。
- **`main=not-entered`**：进程起来了、`main()` 没进去——入口坏了，不是一次放行。
- **`UserPromptSubmit`、`UserPromptExpansion` 上的检查项在转录里一行都没有**：平台不把这两个事件上 hook 的输出记进转录（`-p` 与 `--bg`
  都是，`docs/50` §1）。要数它们，起会话时加 `--debug-file <路径>`，在调试日志里数（下面「转录数出来的是下限」那一条的做法）。
- **`PreToolUse` 被拒的那一次在转录里没有这一行**：拒绝本身就是记录——那次工具结果 `is_error: true`，正文就是那道门禁的拒绝理由原文。
  门禁那一侧其实写了这一行，是平台把拒绝那一次记成了工具结果、没有记成 hook 附件。留痕行上的 `exit=0` 分不出放行与 `PreToolUse` 的
  拒绝（两者都是退出码 0），别拿门禁的 stderr 直接当放行的证据。
- **转录数出来的是下限，不是全数**：CLI 自己起的内部分叉代理停下时也会触发 `SubagentStop`，H5b 照样跑、照样留痕，但那几次的记录不进
  任何一份转录。要全数，起会话时再加一个 `--debug-file <路径>`：留痕开着时，调试日志里 stdout 为空的那几次会有
  `Hook <事件> (<事件>) success:` 后面跟着这一行（stdout 非空的那几次，调试日志只打 stdout）。
- 要对到具体哪一次工具调用：用记录的 `toolUseID` 去对 `tool_use` 块的 `id`。
