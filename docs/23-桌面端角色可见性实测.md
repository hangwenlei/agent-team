# 桌面端角色可见性实测

**日期** 2026-09-25 ｜ **口径** 桌面应用里的真实会话；插件按用户真实的方式从 GitHub 以 `--scope local`
安装（`agent-team@agent-team-marketplace` 0.6.1）

## 0. 这一趟要回答什么

用户最初想要「一个角色一个会话」。追问下去，他要的是两件事：**能像会话那样单独看到每个角色在干什么**，
以及**同一阶段内多个角色并行干活**。本插件的底座是「一个会话 + 子代理」，不是多会话（为什么这么选，
见 `docs/01`、`docs/02` 与规格 §6.1）。所以问题变成：**在这个底座上，桌面应用给不给得出这两个效果？**

这是一个界面问题，只能在桌面应用里看。

## 1. 做法与它的边界

- 探针项目建在用户桌面上的一个临时文件夹，复用 `docs/20` 那一趟 S1–S4 的真实产物，把现场摆到
  S5 开头，省掉整链前半段。
- **会话由用户在桌面应用里新建，截图由用户提供。** 这不是为了省事：平台明确不允许 Claude 操作它
  自己所在的应用窗口，也不允许截这个窗口的图，这条限制不可授予；本会话里也没有能新建桌面会话的工具。
- 证据等级：界面长什么样 = 用户截图（**记录级**）；时间、模型、角色身份 = 会话转录里 CLI 写的记录
  （**记录级**）；项目经理对自己做了什么的叙述 = **模型自述**。

⚠️ **夹具有两处是控制方做坏的**，记在这里，因为项目经理把它们都抓了出来：

1. 原来那一趟的需求是在一个**现成的** notes-board 项目上改功能，架构师在 S3 读过它的四个源文件。
   搬现场时没把 `src/` 带过来，`04-dispatch.md` 里也还写着旧那一趟的 run id。
2. 给 S1–S5 编的时间戳比真实时间还晚了几分钟。

## 2. 项目经理的表现（顺带观察到的，记录级）

派人之前先去磁盘核实，发现契约前提（以一个现成的 notes-board 为前提）与磁盘对不上：`src/` 不存在，
构建命令当场报 `MODULE_NOT_FOUND`。**没有硬派，也没有猜**，而是按 `/agent-team:at` 第 4 节的升级规则
用 `AskUserQuestion` 问用户，给了三个具体选项、各自的后果和推荐项。在桌面应用里，它渲染成一张带选项的卡片。

用户选「照 03 描述从零建底座」之后，它先走契约修订（`escalations` 追加一条 `contract-hole`、契约追加
修订块、`contract_sha` 回写），然后才派发。收尾时它还自己标出了时间戳倒挂那一处。

## 3. 角色在界面上的样子（记录级，用户截图）

- **主对话里**：一次派发收成一行灰色小字「Ran an agent, finished 6 background tasks ›」。
  展开后是一行「S5：架构师并发分发实现 Sonnet 5 ›」和「6 background tasks completed」。
- **Background tasks 面板**（点那一行后在右侧打开）：每个角色单独一条，**包括架构师再派出去的下级**：

  | 条目 | 类型 | 状态 | 用时 | 用量 |
  |---|---|---|---|---|
  | S5：架构师并发分发实现 | Agent | Completed | 26m 27s | 130.6k tokens，21 次工具调用 |
  | 派发后端实现 notes-board | Agent | Completed | 15m 32s | 129.9k tokens，68 次工具调用 |
  | 派发前端实现 notes-board | Agent | Completed | 12m 37s | 101.2k tokens，53 次工具调用 |

  另外几条是项目经理自己在后台跑的命令（类型 Bash）。
- **View transcript**：点开就是那个角色的完整过程：交给它的任务原文、读了哪些文件、派了谁、做了哪些
  技术决定、改动清单、验证过程、最后交回的报告。**形态上就是一个会话的回放。**
- **侧边栏**：会话挂在探针项目自己的分组下，不在「Other」。

## 5. 模型（记录级）

## 6. 结论

用户要的两个效果，**现在的底座加上桌面应用已经给出**，不需要换架构：

- **单独看每个角色**：Background tasks 面板一个角色一条，View transcript 看全过程。
- **同一阶段内并行**：实测后端与前端同时跑了十二分半。

与「一个角色一个会话」剩下的差别：角色是**这一个会话的后台任务**，能看，不能直接对话（只有项目经理
能问用户）。用户明确不需要「直接对话」这一项。

缺的只是**告诉用户去哪看**：两份 README 已补「怎么看每个角色」一节。

## 7. 没量到的，逐条是哪一种

- **在桌面应用里新建会话与截图** —— **需要人来操作**：平台不允许 Claude 操作自己的应用窗口，且不可授予。
- **`/agent-team:at-resume` 在 S5 开头的行为** —— **我没做**：它的文字对「按 `roster` 展开出空集」
  没有明说，可能被读成「产物齐了」而跳过 S5（`docs/11` §5.37）。这一趟为了不让它搅了界面实测，
  改用一句明确的话派发，**绕开了它**。
  **收口（2026-09-25，同日）**：量掉了——改之前三个样本都派了架构师，没有一个跳过 S5；第 2 节补上了那一条、
  配了判据，改之后又量了三个，行为不变，依据变成了那一条。见 `docs/11` §5.37 的收口。
- **S6–S8 在桌面端的显示** —— **我没做**，也不需要：S5 已经展示了顺序派发、嵌套派发与并行三种形态。
- **更深一层的嵌套（执行角色再派下级）的显示** —— **结构上不可能**在本插件里出现：执行角色在花名册里
  的 `can_delegate_to` 是空的，派发白名单拦着。
