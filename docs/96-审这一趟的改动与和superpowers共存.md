# 审这一趟的改动与和 superpowers 共存

> 2026-10-16，分支 `claude/youthful-proskuriakova-d8a8e2`。本轮对照 superpowers 7.0.0 做了一轮源码分析，77 条候选经三个视角（价值、成本、风险）对抗核查；
> 三个视角一致确认的真缺口只有一条：全队没人审代码写得好不好。本轮给 `at-qa` 加「审这一趟的改动（只读）」一节，并在 README 写清与 superpowers 怎么配合。

## 1. 起因

### 1.1 运行时不直接接 superpowers

- 不授 `Skill`（长期决策：任何角色都不授）；`skills:` 不写 `superpowers:*`；`plugin.json` 不声明依赖。
- 平台其实支持跨插件按全名引用 skill，也支持 `dependencies`。不做的理由：
  - 对方没装时静默跳过——角色以为自己有那份方法，其实没有，谁也看不出来；
  - 上游漂移不跟着挪版本：`claude plugin update` 比的是我们的 `version`，superpowers 改了正文，我们这边的行为跟着变、版本号不动；
  - 跨市场的依赖要根市场放行，用户装起来多一道坎；
  - 原文里「先问用户」「用 Skill 工具」「先头脑风暴」这类指令会一起进来，与角色正文、门禁的流程打架（子代理没有 `AskUserQuestion`，项目经理没有 `Skill`）。
- 所以只借方法，用自己的话写进角色正文。本轮借的是 `requesting-code-review/code-reviewer.md` 与 `subagent-driven-development/task-reviewer-prompt.md`
  （MIT）的几处做法：契约没说到的输入照使用者的合理预期判、不信实现者的自评、按实际严重程度分档、只断言替身的测试不算测到、拿不准要不要做的单列交给拍板的人。
  运行时正文不提 superpowers，也不提 docs 编号（`tests/runtime-prose.test.mjs` 与本轮新判据钉着）。

### 1.2 共存

- superpowers 的 SessionStart 会把 `using-superpowers` 注入项目经理的主会话：671 份项目经理转录里 593 份带它。
- 项目经理没有 `Skill` 工具，平台也不给它 skill 列表；670 份转录里没有一份被它带偏（没有先去头脑风暴、没有开放式提问、没有自称要调 skill）。子代理没有注入。
- 裁定：`agents/at-pm.md` 不加对冲规则（加了是为没见过的失效付每一轮的 token），只在 README 里写清怎么配合（§3.3）；这一条登进开放边界（§5）。

### 1.3 三视角核查的共同模式

大多数提议被价值视角以「真实会话没见过这个失效」驳回。照 `docs/91` 的裁定，这些不登开放边界、不逐条挑，只按实测修。

### 1.4 体量

`claude plugin details` 估算 `/agent-team:at` 展开约 2.62 万 token、`at-pm` 正文约 8k。压缩正文是后续的优化空间，前提是先有 `claude plugin eval` 的行为评测——
没有评测就压缩，删掉的是哪一句承重的说不清。本轮不压缩。

## 2. 裁定

1. **审查归 `at-qa`，不另起角色、不加阶段。** `at-acceptance` 原来说「代码写得好不好是 `at-qa` 与架构师的事」，两份正文都没接。`at-qa` 已经在 S6、已经读实现、
   已经持只读的 `Bash`，审查放在它跑完测试之后，不多一次派发。架构师不接：它是方案的作者，审照方案做出来的东西，是自己审自己。
2. **只读。** 取改动只用 `diff`、`status`、`show`、`log`；范围按 `04-dispatch.md`「代码基线」那一节（S4 记的），排除 `.agent-team`；没进版本库的新文件 diff 看不到，
   `status` 列出来整份读。基线写着「不是 git 仓库」「没记」的，按实现记录列的文件读、写明没有 diff；写着「还没有提交」的，`status` 列的整份读。
3. **对照什么**：`01-prd.md` 的完成定义（没有就对契约）、`03-arch.md` 的接口契约与落盘清单；分漏做、多做、做歪。实现记录是自评，不当证据，写了理由的不因理由降级。
4. **定级按对使用者的影响**：「必须修 / 应当修 / 可不修」。崩溃、丢数据、安全问题、吞掉错误、原话要的功能在明显会遇到的输入上出错，契约没提那个输入也照样算。
5. **原话之外的新增行为不进问题清单**，单列「契约没说到的」，交项目经理裁：去掉它的自己定、写进交付文档；要留下它的是扩出原话，照第 4 节问（`tradeoff`）。
6. **第一版只报不判**：写进 `06-test.md` 的「## 审查」一节，不改第一行的结论，门禁不读这一节、一行门禁代码都不改。项目经理推进出 S6 之前读它：
   「必须修」的先读那几行核实，确有其事的照「回退」回到 S5；返工预算已到上限的照 `budget-exhausted` 问用户、不批就带着往下走；「应当修」「可不修」的不回退、收尾时告诉用户。
   只断言替身、或者什么都不断言的测试是唯一的那条新行为，照原有的缺测试那一段算没有测试（第一行写「不通过：缺测试」）——那是那一段在判，不是审查。
   不让审查卡第一行的理由：误报会直接变成一轮返工，在没有真实会话的样本之前，先让项目经理这一层把关。什么时候改成会卡，见 §5。
7. **README**：主会话拿不到 Skill 工具、别的插件的 skill 调不起来；在别处（比如没装 agent-team 的会话里用 superpowers 头脑风暴）想好的需求只贴四样要点，
   不整份贴——`/agent-team:at` 后面的每一句都是原话，整份贴进来，设计文档里「怎么做」与模型自己拍板的小决定都成了用户原话（`docs/95` §1 同一个理由）。

## 4. 实测：sonnet 跑的 at-qa 抓不抓得到、会不会误报

### 4.1 做法

两份最小夹具（scratchpad 里，没进仓库），同一份契约：用户原话要 `loadConfig(path)` 读 JSON 配置，「文件不存在或者不是合法 JSON 时，抛出 ConfigError，消息里带文件路径，
不要让程序带着空配置继续跑」；`01-prd.md` 四条完成定义，`03-arch.md` 写接口、落盘清单与「三条完成定义各一条测试」，`04-dispatch.md` 的代码基线记了初始提交，
S5 的改动没提交（`src/`、`test/` 都是新文件，只有 `status` 看得到）。

- **defect**：`catch (e) { return {} }` 吞掉读失败与解析失败（失败分支没实现，`ConfigError` 定义了没人抛）；为了注入替身给 `loadConfig` 加了第二个参数 `deps`；
  两条测试都只断言替身被调用过，第二条还把异常吞掉；实现记录自称「失败分支已测」。`node --test` 2 条全过。
- **clean**：两种失败都抛带路径的 `ConfigError`，三条测试用临时文件真读。3 条全过。

驱动：`claude -p`（CLI 2.1.301），`--model sonnet`，`--system-prompt-file` 是去掉 frontmatter、`${CLAUDE_PLUGIN_ROOT}` 换成本仓库路径的 `agents/at-qa.md`，
`--tools Bash Read Glob Grep Write`，`--setting-sources project`、`--strict-mcp-config`（不带用户的插件，没有 superpowers 注入），`--no-session-persistence`，
派发提示按六项写。没加载插件，所以门禁不在场：量的是正文，不是门禁。两场各一次，没有重复样本。

### 4.2 结果

| | defect | clean |
|---|---|---|
| 第一行 | 「结论：不通过：缺测试，且实现与契约不符（……）」 | 「结论：通过」 |
| 必须修 | `src/config.js:15-17` 吞掉错误、完成定义 2–4 没做；`ConfigError` 是死代码 | 无 |
| 应当修 | 两条测试只断言替身、空 `catch` 吞异常；`deps` 参数不在接口契约里 | `JSON.parse` 出来的不是对象（`null`、数字、数组）时原样返回、不抛错 |
| 可不修 | 无 | `path` 不是字符串时也包成「读不出」（可以接受） |
| 契约没说到的 | `deps` 参数 | 无 |
| 读了什么 | 写明基线、`status` 看到的两个新文件整份读了 | 同左 |
| 用时 / 费用 | 33 秒，7 轮，0.10 美元 | 25 秒，5 轮，0.09 美元 |

- **抓得到**：埋的两样都抓到了，还拆穿了实现记录的「失败分支已测」，并用真实文件手工复现了「返回 `{}`」。
- **误报**：clean 那一场没有「必须修」；那条「应当修」站得住（接口契约写的是 `object`，原话说不要带着空配置继续跑），算不上误报，但说明对照的口子是开着的——
  契约没说到的输入它会去想，这正是本轮要的。
- **第一行**：defect 的第一行是「不通过」，依据是原有的缺测试那一条（完成定义 1–4 没有一条测试断言到结果），不是审查；但它在冒号后面把审查发现的「实现与契约不符」也写了进去。
  门禁按前缀读，读得出；只报不判守住了「判什么」，没守住「原因写什么」，不改。这一场跑的是复核（§9）之前的正文：那时只断言替身的测试算不算缺测试，两句读得出两种意思。
- **两场都没写 run 目录之外的东西**（`git status` 只有 S5 那两个新目录），没起后台进程，没有要停的。
- **行号**：`src/` 的行号对；defect 的测试文件写成 `:25-37`（文件只有 17 行），clean 的 `JSON.parse` 写成 `:20`（实际 19）。正文那一句补了「行号照 `Read` 或 `grep -n`
  给的抄，不凭印象写」——补了之后没有重跑（§6）。

## 5. 仍然开着的边界

- **审查不卡第一行**：「必须修」只靠项目经理读了之后回退，门禁不读「## 审查」。项目经理不读、读了不回退，带着「必须修」照样能推进与收口。
  什么会让答案改变：真实会话里出现一次项目经理带着核实过的「必须修」推进；或者攒够样本，`at-qa` 的「必须修」在真实会话里几乎没有误报——那时让「必须修」进第一行
  （改 `at-qa` 第一行那一段与门禁的读法，按长期决策给旧 run 留口径）。
- **与 superpowers 的共存不加对冲**：superpowers 的 SessionStart 照旧注入项目经理主会话，`at-pm` 正文不提它。什么会让答案改变：出现一份转录，项目经理因为它先去头脑风暴、
  开放式提问或自称要调 skill。
- **审查的范围靠代码基线**：基线没记、不是 git 仓库时只读实现记录列的文件，实现记录漏列的改动审不到；基线之前就在的改动只靠 `at-qa` 对着基线那一节的 `status` 注明。
- **借来的方法不跟上游**：superpowers 的审查提示改了，这里不会知道（§1.1 有意）。

## 6. 没量到的

- 门禁在场的真实链上 S6 带审查跑一遍（项目经理读不读「## 审查」、核不核实、回不回退）；本轮量的是不加载插件的 `-p`。
- 补了行号那一句之后，测试文件的行号还错不错。
- 改动大、跨几个角色的一趟里，审查会不会读不全、会不会把基线之前的改动算进来；每边只有一个样本。
- 项目经理照不照「契约没说到的」那一条裁、怎么告诉用户。

## 9. 复核与修订

一个子代理（sonnet）对暂存的改动做了一次对抗复核，报了三条，都改了：

1. **只断言替身的测试与缺测试那一段打架**：缺测试那一段判「不通过：缺测试」，新一节说审查（包括只断言替身的测试）不改第一行，一条新行为只有替身测试时两句都引得上。
   改成：一条新行为只有只断言替身、或者什么都不断言的测试的，照缺测试那一段算没有测试；断言到了结果、另有替身测试的，只进审查。新一节里重复的「也不冒泡」删掉（冒泡的两种情形原文已经列了）。
2. **「必须修」回退时预算已到上限没出路**：第一行是「结论：通过」时照现状交付的批准不适用，门禁也不拦推进。补「照第 4 节 `budget-exhausted` 问用户，不批就带着往下走、收尾时原样告诉用户」。
   「S6 测试、S7 验收」那一条被整段钉，不在那里补「读审查」，只靠新加的那一条。
3. **「契约没说到的」引错了段**：第 4 节表下那一段管 S2–S5 的设计分歧、把验证段指回第 3 节。改成在新一条里直接写判据（去掉的自己定，留下的照第 4 节 `tradeoff` 问）。
