# 测试归谁写与没有 paths 的角色

> 2026-10-05，M4f，分支 `m4f-tests-and-nopaths`，v2.4.0。`docs/39` §5 排出来的第二轮：全量审查第 21 条修法 3（新行为的自动化测试
> 归谁写、缺了怎么走）、第 34 条（没有 `paths` 条目的角色在 run 目录外全放行）、第 27 条（触达表把边界最宽的身份报成最窄）。三条改的是
> 同两份正文（`at-qa`、`at-acceptance`），而第 34 条正是第 21 条修法 3 的门禁兜底。现状与证据在 `docs/39` §2.2。

## 0. 一句话结论

- **没有 `paths` 键的 `at-qa`、`at-acceptance` 在 run 目录之外被拒**：写路径隔离第 2 步原来对它们整段放行——能写 `CLAUDE.md`、`.claude/`、
  插件自己的门禁代码，也能改别人认领的实现代码与测试；现在一律拒，拒绝理由给冒泡的出路、不提怎么开口子。建了键的照旧只能写那几个前缀，
  账本报这个键。
- **新行为的自动化测试归 S5 的产者写**：照落盘清单定的位置写、跑通，实现记录带「测试」一节；PM 推进出 S5 之前读它；`at-qa` 核出缺测试
  判「不通过：缺测试」，不写、不冒泡；缺测试的回退回 S5，验收因为缺测试判不了的也回 S5。门禁照旧不读内容。
- **触达表如实标出不受 `paths` 管的身份**：第 34 条之后只剩项目经理（与主线程）。`reach.json` 给它标 `unrestricted: true`，【触达表】单列它，
  不再逐条列成「还能写到」；这个判断与写路径隔离第 1 步共用 `hooks/lib/decide.mjs` 的 `exemptFromPaths`。

## 1. 修法

### 1.1 第 34 条：没有键的 `at-qa`、`at-acceptance` 在 run 目录之外被拒

- `hooks/lib/writepath.mjs` 第 2 步：按设计不认领路径的角色（`NO_PATHS_ROLES`）没有键时，run 目录之外一律拒，不看 `project.json` 其余部分。
  拒绝理由：「你只写 run 目录里自己那份产物，run 目录之外的文件不是你的活。要改实现、补测试或改配置，写进你的报告，冒泡给派你的人。」
  不提 `paths`、不提键：对正想写别人代码的角色说怎么开口子，等于告诉它怎么绕过去。
- 第 7b 步（建了键的）不动：照旧只能写自己那几个前缀，别的说「键本不该有、由 PM 删掉」。`/agent-team:at-init` 照旧禁止给它们建键，理由改成：
  建了键，门禁就照键放行它们写那几个前缀，等于在 run 目录之外给它们开了口子（`at-qa` 顺手写测试、`at-acceptance` 顺手改合格，正是它们被禁止
  的事）。原来的理由是「建了键，正文那句『连拒都不会拒你』就变假」——那句话这一轮翻过来了。
- 正文与理由文字：`at-qa` 的「你有 Bash」与红线、`at-acceptance` 的红线改成「在 run 目录之外拒你的每一次写入」；`/agent-team:at` 第 0 节、
  `hooks/lib/project.mjs` 的两句理由（`paths` 缺失、花名册读坏）、`hooks/gate.mjs` 里 run 进行中 `project.json` 不在那一句，都不再把它们说成例外；
  README 两半「这不是沙箱」那一段照实写。
- PM 不收：它是主会话，`/agent-team:at` 第 6 节「用户明说要你直接改的，照用户说的办」需要它在 run 目录外可写。
- 不选的做法：建了键的也一律拒（「项目真决定测试归 QA」时，键是唯一的口子；账本照旧报它）；审查给的「H6 对 PM 放宽一次」（M4a 起假收口、被清零
  的 run 已经有「另起一趟」这条出路，一个 Bash 能触发的放宽信号本身就是一条新绕路）。

### 1.2 第 21 条修法 3：新行为的自动化测试

- S5 的每个产者（`at-backend`、`at-frontend`、`at-ui`、`at-ios`、`at-android`）加同一节「新行为要有自动化测试」：在 S5 实现的每一条新行为，
  由你写自动化测试，照架构方案「落盘清单」定的位置与命令写、跑通；实现记录里写一节「测试」：每条新行为 → 测试文件或用例 → 命令 → 结果；
  写不了测试的（契约第 3 节写了不要，或者方案定了这个项目不上测试框架），写明为什么。缺了这一节、或者新行为没有测试也没写明为什么，这一段
  不算交齐。
- `at-architect`：交接包的完成定义里写上补测试与「测试」一节。
- `/agent-team:at` 的 S5 那一条：推进出 S5 之前读「测试」一节，缺了在 S5 里经架构师重派补（同一段里重派，不计返工）。「回退」：`06-test.md`
  报新行为缺自动化测试的也算 S6 没过、回 S5（缺口在 S5）；S7 验收因为缺测试判不了的同样回 S5、不回 S6。
- `at-qa`：核新行为有没有自动化测试，对照各份实现记录的「测试」一节与 `03-arch.md`；有缺的，`06-test.md` 的结论写「不通过：缺测试」并列出来；
  不写测试（run 目录之外它写不了——第 34 条），也不冒泡（冒泡只用于「S5 没交齐」与红线里的敏感操作）；契约或方案说不要测试的，照实记、
  不判不通过。
- `at-acceptance`：判不了是因为新行为根本没有自动化测试的，写明是哪几条——那要回 S5 补测试，不是回 S6 补跑。
- `/agent-team:at-resume`：停在 S5 的，「测试」一节缺了的同样不算交齐。门禁给 PM 的执行段提醒（`IMPL_RECORD_NOTE`）补上同一句。
- 不选的做法：测试归 `at-qa` 写（要给它建 `paths`，等于推翻第 34 条；测试由被验的一方写，就失去了独立核验）；归架构师写；门禁读「测试」
  一节（门禁不读内容，这一层在正文里）。

### 1.3 第 27 条：触达表里不受 `paths` 管的身份

- `hooks/lib/decide.mjs` 新增 `exemptFromPaths(role)`：项目经理（`at-pm`）与主线程。写路径隔离第 1 步改用它（原来用 `isContractWriter`，判的是
  同一个集合）；`hooks/lib/reach.mjs` 的 `computeReach` 给每个角色标 `unrestricted: exemptFromPaths(role)`——两处各写一份会分叉，触达表原来就
  把项目经理报成「只够得到别人认领的那几个前缀」。`reach.mjs` 仍然是纯数据推导（`decide.mjs` 只 import `trusted.mjs`，都不碰文件系统）。
- 【触达表】把标了 `unrestricted` 的单列在前（「不受 paths 管：at-pm、__main__——项目经理在 run 目录之外写哪都放行，写路径隔离不看它的前缀。」），
  不再逐条列它们「还能写到」的前缀；只有它们、没有别的角色被放大时，说「其余角色的触达都没有超出」。
- `/agent-team:at-status` 第 4 节：标了的单列一行，不按前缀报；`reach.json` 里一个角色都没有这个字段的是旧快照，照前缀报并提示重跑
  `/agent-team:at-init`。`/agent-team:at-init` 第 3 节：收尾告诉用户时照这样说。
- 第 34 条之后，`at-qa`、`at-acceptance` 在 run 目录之外哪都写不了，它们在触达表里「空」就是真的了。

## 2. 判据与变异

- 第 34 条：`tests/writepath-shape.test.mjs` 那条原来要求放行的改成要求拒（几种 `project.json` 形状、几种目标，理由要有「只写 run 目录里自己那份
  产物」与「冒泡」、不许有 `paths`、删键、「整段放行」、`project.json`）；`tests/agents.test.mjs` 的 `statesPathsEscape` 改成要求「在 run 目录之外拒你
  的每一次写入」，**同一条判据里调 `decideWritePath` 核门禁真拒**——这一轮改代码那一刻，正文那几条判据照旧全绿，正文与门禁就是这样静默分叉的；
  `tests/project.test.mjs`、`tests/gate-ledger-project.test.mjs`、`tests/project-prose.test.mjs` 里原来要求「点名不受影响的 NO_PATHS_ROLES」的几条
  翻成不许点名；README 那一段整句钉。
- 第 21 条修法 3：`tests/tests-and-nopaths-prose.test.mjs`，S5 的产者从 `stages.json` 派生，承重的句子整句钉（空白不计）。
- 第 27 条：`tests/reach.test.mjs`（标记，与写路径隔离第 1 步对账：标了的在 run 目录外写没人认领的地方放行，没标的都被拒）、`tests/ledger.test.mjs`
  （单列在前、不逐条列、「其余角色」那一句）。
- 变异：二十一刀（第 2 步改回放行、拒绝理由提 `paths`、`exemptFromPaths` 恒假、触达表不标、【触达表】不单列与「其余角色」那一句、各处正文删掉或
  改回旧说法、README 改回整段放行、`project.mjs` 与 `gate.mjs` 的理由改回例外），全部打红；每一刀 `cp` 备份、还原后逐字比对。

## 3. 实测

- 门禁与正文：判据与变异见 §2。
- **真实团队会话 M7**（CLI 2.1.286，SDK 宿主同 `docs/37` §4，插件副本与本分支同步，sonnet，开着门禁留痕）：夹具停在 S6，纯后端的待办 API；
  后端代码写了、一条测试都没有（`npm test` 报「No test files found」），实现记录是旧写法、没有「测试」一节；契约第 1 节原话要求「要有自动化
  测试，用 npm test 能跑」。PM 续跑时读实现记录，照 S5 那一条判出「S5 的实现记录没有『测试』一节，磁盘上也没有 `tests/`……S5 不算做完」，
  记了一次回到 S5 的回退（`history` 追加 S5，`rework` 的 S5、S6 各一轮，`rework_base` 记下旧实现记录的 sha），经架构师在 S5 里重派 at-backend；
  at-backend 补了 `tests/todos.test.ts`（五个用例，起真 http 服务用 fetch 请求）与一张「测试」表（每条新行为 → 用例 → 结果），`npm test`、
  `tsc --noEmit` 都跑过。之后推进到 S6，at-qa 照新正文核了「新行为都有测试」、5/5 通过；S7 验收八项全部满足；S8 写交付文档、收口，门禁全程
  没有一次拦截。**at-qa 判「不通过：缺测试」那条路这一场没走到**：缺口写在 PM 看得见的实现记录里时，PM 那一层先接住了（与 `docs/40` §3 的
  M6 同一个形状）。收尾：`~/.claude.json` 里没有 `lastGracefulShutdown: false` 的条目，`~/.claude/jobs` 里只有 `pins.json`，没有残留进程。

## 4. 仍然开着的边界

- **门禁不读「测试」一节**：写了一行「已测」也算交了；`at-qa` 核的是内容，门禁只核实现记录在不在、空不空。
- **`at-qa` 的 Bash 照样写得进 run 目录之外**：挡它的是红线，不是门禁。
- **建了键的 `at-qa`、`at-acceptance` 照键放行**：`/agent-team:at-init` 禁止建、账本报这个键，门禁不拒。
- **有键的角色在自己前缀下写嵌套的 `CLAUDE.md`、`.claude/`**：登记（`docs/39` §2.2 第 34 条那一格），要堵就得按文件名、目录段名拒，会与 S4「用户批了就补
  `.claude/`」那条路冲突。
- **花名册外的调用者照旧不看 `paths`**（`agent_type` 为空串、别的插件的角色）：归第 22、35 条（`docs/39` §5 第四轮）。
- **S5 的返工额度压力变大**：缺测试与测试没过共用 S5 的额度。
- **旧的 `reach.json` 没有 `unrestricted`**：`at-status` 说是旧快照、提示重跑。
- **空目录起的项目要先由架构师定测试框架**：落盘清单写测试放哪、用什么命令跑，正文没写死框架。

## 5. 没量到的

- at-qa 核出缺测试、判「不通过：缺测试」、PM 照「回退」回 S5 的那条路（M7 里 PM 先接住了）；验收因为缺测试判不了、回 S5 的那条路。
- at-qa 想自己写测试、被写路径隔离拒的那一下（判据钉着门禁，真实会话里没撞上）。
- 「测试」一节写得敷衍（只写一行「已测」）时，PM、at-qa 各自怎么判。

## 6. 归属

- 改写路径隔离第 1、2 步或 `NO_PATHS_ROLES` 的人：`tests/writepath-shape.test.mjs`、`tests/agents.test.mjs` 的 `statesPathsEscape`（正文与门禁一起核）、
  `tests/reach.test.mjs` 的对账那一条一起改。
- 改「测试」一节的写法或缺测试的路由的人：`tests/tests-and-nopaths-prose.test.mjs` 的那几句常量与正文一起改。
- 给不认领路径的角色加 `paths` 的项目（测试归 QA）：键是唯一的口子，`/agent-team:at-init` 与账本会报它——那是一次设计变更，不是配置。
