# 测试归谁写与没有 paths 的角色

> 2026-10-05，M4f，分支 `m4f-tests-and-nopaths`，v2.4.0。`docs/39` §5 排出来的第二轮：全量审查第 21 条修法 3（新行为的自动化测试
> 归谁写、缺了怎么走）、第 34 条（没有 `paths` 条目的角色在 run 目录外全放行）、第 27 条（触达表把边界最宽的身份报成最窄）。三条改的是
> 同两份正文（`at-qa`、`at-acceptance`），而第 34 条正是第 21 条修法 3 的门禁兜底。现状与证据在 `docs/39` §2.2。
> 合进 `main` 之前做过一轮对抗复核：§0–§7 写的是修订之后的样子，复核挑出了什么、怎么改的在 §8。

## 0. 一句话结论

- **没有 `paths` 键的 `at-qa`、`at-acceptance` 在 run 目录之外被拒**：写路径隔离第 2 步原来对它们整段放行——能写 `CLAUDE.md`、`.claude/`、
  插件自己的门禁代码，也能改别人认领的实现代码与测试；现在一律拒，项目根之外与 `.agent-team/` 下的非控制文件也一样。拒绝理由点名它自己那份
  产物（`06-test.md`、`07-acceptance.md`），叫它把问题照实写进那份结论、不用为这个冒泡；不提怎么开口子。建了键的照旧只能写那几个前缀，账本报
  这个键。
- **新行为的自动化测试归 S5 的产者写**：照落盘清单定的位置写、跑通，实现记录带「测试」一节。不写测试只有两种情形算数——这一次没有新行为；
  契约第 1 节用户原话或第 4 节修订记录里，用户说了这部分不要——产者、架构师、PM、`at-qa` 用逐字同一句；别的理由由 PM 问用户。`at-qa` 核出
  缺测试判「不通过：缺测试」，不写、不冒泡；缺测试的回退回 S5，验收因为缺测试判不了的也回 S5。门禁照旧不读内容。
- **触达表如实标出不受 `paths` 管的身份**：第 34 条之后只剩项目经理（与主线程）。`reach.json` 给它标 `unrestricted: true`，【触达表】单列它，
  不再逐条列成「还能写到」；这个判断、写路径隔离第 1 步与契约守卫是同一个函数（`hooks/lib/decide.mjs` 的 `exemptFromPaths`）。

## 1. 修法

### 1.1 第 34 条：没有键的 `at-qa`、`at-acceptance` 在 run 目录之外被拒

- `hooks/lib/writepath.mjs` 第 2 步：按设计不认领路径的角色（`NO_PATHS_ROLES`）没有键时，run 目录之外一律拒，不看 `project.json` 其余部分。
  拒绝理由（`at-qa` 的）：「你只写 run 目录里自己那份 06-test.md，run 目录之外的文件不是你的活。要改实现、补测试或改配置的，不要自己动手：
  把看到的问题照实写进 06-test.md 的结论，不用为这个冒泡。」产物名从 `stages.json` 取（这个角色在哪几段是产者、交哪几份），读不出来时泛说
  「自己那份产物」。不提 `paths`、不提键：对正想写别人代码的角色说怎么开口子，等于告诉它怎么绕过去。不叫它冒泡：`at-qa` 的正文说缺测试判
  「不通过：缺测试」、不冒泡，冒泡了就不交 `06-test.md`，PM 当成产物没交（§8）。
- 第 7b 步（建了键的）不动：照旧只能写自己那几个前缀，别的说「键本不该有、由 PM 删掉」。`/agent-team:at-init` 照旧禁止给它们建键，第 2 节照实写：
  没有条目时门禁在 run 目录之外拒它们，与其余没有键的角色一样；建了键，门禁就照键放行它们写那几个前缀，等于在 run 目录之外给它们开了口子
  （`at-qa` 顺手写测试、`at-acceptance` 顺手改合格，正是它们被禁止的事）。原来的理由是「建了键，正文那句『连拒都不会拒你』就变假」——那句话
  这一轮翻过来了。
- 正文与理由文字：`at-qa` 的「你有 Bash」与红线、`at-acceptance` 的红线改成「在 run 目录之外拒你的每一次写入」，出路是照实写进自己那份结论、
  不用为这个冒泡；`/agent-team:at` 第 0 节、`hooks/lib/project.mjs` 的两句理由（`paths` 缺失、花名册读坏）、`hooks/gate.mjs` 里 run 进行中
  `project.json` 不在那一句，都不再把它们说成例外；README 两半「这不是沙箱」那一段照实写。
- PM 不收：它是主会话，`/agent-team:at` 第 6 节「用户明说要你直接改的，照用户说的办」需要它在 run 目录外可写。
- 不选的做法：建了键的也一律拒（「项目真决定测试归 QA」时，键是唯一的口子；账本照旧报它）；审查给的「H6 对 PM 放宽一次」（M4a 起假收口、被清零
  的 run 已经有「另起一趟」这条出路，一个 Bash 能触发的放宽信号本身就是一条新绕路）。

### 1.2 第 21 条修法 3：新行为的自动化测试

- S5 的每个产者（`at-backend`、`at-frontend`、`at-ui`、`at-ios`、`at-android`）加同一节「新行为要有自动化测试」：在 S5 实现的每一条新行为，
  由你写自动化测试，照架构方案「落盘清单」定的位置与命令写、跑通；实现记录里写一节「测试」：每条新行为 → 测试文件或用例 → 命令 → 结果。
- **不写测试只认两种情形**（产者、架构师、`at-qa`、`/agent-team:at` 的 S5 那一条逐字同一句）：这一次没有新行为——新行为指程序对外表现出来、
  以前没有或者不一样的东西（接口、页面上的交互、数据怎么存怎么算），只动了文档、设计稿或纯视觉样式、或者重构没有改变对外的表现，就是没有；
  契约第 1 节用户原话或第 4 节修订记录里，用户说了这部分不要测试。别的理由（不好测、要真机、来不及、方案说不上测试框架）都不算：产者真写不了
  的冒泡，PM 照第 4 节问用户（`tradeoff`；契约原话要求测试的是 `contract-conflict`），答复记进修订记录之后才算数。契约第 3 节是 PM 自己写的：
  `/agent-team:at`、契约的格式（`at-contract-format`）与模板都说「不写自动化测试」不写进那一节、写了也不算数。
- `at-architect`：交接包的完成定义里写上补测试与「测试」一节；落盘清单写测试放哪、用什么命令跑，项目还没有测试框架的把补框架也列进来，觉得这一趟
  不该写测试的写进未决问题、不自己定；读实现记录时核「测试」一节，缺了在 S5 里重派补齐再回报。
- `/agent-team:at`：S3 那一条——方案说这个项目不写测试的，不是架构师定得了的，照第 4 节问用户；S5 那一条——推进出 S5 之前读「测试」一节，缺了
  在 S5 里经架构师重派补（同一段里重派，不计返工）；新加的 S6、S7 那一条——【阶段】说齐了、推进被放行，只说明结论交了，不说明过了，推进之前读
  结论，没过、判不了的照「回退」或第 4 节处理；「回退」——`06-test.md` 报新行为缺自动化测试的也算 S6 没过、回 S5（缺口在 S5）；S7 验收因为缺测试
  判不了的同样回 S5、不回 S6，S5、S6、S7 各记一轮返工。
- `at-qa`：核新行为有没有自动化测试，对照各份实现记录的「测试」一节、`03-arch.md` 与契约；有缺的，`06-test.md` 的结论写「不通过：缺测试」并列出来；
  实现记录说用户不要测试的，去契约第 1、4 节核那一句，写了别的理由的照样算缺；「测试」一节缺了不照「S5 没交齐」冒泡，照这一条判；不写测试
  （run 目录之外它写不了——第 34 条），也不冒泡（冒泡只用于「S5 没交齐」与红线里的敏感操作）。
- `at-acceptance`：判不了是因为新行为根本没有自动化测试的，写明是哪几条——那要回 S5 补测试（S5、S6、S7 各吃一轮返工额度），不是回 S6 补跑。
- `/agent-team:at-resume`：停在 S5 的，「测试」一节照那两种情形判；「产物齐了」那一条里，停在 S6、S7 的先读结论，没过、判不了的不记账推进。
- 门禁给执行段的三句提醒——给 PM 的（`IMPL_RECORD_NOTE`）、给这一段产者的、给别的写者的——都带上「测试」一节。
- README 两半「一趟 run 怎么走」：测试由实现角色写，测试角色只跑、不写，缺测试判不通过、退回实现阶段；只有两种情形不写。
- 不选的做法：测试归 `at-qa` 写（要给它建 `paths`，等于推翻第 34 条；测试由被验的一方写，就失去了独立核验）；归架构师写；门禁读「测试」
  一节（门禁不读内容，这一层在正文里）；例外认契约第 3 节或架构方案（被验的一方能单方面关掉整套机制，§8）。

### 1.3 第 27 条：触达表里不受 `paths` 管的身份

- `hooks/lib/decide.mjs` 新增 `exemptFromPaths(role)`：项目经理（`at-pm`）与主线程。写路径隔离第 1 步改用它；`hooks/lib/reach.mjs` 的 `computeReach`
  给每个角色标 `unrestricted: exemptFromPaths(role)`——两处各写一份会分叉，触达表原来就把项目经理报成「只够得到别人认领的那几个前缀」。契约守卫
  的 `isContractWriter` 现在就是这个函数（`export const isContractWriter = exemptFromPaths`），函数体只有一份。`reach.mjs` 仍然是纯数据推导
  （`decide.mjs` 只 import `trusted.mjs`，都不碰文件系统）。
- 【触达表】把标了 `unrestricted` 的单列在前，顺序照花名册：「不受 paths 管：__main__（主会话）、at-pm——都是项目经理这一个身份，写路径隔离在
  run 目录之外对它一律放行、不看前缀。门禁不拦不等于该它写：项目代码与配置照旧交给执行角色，补 paths 是认领，不是代写。」不再逐条列它们
  「还能写到」的前缀；只有它们、没有别的角色被放大时，说「其余角色的触达都没有超出」。
- `/agent-team:at-status` 第 4 节：标了的单列一行，不按前缀报；`reach.json` 里一个角色都没有这个字段的是旧快照，照前缀报并提示重跑
  `/agent-team:at-init`。`/agent-team:at-init` 第 3 节：收尾告诉用户时照这样说。
- 第 34 条之后，`at-qa`、`at-acceptance` 在 run 目录之外哪都写不了，它们在触达表里「空」就是真的了。

  用户主目录，与 `.agent-team/` 下的非控制文件、另一趟 run 的产物）；理由要点名自己那份产物（从 `stages.json` 取）、「照实写进……的结论，不用为这个

## 3. 实测

- 门禁与正文：判据与变异见 §2。
- **真实团队会话 M7**（CLI 2.1.286，SDK 宿主同 `docs/37` §4，插件副本与本分支第一版同步，sonnet，开着门禁留痕）：夹具停在 S6，纯后端的待办 API；
  后端代码写了、一条测试都没有（`npm test` 报「No test files found」），实现记录是旧写法、没有「测试」一节；契约第 1 节原话要求「要有自动化
  测试，用 npm test 能跑」。PM 续跑时读实现记录，照 S5 那一条判出「S5 的实现记录没有『测试』一节，磁盘上也没有 `tests/`……S5 不算做完」，
  记了一次回到 S5 的回退（`history` 追加 S5，`rework` 的 S5、S6 各一轮，`rework_base` 记下旧实现记录的 sha），经架构师在 S5 里重派 at-backend；
  at-backend 补了 `tests/todos.test.ts`（五个用例，起真 http 服务用 fetch 请求）与一张「测试」表（每条新行为 → 用例 → 结果），`npm test`、
  `tsc --noEmit` 都跑过。之后推进到 S6，at-qa 照新正文核了「新行为都有测试」、5/5 通过；S7 验收八项全部满足；S8 写交付文档、收口，门禁全程
  没有一次拦截。**at-qa 判「不通过：缺测试」那条路这一场没走到**：缺口写在 PM 看得见的实现记录里时，PM 那一层先接住了（与 `docs/40` §3 的
  M6 同一个形状）。收尾：`~/.claude.json` 里没有 `lastGracefulShutdown: false` 的条目，`~/.claude/jobs` 里只有 `pins.json`，没有残留进程。
- 复核之后没有重跑真实会话：门禁放行与拒绝的集合没变（只改了第 2 步的理由文字），正文改的是例外清单与几处路由，M7 走过的那条路（PM 在 S5
  接住缺测试）照旧成立；修订新加的路没量过，见 §5。

## 4. 仍然开着的边界

- **门禁不读「测试」一节**：写了一行「已测」也算交了；`at-qa` 核的是内容，门禁只核实现记录在不在、空不空。
- **`at-qa` 的 Bash 照样写得进 run 目录之外**：挡它的是红线，不是门禁。
- **`at-qa` 用 `Write` 只能写自己那份 `06-test.md`**：临时复现脚本、为了跑起来要建的配置（`.env.test` 这类）也写不了。前者把复现步骤写进
  `06-test.md`（命令与原文输出），后者是环境问题，照正文写进 `06-test.md`、由 PM 照 `env-blocked` 问用户。
- **建了键的 `at-qa`、`at-acceptance` 照键放行**：`/agent-team:at-init` 禁止建、账本报这个键，门禁不拒。
- **有键的角色在自己前缀下写嵌套的 `CLAUDE.md`、`.claude/`**：登记（`docs/39` §2.2 第 34 条那一格），要堵就得按文件名、目录段名拒，会与 S4「用户批了就补
  `.claude/`」那条路冲突。
- **花名册外的调用者照旧不看 `paths`**（`agent_type` 为空串、别的插件的角色）：归第 22、35 条（`docs/39` §5 第四轮）。
- **「这一次没有新行为」由产者自己判**：把有行为的改动说成没有，靠 `at-qa` 对照 `03-arch.md` 与契约逐条列新行为兜，门禁看不出。
- **S5 的返工额度压力变大**：缺测试与测试没过共用 S5 的额度。
- **`reach.json` 里 `__main__`、`at-pm` 那两条照旧带着 `widened` 与前缀**：消费方（【触达表】、`/agent-team:at-status`）先看 `unrestricted`；旧的
  `reach.json` 没有 `unrestricted`，`at-status` 说是旧快照、提示重跑。
- **空目录起的项目要先由架构师定测试框架**：落盘清单写测试放哪、用什么命令跑，正文没写死框架；觉得不该补的由 PM 问用户。

## 5. 没量到的

- at-qa 核出缺测试、判「不通过：缺测试」、PM 照「回退」回 S5 的那条路（M7 里 PM 先接住了）；验收因为缺测试判不了、回 S5 的那条路。
- at-qa 想自己写测试、被写路径隔离拒的那一下（判据钉着门禁与理由文字，真实会话里没撞上）。
- 「测试」一节写得敷衍（只写一行「已测」）时，PM、at-qa 各自怎么判。
