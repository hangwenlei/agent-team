# 收口时列出还没停下的派发

> 2026-10-10，M4u，分支 `m4u-closing-inflight`。第十四轮，从 `docs/00-开放边界.md` §3 挑的：`docs/35` §5「收口时还在跑的后台派发」与 `docs/38` §2.7
> 「收口那一刻拦『还有派发在跑』」——同一件事在两份记录里各登了一次。正文是复核修订之后的样子，复核与改了什么在 §8。

## 0. 一句话结论

- 原来收口成功不发任何回传：项目经理不知道这一趟还有派出去的人在跑，它们之后交的东西、还在改的项目文件，收口之后门禁都不再核。现在这一趟收口之后
  写 `state.json` 时，账本回传一段【派发】，列出这一趟派发记录里门禁没见停下的派发。不拦收口（§1.2）。

## 1. 修法与裁定

### 1.1 列出来

- `hooks/gate.mjs` 的 `inflightHere`：这一趟的派发记录里，`agent_id` 在所有 run 的派发记录里都没有一条不是「拦」的停下行的（只有「拦」的也算没停，
  拦了它会接着跑；冒泡、放行停下的算停了）。别的 run 的派发不算这一趟。与写 `current-run` 时那一段【派发】共用 `finishedAgents`。
- 账本在写 `state.json`、这一趟已经收口时（`closedAt`）回传：「【派发】这一趟收口了，下面这些派发门禁没见它们在收口之前停下：……收口之后门禁
  不再核这一趟，也不再记它们停下（这份名单不会变短）：它们之后交的东西不计入这一趟，还在改的项目文件也没人核。向用户汇报时照实说这几个——可能还在
  跑，也可能早已中断（会话断过、被停掉、被平台的续跑上限放过）；它们那一份没算进这一趟。」不许诺完成通知会到：协调者派出去的人，交互模式下通知
  回到协调者、不到主会话（`docs/38` §1.3）。角色与段只在花名册、阶段链认得它们时说出来（派发记录 `Bash` 写得进），认不出的说「一条认不出角色或段的
  派发」。只在写 `state.json` 时说。
- `/agent-team:at` 第 6 节第五步：同时收到的回传举例里加上【派发】列出的门禁没见停下的人，照它如实告诉用户。

### 1.2 裁定：收口时不拦「还有派发在跑」

- **拒绝的做法**：H6 在收口那一次写入时，这一趟还有门禁没见停下的派发，就拒，叫项目经理等它们停下。
- **它的代价**：「还在跑」只能按停下行认。会话中断、后台被停掉的子代理永远没有停下行；被平台续跑上限放过的，最后一行是「拦」——这一趟就永远收不了口，
  派发记录是门禁专属文件，项目经理清不掉，没有出口（与 `docs/51` §1.2 同一个理由）。
- **什么会让答案改变**：平台给出可靠的子代理存活状态（例如 hook 输入里带着正在跑的子代理），「还在跑」不再靠停下行认。

## 2. 判据与变异

- `tests/gate-closing-inflight.test.mjs`（子进程）：收口之后写 `state.json`——没停下的、只有「拦」的、认不出角色的列出来，放行停下的、冒泡停下的不列，
  整段钉住；别的 run 里没停下的不算、停下行记在别的 run 里的照样认；收口之后写别的文件不说；没收口、没有派发记录、都停下了都不说；`/agent-team:at`
  第五步那一句。
- `tests/trusted-echo.test.mjs`：这一趟派发记录里的段是载荷，收口之后的【派发】不回显。

变异（备份在仓库外，改完逐字节还原）各红：收口之后不说；没收口也说；拦过的也算停了；冒泡停下的也列；停下了的也列；认不出的也照原样说；不说之后交的
不算；`/agent-team:at` 那一句改坏；复核修订之后补的刀在 §8。

## 3. 实测

- 没起真实会话：回传走账本写 `state.json` 那一路，派发记录的读法与写 `current-run` 时那一段【派发】同一份。
- 分支 CI 的结果写在合并之后的收口里。

## 4. 仍然开着的边界

- **不拦**（§1.2，有意）：项目经理照样能在有人还在跑的时候收口、汇报。
- **收口之后每次写 `state.json` 都再说一遍，名单不会变短**：门禁不记「说过了」；收口之后门禁不再记停下行（收了口的那一趟不再记，`docs/49` 那一条），
  收口之后才停下的照样列着。
- **按派发记录认**：门禁不在时派出去的不在里面；派发记录 `Bash` 写得进（§2 那一族）。
- **收口之后它们写的项目文件没人核**：门禁照常判写路径，交付物与账本不再核这一趟。

## 5. 没量到的

- 真实会话里收口时还有派出去的人在跑：项目经理照不照回传等它、照实告诉用户。

## 6. 归属

- `hooks/gate.mjs` 的 `inflightHere`、`closingInflightNotice` 与共用的 `finishedAgents`，接在账本写 `state.json` 的那一段；判据在
  `tests/gate-closing-inflight.test.mjs`。

## 8. 复核与修订

`d8cdd8f` 推上去之后一路对抗复核（变异与实验在仓库外做，逐字节还原）。收口那一次写入的执行路径核过：PostToolUse 时磁盘上已经有 `closed_at`，账本走不到
任何提前退出的出口，这一段确实到得了项目经理。「这一趟」按规范化之后的路径认，别名与大小写都对；停下行跨 run 认；前台派发先有停下行、后有派发行也认得出。

- **中 1　§4 说「人停下之后就不再列」是假的**：收口之后门禁不再记停下行，名单永远不变短，与完成核验「它收口之后才完成」的说法互相矛盾。**改**：不改
  记不记（收了口的那一趟不再记是既定的），回传与 §4 照实说名单不会变短。
- **中 2　新拼进回传的段名没进不回显判据的入口清单**：去掉核段那一步，全量照绿。**改**：补一格（派发记录里只伪造段名），那一刀打红。
- **中 3　回传许诺「完成通知到了」**：协调者派出去的人，交互模式下通知回到协调者、不到主会话；收口之后门禁也不记停下，项目经理没有可观察的终点。
  **改**：不许诺，只说门禁没见它在收口之前停下、两种可能都照实说；`/agent-team:at` 那一句跟着改。
- **低**：所有 run 的派发都算这一趟、写什么都说、只认这一趟的停下行、删掉汇报那一句，四刀存活——补两趟 run、写别的文件两种夹具，整段钉住，各红；
  「最后一回是『拦』的」与代码（有任何一条不是「拦」的就算停了）说法不一——改成「只有『拦』的」；中断的情形补上被平台续跑上限放过的那一种。
