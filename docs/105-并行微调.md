# 105 并行微调

**日期**：2026-11-06　**版本**：8.0.0　**设计**：`docs/superpowers/specs/2026-11-05-边看边改微调与会话归属-design.md`（§5.6–§5.8、§7、§8 第 3 条）　**计划**：`docs/superpowers/plans/2026-11-06-并行微调.md`

---

## 0. 一句话结论

微调不再写 `current-run`：门禁每一次先挑这一趟——子代理按派发记录认回派它的那一趟微调，主线程认这个会话名下没收尾的那一趟，都不是照旧按 `current-run`。几个会话可以同时各跑一趟
微调；子代理第一次写一个项目文件时门禁记下认领，别的没收尾的微调再写它就拒、叫它冒泡。开着微调时起不了完整的一趟，开着完整的一趟时起不了微调，一个会话同一时刻只有一趟微调。
完整的一趟与微调都能经「放弃这一趟」放弃收尾（门禁记批准、不核产物、之后冻结）。

## 1. 起因

用户要多开几个会话、各跑一个微调、同时改几处（设计 §1）。第一步（`docs/103`）把一趟归给一个会话，第二步（`docs/104`）做了单个微调、照旧用 `current-run`；这一步让微调离开
指针，并补上第二步挪过来的放弃收尾与「只有微调的项目」。

## 2. 裁定

### 2.1 挑这一趟

`hooks/lib/runpick.mjs` 的 `pickRun`：带 `agent_id` 的只按派发记录找（收口、放弃了的微调也找——它派出去的人可能还在跑，照它判写路径比落到 `current-run` 或「没有 run」上对；
找不到再按 hook 输入里的会话 id 找这个会话名下恰好一趟没收尾的微调——前台派发的派发记录要等子代理跑完才记，实测出来的，见 §8）；主线程找这个会话名下没收尾的那一趟（正路上只有一趟，不止一趟取 run id 最大的）；都不是回 null。「是不是微调」
只认门禁记过的：`mode` 写 tweak、run 目录里绑着 at-tweak 的原话记录。gate.mjs 里每一处读运行上下文都经 `runCtxFor`（判据数调用点），H2 归属、H1 换花名册、两个批准记录器
「归不归别的会话」改按挑出来的那一趟。主线程读不到会话 id、又开着微调时挑不出：留一行痕再照 `current-run`。

### 2.2 只有微调的项目

`current-run` 不在、`runs/` 下只有门禁记过的微调目录时判 no-run（设计 §5.8：第一趟就是微调的项目、完整的一趟收口之后又跑了几趟微调）；混进一个别的目录照旧判读不出。
no-run 原来对非项目经理全放行（自举），两轮后台安全审查把它收紧（§2.6）。

### 2.3 互斥

H6 在建 run 那一次判（`parallel.mjs` 的 `decideExclusion`，排在 `decideModeKey` 之后）：「完整的一趟」只认 `current-run` 指着的、没收口的那一趟（不论归哪个会话）——开着它时
不能起微调；有没收尾的微调时不能起完整的一趟；一个会话同一时刻只有一趟微调；读不到会话 id 建不了微调。`current-run` 指着升级之前的单个微调时，「另建一趟」不按归属拦
（`ownerWriteBlock` 跳过微调），由互斥判。

### 2.4 认领文件

`claims.mjs`：子代理（带 `agent_id`、不是项目经理）第一次写一个项目文件（项目根之下、`.agent-team/` 之外），落盘之后账本把它记进它那一趟的 `runs/<id>/claims.jsonl`
（门禁专属；读改写在锁里）。认领键是 `norm()` 之后的绝对路径（`web/./a.ts`、Windows 与 macOS 上的大小写都认成同一个文件）。别的没收尾的微调认领了它，H3 在写路径隔离放行
之后拒，理由点名那一趟（run id、起的时间、原话开头）、叫它冒泡、不许换路径或用 Bash 绕。收尾、放弃之后那一趟的认领自然不算。项目经理（主线程）不受认领管。
派发那一刻按 `04-dispatch.md` 预先认领不做（先写先得已经挡住互相覆盖，预先认领要给派发文件定格式）。

### 2.5 放弃收尾

`abandon.mjs`：用户在 `AskUserQuestion` 里选「放弃这一趟」、题面原样写着挑出来的那一趟的 run id，批准记录器往它的 `approvals.jsonl` 追加 `kind: abandon`；之后一次写入记
`closed_at`（门禁的钟）与 `abandoned: true`，`stage` 与 `history` 原样，H6 核批准、不核产物（放弃那一次 `decideClosing` 的关上判据、契约基线、测试报告、验收结论、
「可以了，收尾」都不跑）。用 `closed_at` 加标记而不另开一个时间键：`closedAt` 认它收口——冻结、H2 拒派、归属不再挡、互斥与认领不再算它，这些现成的判定都不用改；冻结里
`abandoned` 也不许再改（不然放弃了的去掉标记就成了「正常收口」）。`abandoned` 进 `STATE_KEYS` 与模板（`false`），可省。只认 `AskUserQuestion`，对话里打字不认。
接手与放弃共用 `owner.mjs` 的 `labelAnswer`。

### 2.6 两轮后台安全审查

- 第一轮：开着微调时，团队角色的子代理只有在 `current-run` 那一趟的派发记录里确有它时才退回按指针判，不然 `runCtxFor` 判读不出（新成因 `agent`），H3、H4 照读不出拒、叫它
  冒泡；只有微调、判 no-run 时，非项目经理写不了 `.agent-team/`（H3、H4 都拦）；花名册外的子代理写项目文件照旧放行。一次没记下的派发不能绕开认领与写路径隔离。
- 第二轮：运行上下文读得出时，非项目经理写 `.agent-team/runs/` 下不是这一趟的 run 目录，H3 拒（排在写路径隔离放行之后，执行角色照旧先拿到「那一趟不是当前 run」的理由）、
  契约 H4 也拒。
- 连带：第二步的整趟微调判据补上 H5a 记派发那一步（夹具原来只跑 H1、H2，比真实会话少一步）。

### 2.7 命令展开与接手

session-notice 多一段【微调】（`tweaksNotice`）：`/agent-team:at` 说有微调开着、不能起完整的一趟；`/agent-team:at-tweak` 说这个会话已有一趟（问先收尾还是当成下一轮）或别的会话
开着几趟（可以并行）；`at-resume` 说这个会话的那一趟接着走、别的会话的怎么接手；`at-status` 列全部。`current-run` 指着升级之前的单个微调时不再说【会话】。接手（`recordTakeover`）
的候选加上别的会话名下没收尾的微调，题面要恰好写着其中一个的 run id；名下已有一趟微调的会话不再接手另一趟微调。

### 2.8 正文

at-tweak：不写 `current-run`、第 1 节两问（这个会话已有一趟、完整需求开着）、第 3 节认领冲突与共用页面服务、第 4 节先看失败碰到的是不是这一趟改的、第 5 节停服务时说明别的微调
可能还在用、新第 6 节放弃；at.md 第 1 节「有微调开着」「放弃这一趟」两段、`abandoned` 的填法；at-resume 认这个会话的微调、接手别的会话的微调、丢了指针时不把指针写到微调身上；
at-status 列没收口的各趟；项目经理一句；五个开发角色「在微调里」逐字加认领冲突那一句；README 两半一段。

## 4. 门禁不核（三样）

共用的页面服务谁起、谁停，测试红了是哪一趟的改动弄坏的，门禁都不核（只靠正文：别的微调起的服务不归这一趟停、失败先看碰到的是不是这一趟改的文件）。

- **拒绝的判据长什么样**：收口第三步停服务时，`## 起过的服务` 里记着的服务要么是这一趟起的、要么别的微调已经收尾；测试报告不通过时，失败的用例碰到的文件要在这一趟的认领里。
- **它打不红的那一刀**：服务是谁起的只写在正文产物里（门禁不读），测试碰到哪些文件门禁看不出（要跑覆盖率才知道）。
- **什么会让答案改变**：真实的并行微调里出现一趟停掉了另一趟还在用的服务、或者把别的微调弄坏的测试当成自己的去修。

## 5. 仍然开着的边界

- 两边在同一刻第一次写同一个文件的竞态不挡（先写先得只在 H3 那一刻查、账本落盘之后才记）。
- 派发那一刻按 `04-dispatch.md` 预先认领不做：两趟预计改同一个文件，后一趟要到第一次写才知道撞了。
- Bash 写的文件不记认领、不查认领（门禁不加 Bash 的 matcher，既有边界）。
- 派发记录写不进的那一次派发：派它的会话名下恰好一趟没收尾的微调时按会话认回那一趟；不然它的子代理在开着微调的项目里每一次写入都被拒、要冒泡重派。
- 互斥有一个秒级的时间窗：完整的一趟写 `state.json` 到写 `current-run` 之间（隔一次工具调用），别的会话建微调看不到它、放行，之后两边同时开着、互不查认领。
- 归属记录写不进（建微调那一次账本写 `owner.json` 失败）：那一趟微调认不回任何会话，项目经理按 `current-run` 判、续不上；只留痕。
- `-p`、后台会话里问不了「放弃这一趟」（只认 `AskUserQuestion`）：那样的会话放弃不了，要在能弹出问题的会话里做。
- `current-run` 指着升级之前的单个微调、又有别的会话的微调开着：照新口径判（认领、互斥都按 `tweaksAt` 认），旧的那一趟可能已经写过 `current-run`，at-resume 照它续。

## 6. 没量到的

- 交互会话里几个会话各自来回改好几轮；用户在浏览器里刷新共用的页面服务。
- 认领冲突在真实会话里项目经理怎么转告用户、用户怎么选（实测里只见到冒泡那一截，见 §8）。
- 交互会话（后台派发）里的整趟；`-p` 只量了前台派发与一次后台重派（§8）。

## 8. 变异与实测

**变异**（`runpick`、`parallel`、`claims`、`abandon`、`gate-parallel`、`parallel-prose`、`runctx`、`owner`、`closing`、`gate-tweak`、`tweak-prose` 一起跑）：27 刀，25 刀红——挑这一趟（不按
agent_id、不看 open、runctx 只有微调仍判读不出、不认挑出来的 runId、认不出的团队角色不判读不出）、互斥四条各去一条与没接进 H6、认领不查不记、放弃不要批准与不核 stage、
放弃那一次仍跑收口判据、冻结不核 `abandoned`、放弃记录器没接上、【微调】不说有微调开着、接手不认微调与不核一个会话一趟、两条安全审查的拦截、另建一趟不跳过微调指针、
开发角色那一句改一个字、at-tweak 又写 `current-run`。两刀本来绿：「读不到会话 id 不留痕」（判据里那两个词别的留痕也带）、「认领键不 norm」（`join` 自己就把 `web/./a.ts`
规范掉了，判据没真测到两种写法）——判据加紧之后复跑红。另加「放弃批准不看 run」一刀（第三轮安全审查之后），红。

**实测**（CLI 当前版本，`claude -p --plugin-dir <本工作树> --permission-mode manual`，放行读写、`Agent` 与几条只读的 Bash；仓库外的探针项目：一个静态页 `web/index.html`、
`web/styles.css`，手写的 `project.json`（前端认领 `web/`，测试命令是占位的 `echo no-tests`），不是 git 仓库、没有 run）。

1. 两个会话同时起：s1 `/agent-team:at-tweak 把大标题「小账本」改成「我的记账本」`，s2 `/agent-team:at-tweak 把页脚颜色改成 #888`。两边各建一趟 `mode: tweak` 的 run，各自的
   `owner.json` 记着各自的会话，**`current-run` 自始至终不在**。都走到 S5、直接派 at-frontend。
2. **实测出一个缺陷**：两边第一次派发都是前台派发（`-p` 里项目经理没带 `run_in_background`），前台派发的派发记录要等子代理跑完才由 H5a 记（`mode: foreground`），子代理跑着的
   时候门禁查不到它，又开着微调——第一轮安全审查加的「认不出就拒」拒了它的每一次写入。s2 的项目经理重派一次（后台）过了；s1 的项目经理停下、如实报告并猜测原因。修法：按
   agent_id 认不出时，按 hook 输入里的会话 id 认这个会话名下恰好一趟没收尾的微调（`via: agent-session`；子代理转录的 `sessionId` 就是主会话那一个）；会话也对不上的照旧拒。
   续上 s1 让它再派一次（仍是前台）：这次写成，`web/index.html` 记进它那一趟的认领——子代理 hook 输入里的会话 id 确是主会话那一个（设计 §7 实测项 1）。
3. s2 发「可以了，收尾」：推进 S6、跑测试、写测试报告、推进 S8、交付、收口，两趟之间互不干扰。测试报告写成了「结论：通过」（占位命令退出码 0）——上一步实测同一条命令写的是
   「跑不起来」：正文没说清，at-tweak 第 4 节补了「占位、一条用例都没跑到的算跑不起来」。
4. **认领冲突**：s1 还停在 S5（认领着 `web/index.html`）时起 s3 `/agent-team:at-tweak 把「记下每一笔收支。」改成「记下每一笔收入和支出。」`。s3 的 at-frontend 写 `web/index.html`
   被拒、以「冒泡：」停下；s3 的项目经理去磁盘核了、告诉用户是哪一趟在改（run id 与原话开头）、给出「等它收尾」与「在它自己的会话里放弃」两条路，没有绕开。
5. s1 发「可以了，收尾」走到收口；续上 s3 说「那一趟已经收口了，继续」：s3 重派、这次写成，`web/index.html` 改记进 s3 那一趟的认领——收尾之后认领自然释放。
6. 七次会话合计约 3.6 美元：s1 三次（约 190、53、52 秒），s2 两次（约 215、58 秒），s3 两次（约 14、24 秒）。没起过任何服务；`-p` 里问不了「放弃这一趟」，s3 那一趟留在探针项目里，
   探针目录随后删掉。

## 9. 终审

整条分支交一个新开的审查者读一遍（opus，看全部改动、计划、设计与账本里的裁定，另写了探针起门禁子进程复核），结论「改完再合」，没有严重的。照效果重新分级之后修了这几条，
每条先写打红的判据、修完复跑那一刀变异：

- **收尾、放弃了的那一趟还在跑的子代理不查认领**，会覆盖别的开着的微调正在改的文件（放弃时子代理往往还没跑完，最容易撞上）。查与记分开：查认领不看自己那一趟开没开、是不是
  微调（`claimCheckOf`），记照旧只记进开着的微调；at.md「放弃这一趟」补「先等派出去的人都停下」。判据「放弃了的 t1 还在跑的 a1 写 t2 认领的文件」（含完整的一趟）。
- **放弃与交付时按代码基线用 git 列「这一趟改过的文件」，并行时混进别的微调的改动，照它退回会抹掉别的会话的活**（计划本身写的）。微调里以这一趟的认领记录与实现记录为准，别的开着的
