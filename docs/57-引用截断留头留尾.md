# 引用截断留头留尾

> 2026-10-10，M4v，分支 `m4v-quote-keeps-tail`。第十五轮，从 `docs/00-开放边界.md` §3 挑的：`docs/27` §4「`quote` 截到 80 或 120 个字符，Windows 上的长路径
> 只剩开头」。

## 0. 一句话结论

- `quote`（门禁把外部值拼进回传、拒绝理由与留痕时用的那一个）原来太长的只留开头：异常消息的末尾正好是出错的文件路径，长路径的最后一段正好是文件名，
  这两样都被截掉。现在截成「头…尾」：头占上限的三分之二，尾占剩下的，一共上限那么多个码点再加一个「…」。

## 1. 修法

- `hooks/lib/trusted.mjs` 的 `clip`：不长于上限的原样；长的按码点取头（上限的三分之二，向上取整）与尾（剩下的），中间放「…」。`quote` 与退到 `quote`
  的 `inline` 都走它。受信前缀在截之前已经消去，头尾中间隔着「…」，拼不回一个前缀；引号、转义、行分隔符的处理都在截之后，照旧。
- 两份判据的写法跟着改：`tests/gate-completion.test.mjs` 的「截断」不再要求「…」紧贴收尾的引号；`tests/trusted-echo.test.mjs` 里项目根带载荷的那一格，
  路径长时载荷可能正好落在被截掉的中间，正向锚点改认那段路径里目录名的开头（它与载荷同在由项目根拼出的那一段路径里，读到它就说明那段路径过了
  `quote`），不回显的几条照旧逐条核。

## 2. 判据与变异

- `tests/trusted.test.mjs`：异常消息里的文件名留得下，开头的错误种类也在；头比尾长，一共上限再加一个「…」；默认上限同样留尾；正好上限的原样、多一个
  才截；表情放在开头、末尾、两头，两个切点都不劈开代理对。

变异（备份在仓库外，改完逐字节还原）各红：只留头（原来的样子）；只留尾；头少尾多；尾按码元切；不标截断；多留一个；不长的也截。

## 3. 实测

- 没起真实会话：`quote` 是纯函数，判据直接测它，门禁各处的用法不变。
- 分支 CI 的结果写在合并之后的收口里。

## 4. 仍然开着的边界

- **中间那一截看不到**：一个很长的值，要紧的那一段正好在中间时照样被截掉（例如长路径里的项目目录名）。
- **上限没改**：80 与 120 照旧；更长的上限会让回传变长，没有实测过多长算合适。

## 5. 没量到的

- 真实会话里带长路径的拒绝理由、【门禁】回传，项目经理读不读得懂截过的那一段。

## 6. 归属

- `hooks/lib/trusted.mjs` 的 `clip`；判据在 `tests/trusted.test.mjs`。
