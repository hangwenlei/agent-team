# M3b · 远端安装路径实测 —— 仓库公开那天，两份 README 的安装那一节当场变假

## 0. 一句话结论

**从 GitHub 公开仓库装（`marketplace add hangwenlei/agent-team` + `install ... --scope local`）
装得上，而且在本轮量到的每一条上都与 `docs/17` 那条本地目录源的路径同形**：
主会话同样被钉成 `at-pm`、四条 `/agent-team:*` 命令同样展开得到、
九个可派发角色的 `tools:` 与 `agents/*.md` 逐字一致、H1 派发白名单同样 fail-closed
且拒绝原文逐字相同、`uninstall` 之后新会话同样干净。

**唯一实质不同的那一条，正是 `docs/17` §5.4 记成「我没做」的那一条**：
`CLAUDE_PLUGIN_ROOT` 解析到**哪里**。
本地目录源解析到**源目录**（活连），**GitHub 源解析到 `~/.claude/plugins/cache/` 下那份
脱离 git 的副本**——既不是市场留下的那个 clone，也不是任何工作树。
`docs/17` §3.4.1 把这条记成「很可能」，本轮把它量成了「是」。

⚠️ **而本轮最该被记住的不是这条结论，是它照出来的一件事**：
两份 README 里那句「尚未发布到任何市场」在仓库公开的那一刻变假，
「GitHub 源的插件根解析到哪里没看过」在 §3.2 做完的那一刻变假，
**而把后一句原样塞回 README 再跑整套，772 / 0，一条没红**（§4.1 有实测记录）。
处置见 §7。

### 3.2 ⭐ 第 7 条：`CLAUDE_PLUGIN_ROOT` 指的是 cache 副本——**记录级，本轮的主结论**

`docs/17` §3.4.1 写着：

> **什么时候这条区别会变成真问题**：`source: "directory"` 的市场之外——
> GitHub 源会先 clone 进 `~/.claude/plugins/marketplaces/`，那时加载的**很可能**就是副本
> 而不是源。

**「很可能」量出来了，而且它猜中了一半、猜错了一半。**
猜中的是「加载的是副本不是源」；**猜错的是副本在哪**——不在
`~/.claude/plugins/marketplaces/`（那个 clone 一次都没被引用过），
在 `~/.claude/plugins/cache/`。

**三份独立证据：**

**一、命令正文里的展开。** `d1b1f3fd` 的转录里，`commands/at-status.md` 正文中的
`${CLAUDE_PLUGIN_ROOT}` 被展开成：

    插件的 `C:/Users/82370/.claude/plugins/cache/agent-team-marketplace/agent-team/0.1.0/stages.json`（阶段链）

**二、六份转录里搜遍三个候选路径**：

| 候选 | 命中 |
|---|---|
| `~/.claude/plugins/cache/agent-team-marketplace/…` | **有** |
| `~/.claude/plugins/marketplaces/…`（那个 clone） | **0** |
| 本仓库工作树 `C:\Users\82370\Desktop\Agent-Team` | **0** |

⚠️ **第三行差点被我判错，方法上的坑写在这里。** 第一次用
`grep -c "Desktop.Agent-Team"` 去扫，每份转录都报二十多条命中，看起来像是
「会话在读本仓库」。**那二十多条全部是假的**——探针工程自己的路径里就含着
`C--Users-82370-Desktop-Agent-Team`（scratchpad 按本仓库名压平出来的目录名）。
换成只认真实分隔符的 `Desktop\Agent-Team` / `Desktop/Agent-Team` 之后，**命中 0**。
**这是 `docs/16` §3.11 那个形状（「我查过的地方没有」≠「没有」）的镜像**：
这一次是**「我查到的命中」≠「真的命中」**，成因同样是判据比它要答的问题宽。

**三、逐字节比对。** 把 cache 副本与本仓库工作树（此刻 = BASE）整目录 diff：

    $ diff -rq --strip-trailing-cr ~/.claude/plugins/cache/agent-team-marketplace/agent-team/0.1.0/ \
                                   /c/Users/82370/Desktop/Agent-Team/
    Only in ~/.claude/plugins/cache/agent-team-marketplace/agent-team/0.1.0/: .in_use

（`.git` 与 `.superpowers` 两项已排除——前者副本没有，后者不在版本库里。）
**除了 CLI 自己加的一个 `.in_use` 标记目录，零差异。**
副本里**没有 `.git`**：`git -C <副本> rev-parse HEAD` 报
`fatal: not a git repository`。

#### 3.2.1 这三条证据支持什么、**不支持**什么——别把它读宽了

**支持的**：本轮这个会话加载的是那份 cache 副本；那份副本的内容等于 BASE；
安装记录里钉着 BASE 的哈希。

**不支持的，逐条**：

- **「往仓库推新 commit 不会改变已装的那一份」**——这是**推论**，不是实测。
  本轮**没有推过任何 commit**，也**没有跑过 `claude plugin update`**。
  副本没有 git 远端、安装记录钉着哈希，这两条让这个推论很自然，
  但**「很自然」正是 `docs/17` §3.4.1 上一轮用过的那个词，而本轮把它证伪了一半**。
  按 §5.3 记成「我没做」。
- **「`docs/17` 那条本地目录源是活连」**——那条在 `docs/17` §3.3.1 里就明写着是**推论**
  （「本轮没有去改源目录验证这一点」）。本轮同样没有去验它。
  **两条路径各有一半是推论，而两份 README 里一句都不许这么写**——措辞按此改（§7）。

### 3.3 第 4 条：主会话被钉成 `at-pm`——**记录级**

六个会话的转录里**每一个**都有 `type: "agent-setting"`、值为
`"agentSetting":"agent-team:at-pm"` 的记录（装着的五个各 3 条上下）。

`e1b7c1e4` 里 `at-pm` 自述的系统提示原文：

> 你是 **AT-PM**，项目经理，也是这个团队里**唯一能问用户的角色**。

它报的工具面是

    Agent / AskUserQuestion / Bash / Read / Glob / Write / Edit

与 `agents/at-pm.md` 的 `tools:` 声明相同（`Agent(...)` 的参数表收敛成 `Agent`）。

⚠️ **`docs/17` §4.2 那条更正在本轮仍然适用，而本轮没有机会用上它**：
`agent-setting` 记录**不是**「此刻还被钉着」的充分条件，判它要**同时**看有没有那条
`type: "system"` / `level: "warning"` 的降级告警。**本轮六个会话一条降级告警都没有**
（也没有任何 `--resume`，见 §5.2），所以两条口径给出同一个答案；
**这不等于那条判据在本轮被复核过**。

#### 3.4.1 `at-init` 不只展开了，它**真的跑完并落了盘**——这条是收尾时捡到的

**但 `at-init` 那一个在被停掉之前已经把活干完了**：收尾删探针工程时，
`app/.agent-team/` 下有 `project.json` 与 `reach.json` 两份文件

## 4. 本轮新出的两条

### 4.1 ⭐ 一句「我们没做过 X」的话，在 X 被做掉的那一刻自动变假，而**没有任何机械形状会因此改变**

`docs/11` §5.20 四记的那条是：**判据把真源选在冻结文档上，它就不是判据，是一句注释。**
本轮照出来的是它的**下一级**：**有些话根本没有真源可选。**

两份 README 的「有意不写，因为没有实测过」那一段里，M2d 留下了这一句（英文那份）：

    Neither has any marketplace that is not a local directory: a GitHub-sourced install may
    resolve the plugin root somewhere else entirely, and this project has not looked.

**它在 §3.2 做完的那一刻变假。** 而本轮的实测是：

- 把它（连同中文那半句）改对之后，整套 **772 / 0 全绿**；
- **把英文那一句原样塞回去再跑，仍然 772 / 0，一条没红。**

**成因不是哪条判据写窄了，是这一族话的形状**：「我们没做过 X」的真值取决于
**仓库之外发生了什么**（有没有人去做 X），而仓库里没有任何东西随之改变。
**它与 §5.20 四那条的区别值得写清楚**：那一条的真源存在、只是选错了（选了冻结文档）；
**这一条是没有真源**。

**拿得到的那一点，和它不假装的那些：**

处置是把这两句加进 `tests/readme-sync.test.mjs` 的 `RETIRED_CLAIMS`
（连同「尚未发布到任何市场」那一句的中英两半，共四条）。
**这条判据钉的是一张退役原话清单，不是「任何把某件事说成没做过的写法」**
——换一种措辞把同一件事说回去，它仍然不会红。
**这不是这次加进去的四条写窄了，是这一族没有更强的那条可拿**：
穷举「把某件事说成没做过」的写法是开放集合，`docs/16` §3.4 判过它的结构性上限。

⚠️ **所以这一节真正的产出不是那四条判据，是一条可照做的话**：
**每次做掉一件 README 里写着「没做过」的事，回去删那句话是收口的一部分，
而不会有任何测试提醒你。** 这与 `docs/11` §5.19 的第三问（「同一刀砍下去，
还有谁本该说话？」）是同一句，只是这一次答案是「**没有谁**」——
而「没有谁」本身必须被写下来，否则下一个人会以为有。

### 4.2 `docs/17` §5.4 那条「我没做」被做掉了，而它的**上一版猜测对了一半**

`docs/17` §3.4.1 的原话是「GitHub 源会先 clone 进 `~/.claude/plugins/marketplaces/`，
那时加载的**很可能**就是副本而不是源」。

**对的那一半**：加载的确实是副本，不是源。
**错的那一半**：副本不在 `marketplaces/`，在 `cache/`；而 `marketplaces/` 下那个 clone
**一次都没有被引用过**（§3.2 证据二）。

**这条值得单独记，理由在方法上**：那句猜测**读起来像是在说位置**
（它点名了一个具体目录），实际承重的只有「是副本不是源」那半句。
**一句推论里哪一半承重、哪一半是顺手写的，写的时候分不开，被引用的时候更分不开。**
`docs/17` 当时把整句都标成了「推论」——**那个标注是对的，也正是它救了这一次**：
如果当时把那句写成结论，本轮就是在推翻一条已经写进记录的「事实」。

**可照做的**：推论要标，而且**标的是整句**，不是句子里你自己觉得弱的那一半。

## 5. 没能验证的项——**逐条说清是哪一种**

分四类：**环境不允许** / **需要人来操作** / **结构上不可能** / **我没做**。

⚠️ **本轮六条里，五条是「我没做」、一条是「需要人来操作」——
「环境不允许」与「结构上不可能」这两类本轮一条都没有。**
这不是疏漏。`docs/17` §5.6 与 `docs/11` §5.20 二刚刚因为把「纪律禁了」错记成
「环境不允许」更正过一次，`docs/18` §5.3 又因为把「我没做」错记成「结构上不可能」
更正过一次——**为了让四类看起来齐整而往前两类里塞，正是那两次更正要防的事。**

### 5.1 「H3 / H4 / H5b / 账本回传 / `rework` 在远端安装下会不会触发」——**我没做**

见 §3.5。这几道**全都要先有一趟进行中的 run** 才有可拒的事；
本轮六个探针会话一趟 run 都没起过，所以它们走 `no-run` 分支 fail open、
退出码 0 且无输出，平台不为它们留记录。**这不是「通过」，是「没量到」。**

⚠️ **这一条本可以做，只是没做。** 要量它得先 `/agent-team:at-init` 把勘察跑完、
再把一趟 run 推到有产物的阶段——**那是一次完整流程的成本，不是一条命令的成本**，
而本轮的自变量是**加载路径**，不是流程。`docs/17` §3.5 已经在本地安装下把六道全量到过。
**但「那边量过」不是「这边量过」**，所以这一条留在这里，不折算。

### 5.2 「远端安装下 `claude --resume` 的行为」——**我没做**

`docs/17` §3.6 在本地目录源上量出了那条最难察觉的陷阱（换了工作目录续会话，
工具面整个掉光，而告警只在转录里）。**本轮一次 `--resume` 都没跑过。**

机制上它取决于 `--scope local` 把插件绑在 `<工程>/.claude/settings.local.json` 上、
而 `--resume` 按**当前 cwd** 解析——**这两件事与市场源是什么无关**，
所以「远端安装下应该同形」这个判断很自然。**但那是推论，不是实测**，
而 §4.2 刚记过一条「很自然」被证伪掉一半的推论。两份 README 的措辞按此改（§7）。

### 5.3 「仓库往前走之后，已装的那一份会怎样 / `claude plugin update` 做什么」——**我没做**

§3.1.1 量到安装记录里钉着 `gitCommitSha`，§3.2 量到加载的是一份不带 `.git` 的副本。
**这两条合起来让「已装的是个快照」很像是真的，但本轮没有推过任何 commit、
也没有跑过一次 `claude plugin update`。**

⚠️ **这一条是本轮自己的发现逼出来的**，所以它比别的几条更该被下一轮接走：
**「装上之后就冻住了」如果为真，它对一个刚公开的仓库是一条很重的用户可见行为**
（别人昨天装的，今天仓库修了 bug，他拿不到）。**而它今天只是一个推论。**

> ⚠️ **注记（同一天追加，正文不动）：这一条已经被做掉了，记录在本文件 §8。**
> 结论是「冻住」，而且比这里猜的硬一格：`claude plugin update` 比的是
> `plugin.json` 里的 `version`，**不是 commit**——上游推了新 commit 而版本号没变时，
> 它回「已经是最新版本」然后什么都不做。上面这一节的每一句仍然说的是那一轮，不改。

### 5.4 「私有仓库 / 需要凭据的远端」——**我没做**

§3.1 那句 `SSH not configured, cloning via HTTPS` 是在**公开仓库**上打出来的，
匿名 HTTPS 就够了。**换成私有仓库会走什么、要什么凭据，本轮没试。**
（这条既不是环境不允许，也不需要人来操作——本机有 `gh` 与已登录的账户；**就是没做。**）

### 5.5 「`uninstall` 对正在运行的会话有没有效」——**我没做**

与 `docs/17` §5.3 同。§3.6 验的是 `uninstall` 之后**新起的**会话；
试它要在一个活会话中途卸载，而本轮收尾前把所有探针会话都先停掉了。

### 5.6 「交互终端（真人手里那种）下的复核」——**需要人来操作**

与 `docs/15` §8.3、`docs/17` §5.5、`docs/18` §5.6 同。本轮全程 `--bg` 常驻后台会话。

## 8. 续测 · 装上之后那份副本会不会随上游更新

⚠️ **这一节是 §5.3 那条「我没做」被做掉之后追加的，同一天（2026-09-21）。**
**§0–§7 一个字没改**，只在 §5.3 末尾加了一条指向这里的注记。
上面每一句仍然说的是那一轮：那一轮确实没有推过 commit、没有跑过 `claude plugin update`。

### 8.0 一句话结论

**「装上之后就冻住」是真的，而且它冻得比 §5.3 那条推论猜的还要硬一格。**

| 你做了什么 | `marketplaces/` 那个 clone | `cache/` 那份副本（真正被加载的） |
|---|---|---|
| 什么都不做 | 不动 | **不动** |
| `claude plugin marketplace update <市场>` | **拉到上游最新 commit** | **不动** |
| `claude plugin update <插件>@<市场> --scope local`，上游动了但 `version` 没变 | 拉到最新 | **不动**，回执是「已经是最新版本」 |
| 同上，但 `version` 变了 | 拉到最新 | **新开一个版本目录**，旧的原样留着 |

**承重的是中间那一行**：`claude plugin update` 比的是 `.claude-plugin/plugin.json` 里的
**`version` 字符串**，不是 commit。上游真的往前走了一个 commit、
市场 clone 也已经站在那个新 commit 上，**只要 `version` 没变，它回
`✔ ... is already at the latest version (0.1.0).` 然后什么都不做**（§8.4.3 有原文）。

⚠️ **对这个仓库当下的直接后果，写在最前面**：
`.claude-plugin/plugin.json` 的 `version` 从 `0.1.0` 起**一次都没动过**，
而今天已经往 `main` 推了两次。**所以「别人昨天装的，拿不拿得到今天推的修复」的答案是：
拿不到，`claude plugin update` 也拿不到。**

**那怎么才拿得到**：`claude plugin uninstall` 再 `claude plugin install` 一遍。
这条路单独量过（§8.4.6，**而且是在真的 `hangwenlei/agent-team` 上量的**）：
`install` 撞上一个已经存在、内容是旧的同版本目录时，**把它整个重写**，
不是「目录在就跳过」。两份 README 按此改（§8.6）。

**第五条**：一个**已经在跑的会话**，在一次真的生效了的 `plugin update` 之后，
下一轮仍然展开**旧版本**的命令正文——与 CLI 自己打的 `Restart to apply changes.` 一致（§8.4.5）。

### 8.2 为什么是两条路，而不是一条

要量「上游动了之后会怎样」，**上游得真的动一次**。而这一节不许推本仓库。
所以拆成两条：

| | A 路 | B 路 |
|---|---|---|
| 市场源 | **真的** `hangwenlei/agent-team`（GitHub 公开仓库） | 我自己起的一个 git 远端 |
| 上游动了吗 | **没有**（不推） | **动了四次，全是真的 `git push`** |
| 量到的 | 安装路径本身的形状：浅克隆、`install` 会先刷新、`update` 在「没有新版本」时的形状，**以及「卸了重装会不会重写那份旧副本」**（§8.4.6） | 「上游动了之后」那四问 |

#### 8.2.1 B 路那个远端是怎么起来的——以及 CLI 只认哪几种源

`claude plugin marketplace add` 的 help 写着 `Add a marketplace from a URL, path, or GitHub repo`。
实测**它认哪几种**：

    $ claude plugin marketplace add file:///C:/.../at-probe.git --scope local
    ✘ Invalid marketplace source format. Try: owner/repo, https://..., or ./path

    $ claude plugin marketplace add git://127.0.0.1:9418/at-probe.git --scope local
    ✘ Invalid marketplace source format. Try: owner/repo, https://..., or ./path

    $ claude plugin marketplace add http://127.0.0.1:9/at-probe.git --scope local
    Adding marketplace…✘ Failed to add marketplace: Failed to clone marketplace repository: ...
    fatal: unable to access 'http://127.0.0.1:9/at-probe.git/': The requested URL returned error: 502

**`file://` 与 `git://` 在格式检查那一关就被顶回，`http://` 过得去**
（第三条是去连一个没人监听的端口，它已经走到 `git clone` 了）。
所以 B 路的远端必须是 **HTTP smart 协议**：

- 裸仓库 `scratchpad/.../upstream/at-probe.git`（`git init --bare --initial-branch=main`）；
- 一个约 60 行、**零依赖**的 node 脚本把 Git 自带的
  `git-http-backend.exe` 当 CGI 拉起来，监听 `127.0.0.1:8899`；
- 工作副本 `upstream/work` 用 `file://` 远端 push 进裸仓库，
  CLI 那一侧走 `http://127.0.0.1:8899/at-probe.git`。

自检：`git ls-remote http://127.0.0.1:8899/at-probe.git` 回
`b8328fc...	HEAD` / `b8328fc...	refs/heads/main`。

⚠️ **B 路那个插件不是 agent-team，是一个叫 `at-probe` 的一次性插件**
（市场名 `at-probe-marketplace`，内容只有 `.claude-plugin/` 两份清单、一个
`MARKER.txt`、一条 `commands/probe-cmd.md`）。**这是有意的**：本节要量的是
**CLI 的更新机制**，那是 CLI 这一层的事、与插件内容无关；
而换个名字同时躲开了与 `agent-team@skills-dir`、以及与 A 路那个安装的命名撞车。

**这条界限要说清楚**：B 路量到的是**机制**（`update` 拿什么当判据、副本往哪写、
运行中的会话跟不跟）。它**没有**量 `hangwenlei/agent-team` 在 GitHub 上被更新时的
那一趟具体 I/O。两边的共同点是 A 路量到的那几条（浅克隆、`install` 先刷新、
`update` 的回执形状）在两条路上**逐字同形**；不同点是 HTTPS 与本机 HTTP 的传输层。
**「传输层不影响版本比较逻辑」是推论，不是实测**，按 §8.5 记成「我没做」。

#### 8.2.2 一条走不通的路，留痕——而它作废的原因本身就是一条结论

原计划本来不打算起 B 路：**把 A 路那个市场 clone 手工倒回 `fb0c9ba`，冒充

**旧版本目录一个字节都没动，也没被删。** 再更新一次（V4，`0.2.0` → `0.3.0`）之后，
`cache/at-probe-marketplace/at-probe/` 下是 `0.1.0`、`0.2.0`、`0.3.0` 三个目录。

⚠️ **这条与 `docs/19` §3.1.1 那句「`uninstall` 不清 cache」合起来才是完整的那句话**：
cache 下的东西**只增不减**——更新一次多一个版本目录，卸载一次一个都不少。
两份 README 的卸载那一段按此扩（§8.6）。

#### 8.4.5 第 5 问：一个**已经在跑的**会话，更新之后仍然是旧的——**记录级**

`claude --bg` 起的后台会话只能收第一条消息，CLI 也没有命令能往一个活着的会话里发第二条
（`attach` 要交互终端）。所以这一条用 **`claude -p --input-format stream-json`** 量：
一个进程、一个会话、两轮用户消息，中间隔着一次真的更新。

- **第 1 轮**（此刻装着 `0.2.0` = V3）：`/at-probe:probe-cmd` → `PROBE-COMMAND-BODY-V3`；
- 第 1 轮结束、**这个会话仍然活着**时，外面 push V4 并跑
  `claude plugin update ... --scope local` → `updated from 0.2.0 to 0.3.0 ... Restart to apply changes.`；
- **第 2 轮**（**同一个进程、同一个会话**）：`/at-probe:probe-cmd` → **仍然是 `PROBE-COMMAND-BODY-V3`**。

四个会话的转录一起看（`grep -o PROBE-COMMAND-BODY-V[0-9]`）：

| 会话 | 起的时机 | 展开到 |
|---|---|---|
| `86bf522b` | 装完 V1 之后 | **V1** |
| `c7d5faea` | 上游已到 V2、什么都没跑 | **V1** |
| `42bd3cb1` | 活会话，两轮跨一次成功的更新 | **两轮都是 V3** |
| `b12d012c` | 更新到 `0.3.0` 之后新起 | **V4** |

⚠️ **这一条的证据只到「运行中的会话拿到的是旧正文」为止，别读宽。**
本节**没有**把「为什么」隔离出来：更新是**新开目录**的，
所以那个会话的 `CLAUDE_PLUGIN_ROOT` 指着的旧目录**至今仍然存在、内容仍然是旧的**
——「会话把注册表缓存在内存里」与「会话每次都去读盘，只是那个盘上的路径没变」
**两种机制会给出同一个观测**。要分开它们得去改那个旧目录再问同一个会话一次，
**我没做**（§8.5）。**用户可见的结论在两种机制下相同，机制不同**。

#### 8.4.6 ⭐ 那条真的拿得到更新的路：**卸了重装**——**记录级，这一条跑在真 GitHub 上**

§8.4.3 只回答了「`plugin update` 拿不到」，**没有回答「那怎么才拿得到」**。
而两份 README 要给用户一条能照做的路，所以这一条单独量，**而且是在真的
`hangwenlei/agent-team` 上量的**（第三个探针工程 `m3c/probe3/app`）。

`cache/<市场>/<插件>/<版本>/` 这个路径**按版本号编址**，所以「重装」撞上的正是
一个**已经存在、而且内容是旧的**同名目录——它会不会被重写，是这条路成不成立的全部。

    $ claude plugin marketplace add hangwenlei/agent-team --scope local
    ✔ Successfully added marketplace: agent-team-marketplace (declared in local settings)
    $ claude plugin install agent-team@agent-team-marketplace --scope local
    ✔ Successfully installed plugin: agent-team@agent-team-marketplace (scope: local)
    （副本 133 个文件，取一份 md5 清单 R1）
    $ claude plugin uninstall agent-team@agent-team-marketplace --scope local
    ✔ Successfully uninstalled plugin: agent-team (scope: local)
    （副本仍在——与 docs/19 §3.1.1 那条一致）

**把留下的那份副本弄成「旧的」**，两处，一处加一处减：

    $ echo STALE-EDIT-MARKER >> <副本>/roster.json
    $ mv <副本>/docs/19-远端安装路径实测.md <scratchpad>/moved-away-docs19.md

然后原地重装：

    $ claude plugin install agent-team@agent-team-marketplace --scope local
    ✔ Successfully installed plugin: agent-team@agent-team-marketplace (scope: local)
    $ grep -c STALE-EDIT-MARKER <副本>/roster.json
    0
    $ ls <副本>/docs/ | grep -c 19-
    1
    $ diff R1 R2
    （无输出）

**加进去的那行没了，搬走的那份文件回来了，整份清单与一次全新安装逐行相同。**
所以 **`uninstall` + `install` 会把那份副本整个重写，而不是「目录已存在就跳过」**
——这就是今天唯一一条真的拿得到新代码的路，两份 README 按此写（§8.6）。

⚠️ **这一条里有一处是合成的，写清楚**：让副本变「旧」用的是手工改两个文件，
**不是**让上游真的往前走。两者对这条判据来说是同一件事——
`install` 面对的都是「一个同版本、但内容与上游不一致的目录」——
**但它们不是同一个因**。**「上游真的动了之后重装能拿到新代码」是推论**，
按 §8.5 记成「我没做」。

### 8.5 没能验证的项——**逐条说清是哪一种**

分四类：**环境不允许** / **需要人来操作** / **结构上不可能** / **我没做**。

⚠️ **本节六条里五条是「我没做」、一条是「需要人来操作」。**
与 `docs/19` §5 同一条理由：为了让四类看起来齐整而往前两类里塞，
正是 `docs/11` §5.20 二与 `docs/18` §5.3 那两次更正要防的事。

#### 8.5.1 「真的往 `github.com/hangwenlei/agent-team` 推一个 commit，再从 GitHub 更新一次」——**我没做**

brief 明写「推之前先问我」，并给了「用已有的两个 commit 做对照」这条替代。
本节走了替代路线（§8.2），**所以那个问也没问**。
**这条既不是环境不允许（凭据齐备），也不需要别人操作（我自己就能推）——就是没做。**

#### 8.5.2 「HTTP 传输与 HTTPS/GitHub 传输在更新逻辑上同形」——**我没做**

§8.4 那四条结论取自一个 `http://127.0.0.1:8899` 的 git 远端。
A 路（真 GitHub）上量到的那几条与 B 路逐字同形（浅克隆、`install` 先刷新、
`update` 在没有新版本时的回执），**但「所以版本比较逻辑也一样」是推论**。
`docs/19` §4.2 刚记过一条「很自然」的推论被证伪掉一半。

#### 8.5.3 「运行中的会话到底是内存快照还是读盘」——**我没做**

见 §8.4.5 末尾那条。两种机制给出同一个用户可见结论，
分开它们要去改那个旧版本目录再问同一个活会话一次。**没做。**

#### 8.5.4 「上游真的动了之后，卸了重装能不能拿到新代码」——**我没做**

见 §8.4.6 末尾那条。量到的是 `install` **会把同版本的旧目录整个重写**
（判据是一份手工改过的副本），**没有**量「上游动了 → 重装 → 拿到新内容」这整条链。
两者之间差的正是 §8.2.2 那条：`install` 会先把市场 clone 刷新到远端最新——
**那一条本身是实测过的**，但把两条接起来仍然是推论。

#### 8.5.5 「版本号倒退、或版本号相同但 commit 更旧时会怎样」——**我没做**

本节只量了 `0.1.0 → 0.1.0`（不动）与 `0.1.0 → 0.2.0 → 0.3.0`（动）。
**上游把 `version` 改小、或者 `version` 是非 semver 的串，一次都没试。**

#### 8.5.6 「交互终端（真人手里那种）下的复核」——**需要人来操作**

与 `docs/19` §5.6 同。本节全程 `--bg` 与 `-p`，没有交互终端。
