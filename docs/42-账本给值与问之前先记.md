# 账：sha 怎么记、触达表、问之前先记、at-status 与产者交代

> 2026-10-06，M4g，分支 `m4g-ledger-and-status`。`docs/39` §5 的第三轮「账与续跑」拆成两条线，这是前一半「账」：全量审查第 28 条（「没记」
> 那一行不带值、`reach.json` 手抄不核）、第 41 条（`/agent-team:at-status` 几处报错，含「问之前先记 escalation」）、第 37 条后半（用户主动
> 改需求怎么记），以及 `docs/39` §3 的「产者交代不并派发记录」。后一半「续跑与对齐」（第 40、38、24-1 条与第 14 条的 S2 进度）另起一条线。
> 现状与证据在 `docs/39` §2.1、§2.3、§3。

## 0. 一句话结论

- **账本比对的两种行都带门禁按磁盘算出来的值**：「没记」与「记账之后被改过」；给 PM 的收尾改成先弄清是谁写的、照这个值记、不自己算、不照着磁盘改账。
- **PM 写完 `.agent-team/reach.json`，门禁按当前 `project.json` 与花名册重算核一遍**：对得上不吭声，对不上、写坏了给出正确的那一份；没有 run
  （`/agent-team:at-init`）与 run 进行中两条路都核。
- **产者交代并上门禁的派发记录**：派发记录里有、只是 `stage_roles`（旧 run 是 `roster`）没记的，单列成「漏记」，出路只有补记，不再与真漏派报成
  同一句。`/agent-team:at` 第 4 条「叫到含下级派出去的那些」与 `at-ui` 那个例子有判据钉着了。
- **问用户之前先记一条 `answer` 为空串的 escalation**，答复之后补上；`/agent-team:at-status` 的「待办升级」与 `/agent-team:at-resume` 认得出问了没答的。
- **用户主动改需求不是升级**：修订块标「用户主动提出」、记新的 `contract_sha`，要重做的照「回退」。
- **`/agent-team:at-status` 的几处报法**：sha 取 `sha256:` 之后的 12 位；当前阶段报这一段谁在干（S5 不再报成 `at-backend`）；没走到的段写「未到」；
  S5 的实现记录读内容；引插件里的文件带上 `${CLAUDE_PLUGIN_ROOT}`。

## 1. 修法

### 1.1 第 28 条：sha 怎么记、触达表

- `hooks/lib/artifact-drift.mjs`：`unrecorded` 每一条从名字改成 `{ name, actual }`——`actual` 与 `drifted` 的、【产物】回传、`rework_base` 同一个算法
  （`sha256OfContract`：先剥 BOM、把 CRLF 折成 LF）。
- `hooks/gate.mjs` 的 `buildDriftNotice`：「没记」那一行带「门禁按磁盘算出来是 sha256:…」，「记账之后被改过」那一行同样说「门禁按磁盘算出来是」。给 PM 的
  收尾原来是「去 run 目录核实磁盘内容，需要的话把 artifacts 改成与磁盘一致」——行里不带值，PM 只好自己算（M5f 里 haiku 版 PM 真的去调了
  `Get-FileHash`），带 BOM、CRLF 的产物上造出假漂移；照着磁盘改账还会把一次真漂移洗成合法（与契约那一条同一个理由，`docs/37`）。现在：先弄清是谁、
  什么时候写的或改的；写它的人回报里报过同一个值、或者是返工与同一段里重派重写的，照上面的值记；对不上又说不清的告诉用户；值一律用上面给的，
  不要自己算。收件人改不了 `state.json` 的那一支（原样冒泡）不变。
- `/agent-team:at` 第 3 节记 `artifacts` 那一句原来说「写完一段产物之后，你会收到一条【产物】回传」——对下级写的不成立，【产物】发给写它的人。改成：
  自己写的收【产物】，下级写的由它在回报里报上来；原样写进去、不自己算；回报里没带的，之后派发返回时的【账本比对】会带着门禁算的值报它「没记」。
- `reach.json`：`hooks/lib/ledger.mjs` 新增 `reachCheckNotice`（语义比较：键序、BOM、CRLF 不算不同）；`hooks/gate.mjs` 在 ledger 的两条路径上接它——
  run 在时写 `.agent-team/reach.json` 归一类（`kind` 为 `reach`），没有 run 时（`/agent-team:at-init` 的正路）在那条只为 `project.json` 留的缝旁边另开一条
  同样理由的缝：触达表的判据只有花名册与 `project.json`，与 run 无关。`project.json` 不在、有阻断或插件问题时不核（那时【触达表】本来就叫 PM 先别写，
  「正确的那一份」也算不准）。`/agent-team:at-init` 第 3 节补一句：写完门禁会核，回传里没有【触达表】就是对上了，有的话照它给的重写。
- `tests/gate-fail-open.test.mjs` 那条「正路不出声」原来往 `reach.json` 写占位的 `{}`——现在会被核出来，改成写 PM 照抄的那一份。

### 1.2 产者交代并上派发记录

- `hooks/lib/coverage.mjs` 的 `decideCoverage` 多收一个 `dispatched`（`{ 段: [角色] }`，与 H6 判「叫过」同一份；`hooks/lib/advance.mjs` 导出 `dispatchedIn`
  给它用）：派发记录里有它在那一段被派出去过的，gap 标 `dispatched: true`；别的段派过不算；读坏的记录按空集算。不选「并进叫到、一声不吭」：那样
  `stage_roles` 永远记窄，`/agent-team:at-status` 与 `at-qa` 按它展开产物时会漏掉这个人。
- `hooks/gate.mjs` 的产者交代回传：标了的单列一段「漏记」——这不是漏派（下级派出去的也算叫到），出路只有补记：PM 并进 `stage_roles` 那一段（`roster`
  里没有就一起累加），不重派、不写进 `trimmed`；收件人不是 PM 的，说补记是 PM 的动作、原样冒泡。真漏派那一段照旧；「最后一段派不出去」那一支只算
  真漏派的。
- `/agent-team:at` 第 3 节第 4 条：删掉「今天没有任何判据钉着这一句（`docs/11` §5.24）」，换成门禁会把派发记录里有、你没记的单列成漏记；「包括你的下级
  派出去的那些」与 `at-ui` 那个例子整句钉——`docs/11` §5.24 说它配机械判据、至今没写，删掉那两句全套照绿（`docs/39` §3）。

### 1.3 第 41 条：问之前先记、at-status

- `/agent-team:at` 第 4 节：问之前先往 `escalations` 追加一条，`answer` 先写空串——会话断在等答复的时候，续跑与 `/agent-team:at-status` 靠它看得见；
  答复之后把 `answer` 补成用户原话（问之前没记的照样补一条完整的），再追加修订块。返工预算耗尽那一支照改：被拒的写入连同问之前记的那一条重写，
  `answer` 补上。原来规定答复之后才记，「待办升级」结构上永远是「无」；M5、M5b 里 PM 问过用户，`state.json` 一次没写（`docs/39` §3）。
- `/agent-team:at-resume`：问了没答的（`answer` 是空串）先重问，答复补进那一条。
- `/agent-team:at-status`：契约与返工基线的 sha 取 `sha256:` 之后的前 12 位（照字面「前 12 位」只剩 5 位十六进制），PENDING 照写；当前阶段报这一段
  谁在干（有 producers 的段列 `stage_roles` 里记着的人，没记账写「本段未记账」；原来照 `stages.json` 那一段的 `role` 把 S5 报成 `at-backend`）；没走到的段
  写「未到」，不标 ✗；S5 的实现记录读内容（被拒没解决、只写了冒泡原因、「测试」一节缺了的标「未交齐」）；「待办升级」是 `answer` 为空串的；
  `hooks/lib/stages.mjs` 那个裸路径带上 `${CLAUDE_PLUGIN_ROOT}`。
- `tests/commands.test.mjs` 那条「提到的 state.json 字段都在模板里」把 `answer` 加进豁免集——它与已经在里面的 `kind` 同一种，是 escalations 每一条自己的字段。

### 1.4 第 37 条后半：用户主动改需求

- `/agent-team:at` 第 4 节：用户在对话里自己提出要改、要加的，不是升级、`escalations` 不记；照样追加修订块，标「用户主动提出」，记新的
  `contract_sha`；要回到更早一段重做的照「回退」；已经收口的另起一趟。不加类别（`docs/39` §2.1 的裁定）。

## 3. 实测

- 门禁与正文：判据与变异见 §2。
- **真实团队会话 M8**（在跑；结果补在这里）：夹具与 `docs/40` §3 的 M6 相同——停在 S5 的纯后端待办 API，架构方案里有一步「删掉项目根下旧的
  `legacy/`」，PM 必须先照 `sensitive` 问用户。三条提示词：先 `/agent-team:at-status`，再续跑到收口，再 `/agent-team:at-status`。看 PM 问之前先记
  escalation、答复之后补上，`at-status` 的新报法。

## 4. 仍然开着的边界

- **escalations 记没记，门禁不核**：问之前先记、答复之后补，都靠 PM。
- **`reach.json` 只在 PM 写它的那一刻核**：之后被人用 `Bash` 改了、或者 `project.json` 改了却没重写，`/agent-team:at-status` 照旧照它报。
- **`project.json` 有阻断、花名册读不出时不核 `reach.json`**。
- **当前段的产物在前台派发跑完那一刻不进「没记」**（M4d 剔掉的，免得每次都报刚交的）：它们的值要等下一次派发返回才出现在【账本比对】里；
  这之前靠写它的人在回报里报。
- **「漏记」只认门禁的派发记录**：记录读不出、被 `Bash` 改过、或者派发没经过门禁（平台事件丢了）时，照旧与真漏派说同一句。
- **`/agent-team:at-status` 是正文**：没有判据去跑它，报法对不对只能看真实会话（`.handoff` 第 5 项）。

## 5. 没量到的

- 会话断在等答复的时候，续跑认出问了没答的、重问（M8 的驱动当场就答，走不到这一格）。
- PM 照【账本比对】给的值记 `artifacts`、不再自己算（要一份 PM 漏记的产物）。
- 产者交代「漏记」那一支在真实会话里撞上（要 PM 把「叫到」读窄）。
- 用户主动改需求那一段。
