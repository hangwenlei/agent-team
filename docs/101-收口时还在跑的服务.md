# 收口时还在跑的服务

> 2026-10-17，分支 `claude/vigorous-franklin-2cc504`。`docs/100` 那一趟真实 run（VPS Airport 的试验 worktree，run `20261016-1552-node-filter`，插件 7.4.0，
> 桌面端起的会话，CLI 2.1.299）收口之后，维护者的会话清理现场时发现还有服务在跑。不重跑整趟 run（用户对 token 敏感），起因对着试验的转录核；
> 试验 worktree 已经删了，run 目录里的产物照转录里那几次 Write 的内容读。

## 0. 一句话结论

- **起因要更正一半**：留下的两个服务是项目经理收口之前自己起给用户看效果的（交付文档与最后一条回复都写了 PID 与怎么停），不是子代理忘了停——
  子代理在 S2、S5、S6 起过的门户、vite、静态服务都在停下之前按 PID 连进程树停了、核过端口（§1.2）。缺的是：收口那几步一句没提服务，留不留由项目经理
  一个人定、没问用户，之后照样跑了七个多小时；各角色起过什么只写在各自的散文里，收口时没有一处可核，也没人核（§1.3）。
- **修法只在正文**（§2）：六个持 `Bash` 的执行角色在停服务那一句后面加同一句——起过服务的在这一次交的 `.md` 产物里写 `## 起过的服务`、停下之前停掉、
  停不掉的写明还在跑；项目经理自己起的用完就停，要留给用户看的写进交付文档同名一节；收口第三步收齐这些记录，逐个按 PID 只读地核，再按项目根文件夹名
  列一遍进程（没记录的只列不碰），还在跑的问用户（这一问另算），批准了才按 PID 连进程树停；第五步告诉用户还在跑的在哪一节、怎么停。
- **门禁不核**（付了三样，§4）；判据钉正文七条（§3）。

### 1.3 缺的是什么

- **收口的几步一句没提服务**：`/agent-team:at` 第 6 节从验收结论、`never_invoked`、交付文档到收口标记，没有一步问「这一趟起过的东西还在不在」。项目经理起服务给
  用户看是它自己的主意，留不留也是它一个人定的；用户知道（交付文档与回复里都写了），但没有人问过他，之后没人回来停，跑了七个多小时，靠别的会话按命令行
  筛出来才停掉。
- **记在哪没有约定**：各角色都记了，写法各不相同——有的在表格的一行里、有的在一段「收尾」里、有的在「知会」里；收口时没有一个固定的地方可收，「停了」
  也只有角色自己说。
- **记哪个 PID 没有约定**：venv 的 `python.exe`、`npx`、`npm` 外面都还有一层，`$!` 给的是 Git Bash 的 PID；角色们各自挑了监听端口的那个 Windows PID，
  `at-backend` 还专门写了一段坑。留下的 66216 是启动器，项目经理报的 69424 是它下面的解释器——按哪一个连树停都停得掉整串，但两个数对不上，核的人要先弄清是哪一层。

## 2. 裁定

### 2.1 执行角色：记进这一次交的产物，停下之前停掉

六个持 `Bash` 的执行角色（`tools:` 里有 `Bash`、不是主会话：`at-backend`、`at-frontend`、`at-ui`、`at-ios`、`at-android`、`at-qa`）在停服务那一句后面紧跟同一句：

> 起过服务的，在这一次交的 `.md` 产物里写一节 `## 起过的服务`，一个服务一行：起的命令、端口、PID（Windows 上写 `taskkill` 认的那个）、停没停。停下之前——冒泡也一样——
> 把自己起的都停掉，核过进程不在了、端口不再监听；停不掉的，那一行写明还在跑，项目经理收口时照它核。

- **固定标题、写进产物**：S5 是实现记录，S6 是 `06-test.md`，S2 的 `at-ui` 是 `02-ui-spec.md`——都是这一次本来就要交的那份 `.md`，不另开文件。标题固定，
  项目经理收口时按标题收；`06-test.md` 的第一行照旧是结论，这一节跟在后面。
- **PID 写 `taskkill` 认的那个**：Windows 上 `$!` 是 Git Bash 的 PID，停服务那一句本来就要换算；用 `run_in_background` 起的拿不到 `$!`，角色照试验里的做法从监听的
  端口找。记下的是之后按它停得掉的那个数。
- **停下之前，冒泡也一样**：平台对子代理说它的后台命令会在最后一条回复之后被结束；结束的是不是整棵进程树没量（§6），所以不靠它。
- 不加「重写产物时把上一份里还在跑的那几行抄过来」：收口时按项目根文件夹名那一遍列得出来（§2.3），代价登在 §5。

### 2.2 项目经理自己起的

项目经理红线里停服务那一句后面加：

> 你自己起的服务用完就停；收口时要留着给用户看效果的，照 `/agent-team:at` 第 6 节写进交付文档的 `## 起过的服务`，与执行角色记下的一起核、问用户。

不禁止项目经理在收口时起服务给用户看：试验里用户真的点进去看了，那是有用的一步。缺的是用户的一句话和一处收口核得到的记录。也不改成「给用户命令、让他在自己的
终端里起」——那样同样要用户回来停，还多一步。

### 2.3 收口第三步：收齐、只读地核、列一遍

写交付文档那一步（第三步）加两段，排在「这一趟改了哪些文件」之后、收口那一次 Write 之前：

- **收齐**：`02-ui-spec.md`、`05-impl/` 下各份、`06-test.md` 里的 `## 起过的服务`，连同项目经理自己要留着给用户看效果的（要起就在这一步之前起）。点名的这几份从阶段链派生
  核过：持 `Bash` 的执行角色在哪一段交 `.md`，那一份就在里面（§3）。
- **逐个按 PID 只读地核**：PID 还在不在、命令行对不对得上记下的命令。Windows 上在 `Bash` 里跑 `powershell -NoProfile -Command 'Get-CimInstance Win32_Process -Filter "ProcessId=<PID>" | …'`，
  macOS、Linux 上 `ps -o pid,ppid,args -p <PID>`。**记着停了的也核**：只停掉外面一层的，到这里才看得出来。**PID 会被重用**：命令行对不上的不算还在跑，也不碰。
- **再按项目根文件夹名列一遍**：Windows 上 `Get-CimInstance Win32_Process` 筛命令行里带文件夹名的、去掉命令行里带 `Get-CimInstance` 的（`Bash` 工具那几层外壳的命令行
  带着整条命令，不去掉就列出它自己——本机核过：只筛文件夹名列出四个，全是这条命令自己和它的外壳；加上那一条，空），macOS、Linux 上
  `ps -eo pid,ppid,args | grep -F <文件夹名> | grep -v 'grep -F'`。它兜的是没记下来的：角色漏记、重写产物时丢了一行、冒泡时没写产物、`Bash` 工具的外壳。
  **记录里没有的只列不碰**：命令行里带项目根的也可能是用户自己的编辑器、开发服务器。只用文件夹名、不用整条路径：命令行里的路径有 `C:\…`、`C:/…`、`/c/…` 几种写法。
- 两条 Windows 命令都在本机的 Git Bash 里跑过（单引号包住整段，`$_` 不会被 Bash 展开）。

### 2.4 还在跑的问用户；这一问另算

- **问**：用 `AskUserQuestion`，逐个写端口、PID、谁起的、起来做什么，选项「停掉」「留着」。项目经理自己起给用户看的也在这一问里：留不留由用户定。
- **另算：不记 escalation、不动契约**——与「要不要把 `.agent-team/` 加进 `.gitignore`」那一问同一类。escalation 与修订块管两件事：会话断在等答复时续跑看得见
  这一问没答；执行角色碰到红线里那几类操作时只认修订块里批准了的那一步。这一问两样都用不上：停的是项目经理自己，答复之后当场就停；会话断了，续跑走到收口会
  照磁盘重核一遍、重问。走 `sensitive` 那一套，就得在收口前一刻改契约、换 `contract_sha`，没有人读那一块。
- **停**：用户选了停掉的，按记下的 PID 连进程树停（Windows 上 `taskkill //PID <PID> //T //F`，macOS、Linux 上 `kill <PID>`），只按 PID、不按名字或端口，停完照上面再核一遍。
  这不碰红线：红线与 `sensitive` 里那一项是「结束不是自己起的进程（按名字或端口一把杀）」，这里是用户批准过、按记下的 PID 停。
- **不停**：用户要留着的、问不了用户的（工具面里没有 `AskUserQuestion`）。交付文档那一节逐个写明结果：停了、停不掉、用户要留着（写上怎么停）、问不了没停、
  记录里没有只列出来的；什么都没有的写「没有」。第五步告诉用户这些（停不掉的、要留着的、没停的、只列出来的）在交付文档哪一节、逐个说端口、PID、怎么停。README 两半「什么时候会问你」补一句。

### 2.5 不选的

- **门禁核**：见 §4。
- **放到收口之后（第五步）再问**：交付文档那时已经写完、这一趟已经冻结，问出来的结果没有地方落。
- **项目经理连没记录的一起停**：见 §2.3，那可能是用户自己的进程。
- **改红线或 `sensitive` 那一行**：清单不变（`tests/redlines-setup-prose.test.mjs` 两个方向逐项比的那一条照旧绿），新句子跟在 `docs/43` §1.5 那一句后面，不改它。

## 3. 判据

`tests/redlines-setup-prose.test.mjs` 加七条（标题 `## 起过的服务` 只在判据里写一次，三处句子都从它拼）：

- 每个持 `Bash` 的执行角色：停服务那一句后面紧跟着「起过的服务」那一句（逐字，空白不计）。执行角色照旧从 `tools:` 派生。
- 项目经理的红线：进程那一条、停服务那一句、自己起的服务那一句三段紧挨着。
- 收口第三步：承重的句子逐句钉——收齐、逐个按 PID 只读地核（两条命令）、记着停了的也核、PID 重用不碰、按文件夹名列一遍（两条命令）、没记录的只列不碰、问用户、
  另算、按 PID 连树停（两条命令）、只按 PID、不停的两种、交付文档写明结果。
- 收口第三步点名的产物从 `stages.json` 派生：持 `Bash` 的执行角色在哪一段交 `.md`，那一份就要点到（`05-impl/<role>.md` 认作 `05-impl/`）；身份锚是实现记录与测试报告
  两类必须在派生集里（只钉「非空」挡不住少一个，`docs/16` §3.13）。
- 收口第五步：还在跑的告诉用户在哪一节、怎么停；第 6 节里不出现按名字停进程的 `/IM`、`pkill`、`killall`、`Stop-Process`。
- 项目经理「什么时候打断用户」：收口那一问另算。
- README 两半「什么时候会问你」各一句（中文那句在分界之前，英文那句在之后）。

先写判据、跑出七条红（都是缺句子），再改正文转绿。变异见 §8。

## 4. 门禁不核（三样）

门禁照旧不挂 `Bash`（`docs/40` §1.1）：这一套只在正文里。照 `docs/16` §3 开头那条付三样：

1. **拒绝的判据长什么样**：两道。一道在子代理停下（H5b、交回之前的 `handback`）：读它这一次交的产物，起过服务却没有 `## 起过的服务`、或者那一节里有一行写着
   还在跑的，拦下叫它先停。一道在收口（H6）：读各份产物的那一节，逐个按 PID 查进程，有还在跑的、又没有一条用户批准「留着」的记录，就拒收口。
2. **它打不红的那一刀**：角色用 `run_in_background` 起了服务、一个字都不写——门禁看不见 `Bash`；就算挂上 matcher，那条工具结果里只有后台任务的编号、没有 PID
   （试验转录里每一条都是「Command running in background with ID: …」），门禁不知道起没起、起的是哪一个。角色只停掉外面那层 `npm`、写「停了」，第一道照样放行。
   第二道要在钩子的时限里调平台的进程工具（Windows 上是 `powershell`/CIM），还分不出「用户要留着」与「忘了停」，除非再加一份门禁专属的批准记录——而「用户要留着」
   恰恰是试验里那一种。
3. **什么会让答案改变**：真实转录里出现记着「停了」、收口时却还在跑的服务，或者收口那一遍列漏了团队起的进程；或者平台把后台命令的 PID、结束事件交给钩子
   （`run_in_background` 的工具结果带上 PID，或者有「后台任务结束」「会话结束」的钩子事件）——那时门禁能自己记谁起了什么，第一道就不再依赖角色自己写。

## 5. 仍然开着的边界

- **只在正文里，门禁不核**（付了三样，§4）：角色照不照写、项目经理照不照核，都没有门禁兜。
- **没记下来的只靠按文件夹名那一遍**：角色漏记、重写产物时丢了上一份里还在跑的那一行、冒泡时没写产物（`at-qa` 没开跑就冒泡不写 `06-test.md`）的，收口时只能从
  那一遍里看到、只列不碰；命令行里不带项目根的（venv 启动器下面的解释器、全局装的工具）列不出来——它外面那层启动器、外壳一般带着，连树停外层停得掉。
- **文件夹名太常见**（`app`、`web` 这类）时会列出不相干的进程：只列不碰，交付文档多几行（有意）。
- **用户选了「留着」的，收口之后照样在跑**（有意，用户的决定）：交付文档写着怎么停；之后谁来停、什么时候停，不在这一套里。
- **收口之后用户再要起服务看效果的不在这一套里**：这一趟已经冻结，项目经理照用户说的办、告诉用户怎么停。
- **放弃的一趟留下的服务不核**：`/agent-team:at` 第 1 节「放弃」那一支不走收口。
- **不监听端口的进程不算「服务」**：iOS、Android 的模拟器没有说法；`at-ui` 的浏览器靠它正文里的「用完关掉浏览器」。

## 6. 没量到的

- 改完之后的一趟真实 run：角色照不照写这一节、项目经理照不照核与问（没重跑，用户对 token 敏感）。
- 子代理用 `run_in_background` 起的后台命令：平台在工具结果里对子代理说，它给出最后一条回复时那条命令会被结束；结束的是整棵进程树还是只有 `Bash` 那层外壳，没量——
  试验里各角色都在停下之前自己停了。
- 主会话的后台命令在会话结束（关掉桌面端、`claude stop`）时停不停：试验那个会话一直开着。
- macOS、Linux 上的两条只读命令与 `kill <PID>`（`npm` 拉起来的服务停不停得掉，`docs/43` §5 那一条照旧）。
- 中文或带空格的项目文件夹名：从 Git Bash 传给 `powershell` 的 `-like` 模式能不能匹配上。

## 7. 版本

挪中间一位到 7.6.0（`agents/`、`commands/` 是插件会加载的）。
