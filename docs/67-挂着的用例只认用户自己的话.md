# 挂着的用例只认用户自己的话

> 2026-10-10，分支 `r25-live-m16`。第二十五轮（实测）：上一轮（`docs/66`）给测试报告加了固定首行，真实会话没量过（`docs/66` §5）。这一趟给项目里放一条
> 本来就挂着的用例，看 `at-qa` 怎么判、项目经理怎么走。

## 0. 一句话结论

- **M16**：用户在 `/agent-team:at` 里说那条挂着的用例「跟这次无关，别改它」。项目经理在派 `at-qa` 的提示里写了判定口径——「它失败不算本趟问题……以新增用例全过，
  且除它外无其它失败为通过」——`at-qa` 照着判了「结论：通过」，理由写的是「按派发口径不算本趟问题」。它自己的正文写的是「这一趟之前就挂着的用例照样判不通过……
  要不要带着它们往下走，由项目经理问用户」。这一趟用户自己说过，结果不算错；可依据是项目经理的话——只有项目经理这么说，它也会这么判。
- **裁定**：挂着的用例只认用户自己的话说不算——契约第 1 节用户原话、第 4 节修订记录；派发提示里的判定口径、契约第 2 节与第 3 节、产品定义、架构方案都不算
  （与「不写测试」那一条同一个口径，`docs/41`）。不因它们判不通过的，照样逐条注明它们挂着、用户在哪一节说的。`agents/at-qa.md` 与 `/agent-team:at` 的 S6 那一条
  用同一句，项目经理那一侧写明派 `at-qa` 时不替用户定。门禁不读内容，这一层在正文里，判据整句钉。
- **M16b**（用户没提那条用例，插件换成改过正文的副本）：架构师在 `03-alignment.md` 里把它列成要问用户的未决问题，项目经理在 S3 问了用户（`tradeoff`），答复写成修订块；
  `at-qa` 判「结论：通过」，依据写的是「契约第 4 节修订记录 升级 #1」——正是新规矩的样子。两趟都没走到「测试报告不通过 → 问用户照现状交付」那一路。

## 2. 观察

- **派发提示压过了角色正文**：`at-qa` 照项目经理写的口径判，引的就是派发口径。正文里的规矩只在派发提示不跟它打架时才稳——所以项目经理那一侧也要写明不替用户定。
- **问在前面的那一路更顺**：M16b 里架构师把它列成未决问题、项目经理在 S3 就问了，`at-qa` 有用户的原话可引，不用等到 S6 判不通过、推进被拒再问。
- **两种派法**：M16 的项目经理都是后台派（派发记录里 `mode` 是 `background`，架构师派 `at-backend` 那一次是前台），M16b 全是前台派（`foreground`）——前台派时派发记录里
  那个人的停下行排在派发行前面（H5a 在子代理跑完之后才到）。门禁按 `agent_id` 对停下行，不看先后；前台派的子代理跑着时项目经理被挡着，改不了契约，「派出去之后才交」那一格也不受影响。
- **时间是编的，照旧**：M16 的 `history` 写的是本地时间带 `Z`（20:40Z 起，会话实际在 03:57Z 前后）；M16b 写的比真实时间晚（收口记 04:48Z，会话 04:14Z 就结束了）。
  门禁只核 ISO 形状（`docs/58` §4）。

## 3. 判据与变异

- `tests/gate-test-verdict.test.mjs` 加一条：`at-qa` 那一句紧跟在「照样判不通过……由项目经理问用户。」后面、后面接「不因它们判不通过的，照样逐条注明……」；
  `/agent-team:at` 那一句紧跟在 S6 那一条「跑不起来的放行……问用户。」后面。比较时去掉换行与空格。
- 变异（备份在仓库外，每一刀改完逐字节还原）：`at-qa` 去掉例外那一句、例外里认派发提示、去掉「照样逐条注明」、放宽成项目经理说的也算；`/agent-team:at` 改成可以替用户定、
  用户没说的照派发口径判——每一刀都有判据红。

## 4. 仍然开着的边界

- **验收那一侧没收**：`at-acceptance` 的判据来自契约与产品定义的完成定义（它的正文就这么写），项目经理写进契约第 2 节、叫产品经理写进产品定义的「挂着不算」，
  验收照样认。验收结论没过时门禁照旧要用户批准照现状交付；这一轮没改验收的正文。
- **门禁不读内容（有意）**：`at-qa` 引没引用户的原话、引的那一句在不在，门禁不核（`docs/00-开放边界.md` §2「门禁不读内容」那一族）。

## 5. 没量到的

- 测试报告首行「结论：不通过」之后推进被 H6 拒、项目经理问用户照现状交付、门禁记下批准再放行——两趟都没走到（用户的话都在前面）。
- `at-qa` 首行写坏、停下时被 H5b 拦回来改——两趟的首行都对。
