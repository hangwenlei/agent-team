# 第三轮：普查收口与最终结论

调研日期：2026-09-15
目标环境：Windows 11 / Claude Code **2.1.237**（autoUpdates 关闭，落后未版本化文档约 35 个发行版）/ Claude **桌面应用 Code 标签页**

本轮覆盖 6 个前两轮未碰的范畴：学术界实现（AgileCoder / MAGIS 及其源码）、学术界综述层面的角色索引、竞品 IDE 的 agent 格式（VS Code / Copilot / Cursor / Windsurf / Devin / Factory / Kiro / Augment / Trae / Zed）、企业多 agent 平台（Bedrock / Copilot Studio / LangGraph / Agno）、**非 GitHub 中文托管**（Gitee / GitCode / ModelScope）、以及 Anthropic 一方全部仓库的角色普查。外加两次针对剩余两个空白的对抗性定向搜索。

## 1. 最终回答

### 1.1 一段话

**有一半。**十个角色里有 **6 个**现在可以拿到授权干净、质量可用的现成正文（其中 4 个来自 Anthropic 一方、Apache-2.0）；两个「全网确认没有」的空白——**业务体验官**和**项目经理作为层级派发枢纽**——在本轮**双双被部分推翻**：业务体验官这个职能已有至少 4 个独立项目实现并打包成 Claude Code 插件/技能（`codefin-lab/skills` 的 `cf-po`、`AI-Shipping-Labs` 的 ACCEPT/REJECT 验收 agent、`phanlemanh/acceptance-gate-kit`、`dl-ezo` 的 `uat-coordinator`），层级派发枢纽的**机制**也已在 Claude Code 原生文件格式里被跑通（`fredericvilcot/clean-claude` 的 `orchestrator.md` frontmatter 带 `Task`；Anthropic 自家 `claude-security` 用 `Agent(...)` 白名单 + `role.md` 团队宪章做了完整样板）。**但依然没有任何一个成品同时具备「10 个业务角色 + 层级 + 强制顺序 + 人工签核」**——这一条经受住了三轮冲击，且本轮是被最强烈地正面撞击后依然成立的。所以答案是：**装不到成品团队，但可以装到 6 个角色的正文、2 个验收范式、1 套层级机制和 1 套门禁机制，剩下的缝合工作必须自己做。**

### 1.2 用 / 抄 / 不用 三级总表（跨三轮全部候选）

**可用性列的含义**：`可装` = 桌面应用 Code 标签页里能直接装并跑；`可拿文件` = 不是插件但 .md/SKILL.md 可直接落进自己的插件；`仅参考` = 只能读设计，不可搬运（授权或形态原因）；`不可用` = 在本环境结构性跑不了。
