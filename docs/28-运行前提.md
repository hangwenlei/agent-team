## 0. 一句话结论

门禁全是 command hook，要靠 Claude Code 启动时 PATH 上的 node 起进程；原生安装的 Claude Code 自己并不需要
Node。hook 起不来——没有 node、Node 旧到入口都解析不了、Claude Code 早于 2.1.139 丢掉 `args`、hooks 被关掉——
平台一律放行，错误不进模型的上下文；用户那边至多几行灰字，缺 node 时每道门禁只在整个进程里第一次出现，hooks
被关掉时一个字都没有。审查说「静默消失」：对模型成立；对用户，缺 node 时除了第一次也成立。平台没有给 command
hook 任何 fail-closed 的手段，插件清单也没有最低版本字段，所以这一条修不成「前提不满足就拦住」，只能修成
「前提不满足时，PM 按协议会发现并停下」：PM 在三条命令开头与每轮第一次动手之前故意写一个门禁一定会拦的
文件，拿到「在线」才往下走（例外见 §4）。另外：boot.mjs 先查 Node 版本、太旧就大声拒绝；README 写明两条前提；
CI 在最低版本的 Node 上跑门禁，并用真的旧 Node 确认它会大声拒绝。

## 1. 问题

- **门禁起不来时平台怎么做**（实测级）。exec 形式的 command hook 起不来（`Executable not found in $PATH: "node"`）
  或起来了但 exit 1（旧 CLI 丢掉 `args` 后裸 `node` 把 hook 输入当脚本读、报 SyntaxError），都按 non-blocking
  error 处理：工具照常执行，PreToolUse 不拦。command hook 的 schema 里没有 fail-closed 开关，多写的键被静默丢掉。
- **谁看得见**（实测级 + 源码级）。
  - 模型：永远看不见。`hook_non_blocking_error` 附件在转成 API 消息时是空数组。
  - 用户：每道失败的门禁在对应调用下面两行灰字（`<事件>:<工具> hook error` 加 stderr 的第一个非空行，截到
    200 字），不是红字。起不来的那一种按「事件 + 命令 + 参数」在整个进程里只报第一次——第一次写入下面 3 + 1 对，
    第一次派发 2 + 1 对，之后一个字都没有——主线程与子代理共用这张表，第一次若落在子代理里，主界面上也没有。
    起来了但 exit 非 0 的每次都报。hooks 被关掉时什么都没有。SubagentStop（stop-gate）的失败主界面从不显示。
- **Node 太旧**（源码级 + 模拟 + 真 Node 16.17.1）。门禁代码用到的最新内建是 `Object.hasOwn`（16.9）。boot.mjs
  原来用了顶层 await 与 `node:` 前缀，低于 14.13.1 时它自己就解析或链接失败，同上静默放行；14.13.1–16.8 能加载，
  但 H1 拒掉一切派发、理由不提 Node，stop-gate / deliverable / ledger 静默崩掉。
- **Claude Code 太旧**（文档级 + 推断）。`args` 从 2.1.139 起才有；更早的版本大概率把它当未知键丢掉（2.1.283 的
  schema 就是这样处理未知键的），只剩裸 `node`。本机没有早于 2.1.139 的二进制，这一条没有实测。
- **README 写着「零运行时依赖」**，而 Node 是前提。

## 2. 修法

### 2.1 门禁自检

`hooks/lib/gate-check.mjs`：PM 用 Write 写 `.agent-team/gate-check`，H3 对它一律拒——排在主线程豁免与读运行上下文
之前，所以在没有 `.agent-team` 的项目里、坏掉的 run 里、由主线程发起时都拿得到回答。拒绝理由以「agent-team 门禁
自检：在线」开头，带着门禁用的 node 版本与路径，并写明这个结果只管到这一轮用户消息结束。

匹配规则：字面路径（`resolve()` 之后按本平台分隔符切，不碰文件系统）或物理路径（`norm()`）任一的末两段恰好是
`.agent-team/gate-check`，不分大小写，不锚定项目根（用户 `/cd` 之后再 `/agent-team:at-init`，门禁认的项目根未必
是那里）。它不是控制文件：控制文件是「只有 PM 能写」，这里是「谁都不许写」。

协议只写在 `agents/at-pm.md` 的「门禁自检」一节，三条命令（`at`、`at-resume`、`at-init`）开头各有一步指过去，
`at-status` 只读、声明不做。判读只有一条能往下走：

- 工具结果**含有**「在线」→ 继续，对用户说一句自检通过（只能引用这一轮拿到的工具结果）。按「含有」判而不是「以它
  开头」：平台会在拒绝理由前面加一截 `PreToolUse:Write hook error: `，复核的 17 次健康会话里每次都带。
- 平台说文件还没读过（`File has not been read yet`，某些模型上残留的自检文件会触发）→ 先 Read 再 Write 一次。
- 其余一切 → 停下：写入成功、弹出写入确认、被用户或权限设置拒绝（PreToolUse 在权限判定之前运行，走到权限这一步
  本身就说明门禁没拦下它；权限模式挡不住自检，所以不许把原因归到权限上）、agent-team 的别的拒绝理由、平台在调用
  之前就报的错。

门禁没在跑时，PM 把一段固定的排查清单原样给用户（Node 版本与「启动时的」PATH、Claude Code 版本、`disableAllHooks`
的各个来源——含 `--settings` 与组织托管设置的 `allowManagedHooksOnly`——、`--bare`、工作区信任），不许提议在门禁
不在时继续。

**为什么反过来查**：让模型注意到「少了一条回传」靠不住；自检把健康与不健康都变成模型一定看得见的工具结果。
**为什么不用 SessionStart 标记**：续会话时，上一次成功注入的标记留在转录里、照样渲染进上下文，而这一次的失败模型
看不见——旧标记冒充新标记。**为什么不让 PM 用 Bash 跑 `node --version`**：Bash 工具的环境与 hook 进程的 PATH 可以
不同（桌面端、IDE 起的会话尤其如此）。

**第二张网**：`/agent-team:at` 写完契约、`/agent-team:at-init` 写完 `project.json` 之后，本来就必然收到一段账本回传
（契约的 sha256、触达表）。两条命令都写明：没收到就停下，照「门禁自检」一节告诉用户，不要自己补一个。它兜的是
开头自检之后门禁才掉线的情形。

### 2.2 每轮提醒

`hooks/hooks.json` 加一条 UserPromptSubmit hook：shell 形式的一行 `echo`，每轮往上下文里放一句以
`agent-team reminder:` 开头的提醒，让 PM 在这一轮第一次派发或写 `.agent-team` 之前自检。它补的是不经命令的那几条
路：续会话之后直接说「继续」、压缩之后接着跑、新会话里直接对话。挂在 UserPromptSubmit 而不是 SessionStart：后者只在
会话开头注入一次，续会话时同样的文本不再注入，恰好丢掉要补的那条路。

效果（sonnet，`-p`，CLI 2.1.283，续会话后门禁离线、说「继续」）：设计评审在探针插件上测，只改正文 5 次里一次都没有
自检，加提醒的草稿 3/3；发布版复测 3/3（会话 `da0fc51a`、`9c5ba0c1`、`e5d5ec70`），另一路独立复测 3/3。提醒两半都
承重：只删「去做自检」那半句 4/6，整段删光 3/6。

它故意不走 node，好在 node 缺失时照样出现；Claude Code 早于 2.1.139 时，只在它把 `args` 当未知键丢掉的那一支成立
（§1 的推断）。纯 ASCII，因为 Windows 没有 Git Bash 时 shell 形式退到 PowerShell 5.1，中文会乱码；整句用单引号括住，
bash 与 PowerShell 里都是字面量。

### 2.3 boot.mjs 先查 Node 版本

boot.mjs 改写成旧 Node 也能解析的写法（不用顶层 await、`?.`、`??`、`Object.hasOwn`，内建模块写 `'fs'` 不写
`'node:fs'`），第一件事比较 `process.versions.node` 与 `MIN_NODE`。太旧就不加载 gate.mjs，按 `checks.mjs` 的失败
策略表收尾：fail closed 的四道拒绝，理由写明要哪个版本、门禁用的 node 是哪一版、在哪；fail open 的四道 exit 1。
这样 Node 12.17 起（13.2 起）的「太旧」都是一句清楚的拒绝，门禁自检也拿到这句拒绝而不是假的「在线」——没有版本
检查的话，14.13–16.8 上 H3 那一支走不到缺失的内建，会报「在线」，而 H1 正在拒一切派发（复核用真 Node 16.17.1
加 V8 开关模拟缺失的内建，印证了这一点）。

`MIN_NODE` 取技术下限 16.9.0，而不是 18 或 22：取更高的数会把今天能用的人整体拒掉（RHEL 9 默认的 nodejs 16、停在
16 / 17 的 nvm 用户），而取技术下限并且在 CI 上钉住它，声明与强制是同一个数、也有实测兜底。插件只声明并强制这一个
技术下限，不给版本建议。

### 2.4 README 与 CI

- README 两半的安装一节写明两条前提（Node 在「Claude Code 启动时的」PATH 上）、门禁自检是怎么回事、哪三条命令做、
  每条消息之后也做、Node 太旧与 Claude Code 太旧时各会怎样；「零运行时依赖」改成「零 npm 依赖」，runtime deps 徽章
  撤掉；开发一节补「跑测试要 Node 22 起、`hooks/` 下的代码受最低版本约束」。
- `.github/workflows/min-node.yml`：三个系统上，测试框架跑在 Node 24，门禁子进程跑在 16.9.0（`AGENT_TEAM_GATE_NODE`）；
  仅 Linux 再装 12.17.0 与 12.22.12，交给 `tests/boot-old-node.test.mjs` 确认 boot.mjs 在它们上面能解析、按失败策略表
  拒绝。测试框架本身留在新版本上：它依赖 Node 22 起的行为（`node --test tests/` 的发现语义，`tests/readme-sync.test.mjs`
  断言它）。
- 所有门禁子进程都经 `tests/helpers/gate-runner.mjs` 一个出口起：`tests/gate-runner.test.mjs` 扫 tests/ 下的源码（跨行
  也认），别处不许拿 node 起子进程，`process.execPath` 只准出现在清单里；出口在子进程根本没跑起来时抛出来，不让空的
  stdout 冒充「放行」。断网垫片从 `--import` 的 .mjs 改成 `-r` 的 .cjs（`--import` 要 18.18 起），装上时打一行标记，
  调用方确认看到它。

## 3. 复核

**调研**。四路并行，每条结论配一位反驳者：文档与二进制里的平台事实、真实会话实测（用最小插件模拟没有 node、裸
`node`、SessionStart 标记）、版本与「不依赖 PATH 上的 node」的出路、Node 最低版本。反驳者推翻或修正了不少说法：错误
显示成灰字不是红字；缺 node 时只报第一次；SubagentStop 的失败主界面从不显示；「2.1.237 跑通过」是环境表的错标，嵌套
派发链有实测兜底的最低版本是 2.1.276（订正写在 `docs/12` 原话底下）。

**设计评审**。三个角度（平台与权限、模型能不能照做、可测性与 CI），每条反对意见配一位反驳者，下面几条成立并被采纳：
原稿把「被用户或权限设置拒了」判成「自检没做成」，实测 PM 随后主动提议「跳过自检继续」——改成一律判门禁没在跑；
原稿写「以固定串开头」，实测平台有时加前缀——改成「含有」；排查清单原稿交给模型现编——改成固定原文；原稿只在命令
开头自检——加了每轮提醒（草稿 3/3，只改正文 0/5）；原稿 `MIN_NODE` 取 18——改成技术下限 16.9，调研时一位反驳者
提出的「Windows 上 18.12 以下的 Node 读不到 hook 的 stdin、下限得是 18.13」被评审用真 Node 16.17.1 在真实 CLI 下
推翻；原稿测试基础设施有好几处会让最低版本作业空转——收成单一出口、断网垫片改 `-r`、出口在没跑起来时抛。

**实现中**。版本太旧那一支在模块求值时同步执行，用到了定义在文件末尾的 `const`（暂时性死区），判据当场红。变异：
去掉版本检查、改成字符串比较、去掉 `norm()` 的网络路径守卫（确认 `-r` 垫片下网络判据照样咬得住），都被打红。第一次
CI：Linux 与 macOS 上两条判据把 Windows 的反斜杠写法当成了跨平台的（反斜杠在那里不是分隔符），改成只在 Windows 上
测；同一次里 boot.mjs 在真的 Node 12.17.0 与 12.22.12 上解析、按失败策略表拒绝，三个系统的门禁子进程都跑在 16.9.0 上。

**独立复核**。四路，每条发现配一位反驳者：

- **变异**（隔离 worktree，85 刀，每刀还原后逐字节核对）：44 刀打红；其余是等价变异，或本地 Node 24 / 16.17.1 抓不到、
  只能靠 CI 的真旧 Node——把 `'fs'` 换回 `'node:fs'` 只有 12.17.0 那一档抓得到（12.20 起 ESM 认 `node:`），将来别把它
  换掉；顶层 await 与 `?.` 两档都抓得到。用本机的 Node 16.17.1 当门禁子进程跑全套，只有「恰好等于 16.9.0」那条锚红。
  存活的都补了判据：最低版本作业的锚只核常量、没核出口实际起的 node（出口默认值改回新版本时照样绿）；扫描按行匹配、
  调用折成两行就漏；at-pm.md 的停下、不跳过、不自己查 node、每轮都查等关键句，排查清单逐条，命令开头那一步的措辞，
  提醒挂的事件、键集与文字，理由的单行化，都删得掉。
- **真实会话**（48 个 `-p` 会话，sonnet，插件取自本分支）：健康时 17/17 第一步就是写 `gate-check`，拿到的结果每次都带
  平台前缀、每次判对；门禁不在（acceptEdits / bypassPermissions）7/7、权限拒绝（default、dontAsk）8/8 都停下给清单，
  没有提议跳过、没有要授权、没有用 Bash 绕写，48 个会话里没有一次派发。找到两处要修：
  - 没有提醒的续会话里，PM 不重做自检，还拿上一个进程的「在线」对用户说自检通过（0/6）。拒绝理由写明「只管这一轮」
    之后 4/4 重做自检；at-pm.md 加了「只能引用这一轮拿到的工具结果」，两条命令加了第二张网（§2.1）。
  - 排查清单逐字照做的只有 10/23，dontAsk 下有一次补了一条把原因引到权限模式的误导项（6/12 次把原因归到权限上）。
    权限那一支补了「权限模式挡不住自检」这句事实，复测 1/6。
- **找假在线与假报警**：`.agent-team` 是指向名字不同的目录的 junction 或软链时，`norm()` 解析出的物理路径末两段不是
  `.agent-team/gate-check`，自检永远拿不到「在线」——门禁明明好好的，PM 却判它没在跑、给出一份查不出原因的清单。
  这是本分支引入的回归，改成字面或物理路径任一命中（§2.1），补了链接夹具。另外，排查清单漏了组织托管设置
  （`allowManagedHooksOnly`、托管设置里的 `disableAllHooks`），补上。其余方向实测都不成立：别的钩子返回 allow / ask
  时 deny 胜出；PostToolUse / SubagentStop / UserPromptSubmit 条目非法时被逐条丢弃、自检照报在线（§4 已登记）；残留
  文件内容恰好是协议固定句时照样拿到在线；`.agent-team` 是文件时门禁先拒；PATH 上只有 `.cmd` 包装时 exec 形式能按
  PATHEXT 解析到。
- **正文与文档**：README 把「平台不告诉你」「自检只在命令开头和续会话后」说过头、英文半的命令代称对不上命令表；
  at-pm.md 开头把「Node 太旧」也归进「一律放行」，与 boot.mjs 矛盾；本文的若干说法（「一定会发现」「一行灰字」、
  测试框架依赖 `--import`、本机最老的二进制、提醒效果没量过）不准；HANDOFF 与判据标题里「每一条 hook 都走 node」
  「零运行时依赖」变成了假话。都改了。

## 4. 仍然开着的边界

- **自检只证明写路径门禁在跑。** 平台对 hooks.json 逐条校验；只针对 PostToolUse / SubagentStop / UserPromptSubmit 条目的
  收紧、平台不再认识这几个事件名、用户手改已安装副本的 hooks.json，都会让自检照报在线而那几道不在（实测：这几类条目
  非法时被逐条丢弃，提醒也跟着静默消失）。
- **子代理不能再派子代理时**：门禁在跑、自检通过，但 S2 的 at-product → at-ui、S5 的 at-architect → 执行角色都派不
  下去。已知成因：Claude Code 2.1.139–2.1.171 还不支持嵌套（2.1.172 才加，文档级）；2.1.217–2.1.218 默认深度 1（文档级）；
  `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 设成 1（与版本无关）；没设这个变量时默认深度先取服务端开关，服务端不发版就能
  改成 1（2.1.276、2.1.278、2.1.283 源码级）。自检不核 CLI 版本：hook 拿不到可靠的 CLI 版本（`AI_AGENT` 不是 hook 契约，
  settings 的 env 能改）。更好的修法是按症状拦：协调者派不动下游时回报一个固定串、PM 停下，四种成因都能覆盖。这一轮
  没有做。
- **hooks 整体被关掉、工作区不受信任、续会话时插件没加载**：每轮提醒也一起消失，只剩命令开头的自检、正文里那条每轮
  规矩与第二张网；不经命令时查不查看模型（复核：sonnet 照做，haiku 4.5 一次没做、直接写了 `.agent-team`）。
- **Claude Code 早于 2.1.139**：若它不是丢掉 `args` 而是拒收（没有实测，§6）——按 2.1.283 的粒度，一条非法的 PreToolUse
  条目会让整个插件不加载，at-pm、命令和提醒都不在，一眼可见；若旧版只拒收 hooks.json 而插件其余部分照常加载，提醒会随
  门禁一起消失，只剩命令开头的自检。
- **比 12.17 更旧的 Node**（10.x、11.x、12.0–12.16、13.0–13.1）：boot.mjs 仍解析不了，静默放行——由门禁自检兜住。要让它们
  也大声拒绝，入口得换成 CommonJS，这一轮没做。
- **别的钩子也拒同一次写入时**，模型只看得到其中一条理由，自检的「在线」可能被盖掉。方向安全（PM 会停下），但那样的
  项目里自检永远过不了。
- **dontAsk 模式下**，门禁修好之后，后续写入仍会被权限模式拒掉——那是另一道障碍，不归自检。
- **排查清单不总是逐字照给**：开头与结尾一句常被改写（第 1–4 条几乎逐字）。无害的改写没有再收紧。
- **一份大到转不成字符串的产物**（`docs/27` §4）与本条无关，照旧开着。

## 5. 平台事实（CLI 2.1.283）

- exec 形式（带 `args`）用 `child_process.spawn` 直接起进程，不经 shell；command 按 PATH 解析（Windows 上按 PATHEXT，
  不搜 cwd）。
- shell 形式在 Windows 上：hook 写了 `shell` 就用它；没写时找得到 Git Bash 用 bash，找不到退到 PowerShell，从不用
  cmd.exe。
- 起不来：`{status:1, spawnFailed:true}` → non-blocking；按「事件:命令+参数」进程级去重，只第一次出附件。
- exit 非 0 非 2：non-blocking，不去重，每次都出附件。附件永远不进模型上下文。
- 界面：`<事件>:<工具> hook error` 加 stderr 的第一行（截到 200 字），灰色；Stop 汇总成 `stop_hook_summary` 并通知；
  SubagentStop 的主界面上什么都没有。
- PreToolUse 在权限判定之前运行；hook 的 deny 是终局，不再走确认框、auto 分类器或 dontAsk。Write 的调用前校验（设置
  里的 edit deny 规则、「先读后写」——后者只对部分模型强制）在 hook 之前。
- hook 的 deny 理由进模型上下文时，平台有时在前面加 `PreToolUse:<工具> hook error: `。
- 多个 hook 都拒同一次调用时，模型只看到其中一条理由；一个 deny 与别的 hook 的 allow / ask 并存时，deny 胜出。
- 插件的 SessionStart 与 UserPromptSubmit hook 的纯文本 stdout 进主会话模型的上下文；钉住主线程角色时照样触发。
  SessionStart 在续会话时不再注入同样的文本。
- hooks.json 里非法的 PreToolUse 条目让整个插件不加载；PostToolUse / SubagentStop / UserPromptSubmit 的非法条目被逐条丢弃。
- 组织托管设置里的 `allowManagedHooksOnly` 或 `disableAllHooks`、用户各层设置与 `--settings` 里的 `disableAllHooks`，都会
  让插件的 hook 全部不跑，而插件的 agent、命令与 settings.json 照常加载。托管设置这一源在本机没法实测（本构建里
  `CLAUDE_CODE_MANAGED_SETTINGS_PATH` 不生效），与已实测的 flag 来源走同一分支。
- 未公开、不可用的：`type: "script"` hook（本构建禁用，写进 PreToolUse 会让整个插件不加载）、hooks.json 的 `modules`
  （默认关）。`BUN_OPTIONS="--preload …"` 能让 claude.exe 用内嵌的 Bun 跑门禁，结果与 node 一致，但路径写法稍错就会
  静默起一整个会话，平台自己也把这个变量当代码注入来防——不采用。

## 6. 没量到的

- 真的旧 Claude Code（早于 2.1.139）对 `args` 怎么处理：本机最老的是 2.1.220（Python Agent SDK 自带），没有早于 2.1.139 的
  二进制。
- 交互界面上的实际样子：探针用的是 `-p`，界面上的呈现是源码级；default 模式的确认框在 `-p` 下只表现为 `haven't granted`。
- 12.17.0 与 12.22.12 之外的旧 Node：只在 CI 上跑这两个；更旧的是推断。
- 每轮提醒：量过的只有「续会话后门禁离线、说『继续』」与「新会话里直接说继续」两种情形，sonnet，`-p`。没量的：交互界面、
  多轮 run 中间、压缩之后接着跑、sonnet 以外的模型。
- 自检协议第 2 支（`File has not been read yet`）：sonnet 上没有触发过，haiku 上触发、照做对了。
