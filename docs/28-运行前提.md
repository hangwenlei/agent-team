# 运行前提

**日期** 2026-09-29 ｜ **口径** 分支 `m3t-runtime-prereqs`，版本 `1.2.0`；修的是全量审查（`docs/24-附录-全量审查报告.md`）第 4 条。
平台行为在本机 CLI 2.1.283 上实测或从它的二进制里读出，另在 2.1.276、2.1.278 的二进制上核过关键几处

**Node 下限** 16.9.0（真源是 `hooks/boot.mjs` 的 `MIN_NODE`）

**Claude Code 下限** 2.1.276

## 0. 一句话结论

门禁全是 command hook，要靠 Claude Code 启动时 PATH 上的 node 起进程；原生安装的 Claude Code 自己并不需要
Node。hook 起不来——没有 node、Node 旧到入口都解析不了、Claude Code 早于 2.1.139 丢掉 `args`、hooks 被关掉——
平台一律放行，错误不进模型的上下文，用户那边也只有一行灰字，缺 node 时整个会话只报第一次。审查说「静默消失」，
实测比那还安静一点。平台没有给 command hook 任何 fail-closed 的手段，插件清单也没有最低版本字段，所以这一条修
不成「前提不满足就拦住」，只能修成「前提不满足时，PM 一定会发现并停下」：PM 在命令开头与每轮第一次动手之前
故意写一个门禁一定会拦的文件，拿到「在线」才往下走。另外三件：boot.mjs 先查 Node 版本、太旧就大声拒绝；README
写明两条前提；CI 在最低版本的 Node 上跑门禁，并用真的旧 Node 确认它会大声拒绝。

## 1. 问题

- **门禁起不来时平台怎么做**（实测级）。exec 形式的 command hook 起不来（`Executable not found in $PATH: "node"`）
  或起来了但 exit 1（旧 CLI 丢掉 `args` 后裸 `node` 把 hook 输入当脚本读、报 SyntaxError），都按 non-blocking
  error 处理：工具照常执行，PreToolUse 不拦。command hook 的 schema 里没有 fail-closed 开关，多写的键被静默丢掉。
- **谁看得见**（实测级 + 源码级）。
  - 模型：永远看不见。`hook_non_blocking_error` 附件在转成 API 消息时是空数组。
  - 用户：对应工具调用下面一行灰字（不是红字），只显示 stderr 的第一行。起不来的那一种按「事件 + 命令 + 参数」
    在整个会话进程里只报第一次，主线程与子代理共用一张表，所以第一次若落在子代理里，主界面上一个字都没有。
    SubagentStop（stop-gate）的失败主界面从不显示。
- **Node 太旧**（源码级 + 模拟 + 真 Node 16.17.1）。门禁代码用到的最新内建是 `Object.hasOwn`（16.9）。boot.mjs
  用了顶层 await 与 `node:` 前缀，低于 14.13.1 时它自己就解析或链接失败，同上静默放行；14.13.1–16.8 能加载，
  但 H1 拒掉一切派发、理由不提 Node，stop-gate / deliverable / ledger 静默崩掉。
- **Claude Code 太旧**（文档级 + 推断）。`args` 从 2.1.139 起才有；更早的版本大概率把它当未知键丢掉（2.1.283 的
  schema 就是这样处理未知键的），只剩裸 `node`。本机没有更早的二进制，这一条没有实测。
- **README 写着「零运行时依赖」**，而 Node 是前提。

## 2. 修法

### 2.1 门禁自检

`hooks/lib/gate-check.mjs`：PM 用 Write 写 `.agent-team/gate-check`，H3 对它一律拒——排在主线程豁免与读运行上下文
之前，所以在没有 `.agent-team` 的项目里、坏掉的 run 里、由主线程发起时都拿得到回答——拒绝理由以「agent-team 门禁
自检：在线」开头，带着门禁用的 node 版本与路径。匹配规则：`norm()` 之后末两段恰好是 `.agent-team/gate-check`，
不分大小写，不锚定项目根（用户 `/cd` 之后再 `/agent-team:at-init`，门禁认的项目根未必是那里）。它不是控制文件：
控制文件是「只有 PM 能写」，这里是「谁都不许写」。

协议只写在 `agents/at-pm.md` 的「门禁自检」一节，三条命令（`at`、`at-resume`、`at-init`）开头各有一步指过去，
`at-status` 只读、声明不做。判读只有一条能往下走：

- 工具结果**含有**「在线」→ 继续。按「含有」判而不是「以它开头」：平台有时会在拒绝理由前面加一截
  `PreToolUse:Write hook error: `。
- 平台说文件还没读过（`File has not been read yet`，某些模型上残留的自检文件会触发）→ 先 Read 再 Write 一次。
- 其余一切 → 停下：写入成功、弹出写入确认、被用户或权限设置拒绝（PreToolUse 在权限判定之前运行，走到权限这一步
  本身就说明门禁没拦下它）、agent-team 的别的拒绝理由、平台在调用之前就报的错。

门禁没在跑时，PM 把一段固定的排查清单原样给用户（Node 版本与所在的 PATH、Claude Code 版本、`disableAllHooks`、
`--bare`、工作区信任），不许改写，不许提议在门禁不在时继续。

**为什么反过来查**：让模型注意到「少了一条回传」靠不住；自检把健康与不健康都变成模型一定看得见的工具结果。
**为什么不用 SessionStart 标记**：续会话时，上一次成功注入的标记留在转录里、照样渲染进上下文，而这一次的失败模型
看不见——旧标记冒充新标记。**为什么不让 PM 用 Bash 跑 `node --version`**：Bash 工具的环境与 hook 进程的 PATH 可以
不同（桌面端、IDE 起的会话尤其如此）。

### 2.2 每轮提醒

`hooks/hooks.json` 加一条 UserPromptSubmit hook：shell 形式的一行 `echo`，每轮往上下文里放一句以
`agent-team reminder:` 开头的提醒，让 PM 在这一轮第一次派发或写 `.agent-team` 之前自检。它补的是不经命令的那几条路：
续会话之后直接说「继续」、压缩之后接着跑、新会话里直接对话。设计评审实测过只改正文的版本，续会话之后 5 次里一次都
没有自检。它故意不走 node，好在 node 缺失、Claude Code 太旧时照样出现；纯 ASCII，因为 Windows 没有 Git Bash 时
shell 形式退到 PowerShell 5.1，中文会乱码；整句用单引号括住，bash 与 PowerShell 里都是字面量。

### 2.3 boot.mjs 先查 Node 版本

boot.mjs 改写成旧 Node 也能解析的写法（不用顶层 await、`?.`、`??`、`Object.hasOwn`，内建模块写 `'fs'` 不写
`'node:fs'`），第一件事比较 `process.versions.node` 与 `MIN_NODE`。太旧就不加载 gate.mjs，按 `checks.mjs` 的失败
策略表收尾：fail closed 的四道拒绝，理由写明要哪个版本、门禁用的 node 是哪一版、在哪；fail open 的四道 exit 1。
这样 Node 12.17 起（13.2 起）的「太旧」都是一句清楚的拒绝，门禁自检也拿到这句拒绝而不是假的「在线」——没有版本
检查的话，14.13–16.8 上 H3 那一支走不到缺失的内建，会报「在线」，而 H1 正在拒一切派发。

`MIN_NODE` 取技术下限 16.9.0，而不是 18 或 22：取更高的数会把今天能用的人整体拒掉（RHEL 9 默认的 nodejs 16、停在
16 / 17 的 nvm 用户），而取技术下限并且在 CI 上钉住它，声明与强制是同一个数、也有实测兜底。建议用户用仍受支持的
LTS，但那不是插件的强制。

### 2.4 README 与 CI

- README 两半的安装一节写明两条前提、门禁自检是怎么回事；「零运行时依赖」改成「零 npm 依赖」，runtime deps 徽章撤掉。
- `.github/workflows/min-node.yml`：三个系统上，测试框架跑在 Node 24，门禁子进程跑在 16.9.0（`AGENT_TEAM_GATE_NODE`）；
  仅 Linux 再装 12.17.0 与 12.22.12，交给 `tests/boot-old-node.test.mjs` 确认 boot.mjs 在它们上面能解析、按失败
  策略表拒绝。测试框架本身留在新版本上：它依赖 Node 22 起的行为（`node --test tests/` 的语义、`--import`）。
- 所有门禁子进程都经 `tests/helpers/gate-runner.mjs` 一个出口起，`tests/gate-runner.test.mjs` 钉着别处不许自己
  起 node；出口在子进程根本没跑起来时抛出来，不让空的 stdout 冒充「放行」。断网垫片从 `--import` 的 .mjs 改成
  `-r` 的 .cjs（`--import` 要 18.18 起），装上时打一行标记，调用方确认看到它。

### 2.5 判据

- `tests/gate-check.test.mjs`：路径判定（写法、大小写、相对路径、相似路径）；三种调用者 × 三种项目状态 × 三种工具
  都拿到「在线」；`CLAUDE_PROJECT_DIR` 指向别处时照样拿到；同组的其余检查项对 PM 的自检写入一声不出。
- `tests/boot.test.mjs`：伪造版本号（预加载 `-r`），从 `MIN_NODE` 派生边界——紧挨着的前一个版本、跨位数的版本、
  真实会碰到的旧版本——每一档 fail closed 拒、fail open exit 1、自检拿不到「在线」；恰好 `MIN_NODE` 与更高的跨位数
  版本照常判定；六种加载失败下自检也拿不到「在线」。
- `tests/boot-old-node.test.mjs`：真的旧 Node（只在 CI 的最低版本作业里有）。
- `tests/gate-check-prose.test.mjs`：协议在 at-pm.md 里恰好一节；Node 版本等于 `MIN_NODE`；判读与禁令的关键句；
  命令开头指向它、豁免只读的那一条、命令里不重复写路径与固定串。上限：认不出「说反话」的改写（按 `docs/16` §3
  付三样，写在该文件头部）。
- `tests/hooks-registration.test.mjs`：提醒 hook 恰好一条、shell 形式、不带 `args`、不调 node、纯 ASCII，并在
  本机的 Git Bash 与 PowerShell 下真的原样打出来。
- `tests/readme-sync.test.mjs`：两半安装一节的 Node 下限等于 `MIN_NODE`；Claude Code 下限在两半、at-pm.md 与本文开头
  那一行一致；讲了自检；「零运行时依赖」退役。
- `tests/gate-runner.test.mjs`：单一出口、出口在没跑起来时抛、最低版本作业真的跑在 `MIN_NODE` 上、工作流的配置。

## 3. 复核

**调研**。四路并行，每条结论配一位反驳者：文档与二进制里的平台事实、真实会话实测（`-p` 与 `--bg` 起的探针会话，
用最小插件模拟没有 node、裸 `node`、SessionStart 标记）、版本与「不依赖 PATH 上的 node」的出路、Node 最低版本。
反驳者推翻或修正了不少说法：错误显示成灰字不是红字；缺 node 时只报第一次；SubagentStop 的失败主界面从不显示；
「2.1.237 跑通过」是环境表的错标，嵌套派发链有实测兜底的最低版本是 2.1.276；Windows 上旧 Node 读不到 hook 的
stdin 这一说被真的 Node 16.17.1 推翻。

**设计评审**。三个角度（平台与权限、模型能不能照做、可测性与 CI），每条反对意见配一位反驳者，下面几条成立并被
采纳：原稿把「被用户或权限设置拒了」判成「自检没做成」，实测 PM 随后主动提议「跳过自检继续」——改成一律判门禁
没在跑；原稿写「以固定串开头」，实测平台有时加前缀——改成「含有」；排查清单原稿交给模型现编——改成固定原文；原稿
只在命令开头自检——加了每轮提醒；原稿 `MIN_NODE` 取 18——改成技术下限 16.9；原稿测试基础设施有好几处会让最低版本
作业空转——收成单一出口、断网垫片改 `-r`、出口在没跑起来时抛。

**实现中**。版本太旧那一支在模块求值时同步执行，用到了定义在文件末尾的 `const`（暂时性死区），判据当场红。
变异：去掉版本检查、改成字符串比较、去掉 `norm()` 的网络路径守卫（确认 `-r` 垫片下网络判据照样咬得住），都被打红。
用本机一个第三方应用自带的 Node 16.17.1 当门禁子进程跑全套：只有「恰好等于 16.9.0」那条锚红，其余全绿。

## 4. 仍然开着的边界

- **自检只证明写路径门禁在跑。** 平台对 hooks.json 逐条校验；只针对 PostToolUse / SubagentStop 条目的收紧、平台不再
  认识这两个事件名、用户手改已安装副本的 hooks.json，都会让自检照报在线而那几道不在。
- **Claude Code 在 2.1.139 与 2.1.276 之间**：门禁在跑、自检通过，但子代理可能不能再派子代理（2.1.217、2.1.218
  默认关嵌套；`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 小于 2 时同样）。自检不核 CLI 版本：hook 拿不到可靠的 CLI 版本
  （`AI_AGENT` 不是 hook 契约，settings 的 env 能改）。更好的修法是让协调者在派不动下游时回报一个固定串、PM 停下，
  这一轮没有做。
- **hooks 整体被关掉、工作区不受信任时**，每轮提醒也一起消失，只剩命令开头的自检。
- **提醒 hook 在 macOS / Linux 的 sh 与没有 Git Bash 的 Windows PowerShell 上**，本机判据只跑了 Git Bash 与
  PowerShell 两种；CI 上三个系统各跑一种。
- **比 12.17 更旧的 Node**（10.x、11.x、12.0–12.16、13.0–13.1）：boot.mjs 仍解析不了，静默放行——由门禁自检兜住。
  要让它们也大声拒绝，入口得换成 CommonJS，这一轮没做。
- **别的钩子也拒同一次写入时**，模型只看得到其中一条理由，自检的「在线」可能被盖掉。方向安全（PM 会停下），但那样的
  项目里自检永远过不了。
- **一份大到转不成字符串的产物**（`docs/27` §4）与本条无关，照旧开着。

## 5. 平台事实（CLI 2.1.283）

- exec 形式（带 `args`）用 `child_process.spawn` 直接起进程，不经 shell；command 按 PATH 解析，Windows 上不搜 cwd。
- shell 形式在 Windows 上：hook 写了 `shell` 就用它；没写时找得到 Git Bash 用 bash，找不到退到 PowerShell，从不用
  cmd.exe。
- 起不来：`{status:1, spawnFailed:true}` → non-blocking；按「事件:命令+参数」进程级去重，只第一次出附件。
- exit 非 0 非 2：non-blocking，不去重，每次都出附件。附件永远不进模型上下文。
- 界面：`<事件>:<工具> hook error` 加 stderr 的第一行（截到 200 字），灰色；Stop 汇总成 `stop_hook_summary` 并通知；
  SubagentStop 的主界面上什么都没有。
- PreToolUse 在权限判定之前运行；hook 的 deny 是终局，不再走确认框、auto 分类器或 dontAsk。Write 的调用前校验（设置
  里的 edit deny 规则、「先读后写」）在 hook 之前。
- 多个 hook 都拒同一次调用时，模型只看到最后完成的那一条理由。
- 插件的 SessionStart 与 UserPromptSubmit hook 的纯文本 stdout 进主会话模型的上下文；钉住主线程角色时照样触发。
- 未公开、不可用的：`type: "script"` hook（本构建禁用，写进 PreToolUse 会让整个插件不加载）、hooks.json 的
  `modules`（默认关）。`BUN_OPTIONS="--preload …"` 能让 claude.exe 用内嵌的 Bun 跑门禁，结果与 node 一致，但路径
  写法稍错就会静默起一整个会话，平台自己也把这个变量当代码注入来防——不采用。

## 6. 没量到的

- 真的旧 Claude Code（早于 2.1.139）对 `args` 怎么处理：本机只有 2.1.276 起的二进制。
- 交互界面上的实际样子：探针用的是 `-p` 与 `--bg`，界面上的呈现是源码级。
- 12.17.0 与 12.22.12 之外的旧 Node：只在 CI 上跑这两个；更旧的是推断。
- 每轮提醒在真实会话里对 PM 的效果：设计评审测过只改正文的版本（0/5）；加上提醒之后的效果，见 §3 待补的复核。
