# 104 单个微调

**日期**：2026-11-05　**版本**：7.9.0　**设计**：`docs/superpowers/specs/2026-11-05-边看边改微调与会话归属-design.md`（§5.3–§5.5、§5.8、§8 第 2 条）　**计划**：`docs/superpowers/plans/2026-11-05-单个微调.md`

---

## 0. 一句话结论

新命令 `/agent-team:at-tweak <要改什么>` 起一趟微调：`state.json` 的 `mode` 为 `"tweak"`，门禁按 `stages.tweak.json` 的短链判（S1 记原话 → S4 复核小不小、写派发 →
S5 来回改 → S6 跑测试 → S8 交付），项目经理直接派负责的开发角色，用户点「可以了，收尾」门禁才放它推出实现段；没有验收段，收口读测试报告。只有用户发了这条命令才建得成微调。

## 1. 起因

用户：小改动（换全站字体、改一个小标题、弹窗换抽屉、后端小功能）不该也走产品定义、架构方案、派发裁决、业务验收；要「边看边改」，改了给他看、他说可以了才收尾，
但又不离开团队（记录、写路径隔离、测试照旧）。第一步（`docs/103`）做了「一趟只归一个会话」，这一步做单个微调，第三步做并行。

## 2. 裁定

### 2.1 微调照旧用 `current-run`

第二步只做单个微调：微调像完整的一趟一样由 `current-run` 指着，运行上下文、H2、H3 这些现成的机制不用改认法。按会话认这一趟、微调不写指针、微调与完整一趟的互斥、
认领文件都在第三步。代价：第二步里「有一趟没走完又起微调」照 `/agent-team:at` 第 1 节那一问走（续跑还是放弃），与今天相同。

### 2.2 键名叫 `mode`

设计里叫「种类键」，计划写成 `kind`；`state.json` 的已知键两两至少差四步（拼错时只指向一个，`tests/state-unknown-keys.test.mjs`），`kind` 与 `run_id` 太像，改叫 `mode`。
取值 `full`、`tweak`；缺、坏值都按 `full` 读（坏值 `validateState` 报），模板写 `"full"`，可省（没有它的旧 run 是完整的一趟）。

### 2.3 短链沿用段号与产物名

`stages.tweak.json` 只有 S1、S4、S5、S6、S8，段号与产物名同正常链：`at-status`、`at-resume`、门禁回传与各角色正文里「S5」「实现记录」这些说法在微调里意思不变，
测试结论、收口、交付快照、新鲜度这些判据能直接认。S6 由项目经理产出，靠段上的 `"test": true` 被认成测试段（正常链不带，照旧认 `at-qa`）。

### 2.4 选链与 `mode` 的守卫

选链只问 `tweak.mjs` 的 `stagesFileFor`（运行上下文、H6、【会话】三处）。H6 不许建好之后改 `mode`（`decideModeKey`）。**写成 `"tweak"` 要有门禁记下的 `/agent-team:at-tweak`**
（安全审查连提三条：`state.json` 里自报的 `mode` 能换链、能放宽派发白名单、读不出旧状态时放行）：原话记录加 `command`（`at`、`at-tweak`），建 run 那一次看这个会话挂着的、
还没绑也没作废的记录，`state.json` 坏了在修时看 run 目录里绑上的那一份；需求稿批准只沿用这个会话还挂着的命令（又一条安全审查：旧的 at-tweak 不能让之后的需求稿建成微调）。
不带参数的 `/agent-team:at-tweak` 记不下原话，正文叫用户带着要改的重发。

### 2.5 派发白名单只换项目经理两行

不另放一份花名册：H1 在门禁记过（run 目录绑着 at-tweak 原话记录）、没收口的微调里用 `tweakRoster(roster, 短链)`，只把 `__main__`、`at-pm` 的 `can_delegate_to` 换成短链里不归
项目经理的那几段的参与者；别的花名册用处（触达表、覆盖、项目校验）照旧用 `roster.json`。正常一趟里项目经理派开发角色照旧拒。

### 2.6 没有验收段的链

短链收口照「验收整段裁掉」那一套读测试报告：通过放行，跑不起来、不通过、读不出要用户批准「照现状交付」（批准绑在测试报告上）。只对带 `"test": true` 测试段的链成立——
一开始按「有测试段就算」放宽，撞了「正常链被改坏、丢了验收段要留痕」那条判据，收窄了。

### 2.7 「可以了，收尾」

两个批准记录器认它（`AskUserQuestion` 里干净地单选，或者对话里单独发这一句），`current-run` 那一趟是微调、停在实现段、不归别的会话时，往 `approvals.jsonl` 追加
`kind: tweak-done`、绑门禁按磁盘算的契约 sha 的一行。H6 推出实现段时要有一条等于现在契约 sha 的记录：用户之后又提了一轮（契约加了修订块）就不算了，要重新问。
这一行不算返工批准（`readGrants` 只认带 `covers` 的行）。

### 2.8 其余

- 放弃收尾（完整的一趟与微调）挪到第三步：照旧用 `current-run` 时切走指针就等于放弃，显式的放弃收尾要等微调离开指针才有用。
- 文件锁（批准记录、项目一级原话记录共用 `withFileLock`）遇到 `EPERM`、`EACCES`、`EBUSY` 也等：全量负载下并发判据丢过一条，Windows 上别的进程正在删锁文件时独占创建报
  `EPERM`，原来只认 `EEXIST` 就放弃加锁、不等就写。
- 正文：新命令 `commands/at-tweak.md`；五个开发角色逐字同一节「在微调里」；项目经理「你在哪一段」补微调、门禁自检的命令清单加 at-tweak；at-status 标「（微调）」、at-resume
  照 at-tweak 续跑、at-init 末尾一句；`stages.produces.md` 一节；README 两半命令表与门禁自检那一句。at-tweak 里「谁改」不写死角色名（命令判据禁止写死班底），指短链 S5 的
  产者与 `project.json` 的 `available_roles`。

## 3. 判据

- `tests/tweak.test.mjs`：常量、`modeOf`、`stagesFileFor`、`tweakRoster`、短链与正常链的对应、`testStageOf` 认 `test`、`trimmedCloseBlock` 在短链上、「可以了，收尾」的认法与 H6 判定。
- `tests/gate-tweak.test.mjs`：门禁子进程——按 `mode` 选链、项目经理写 S6、`mode` 不许改、建微调要 at-tweak 原话记录（没发、发的是 at、别的会话发的都拒）、修坏的
  `state.json` 看 run 目录、`mode` 写坏按正常链读、H1 换白名单（与不换的几种）、推出 S6 读测试结论、收口读测试报告与照现状交付、「可以了，收尾」记与核、at-tweak 的原话绑进
  run 目录、**一整趟微调从建 run 走到收口**（每次写入都过 H3、H4、H6 与账本）。
- `tests/tweak-prose.test.mjs`：at-tweak 的各节、整句钉住的问法、点名的 at.md 小节真的在那一节、五个开发角色那一节逐字相同、别的正文都提到微调。
- 配套：`state-unknown-keys`、`templates`（`mode` 进可省的键）、`version-bump`（`stages.tweak.json` 是插件会加载的）、`commands`（六条命令）、`plugin-name-sync`（两条 matcher）、
  `user-words`、`gate-brief`（需求稿沿用命令）、`gate-owner`（at-tweak 的【会话】）。

## 4. 门禁不核（三样）

S4 复核「小不小」、派发里写的「谁改、改哪些文件」、每一轮改完问没问用户、测试有没有改成新样子，门禁都不核（只核「可以了，收尾」记没记、测试报告第一行）。

- **拒绝的判据长什么样**：推进出 S4 时要 `04-dispatch.md` 里列着的文件都在某个开发角色的 `paths` 里、而且没有新接口；推进出 S5 时要实现记录的「测试」一节点名了改过的行为。
- **它打不红的那一刀**：项目经理把一个要改接口的需求写成「只改前端」，或者改了行为却在「测试」一节写「纯样式」。读懂改动才分得出，门禁读不懂。
- **什么会让答案改变**：真实微调的转录里出现大改动被当成微调走完、或者行为改了却没有测试。

## 5. 仍然开着的边界

- 「算不算小」靠项目经理复核与用户的选择，门禁不判（§4）。用户坚持照微调继续的照走。
- 微调与完整的一趟互斥靠 `/agent-team:at` 第 1 节那一问（第三步改成门禁按会话判）；同一时刻只能有一趟由 `current-run` 指着。
- 放弃收尾（完整的一趟与微调）在第三步。
- 不带参数的 `/agent-team:at-tweak` 建不了微调：要用户带着要改的重发（正文写明）。
- `-p`、后台会话里问不了「可以了，收尾」：用户要在对话里单独发这一句；问不了也发不了的停在实现段。
- Bash 写 `state.json` 与 run 目录的原话记录照旧挡不住（既有边界：门禁不加 Bash 的 matcher）。
- 开发角色「不起页面服务给用户看、不截图」、`at-ui` 只在要设计帮忙时叫，都只靠正文。

## 6. 没量到的

- 交互会话里来回改两轮以上（实测在 `-p` 下只改了一轮，选择题换成在对话里单独发那一句，见 §8）；交互会话里起本地页面服务、用户刷新看。
- 来回好几轮时每一轮的时间与 token（一轮的数在 §8）。
- 微调里 `at-ui` 被叫去做设计的样子。

## 8. 变异与实测

**变异**（`tweak`、`gate-tweak`、`tweak-prose`、`gate-brief`、`user-words`、`gate-owner`、`state-unknown-keys` 一起跑）：18 刀，17 刀红——`modeOf`、`stagesFileFor`、`tweakRoster`、
建微调不核 at-tweak、`mode` 改了也放、H1 不核原话记录、H1 已收口也换、测试段不认 `test`、短链收口不读测试报告、不核「可以了」、「可以了」不看备注、「可以了」不看停在哪段、
需求稿沿用旧命令、【会话】不认 at-tweak、原话记录不认 at-tweak、一个开发角色那一节改了一个字、`validateState` 不报坏 `mode`。「正文丢了『可以了，收尾』的问法」那一刀本来绿
（第 3 节别处也提到这个标签，判据只看字在不在），判据改成钉整句之后复跑红。

**实测**（CLI 2.1.310，`claude -p --plugin-dir <本工作树>`，仓库外的探针项目：跑过 at-init、一个小网页、测试命令是占位的 `echo no-tests`、还没有 run）。
一个会话分四次（`--resume` 续上，会话 id 不变、归属一直对得上）：

1. `/agent-team:at-tweak 把 web/index.html 页面上的大标题「小账本」改成「我的记账本」，浏览器标签页的标题不用动`：建出 `mode` 为 `tweak` 的一趟，原话记录绑进 run 目录、
   `command` 是 `at-tweak`，归属记下。之后 API 报 TLS 握手失败、会话中断（网络，与插件无关）。
2. 续上：写契约推进到 S4、写 `04-dispatch.md` 推进到 S5，项目经理直接派 `at-frontend`（H1 在微调里放行）；前端只改了 `<h1>`、`<title>` 没动，实现记录写明只改文案、
   没有新行为、不加测试；项目经理去磁盘核了文件与实现记录。起本地页面服务要权限确认，`-p` 里批不了，改叫用户直接用浏览器打开文件。它想用 `AskUserQuestion` 问
   「可以了，收尾」——`-p` 里没有这个工具——照正文请用户在对话里单独发那一句，停在 S5。
3. 发「可以了，收尾」：approval-prompt 记下（`kind: tweak-done`、`source: prompt`、绑契约 sha）；推进到 S6，跑测试命令，如实写「结论：跑不起来」；推进到 S8、写交付文档，
   请用户批准「照现状交付」（说清它替不了）。
4. 发「照现状交付」：记录器把批准绑在测试报告上（`product: 06-test.md`），项目经理算 `never_invoked`、写 `closed_at` 收口，门禁放行；交付里写明没有自动化测试、页面没人在
   浏览器里看过。四次合计约 0.81 美元、约 6 分钟（不算中断的那一次）。

## 9. 终审

整条分支交一个新开的审查者读一遍（opus，看全部改动、计划、设计与账本里的裁定），结论「改完再合」。照效果重新分级之后修了这几条，每条先写打红的判据：

- 测试报告第一行读不出时，拒绝理由叫「重派 at-qa」——短链的测试报告是项目经理自己写的，at-qa 在微调里派不出去。改成按测试那一段的产者说：项目经理自己写的，
  叫它照格式重写第一行（`test-verdict.mjs` 的 `testBlock` 带 `writer`）。判据 `tweak.test.mjs`「testBlockText：短链上…」。
- 微调里派非开发角色，H1 的拒绝理由说的是花名册（「它不在可派名单里」），项目经理读不出该怎么办。改成说微调只派开发角色、要产品定义、架构、测试或验收的
  不算微调，改走 `/agent-team:at` 另起（`gate.mjs` 的派发白名单那一支，`delegationRoster` 报 `tweak`）。判据 `gate-tweak.test.mjs` 那一条。
- 建微调那一次 `stage` 写的不是第一段，会建出一趟谁都推不动的 run（推进出 S1 的判据全落空）。H6 拒，理由说要写第一段（`decideModeKey` 收 `firstStage`）。
- 微调停在 S5、实现记录交齐时，【阶段】那一句指向 `/agent-team:at` 第 3 节的做法、不提「可以了，收尾」——推进时才被 H6 拒。改成微调专用的一句
  （`ledger.mjs` 的 `IMPL_RECORD_TWEAK_NOTE`，指向 at-tweak 第 3 节、先问那一句）。判据 `gate-tweak.test.mjs`「微调停在 S5、实现记录交齐…」。
- 正文缺步：`at-resume` 第 4 节对谁都说「S5 派 at-architect 分发」、第 2 节停在 S4 要核落盘清单；at-tweak 没说建 run 之前核登记的 skill、`04-dispatch.md` 没要求
  记代码基线（收尾列改了哪些文件靠它）、测试之后又要改的怎么走；`at.md` 第 1 节替只差收口的那一趟收口时只读验收结论。逐条补上，判据钉在 `tweak-prose.test.mjs`。
- HANDOFF 与命令判据的标题里写死的命令条数改成不报总数。

没修、留着的（不影响走通）：

- 管理类修订（敏感操作批准、环境阻塞、返工预算的答复）也会让「可以了，收尾」作废——它绑的是整份契约的 sha。作废的出路是再问一次，代价是多问一句；要改就绑在去掉
  `ADMIN_KINDS` 修订块之后的契约上。
- H6 按写入之后的 `mode` 选链：去掉 `mode` 与收口写在同一次时，拒绝理由讲的是缺验收、不是 `mode` 不许改。两者都拒，只是理由绕了一步。
