# H1 与花名册：调用者认不出就拒、项目经理只能是主会话、带 name 的派发、state.json 写裸名

> 2026-10-06，M4i，分支 `m4i-h1-and-roster`。`docs/39` §5 第四轮「H1 与花名册」：全量审查第 35 条（`agent_type` 为空串或非字符串时 H1
> 整段放行；项目经理被拒时文案叫它「冒泡给上级」）、第 42 条（开了 agent teams 时带 `name` 的派发起成 teammate，H5a 把它当旧版 CLI）、
> 第 22 条剩下的两点（主会话被设置里别的 agent 盖住时自检不报身份；谁都能把 `at-pm` 派成子代理）、第 36 条（`roster`、`stage_roles` 写全名
> 时按段判据失效；派发裁决模板叫 S4 写 `never_invoked`；`roster` 与 `never_invoked` 的交集不核）。现状与证据在 `docs/39` §2、§3。

## 0. 一句话结论

- **认不出调用者就拒**：hook 输入里的 `agent_type` 在、却不是非空字符串时，H1 拒（原来走「花名册外的调用者放行」）。缺失与 null 照旧是主线程。
- **项目经理被拒时说由谁派**：项目经理（与主线程）派花名册外的角色被拒，理由说那个角色由谁派（从花名册现算），不再叫它「冒泡给上级」。
- **项目经理只能是主会话**：任何调用者派 `at-pm` 一律拒——花名册外的也拒，裸名也拒。主会话被设置里别的 agent 盖住时，自检的「在线」
  后面说清身份与出路（去掉那一项设置，或者 `claude --agent agent-team:at-pm`）。
- **不支持 teammate**：受管辖的派发带非空 `name` 一律拒（与 `isolation` 同形）；README 两半写明。
- **state.json 写裸名**：`validateState` 报带插件前缀的角色名（`roster`、`stage_roles`、`trimmed`、`never_invoked`）与 `roster` ∩ `never_invoked`；
  `/agent-team:at` 写明记账用裸名；派发裁决模板不再叫 S4 写 `never_invoked`。

## 1. 修法

### 1.1 第 35 条：认不出调用者、项目经理被拒时的出路

- `hooks/lib/decide.mjs` 的 `decideDelegation`：`agent_type` 在、却不是非空字符串（空串、数字、对象、布尔）时拒——`callerOf` 会把它原样当名字，
  花名册里查不到，走「未登记的调用者放行」，一个畸形字段就绕过了整个 H1。拒绝理由叫收件人停下、原样告诉用户（多半是 Claude Code 改了 hook
  输入的形状，或者别的插件改写了它）。缺失与 null 照旧是主线程（`callerOf` 不动）。字面量 `"__main__"` 当 `agent_type` 那一格照 `docs/39` 保持登记。
- 项目经理（与主线程）被拒时：原来叫它「冒泡给上级」——它没有上级。改成说那个角色由谁派，从花名册现算（不点名门禁内部的哨兵 `__main__`，
  也不点名调用者自己）：一个派发者时「派它」，几个时「派其中一个」，没有时说它不是这支团队里干活的人。不是项目经理的照旧冒泡。

### 1.2 第 42 条：带 name 的派发

- `decideDelegation`：受管辖的调用者派白名单里的角色时，带非空 `name` 拒——开了 agent teams 时，带 `name` 的 Agent 调用起的是 teammate，不是
  子代理：门禁按子代理的返回与停下核它交没交、记派发记录，teammate 不走这一条，它停下时门禁看不见（H5a 把 `teammate_spawned` 当成旧版
  CLI 那一格，派出去那一刻就报缺、不记派发记录）。与 `isolation` 同形：排在白名单之后（目标本身不许派时报白名单那条），花名册外的调用者不管。
  `name` 是调用方这次给的参数，过 `inline`（`docs/27` §2.1）。
- README 两半的「已知边界」各加一条：不支持 agent teams 的 teammate。

### 1.3 第 22 条：项目经理只能是主会话

- `decideDelegation`：任何调用者派 `at-pm` 一律拒，排在「花名册外的调用者放行」之前——主会话被设置里别的 agent 盖住时，它就是花名册外的
  调用者；子代理里的 `at-pm` 带着项目经理的写权限（契约、控制文件），却不是主会话。裸名 `at-pm` 也拒：门禁按剥前缀的名字认项目经理，起出来的
  子代理同样会被当成它。别的插件的同名 agent（带别的前缀）不归本门禁管。
- `hooks/lib/gate-check.mjs` 的 `selfCheckIdentity`（接在自检拒绝理由的末尾）：hook 输入带 `agent_type`、不是项目经理、没有 `agent_id`（子代理才带）
  时，说发起自检的是谁（设置里的名字，过 `quote`）、这样跑不了团队（派发不归花名册管，第一次写 `state.json` 就被拒）、停下来告诉用户出路：
  去掉设置里的 `agent`，或者 `claude --agent agent-team:at-pm` 起会话（CLI 2.1.286 的 `--agent`：「Overrides the 'agent' setting」）。
- README 两半的「已知边界」各加一条：设置里的 `agent` 会盖掉项目经理，出路同上。

### 1.4 第 36 条：state.json 写裸名

- `hooks/lib/state.mjs` 的 `validateState`：`roster`、`stage_roles`、`trimmed` 的键、`never_invoked` 里带插件前缀的角色名各报一次（同一个名字只报一次），
  说写裸名——带前缀的对不上 `stages.json` 的产者名，按段的判据认不出，没有派发记录时缺产物的推进会被放过、【阶段】哑掉。`trimmed` 的键带前缀、
  裸名是产者的，不再另说它「不是任何阶段的产者」。`roster` 与 `never_invoked` 的交集也报（`/agent-team:at` 第 6 节叫 PM 写完自查，此前门禁不核）。
  这些问题经写 `state.json` 时的账本回传报给项目经理。
- `/agent-team:at` 第 3 节第 4 条：角色名写裸名——派发时 `subagent_type` 写全名，记账不带前缀，四个字段都一样。
- `templates/04-dispatch.md` 第 1 节：不再说「后者写进 state.json 的 never_invoked」——它收口时才算（第 6 节）。

## 3. 实测

探针（SDK 宿主、`sonnet`、CLI 2.1.286；插件副本里另加了一道只记 hook 输入的 PreToolUse hook，仓库里没有它）：

- **M10**：项目里放一个自定义 agent `my-main`，`--agent my-main` 起会话，叫它写 `.agent-team/gate-check`、再派 `agent-team:at-pm`。主线程的
  hook 输入里 `agent_type` 是 `"my-main"`，没有 `agent_id`——身份那一句依赖的条件在真实会话里成立（`docs/39` §6 第 22 条那一格）。自检回「在线」，
  后面跟着身份与出路那一句；派 `at-pm` 被 H1 拒，理由是新的那一句。
- **M10c**（对照）：照常由插件把主会话钉成项目经理，跑 `/agent-team:at-init`。主线程的 `agent_type` 是 `"agent-team:at-pm"`，同样没有 `agent_id`；
  自检只回「在线」，没有身份那一句。
- 收尾：两个会话都是 SDK 宿主；`~/.claude.json` 里没有 `lastGracefulShutdown: false`，`~/.claude/jobs` 只有 `pins.json`，没有留下的进程；
  插件副本重新同步过，探针 hook 删了。

## 4. 仍然开着的边界

- **H1 对花名册外的调用者照旧放行**：主会话被设置里别的 agent 盖住时，它能直接派任何团队角色（派 `at-pm` 除外）。门禁不把它当项目经理，
  也就不按花名册管它的派发——自检的身份那一句叫它停下，靠的是它照做。
- **身份只认 `agent_type` 与 `agent_id` 在不在**：没有 `agent_id` 的子代理（旧版 CLI 不带它）来自检，也会收到身份那一句；执行角色不做自检，碰不到。
- **teammate 只在 H1 拦**：H5a 照旧把 `teammate_spawned` 当成未知形状；花名册外的调用者带 `name` 起的 teammate 不归门禁管。agent teams 下 teammate
  停下时触发哪个事件、工具表里有没有 `SendMessage`，没量（`docs/39` §6）。
- **`validateState` 只报、不拦**：带前缀的名字与交集在写 `state.json` 之后的回传里报，H6 不拒这次写入。
- **字面量 `"__main__"` 当 `agent_type`**：照 `docs/39` 保持登记——堵它要改门禁内部的哨兵传递。

## 5. 没量到的

- agent teams 下带 `name` 的派发：没开实验开关跑过，H1 拒 `name` 只在判据里量过；teammate 停下时触发哪个事件，照旧没量（`docs/39` §6）。
- 主会话被盖住之后，那个 agent 收到身份那一句会不会停下告诉用户：M10 里探针 agent 被叫去原样贴出返回，没让它自己定。
- 带前缀的角色名在真实会话里写进 `state.json` 时的回传：真实会话里项目经理写的一直是裸名，这一格只有判据量过。
