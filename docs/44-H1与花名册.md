> 整段放行；项目经理被拒时文案叫它「冒泡给上级」；主线程被拒时理由里写着 `__main__`）、第 42 条（开了 agent teams 时带 `name` 的派发起成
> teammate，H5a 把它当旧版 CLI）、第 22 条剩下的两点（主会话被设置里别的 agent 盖住时自检不报身份；谁都能把 `at-pm` 派成子代理）、第 36 条

## 0. 一句话结论

- **认不出调用者就拒**：hook 输入里的 `agent_type` 在、却认不出（不是非空字符串，或者只剩插件前缀）时，H1 拒派发、H3 拒写入（原来都走
  「花名册外的调用者放行」）。缺失与 null 照旧是主线程。
- **项目经理被拒时说由谁派**：项目经理（与主线程）派花名册外的角色被拒，理由说那个角色由谁派（从花名册现算），不再叫它「冒泡给上级」；
  主线程被拒时理由说「主会话」，不写 `__main__`。
- **项目经理只能是主会话**：任何调用者派 `at-pm` 一律拒——花名册外的也拒，裸名也拒；说法按调用者分（项目经理自己：at-pm 就是你；团队里
  别的角色：冒泡；花名册外的：只说项目经理只能是主会话）。主会话被设置里别的 agent 或启动时的 `--agent` 换掉时（实测：`agent_type` 是那个
  名字、没有 `agent_id`），自检与 H1、H3、H4 的拒绝理由末尾都说清身份与出路。
- **不支持 teammate**：受管辖的派发带非空 `name` 一律拒（与 `isolation` 同形）；README 两半写明。
- **state.json 写裸名**：`validateState` 报带插件前缀的角色名（`roster`、`stage_roles`、`trimmed`、`never_invoked`）、`roster` ∩ `never_invoked`、
  项目经理被记进 `roster` 或 `stage_roles`；`/agent-team:at` 写明记账用裸名；派发裁决模板不再叫 S4 写 `never_invoked`。

## 1. 修法

### 1.1 第 35 条：认不出调用者、项目经理被拒时的出路

- `hooks/lib/decide.mjs` 的 `malformedCaller`：`agent_type` 在、却认不出——不是非空字符串（空串、数字、对象、布尔），或者只剩插件前缀
  （`agent-team:`，`stripPluginPrefix` 对它原样返回）。`callerOf` 会把它原样当名字，花名册里查不到，走「花名册外的调用者放行」，一个畸形字段就
  绕过了整个 H1。H1（`decideDelegation`）与 H3（`hooks/gate.mjs` 的写路径那一支，排在主线程豁免之前）共用它，按安全边界拒；拒绝理由
  （`malformedCallerReason`，动作词「派发」或「写入」）叫收件人停下、原样告诉用户（多半是 Claude Code 改了 hook 输入的形状，或者别的插件改写了
  它）。缺失与 null 照旧是主线程（`callerOf` 不动）。字面量 `"__main__"` 当 `agent_type` 那一格照 `docs/39` 保持登记。
- 项目经理（与主线程）被拒时：原来叫它「冒泡给上级」——它没有上级。改成说那个角色由谁派，从花名册现算、不点名门禁内部的哨兵 `__main__`：
  一个派发者时「派它」，几个时「派其中一个」，没有时说它不是这支团队里干活的人。不是项目经理的照旧冒泡。
- H1 的几种理由（白名单、`isolation`、`name`、缺 `subagent_type`）对主线程一律说「主会话」，不写 `__main__`。

### 1.2 第 42 条：带 name 的派发

- `decideDelegation`：受管辖的调用者派白名单里的角色时，带非空 `name` 拒。开了 agent teams 时，带 `name` 的 Agent 调用起的是 teammate，不是
  子代理：门禁按子代理的返回与停下核它交没交、记派发记录，teammate 不走这一条，它停下时门禁看不见（H5a 把 `teammate_spawned` 当成旧版
  CLI 那一格，派出去那一刻就报缺、不记派发记录）。没开时 `name` 只是让子代理能被 `SendMessage` 找到，团队角色用不上它——理由两种情形都说。
  与 `isolation` 同形：排在白名单之后（目标本身不许派时报白名单那条），花名册外的调用者不管。`name` 是调用方这次给的参数，过 `inline`
  （`docs/27` §2.1）。
- README 两半的「已知边界」各加一条：不支持 agent teams 的 teammate。

### 1.3 第 22 条：项目经理只能是主会话

- `decideDelegation`：任何调用者派 `at-pm` 一律拒，排在「花名册外的调用者放行」之前——主会话被换掉时，它就是花名册外的调用者；子代理里的
  `at-pm` 带着项目经理的写权限（契约、控制文件），却不是主会话。裸名 `at-pm` 也拒：门禁按剥前缀的名字认项目经理，起出来的子代理同样会被当成
  它。别的插件的同名 agent（带别的前缀）不归本门禁管。说法按调用者分：项目经理自己（与主线程）——「at-pm 就是你：你自己那几段的产物你自己写，
  不派人」；团队里别的角色——要项目经理做的事写进回报冒泡；花名册外的——只说项目经理只能是主会话，被换掉的主会话由下一条的身份那一句给出路。
- `hooks/lib/gate-check.mjs` 的 `selfCheckIdentity`：hook 输入带 `agent_type`、不是项目经理、没有 `agent_id`（子代理才带）、认得出时，以「注意：」
  开头说发起这次自检（派发、写入）的是谁（设置里的名字，过 `quote`）、设置里的 agent 或者启动时的 `--agent` 换掉了主会话、门禁不把它当项目经理
  （建 run、记 `state.json` 这些项目经理的写入会被拒）、停下来告诉用户出路：去掉设置里的那一项 agent、起会话时不带别的 `--agent`，或者
  `claude --agent agent-team:at-pm` 起会话（CLI 2.1.286 的 `--agent`：「Overrides the 'agent' setting」）。接在自检的「在线」后面，也接在 H1、H3
  （写路径隔离与读不到运行上下文那两支）、H4（契约保护与读不到运行上下文那两支）的拒绝理由后面；别的调用者返回空串。
- README 两半的「已知边界」各加一条：设置里的 `agent`（或启动时别的 `--agent`）会盖掉项目经理，门禁会说出来，出路同上。

### 1.4 第 36 条：state.json 写裸名

- `hooks/lib/state.mjs` 的 `validateState`：`roster`、`stage_roles`、`trimmed` 的键、`never_invoked` 里带插件前缀的角色名各报一次（同一个名字只报一次），
  说写裸名——带前缀的对不上 `stages.json` 的产者名，按段的判据认不出，没有派发记录时缺产物的推进会被放过、【阶段】哑掉。`trimmed` 的键带前缀、
  裸名是产者的，不再另说它「不是任何阶段的产者」；只剩前缀的退化名不说「写裸名」。`roster` 与 `never_invoked` 的交集也报（`/agent-team:at`
  第 6 节叫 PM 写完自查，此前门禁不核）；项目经理被记进 `roster` 或 `stage_roles` 也报（它们记的是叫到的角色，M5f 里 haiku 版 PM 这样记过）。
  这些问题经写 `state.json` 时的账本回传报给项目经理，只报不拦。
- `/agent-team:at` 第 3 节第 4 条：角色名写裸名——派发时 `subagent_type` 写全名，记账不带前缀，四个字段都一样。
- `templates/04-dispatch.md` 第 1 节：不再说「后者写进 state.json 的 never_invoked」——它收口时才算（第 6 节）。

## 4. 仍然开着的边界

- **H1 对花名册外的调用者照旧放行**：主会话被换成花名册外的 agent 时，它能直接派任何团队角色（派 `at-pm` 除外）。门禁不把它当项目经理，
  也就不按花名册管它的派发——身份那一句叫它停下，靠的是它照做。
- **还没有 run 时 H3 对谁都放行**：被换掉的主会话能写 `project.json`、第一次写 run 的 `state.json`（M10d、M10f）；到写 `current-run` 才被拒。
  这是 `/agent-team:at-init` 自举的既有设计，不为这一格改它。
- **身份只认 `agent_type` 与 `agent_id` 在不在**：没有 `agent_id` 的子代理（旧版 CLI 不带它）被拒时，也会收到身份那一句；执行角色不做自检，碰得到
  的只有被拒的写入与派发。
- **teammate 只在 H1 拦**：H5a 照旧把 `teammate_spawned` 当成未知形状；花名册外的调用者带 `name` 起的 teammate 不归门禁管。没开 agent teams 时带
  `name` 的派发也被拒（多一次重派）。agent teams 下 teammate 停下时触发哪个事件、工具表里有没有 `SendMessage`，没量（`docs/39` §6）。
- **`validateState` 只报、不拦，只认本插件的前缀**：带前缀的名字、交集、项目经理进了 `roster` 在写 `state.json` 之后的回传里报，H6 不拒这次写入。
  别的插件前缀、拼错的角色名不报——审查第 36 条原来的修法是剥前缀之后对花名册核，`validateState` 手上没有花名册，测试夹具的阶段也不全。
- **字面量 `"__main__"` 当 `agent_type`**：照 `docs/39` 保持登记——堵它要改门禁内部的哨兵传递。

## 5. 没量到的

- agent teams 下带 `name` 的派发：没开实验开关跑过，H1 拒 `name` 只在判据里量过；teammate 停下时触发哪个事件，照旧没量（`docs/39` §6）。
- 主会话被换掉之后，那个 agent 收到身份那一句会不会停下告诉用户：探针 agent 都是被叫去原样贴出返回，没让它自己定。
- 带前缀的角色名、项目经理进了 `roster` 在真实会话里写进 `state.json` 时的回传：真实会话里项目经理写的一直是裸名，这一格只有判据量过。
